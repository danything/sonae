# 地図の層と出典

地図 (1 つの画面の左の広い所。スマホの形は「地図」のタブ。[docs/ui.md](ui.md)) は MapLibre GL JS で描く (選んだ理由は docs/design.md の 4 章)。
下地は国土地理院のシームレス空中写真 (ズーム 9 から。日本全体を見るような引いた縮尺では NASA の Blue Marble。下の「引いたときの下地」) で、その上に道路・地名・施設の記号 (地理院地図Vector) と付加情報の層を重ねる。**層はいつも全部出し、オン・オフは置かない** (持ち主の決定、2026-11-14)。例外は面を塗る図 (重ねる図。雨雲・雨雲 (いま→予測)・今後の雨・雷・竜巻・キキクル・ハザードマップ・活断層・J-SHIS の図) で、色がぶつかるので、右下の「重ねる」で 1 つだけを選ぶ (既定はなし。選択肢の並びは下の「重ねる図の選択肢」)。選んでいる間は、面で塗る付加情報の色を隠す (下の「ハザードマップを重ねている間」。どの重ねる図でも同じ)。
色の意味は「出典と注意」の窓の「地図の見方」に書く (`#lib/map/style.ts` の `MAP_LEGEND`)。前に層のオン・オフを覚えていた localStorage の `sonae.map.layers` は読まず、開いたときに消す。

機能は Zero Quake の「付加情報を重ねて切り替えられる」ことだけを参考にした。コードは読んでいない。

## 出典の出し方

国土地理院の[出典の記載](https://www.gsi.go.jp/LAW/2930-meizi.html) (確かめた日: 2026-11-15) は、「システムやWebサイトに測量成果を利用する場合、原則、測量成果が表示画面に表示されている間は、常に見えるように表示画面に明示」とする。
そのため MapLibre の出典の (i) (押すまで見えない) は出さず (`attributionControl: false`)、地図の右下に短い出典をいつも出す (`#lib/notice.ts` の `mapCredit`)。

- 見た目は、地図の右下の角にぴったり付けた、余白の無い小さく薄い帯 (字は 10px ほど、地の色を 65% の濃さで敷く。写真の上でも読める。よくある Web 地図の出典の形)。スマホの形では地図の右上の角 (2026-11-15。下のタブと dock のすぐ上では地図の途中に浮いて見えたため。下の端は浮いた下のタブ・dock・右下の操作が重なり、ぴったり付ける角が無い。上の端は何も重ならず、音が止まっているときの帯は地図を押し下げるので、帯にも隠れない)。吹き出しは出典と右下の操作の側へは開かない (`#lib/map/edges.ts`)
- 文は「出典: 国土地理院・気象庁 ほか」。ハザードマップを重ねていて、その図がいまのズームで重なっているとき (`hazardCovers`。活断層はズーム 11 から) は「ハザードマップポータルサイト」(活断層を選んでいるときは「都市圏活断層図」、J-SHIS の図を選んでいるときは「J-SHIS (防災科研)」)、GRUS 画像の範囲 (北緯 20°24′28″〜20°27′21″、東経 136°03′58″〜136°08′25″。沖ノ鳥島のあたり) を写真のタイル (ズーム 13 から) で映しているときは「GRUS画像（© Axelspace）」も足す (地理院タイル一覧の「写真」の備考)。雨雲・今後の雨・雷・竜巻・キキクルを重ねているときは足さない (「気象庁」をもう含む。凡例の下に「気象庁 (高解像度降水ナウキャスト)」「気象庁 (今後の雨)」「気象庁 (雷ナウキャスト)」「気象庁 (竜巻発生確度ナウキャスト)」「気象庁 (キキクル)」を出す)
- 押すと「出典と注意」の窓が開き、規約の文言どおりの全文 (`CREDITS`) とリンクがある。地理院タイルは「出典：国土地理院（地理院タイル…）」と[地理院タイル一覧](https://maps.gsi.go.jp/development/ichiran.html)へのリンク、加工したものは「地理院タイルに震度・警報等の区域・避難場所・ハザード情報等を追記して掲載」
- 都市圏活断層図は、一覧の備考の「引用する場合は、調査者名を明記」に沿い、調査者が図ごとに違うので、国土地理院の「活断層図（都市圏活断層図）について」(各図の調査者がある) へのリンクと例を書く。活断層を選んだときは、凡例の代わりに同じページへのリンクを地図の右下に出す。画面にいま映っている図の調査者を出すことはしていない
- 写真は窓にいつも Landsat8・GEBCO・GRUS (© Axelspace) を書く。引いたときの Blue Marble は「NASA Earth Observatory」と GIBS の謝辞の文を窓に書く (隅の短い出典には足さない。NASA は常に見せる出典を求めていない)

**一覧で選んだ地震の、電文に並ぶ震度観測点を、気象庁の地図と同じく震度の色の丸で置く** (持ち主の決定、2026-11-19)。
観測された震度をその観測点に置くだけで、観測点の間を補って面で塗ることも、観測点の無い所の震度を推し量ることもしない (docs/design.md の 5 章)。描くのは `#lib/map/stations.ts` の `stationFeatures` と、`#lib/map/style.ts` の層 `intensity-stations`。

### 電文の観測点の引き方

- **気象庁の XML (VXSE53):** 観測点のコード (`IntensityStation/Code`) で引く。電文を読むときにコードを持たせる (`StationIntensity.code`)。コードを持たせる前に保存した報は名前で引く
- **P2P地震情報:** 名前で引く (コードが無い)。都道府県は見ない (名前が全国で重ならないため)
- 名前は、後ろの「＊」(気象庁以外の観測点の印。XML だけに付く) と前後の空白を外してから引く (`stationKey`)
- 「5弱以上未入電」の観測点は、震度が決まっていないので点にしない (詳しい内容の一覧には出る)
- **位置の引けない観測点は出さない。** 数と名前を、詳しい内容の「観測点の震度」の下に「地図に出していない観測点 (n 点。位置の表にありません): …」と出す。地図が置いたとき (`QuakeMap` の `onstations`) に数える

### 見た目

- 色は震度の色 (docs/design.md の 4 章、配色の指針 表 2-2)。大きい震度ほど上に描く (`circle-sort-key` に震度の順位)。震度 1 の白い丸も写真の上で見えるよう、黒い細い縁 (不透明度 0.65) を付ける
- 丸の大きさはズームで変える (半径 ズーム 4 で 2.5 px・7 で 4・10 で 7・13 で 9)。丸の中に数字は書かない。数字を入れられる大きさにすると、引いたときに丸が重なって読めない。数字は地域のラベルにあり、観測点ごとの値は詳しい内容の一覧で読む
- 置き場は震源の丸と海外の地震の丸の上、地名の注記と避難場所の印の下 (選んだ地震の中身なので震源より上。地名は読めるように残す)
- **地域ごとの塗りは消さず、観測点の丸を出している間は、寄せるほど薄くする** (不透明度をズーム 6 で 0.75 から 9 で 0.3 へ。`quakeFillOpacity`)。引いているときは数百〜千の丸が重なり、地域の塗りが全体の見当になる。寄せると丸が離れて観測点ごとに読めるので、塗りは下地に回す。拡大で塗りを消して切り替える形にしなかったのは、境のズームで見た目が急に替わるのと、観測点の少ない地域 (島や山の中) で塗りが無くなると震度が読めなくなるため。地域のラベル (数字) はいつも残す
- ハザードマップを重ねている間は、地域の塗りは隠し、観測点の丸は残す (下の「ハザードマップを重ねている間」)
- 地震を選んでいる間は、気象警報・注意報の塗りを隠す (下の「地震を選んでいる間」)
- 重さ: 点は 1 つの GeoJSON の source と circle の層で、選んだ地震が替わったときだけ差し替える。2026-11-19 の熊本県天草・芦北地方の地震 (最大震度 5 弱) は 578 点。DOM の印は使わない (地域のラベルと震央の × だけ)

### 押したとき

**丸を押すと、その観測点の吹き出しを出す** (2026-11-19。持ち主の声「観測点ってクリックしても場所の詳細見れないの？」)。部品と見た目は、避難場所と気象警報・注意報の吹き出しと同じ (MapLibre の Popup。メニューと同じ面と影。隅の出典と右下の操作の側へは開かない)。中身は `#lib/map/stations.ts` の `stationPopup` が組み、点の properties に持たせる。

- 中身は上から次の 4 つ
  - 観測点の名前。後ろの「＊」は外す。「＊」は気象庁以外の観測点の印で、設置者を文で出すため
  - 震度。一覧の震度と同じ色のラベル (「震度5弱」)
  - 都道府県と市町村 (「静岡県・西伊豆町」)。都道府県は観測点のコードの上 2 桁、市町村は位置の表から
  - 設置者 (「気象庁の観測点」「地方公共団体の観測点」「防災科学技術研究所の観測点」)。位置の表の `affi` から。表に無ければ、XML の「＊」の有無で「気象庁以外の観測点」か「気象庁の観測点」だけを出す (P2P は印が無いので出さない)
- 押せる範囲は丸より広い。指は押した所から 22 px (44 px 四方。denpa の design.md の押せる大きさ)、マウスは 10 px。範囲に幾つもあるときは、押した所にいちばん近いもの、同じ近さなら大きい震度 (上に描いているもの) を選ぶ (`nearestStation`)。指かどうかは押したときの `pointerType` で見る。マウスでは丸の上でだけ指の形にする
- メニューを開いている間と、長押しの指を離したときは出さない (ほかの吹き出しと同じ。下の「地図のメニュー」)
- 吹き出しは地図の上に 1 つだけ。開くと、ほかの吹き出しを閉じる。選んだ地震か報が替わったときも閉じる (前の中身のため)
- キーボードでは丸を選べない (避難場所の印と警報・注意報の面も同じ)。観測点ごとの震度は、詳しい内容の「観測点の震度」の一覧で読める。地図にフォーカスがあるときは、Esc で開いている吹き出しを閉じる (読み上げを止める Esc より先)

### 表を作り直すとき

コード表は観測点を移すたびに更新される (技術資料のページの更新履歴)。更新されたら、次の順で作り直す。

1. 技術資料のページからコード表の zip (`jmaxml_<日付>_Code.zip`) を落とし、作業用の所に置く
2. `wslc run --rm -v "$PWD:/w" -w /w oven/bun:1.4.5-slim bun tools/stations/build.ts <zip>` (位置の表は気象庁ホームページから取る。手元の写しを 2 つ目の引数で渡してもよい)
3. 出てくる「位置の無い観測点」と「使わなかった位置」を見る
   - 使わなかった位置があれば、改名か、コード表から外れた前の観測点。bosai の地震 JSON か電文でコードを確かめて、`extra.tsv` に出どころと一緒に足す
   - 「もう名前で結び付きます」と出た `extra.tsv` の行は消す
   - 位置の無い観測点は、位置の表が更新されるのを待つ (この docs の数も直す)
4. 出てくる「設置者の分からない観測点」と「市町村の分からない観測点」を見る (0 でなければ、その観測点の吹き出しに設置者か市町村が出ない)
5. 大きさをこの docs に書き直し、テスト (`tests/map-stations.test.ts`) を通す

## 押せる所が重なったとき

**いちばん上に描いているもので、押して何かが起きるものだけを選ぶ。** 吹き出しも選ぶ地震も持たない印は、押しても下のものに渡す。押せる所の順は描く順と同じにする (持ち主の決定、2026-11-21)。上から次の順。

| 押した所にあるもの (上から)                                         | 押したとき                                                                                                                      |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 震央の ×・震度のラベル・火山の印 (DOM の印)                         | 何も持たないので、下のものに渡す                                                                                                |
| 避難場所の印                                                        | 避難場所の吹き出しだけ                                                                                                          |
| 観測点の丸 (地震を選んでいるとき。押せる範囲は丸より広い)           | 観測点の吹き出しだけ                                                                                                            |
| 火山の監視カメラの印 (押せる範囲は印より広い)                       | カメラの吹き出しだけ                                                                                                            |
| 海しるの点 (押せる範囲は点より広い)                                 | 海しるの点の吹き出しだけ                                                                                                        |
| 台風のいまの中心・予報円の中心 (押せる範囲は点より広い)             | 台風の吹き出しだけ (同じ近さなら、いまの中心)。予報円・暴風警戒域などの線・これまでの経路の線と点は押しても何も出さず、下に渡す |
| 通行止め (災害) の線・通れた道 (目安) の線 (押せる範囲は線より広い) | 線の吹き出しだけ (通行止めが先)                                                                                                 |
| 震源の丸・海外の地震の丸 (押せる範囲は丸より広い)                   | その地震を選ぶ (一覧で選んだのと同じ。下の「震源の丸を押したとき」)                                                             |
| 気象警報・注意報で塗った市町村等                                    | 警報・注意報の吹き出し。地震を選んでいる間と重ねる図を選んでいる間は塗らないので出さない                                        |
| 地域の震度の塗り                                                    | 何も出さない (値は地域のラベルと詳しい内容で読む)                                                                               |

- 震央の × は何も持たない (震源は詳しい内容で読む)。× を受け止めて何も出さないと、震央のすぐそばの観測点と震源の丸を押せなくなるので、下に渡す
- 地域の震度の塗りに吹き出しは付けない。地域の値はラベルにいつも出ている
- 台風の線 (予報円・暴風警戒域・暴風域・強風域) は何も持たない。どれも数百 km の大きな円で、押せるようにすると、その中の警報・注意報の面や震源の丸を押せなくなる。押せるのは中心の点だけにする
- 震源の丸は、通行止めと通れた道の線・海しるの点の下に描く (2026-11-21 から。前は線と点の上)。大きく半分透けた丸の上に細い線と小さな点を描くと、両方が見えて押し分けられる。台湾・有志の観測点の揺れは、今までどおり震源の丸の下

## 震源の丸を押したとき

**震源の丸 (新しい 50 件の地震) を押すと、一覧でその地震を選んだのと同じになる** (持ち主の決定、2026-11-21)。海外の地震の丸も同じ。押した所から選ぶ地震を決めるのは `#lib/map/epicenters.ts` の `nearestEpicenter`。

- 詳しい内容を出し、URL の query は一覧の行を押したときと同じ (`?q=…`。海外の地震は `?f=…`) にする。地図には、選んだ地震の震度の塗りと数字・観測点の丸・震央の × を出す。海外の地震は × を出し、地図を引いて (ズーム 4) そこへ寄せる。どれも一覧で選んだときの決まりのまま
- スマホの形では一覧のタブへ移り、詳しい内容を出す (吹き出しから府県予報区の警報・注意報を開いたときと同じ)
- 押せる範囲は丸より広い。観測点の丸と同じく、指は押した所から 22 px (44 px 四方)、マウスは 10 px。丸の半径がそれより大きいときは、丸の中ならどこでも押せる。丸の大きさは M から `radiusAt` で求め、地図の式 (`radiusExpr`) と同じ段を使う。範囲に幾つもあるときは、中心が押した所にいちばん近いもの、同じ近さなら上に描いているもの (海外の地震、同じ層では新しいもの) を選ぶ
- マウスでは丸の上で指の形にする
- メニューを開いている間と、長押しの指を離したときは選ばない (吹き出しと同じ)
- キーボードでは丸を選べない (観測点の丸と同じ)。地震は一覧で選べる

## 雨雲

**右下の選択で「雨雲」を選ぶと、気象庁の高解像度降水ナウキャストの「いま」の降水強度を写真の上に重ねる** (2026-11-20。持ち主の声「sonae に気象レーダーとか追加してよ」)。決まりは `#lib/map/rain.ts` と、`#lib/map/style.ts` の `rainShown`・`rainVisibility`・`overlayVisibility`。確かめた日: 2026-11-20。

### 選ぶ層にしたわけ

- 雨雲の色は気象庁の配色の指針の表 2-1 (降水量) で、震度の色 (表 2-2) と 6 色が同じ (180,0,104・255,40,0・255,153,0・0,65,255・242,242,255 など)、警報・注意報の赤・黄 (表 1-1) ともほぼ同じ。いつも重ねると、警報・注意報の塗りと見分けられない
- そのため、ハザードマップと同じく「1 つだけ選ぶ」選択に入れた。ハザードマップと雨雲は同時に出さない (どちらも面を塗る)。既定はなし。選んだものは端末に覚える (`sonae.map.hazard` の `rain`)
- 選択のボタンの文言と選択肢の並びは、下の「重ねる図の選択肢」

### 出し方

- **配信:** 時刻の表 `targetTimes_N1.json` (いまと過去 3 時間、5 分ごと。`Cache-Control: max-age=60`) から、`basetime` と `validtime` が同じ (観測) でいちばん新しいものを選び、その時刻のタイルを読む。タイルは `max-age=86400` で、時刻ごとに URL が替わる。どちらも CORS は `*`
- **ズーム:** タイルは偶数のズーム (4・6・8・10) にしか無く、ほかのズームは雨の無い所と同じ空のタイル (334 バイト) が返る。そこで段ごとに source を分け (`rain-4`〜`rain-10`。source の minzoom と maxzoom を同じにする)、層は地図のズーム n − 1 から n + 1 の手前で出す (MapLibre の地図のズーム z は 256px のタイルの z + 1 を読むため。10 より寄せたら 10 を引き伸ばす)。MapLibre は見えない層の source を読まないので、読むのはいまの段だけ
- **見た目:** 不透明度 0.8。引き伸ばしても色を混ぜない (`raster-resampling: nearest`。凡例に無い色を作らない)。差し替えで動きを付けない (`raster-fade-duration: 0`)。置き場はハザードマップと同じ写真のすぐ上
- **凡例:** 右下の操作の上に、凡例 (8 色と mm/h の区切り。指針の表 2-1 のまま) と出典 (気象庁 (高解像度降水ナウキャスト) と、予測は出さないこと) を出す
- **時刻:** 凡例の先頭に「11/20 23:25 の観測 (5 分ごとに更新)」と出す。古い雨雲をいまの雨と取り違えないよう、いつも出す。最後に取りに行った時点で観測が 15 分より古ければ (3 回続けて更新が取れていない)、注意のアイコンと「… の観測です。新しい雨雲を読めていないため、いまの雨ではありません」に替える。まだ 1 枚も読めていないときは「雨雲を読み込めませんでした。1 分後に再試行します」
- **重さ:** 時刻の表は、いまの観測の次の時刻が出そろう頃 (観測の時刻 + 5 分 + 90 秒。表は観測の約 20 秒後に書き換わり、CDN が 60 秒覚える) に取る。まだ替わっていなければ 1 分後に取り直す。取るのは雨雲を出している間だけで、画面が見えていない間 (`visibilitychange`) と地震を選んでいる間は止める。見えるようになったらすぐ取る。タイルは日本全体で 20 枚ほど (雨の無い所は 334 バイト、雨の所で 1〜7 KB)、5 分に 1 度。時間で動くものは無いので、`data-lite` で止めるものも無い
- **ブラウザから直接読む。** sonae のサーバーで取って配り直す形にはしない。規約は直接の読み込みを禁じておらず (下の「規約」)、配信は CDN (CloudFront) で、1 つの家の数台が 5 分に 1 度読む量は小さい。サーバーを通すと家の回線を 2 度通り (取る・配る)、サーバーにタイルを覚える場所と処理が要る。端末の IP は気象庁に届く (地理院タイル・ハザードマップと同じ)。時刻の表は Cookie と Referer を付けずに取る

### 規約と気象業務法

- 気象庁ホームページの[利用規約](https://www.jma.go.jp/jma/kishou/info/coment.html)は、権利表記の無いコンテンツを公共データ利用規約 第 1.0 版で使えるとする。例外はロゴ・キャラクターと、別のルールを明示したものだけで、ナウキャストのタイルは当たらない。サイトは「リンクフリー」。機械で取りに行くことや、画像を直接読み込むことを禁じる記述は無い (2026-11-20 に読んだ)
- 「[ご利用上の留意事項](https://www.data.jma.go.jp/developer/ryuui.pdf)」(平成 29 年 3 月) は、二次利用は気象業務法の趣旨に反しない限り制限が無く商用も可、出典の明記、加工したら加工したことと編集の責任を書く、とする。コンテンツは予告なく変わる
- **気象業務法 17 条 (予報業務):** 留意事項は「観測資料に基づいた独自の予想を他者に繰り返し提供したりすることは、独自の予報をする業務に該当します」とする。sonae は気象庁が作った観測の 1 枚を、色も値も変えずに地図に重ねるだけで、外挿・合成・補間で先の雨を予想しない。予報業務の許可の[よくある質問](https://www.jma.go.jp/jma/kishou/minkan/q_a_m.html)も、気象庁の予報を解説するだけなら許可は要らず、格子の値を空間内挿などで意味を変えると独自の予報になる、とする。気象庁の 1 時間先の予測 (`targetTimes_N2.json`) をそのまま出すのも予報業務には当たらないと読んだ。雨雲に並べないわけは下の「今後の雨」
- 2021 年 8 月に気象庁ホームページがアクセスの集中で見にくくなったことがある ([報道発表](https://www.jma.go.jp/jma/press/2108/20a/210820_HPtaisaku.pdf))。sonae が読むのは雨雲を選んで画面を見ている間だけで、5 分に 1 度に絞る

### 雨雲を重ねている間

ハザードマップを重ねている間と同じ層を隠す (`overlayVisibility` の `HIDDEN_UNDER_HAZARD`。下の「ハザードマップを重ねている間」の表の「雨雲・今後の雨・雷・竜巻・キキクル」の行)。凡例の下に「色がぶつからないよう、警報・注意報の塗りを隠しています (特別警報・緊急地震速報は縁取りで出します)。「なし」に戻すと元に戻ります。」と書く (通れた道の線を出していれば「警報・注意報の塗り・通れた道 (目安) の線を隠しています」。線を描かないズーム 13 以上では書かない)。

## キキクル

**右下の選択の見出し「キキクル (危険度分布)」で「土砂」か「大雨 (浸水・洪水)」を選ぶと、気象庁のキキクルのいまの危険度を写真の上に重ねる** (2026-11-21)。決まりは `#lib/map/risk.ts` と、`#lib/map/style.ts` の `riskShown`・`riskVisibility`・`overlayVisibility`。確かめた日: 2026-11-21。

### 選択肢を土砂と大雨の 2 つにしたわけ

- 気象庁は 2026 年 5 月 29 日からの新しい防災気象情報で、浸水キキクルと洪水キキクルを重ねた「大雨キキクル」を新しく出した (気象庁の[気象白書 2026 の特集](https://www.jma.go.jp/jma/kishou/books/hakusho/2026/index3.html)、[キキクルの改善の報道発表](https://www.jma.go.jp/jma/press/2602/24a/20260224_kikikuru.html))。キキクルの画面 (`https://www.jma.go.jp/bosai/risk/`) の設定 `risk.properties` (2026-05-25 版) にも、土砂 (`land`)・大雨 (`rain_mesh`)・浸水 (`inund`)・洪水 (`flood`) の 4 つが並ぶ。大雨の凡例は「大雨の危険度 ※低地の浸水や中小河川の氾濫のおそれ」
- 4 つを全部並べると、選択の中身が 2 つ増え、ハザードマップの「土砂災害」「洪水」と名前が似たものが増えてうるさい。大雨は浸水と洪水を重ねたものなので、浸水と洪水を別に並べなくても、どこで危険度が上がっているかは大雨で見える。そこで土砂と大雨の 2 つにした (浸水だけ・洪水だけを見たいときは、凡例の下の出典のリンクから気象庁の画面へ行ける)
- 洪水キキクルの川の線 (ベクトルタイルの `flood` と、指定河川の GeoJSON `designated_river`) は入れていない。大きな川 (指定河川) の氾濫は、指定河川洪水予報 (一覧の「気象」) で出している。川の線の描き方を決めるのは後 (docs/design.md の 9 章)
- 選んだものは端末に覚える (`sonae.map.hazard` の `risk-land`・`risk-heavyrain`)。ボタンの文言は下の「重ねる図の選択肢」

### 出し方

- **配信:** 時刻の表 `https://www.jma.go.jp/bosai/jmatile/data/risk/targetTimes.json` (10 分ごと、いまと過去 6 時間ほど。`Cache-Control: max-age=60`) から、選んだ要素 (`land` か `rain_mesh`) を含み、`basetime` と `validtime` が同じ行のいちばん新しいものを選ぶ。タイルの URL の途中には行の `member` を入れる (新しい 3 枚は `immed0`〜`immed2`、それより前は `none`。どちらも同じタイルが返る)。タイルは `max-age=86400` で、時刻ごとに URL が替わる。どちらも CORS は `*`
- **ズーム:** 雨雲と同じく、タイルは偶数のズーム (4・6・8・10) にしか無く、ほかのズームは何も塗っていない空のタイル (334 バイト) が返る (キキクルの画面の設定も `zoomUse="even"`)。段ごとに source を分け (`risk-4`〜`risk-10`)、層の出すズームも雨雲と同じ (`rainLayerZoom`)。土砂と大雨は同じ source の URL を替えて使う
- **見た目:** 不透明度 0.8。引き伸ばしても色を混ぜない (`raster-resampling: nearest`)。差し替えで動きを付けない (`raster-fade-duration: 0`)。置き場は雨雲と同じ写真のすぐ上
- **色と凡例:** タイルの PNG のパレットは 12,0,12 (黒)・170,0,170 (紫)・255,40,0 (赤)・242,231,0 (黄) の 4 色と、透明 (いちばん低い「今後の情報等に留意」の白) だけ (2026-11-21 に読んだ)。気象庁の配色の指針の表 1-1 (大雨の警戒レベルと相当する情報) の 5〜2 相当の色と同じで、色はタイルのまま変えない。凡例は 4 段を危険度の高いものから並べ、言葉はキキクルの凡例のまま「災害切迫 (レベル 5 相当)」「危険 (レベル 4 相当)」「警戒 (レベル 3 相当)」「注意 (レベル 2 相当)」(キキクルの凡例の「警戒レベル」は、スマホの形で凡例の幅に収めるため「レベル」と書く)。下に、何の危険度かと「色が無い所は「今後の情報等に留意」です」、出典「気象庁 (キキクル)」を書く。大雨では「大きな川の氾濫は、一覧の「気象」の指定河川洪水予報を見てください」を足す
- **時刻:** 凡例の先頭に「11/21 00:50 の危険度 (10 分ごとに更新)」と出す。表はその時刻の約 10 分 10 秒後に書き換わるので、ふだんでも 10〜21 分前の判定になる。最後に取りに行った時点で判定が 40 分より古ければ (2 回続けて更新が取れていない)、注意のアイコンと「… の危険度です。新しいキキクルを読めていないため、いまの危険度ではありません」に替える。まだ読めていないときは「キキクルを読み込めませんでした。1 分後に再試行します」。土砂と大雨を選び替えたら、前の 1 枚は使わずに読み直す
- **重さ:** 時刻の表は、次の時刻が表に載る頃 (判定の時刻 + 10 分 + 11 分 30 秒。表が書き換わる 10 分 10 秒と、CDN が覚える 60 秒に、20 秒の余裕を足す) に取る。まだ替わっていなければ 1 分後に取り直す。取るのはキキクルを出している間だけで、画面が見えていない間 (`visibilitychange`) と地震を選んでいる間は止める。タイルは日本全体で 20 枚ほど (塗る所の無いタイルは 334 バイト)、10 分に 1 度
- **ブラウザから直接読む。** 雨雲と同じわけで、sonae のサーバーで取って配り直す形にはしない

### 規約と気象業務法

- 規約は雨雲と同じ気象庁ホームページの[利用規約](https://www.jma.go.jp/jma/kishou/info/coment.html) (公共データ利用規約 第 1.0 版) と[留意事項](https://www.data.jma.go.jp/developer/ryuui.pdf)。キキクルの画面に別のルールの明示は無い (2026-11-21 に読んだ)
- **気象業務法 17 条 (予報業務):** キキクルは、気象庁が雨の実況と予測から判定した危険度。sonae は判定した結果のタイルを色も値も変えずに重ね、いつの判定かと出典を出すだけで、危険度を判定し直さない。気象庁の情報の中継にとどまると読んだ (docs/design.md の 5 章)

### キキクルを重ねている間

雨雲と同じく、ハザードマップを重ねている間と同じ層を隠す (下の「ハザードマップを重ねている間」の表の「雨雲・今後の雨・雷・竜巻・キキクル」の行)。キキクルの黄・赤・紫・黒は、警報・注意報の塗りと同じ色 (指針の表 1-1) なので、塗りを残すとどちらの色か読み分けられない。凡例の下に、雨雲と同じ一言を書く。
特別警報の縁取り (白い縁の黒い線) は、キキクルの黒 (災害切迫) の上でも白い縁で見分けられる。

## 雷・竜巻

**右下の選択の見出し「雨・雷・竜巻」で「雷 (いま)」か「竜巻 (いま)」を選ぶと、気象庁の雷ナウキャストか竜巻発生確度ナウキャストの、いまの解析を写真の上に重ねる** (2026-11-21。docs/design.md の 9 章の未決を決めた)。決まりは `#lib/map/nowc.ts` と、`#lib/map/style.ts` の `nowcShown`・`nowcVisibility`。確かめた日: 2026-11-21。

- **選ぶ層にしたわけ:** 雷の色 (活動度 4 は 200,0,255、3 は 255,40,0) と竜巻の色 (確度 2 は 255,40,0) は、津波・火山・警報・注意報・震度の色と同じ。雨雲と同じく、いつも重ねると読み分けられないので、1 つだけ選ぶ選択に入れた。雨雲と同時には出さない
- **配信:** 時刻の表 `targetTimes_N3.json` (10 分ごと。`Cache-Control: max-age=60`) から、`basetime` と `validtime` が同じで要素 (`thns` か `trns`) を含む、いちばん新しい行を選ぶ (`latestAnalysis`)。1 時間先までの予測の行 (`validtime` が先) は使わない。タイルは `max-age=86400`。CORS は `*`
- **ズーム:** 気象庁の画面の設定 (`nowc.properties`) は `zoomUse="even"`・`maxNativeZoom` 9 で、タイルはズーム 4・6・8 にだけある (ほかは 334 バイトの空のタイル)。雨雲と同じく段ごとに source を分け (`nowc-4`〜`nowc-8`)、8 より寄せたら 8 を引き伸ばす。雷と竜巻は同じ source の URL を替えて使う
- **見た目:** 不透明度 0.8。引き伸ばしても色を混ぜない (`raster-resampling: nearest`)。差し替えで動きを付けない
- **凡例:** 色は気象庁の画面の凡例 (`legend_jp_normal_thns.svg`・`legend_jp_normal_trns.svg`) とタイルのまま。雷は 4 段 (4 激しい雷・3 やや激しい雷・2 雷あり・1 雷可能性あり)、竜巻は 2 段 (2 可能性があり注意が必要・1 可能性がある)。下に何の解析かの 1 文と出典
- **時刻:** 凡例の先頭に「11/21 02:00 の解析 (10 分ごとに更新)」。35 分より古いものしか読めていないときは、注意のアイコンと「…の解析です。新しい解析を読めていないため、いまのものではありません」に替える
- **重さ:** 時刻の表は、次の解析が載る頃 (解析の時刻 + 10 分 + 5 分) に取り、まだなら 1 分後に取り直す。取るのは出している間だけで、画面が見えていない間と地震を選んでいる間は止める
- **規約と気象業務法:** 雨雲と同じ気象庁ホームページの利用規約。気象庁が解析した 1 枚を色も値も変えずに重ねるだけで、sonae が雷や竜巻を予想することはしない (docs/design.md の 5 章)

## 今後の雨

**右下の選択で「今後の雨 (予測)」を選ぶと、気象庁の降水短時間予報 (今後の雨) の 1 時間の雨量の予測を重ねる** (2026-11-21。docs/design.md の 9 章の未決を決めた)。決まりは `#lib/map/nowc.ts` の `forecastFrames` と、`#lib/map/style.ts` の `rasrfVisibility`。確かめた日: 2026-11-21。

- **入れたわけ:** 持ち主の頼み「災害の事前の情報を見られるようにしたい」の、先の雨の情報にあたる。気象庁の予測を色も値も変えずに出すので、気象庁の情報の中継にとどまる (docs/design.md の 5 章)
- **配信:** 時刻の表 `https://www.jma.go.jp/bosai/jmatile/data/rasrf/targetTimes.json` (`Cache-Control: max-age=60`)。予測の行 (`validtime` が `basetime` より先で、要素に `rasrf` を含む) のうち、いちばん新しい `basetime` の行を先の時刻の順に並べる。30 分ごとの速報 (`member` は `immed`) は 6 時間先まで、毎正時の予報 (`none`) は 15 時間先まで、1 時間ごと。タイルの URL の途中には行の `member` を入れる (入れないと 404)
- **ズーム:** 雨雲と同じく 4・6・8・10 (`rasrf-4`〜`rasrf-10`)
- **いまの雨と取り違えない見せ方:** 凡例の見出し (「今後の雨 (1 時間の雨量 mm)」) の下に「11/21 03:50 までの予測」を大きく (`--so-text-lg` の太字) 出し、下に「2 時間先」、さらに「11/21 01:50 の解析にもとづく気象庁の予測です。いまの雨ではありません。」と書く。選択肢とボタンの名前も「今後の雨 (予測)」
- **時刻の動かし方:** ‹ › のボタンで 1 時間ずつ動かす (押せる大きさは 44px)。**この選択肢では、自動で枚を替える再生はしない。** 地図の上が動き続けてうるさいため。いまと先の雨を自動で見せ続けたいときは、別の選択肢「雨雲 (いま→予測)」(下の節) を選ぶ。‹ › は凡例の中に置くので、地図の上の操作は増えない。新しい予測が来ても、選んでいる何番目 (何時間先) かは保つ
- **色と凡例:** 気象庁の画面の凡例 (`legend_jp_normal_rasrf.svg`) の 8 色と区切り (1 時間の雨量 mm)。配色の指針の表 2-1 と同じ区切り
- **古さ:** 解析の時刻から 80 分より経ったら (2 回続けて新しい予測が取れていない)、注意のアイコンと「新しい予測を読めていません」を足す
- **重さ:** 時刻の表は出している間だけ 10 分ごとに取る。タイルは選んでいる 1 枚だけを読む (先の時刻の枚は ‹ › で選んだときに読む)
- **雨雲の 1 時間先の予測は入れない:** 高解像度降水ナウキャストの 5 分ごとの予測 (`targetTimes_N2.json`) は、今後の雨と同じ雨の予測で、並べると取り違えやすく時刻の操作も 2 つ要るため。雨雲は観測の「いま」の 1 枚のまま

## 雨雲 (いま→予測)

**右下の選択で「雨雲 (いま→予測)」を選ぶと、雨雲のいまの観測と、今後の雨の 1・2・3 時間先の予測を、決めた間で順に自動で見せ続ける** (2026-11-28。使う人の声「車で雨雲レーダーアプリを動かすことが多いが、現在と未来の雨雲を自動で表示し続けてくれると嬉しい」に、持ち主が「別レイヤーとして、地図のレイヤーを重ねたら、その画面にする」と決めた)。**自動で枚を替える再生は、この選択肢を選んだときだけ** (持ち主の決定、2026-11-28)。ほかの選択肢 (雨雲・今後の雨など) は、これまでどおり動かない。決まりは `#lib/map/rain-loop.ts` と、`#lib/map/style.ts` の `loopShown`・`loopVisibility`・`loopOpacity`。

- **見せる枚:** 0 枚目が雨雲 (高解像度降水ナウキャスト) のいまの観測 (上の「雨雲」と同じ時刻の表とタイル)、1〜3 枚目が今後の雨 (上の「今後の雨」と同じ表) の予測のうち、いまの観測より先の時刻のものを近い順に 3 枚 (`loopForecast`)。予測は 1 時間ごとなので、ふつうは 1・2・3 時間先。予測がまだ読めていない・足りないときは、読めた枚だけを回る。どれも気象庁の 1 枚を色も値も変えずに出すだけで、枚の間を補う (なめらかにつなぐ) ことはしない (docs/design.md の 5 章)
- **間:** 1 枚 2.5 秒 (`LOOP_FRAME_MS`)。最後の枚 (いちばん先の予測) は 4.5 秒 (`LOOP_LAST_MS`) 止めてから、いまへ戻る。1 回りは 12 秒ほど
- **替え方:** 枚ごとに source と層を分け (`rainloop-<枚>-<ズーム>`。段は雨雲と同じ 4・6・8・10)、読めた枚の層は全部出して、見せる枚だけ透明度を雨雲と同じ 0.8 にし、ほかは 0 にする (`setPaintProperty`)。MapLibre は透明度 0 の層を描かないが、タイルは読んだまま持つので、替えたときに白く抜けない。透かしの移り変わり (`raster-opacity-transition`) は 0 にし、動きは付けない (移り変わりを付けると、その間 MapLibre が描き続ける)。次の枚のタイルがまだ読めていなければ、0.5 秒ずつ 5 秒まで待ってから替える (雨の無い所のように見せない)
- **時刻の見せ方:** 凡例の先頭に、見せている枚を大きく (`--so-text-xl` の太字)「いま」か「+1 時間」のように出し、前に「観測」か「予測」の印 (予測は主の色の地) を付け、横に「11/28 14:25 の観測」「11/28 16:00 までの 1 時間」と時刻を書く。「+N 時間」は今後の雨と同じく予測の解析の時刻から何時間先か (`hoursAhead`)。下に「いま」「+1」「+2」「+3」のチップ (読み上げは「+1 時間」のように。同じ幅で 1 行に並べ、押せる高さは 44px。スマホの形の細い凡例 (12rem) にも入る) を並べ、見せている枚に下線を引く。枚が替わるたびに読み上げると止まらないので、`aria-live` は付けない
- **止める・選ぶ:** 大きな時刻の右の ⏸ で止め、▶ でまた始める。チップを押すとその枚で止まる。選び直すと、いまから自動で始める
- **自動で替えないとき:** 画面が見えていない間 (`visibilitychange`。裏のタブ・閉じた画面) と、地震を選んでいる間 (雨雲を隠す) は止める。ソフトウェアで描いている端末 (`<html data-lite>`。`#lib/lite.ts`) と動きを減らす設定 (`prefers-reduced-motion`) では、初めから止めて「この端末では自動で替えません。▶ を押すか、時刻を選んでください。」と書く。▶ を押せば、その端末でも替える (人が選んだので)
- **重さ:** 時刻の表は、雨雲と今後の雨の決まりのまま (雨雲は 5 分ごと、今後の雨は 10 分ごと) で、出している間だけ取る。タイルは 4 枚分 (日本全体で 80 枚ほど、1 枚 1〜7 KB)。新しい観測・予測が来たら、その枚の URL だけを差し替える (同じ URL は差し替えない)。地図を描き直すのは 2.5 秒ごとの 1 回だけ
- **古さ:** 雨雲の観測が 15 分より古い・今後の雨の解析から 80 分より経った・まだ読めていないときは、チップの下に注意のアイコンと「新しい雨雲を読めていないため、いまの雨ではありません」「新しい予測を読めていません」などを書く
- **凡例:** 色は雨雲と今後の雨で同じ 8 色と区切り (気象庁の配色の指針の表 2-1)。単位が違うので「観測は降水強度 (mm/h)、予測は 1 時間の雨量 (mm)」と書く。出典は「気象庁 (高解像度降水ナウキャスト)・気象庁 (今後の雨)」
- **ほかの重ねる図との関係:** ほかの重ねる図と同じく、1 つだけ選ぶ選択の 1 つ。ハザードマップ・キキクルなどとは併用しない (雨雲の色が浸水深・警戒区域・キキクルの色とぶつかって読めない。上の「選ぶ層にしたわけ」)。選んでいる間は、雨雲と同じ層を隠す (下の「ハザードマップを重ねている間」)
- **現在地:** 追う決まりは変えない (下の「現在地を自動で始めるとき」。初めに取れた所へ 1 回寄せるだけ)。車で動きながら見るなら、現在地を画面の真ん中に保ち続ける形 (人が地図を動かすまで) が要るかもしれない。決めていない (docs/design.md の 9 章)

## 線状降水帯

**気象庁が線状降水帯の雨域を解析している間だけ、その範囲を白い縁の赤い線で囲む。重ねる図の選択とは別に、いつも出す層にする** (2026-11-21)。決まりは `#lib/map/nowc.ts` の `slmcsFeatures` と、`#lib/map/style.ts` の層 `slmcs-casing`・`slmcs-line`。

- **いつも出すわけ:** 層はいつも全部出す決まり (この docs の冒頭) で、線状降水帯は災害の危険度が急に高まっていることを伝える情報。線で囲むだけなので、警報・注意報や震度の面の色を隠さず、地震を選んでいる間・重ねる図を選んでいる間も出す。出ていないときは何も描かない
- **見た目:** 気象庁の画面 (`nowc.properties` の `slmcs_unify`。白い縁の赤い線、幅 4) に合わせ、白い縁 (幅 6) の上に赤 (255,0,0、幅 3)。通行止めの線 (白い縁の赤) と似るが、楕円の形で道路の線と見分けられる
- **置き場:** 警報・注意報の面と住んでいる地域の縁取りの上、台湾・有志の観測点と震源の丸の下。押しても何も出さない
- **配信:** 画面が見えている間は、時刻の表 `targetTimes_N3.json` を 10 分ごと (次の解析が載る頃) に取り、`slmcs_unify` を含むいちばん新しい解析の GeoJSON (`…/surf/slmcs_unify/data.geojson`) を読む。2026-11-21 は線状降水帯が無く、空の FeatureCollection (71 バイト) だった。出ているときの形は確かめていないので、面 (Polygon・MultiPolygon) と線 (LineString・MultiLineString) を線で描き、点などほかの形は捨てる
- **古い線を残さない:** 時刻の表から雨域の要素が消えたときと、描いている雨域の解析が 35 分より古いまま新しい解析を読めないときは、線と右下の一言を消す。雷・竜巻の時刻の表と同じ URL を別に取る (雷・竜巻を選んでいる間だけ 10 分に 2 回になる。1 回 6 KB ほどなので、まとめていない)
- **知らせ:** 描いている間だけ、右下の操作の上に「赤い線: 線状降水帯の雨域 (11/21 02:00 の解析・気象庁)」と出す (いつも描く層なので凡例の代わり)。低い地図 (高さ 420px 未満) では出さない。一覧・音・読み上げ・通知では知らせない (気象庁の「顕著な大雨に関する気象情報」の電文を一覧に出すかは別に決める)

## 台風

**台風ごとにいちばん新しい台風解析・予報情報の予報円と暴風警戒域を、気象庁の台風の図と同じ色と線で描く** (2026-11-21。持ち主の頼み「全ての災害情報と、災害の事前の情報を見られるようにしたい」)。読み方は docs/design.md の 2.8 の「台風」、描くのは `#lib/map/typhoon.ts` (`typhoonFeatures`・`typhoonLineLayers`・`typhoonPointLayers`)。確かめた日: 2026-11-21 (気象庁の「[台風情報の種類と表現方法](https://www.jma.go.jp/jma/kishou/know/typhoon/7-1.html)」)。

- **色と線 (気象庁の図のまま):** 予報円は白の破線、予報円の中心を結ぶ線は白の細い破線、暴風警戒域は赤の実線、いまの暴風域は赤の太い実線、強風域は黄の実線。赤は配色の指針の赤 (255,40,0)、黄は `#ffe600`。塗らない (黄・赤の面は警報・注意報と震度の塗りと同じ色で、重ねると読み分けられない)。写真の上で読めるよう、実線の下に黒い細い縁を引く
- **円:** 電文の中心から、電文の半径 (km) で球面の上に描く。片寄った円 (「北東 200 km・南西 130 km」) は、気象庁の図と同じく 2 つの方向を直径の両端にした円 (中心を広いほうへずらす)。それ以外の並びは、いちばん大きい半径で中心から描く (狭く描かない)
- **暴風警戒域:** いまの暴風域と、予報ごとの暴風警戒域の円 (「なし」の予報は飛ばす) を時刻の順に並べ、隣り合う 2 つの円の凸包 (接線でつないだ形) を重ねた外周を 1 本の線で引く。外周は、どの凸包の中にも入らない辺の部分だけを残して作る (地図と同じ Web メルカトルの平面で計算する)。予報に暴風警戒域が 1 つも無ければ描かない
- **これまでの経路** (2026-11-28。docs/design.md の 9 章の未決を決めた): 気象庁の図の青い線にならい、sonae が受けた台風解析・予報情報の実況の中心を、時刻の順に黒い縁の青い実線 (`#4a8cff`) でつなぎ、受けた実況ごとに小さな青い丸を置く。電文には過去の位置が無いので、受けた報の実況だけを使い、点の間を補ったり、なめらかにしたりしない (docs/design.md の 5 章)。描くのは `trackPoints`・`trackSegments`、画面は台風の報が替わるたびに `/api/typhoon-track?series=…` で読む
  - **抜け:** 隣り合う実況の間が 6 時間 (`TRACK_GAP_MS`) を超えたら、sonae が報を受けていなかった間とみなし、線を引かずに空ける。点はそのまま置く。実況はふだん 3 時間ごと (近づくと 1 時間ごと) なので、6 時間を超えれば 1 通より多く欠けている。1 通だけ欠けた 6 時間の間はつなぐ
  - **抜けの見せ方で比べたもの:** (1) 空けて点だけ置く (採った)、(2) 抜けを同じ青の破線でつなぐ、(3) 抜けを薄い灰色の点線でつなぐ。破線は、気象庁の図で予報 (予報円の中心を結ぶ白の破線) に使う形で、見ていない間の進路を推し量った線に見える。薄い点線は、写真の上とスマホの引いた地図ではほとんど見えず、区域の境界 (灰色の破線) とも紛れる。空ければ「この間は受けていない」が線の形でそのまま分かり、点で受けた報の所も分かる。色覚のシミュレーション (Chromium の 1 型・2 型・3 型・1 色覚) では、1〜3 型で青は赤 (暴風域)・黄 (強風域)・白 (予報円) と見分けられた。1 色覚では暴風域の線と近い灰色になるが、丸の並んだ線の形で見分けられる
  - 実況の時刻は電文の `DateTime type="実況"` (`TyphoonNow.time`)。この値を読むようにする前に受けた報は、発表の時刻で並べる。同じ実況の時刻の報が幾つもあれば (訂正)、後に発表したものを採る。取消・訓練・試験の報は使わない。経路は、地図に描いている台風 (いちばん新しい報があるもの) だけに描く
  - sonae を立てる前の経路は描けない (受けた報しか無い)。地図の見方 (`MAP_LEGEND`) に、受けた報の実況をつないだものであることと、受けていなかった間は空けることを書く
  - 経路の線と点は押しても何も出さず、下に渡す (中心の点だけが吹き出しを出す)
- **点と字:** いまの中心は白い縁の赤い丸、予報円の中心は黒い縁の白い小さな丸。そばに名前 (「台風第 18 号」。番号の無い熱帯低気圧は「熱帯低気圧」) と予報の時刻 (「22日 0時」) を白い字・黒い縁で書く。引いているとき (ズーム 6 未満) は、いまの名前と 24 時間ごとの予報の時刻だけにする (3 時間ごとの予報は中心のまわりに詰まり、字が重なるため)。重なった字は MapLibre が間引く
- **置き場:** 線は警報・注意報の塗りと特別警報の縁取りの上 (これまでの経路は台風の線のいちばん下)、道路・地名・住んでいる地域の縁取り・震源の丸の下。点は通行止めの線の上、海しるの点の下 (上の「押せる所が重なったとき」)
- **描く台風:** 台風ごとにいちばん新しい報だけ。取消・訓練・試験・消滅の報と、新しい報が 12 時間より来ていない台風は描かない。同時に幾つあっても全部描く。台風が無ければ何も描かない (`typhoonsOnMap`)
- **押したとき:** いまの中心か予報円の中心を押すと吹き出し。部品は海しるの点と同じ (押せる範囲は指 22 px・マウス 10 px)。中身は上から、名前と号数 (「台風第 18 号 (TALIM)」)・いつのものか (「11/21 01:28 発表の実況」か「11/22 00:00 の予報 (24 時間後)」)・強さと大きさの階級・中心気圧・最大風速 (最大瞬間風速)、予報なら予報円と暴風警戒域の半径と「予報円は、台風の中心が 70% の確率で入る範囲です」、いまの中心なら位置の文。いちばん下に「出典：気象庁「台風解析・予報情報」を加工して作成」
- **一覧で台風を選んだとき:** その台風の線を 1.5 倍の太さにし、いまの強風域と予報円・暴風警戒域が収まるよう寄せる (ズーム 3.5〜6)。ズーム 3.5 に収まらない (スマホの形の一覧のタブの低い地図) ときは、72 時間後・24 時間後までの予報で収め直し、いまの中心の近くを見せる。続報では寄せ直さない。閉じたら開く前の位置へ戻す (下の「詳しい内容を閉じたら戻す」)
- **重ね順:** 線と点なので、右下の選択で図 (ハザードマップ・雨雲・キキクル・J-SHIS など) を重ねている間も、地震を選んでいる間も隠さない (下の「ハザードマップを重ねている間」「地震を選んでいる間」の表)

## 降灰予報の範囲

**一覧で降灰予報 (定時・速報・詳細) を選んだときだけ、電文の降灰の量ごとの範囲を、気象庁の降灰予報の地図と同じ色で塗る** (2026-11-28。docs/design.md の 9 章の未決を決めた)。読み方は docs/design.md の 2 章の「火山」、描くのは `#lib/map/ash.ts` (`ashFeatures`・`ashLayers`・`ashStyle`) と、`#lib/map/style.ts` の `overlayVisibility`。確かめた日: 2026-11-28 (気象庁ホームページの降灰予報の地図 `bosai/map.html` の設定と、解説資料のサンプル電文)。

- **色:** 配色の指針に降灰量階級の色は無いので、気象庁ホームページの降灰予報の地図の色に合わせる。降灰 (定時) と少量は灰 (#b0b0b4、縁 #c8c8cb、透かし 0.8)、やや多量は黄 (#faf500、0.5)、多量は赤 (#ff2800、0.5)、小さな噴石の落下範囲は白地に赤の斜めの縞と赤い縁。重い種類を上に重ね、縁は写真の上で読めるよう黒い細い縁の上に引く
  - 火山灰予報 (名前が変わったあとの電文。2026-11-18 の技術資料。提供の時期は未定) の深さの階級 (31 0.1 mm 未満〜37 30 cm 以上) は、気象庁の地図の色がまだ無い。降灰量階級の境 (少量 0.1 mm 未満・やや多量 0.1〜1 mm・多量 1 mm 以上) で灰・黄・赤に当て、深いものほど上に重ねる (同じ赤が重なって濃く見える)。凡例は同じ色の種類を 1 行にまとめ、名前は電文のまま。気象庁の地図が色を決めたら合わせ直す
- **描くとき:** 一覧で選んだ降灰予報の 1 つだけ。範囲は `/api/volcano-ash?id=…` から読む (一覧の報には持たせない)。取り消された報は描かない。有効期限を過ぎた報も描くが、凡例に「有効期限 (…) を過ぎた予報です」と書く。範囲を残していない報 (新しい報に置き換わった定時と、範囲を読むようにする前に受けた報) は、右下にそう書く
- **時刻の区切り:** 電文の区切り (定時は 3 時間ごとに 18 時間先まで、詳細は噴火から 1〜6 時間後まで積み上げ、速報は噴火から 1 時間以内) を 1 つずつ見せる。初めはまだ終わっていない区切りのいちばん早いもの (`ashDefaultWindow`)。凡例の ‹ › で動かし、自動では動かさない (今後の雨と同じ)。凡例の先頭に、気象庁の地図と同じく「28日12時〜15時」(定時)・「28日15時まで」(詳細)・「噴火から 1 時間以内」(速報) を大きく出す
- **いま降っている所と取り違えない:** 定時は噴火していなくても火山ごとに 3 時間おきに出る「噴火した場合」の予想なので、凡例にいつも「噴火した場合の予想で、いま降っている所ではありません」と書く。速報と詳細は「◯日◯時◯分頃の噴火から…の予想です」
- **寄せ方:** 選ぶと火山へ寄せ、範囲を読めたら全部の区切りの範囲が収まるよう 1 度だけ寄せ直す (ズーム 7〜11。広い形は右下の凡例の分を右に空ける)。続報や ‹ › では寄せ直さない
- **重ね順:** 警報・注意報と震度の塗りの上、津波の線と特別警報の縁取りの下。押しても何も出さない (範囲の名前と色は凡例で読む)
- **選んでいる間:** 地震を選んでいる間と同じく、警報・注意報の塗りと、色のぶつかる重ねる図 (雨雲・雨雲 (いま→予測)・今後の雨・雷・竜巻・キキクル) を隠す。ハザードマップ・地震の備えの図を重ねている間は、範囲の塗りを隠して縁だけを残す (地震の震度の塗りと同じ扱い。下の「ハザードマップを重ねている間」)。隠していることは凡例の下に書く
- **比べた候補 (2026-11-28):**

  | 候補                                                       | 見たこと                                                                                                                                                   | 採ったか |
  | ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
  | 選んだときだけ、気象庁の色で塗り、警報・注意報の塗りを隠す | 範囲の色だけが見え、気象庁の地図と同じ見え方。色覚のシミュレーション (1 型・2 型・3 型・全色盲) でも、灰・黄・赤は明るさの差と入れ子の形で分かれる         | 採った   |
  | 同じ塗りで、警報・注意報の塗りを残す                       | 冬の乾燥注意報などで九州が黄に塗られていると、灰の範囲が黄と混ざって読めない。やや多量の黄・多量の赤は注意報・警報の黄・赤と同じ色                         | 採らない |
  | 縁の線だけ (塗らない) で、警報・注意報の塗りを残す         | 灰と黄の縁が注意報の黄の塗りの上で沈み、入れ子の範囲の内と外が分かりにくい。小さな噴石の縞も出せない                                                       | 採らない |

## 海しるの点

## 災害時の通行止め

**国土交通省が災害ごとに出す「通れるマップ」の GeoJSON を、線で引く** (持ち主の決定、2026-11-20)。サーバーが国土交通省 道路局のトップページから災害を自動で見つけて取る。見つからない災害は、サーバーの管理者が URL を登録できる (見つけ方・取り方・登録の仕方・規約は docs/design.md の 2.12)。描くのは `#lib/map/style.ts` の層 `road-speed`・`road-closed-casing`・`road-closed`、吹き出しの中身は `#lib/map/roads.ts` の `roadPopup`。

  - 道路に寄せる (マップマッチング) には道路の網のデータと処理が要るので、しない。寄せたときはずれが道路と取り違えるほど大きく見えるので、薄くしてから隠す。ズーム 12 では 300 m が 19 px ほど (北緯 33 度)
  - 吹き出しと地図の見方に「車の記録の点を直線でつないだ目安の線で、道路の形ではありません」と書く (持ち主の声「最初なんの線かと思った」、2026-11-21)
- **置き場:** 震源の丸の上、海しるの点の下 (2026-11-21 から。前は震源の丸の下)。通れた道の細い線を下に、通行止めを上に描く

  - 通行止め: 路線名 (無ければ道路種別)・「通行止め (災害)・全面通行止め」・区間 (始点〜終点、無ければ住所)・理由と始めた時刻と延長・ファイルの更新の時刻 (国土交通省)・出典

## 火山の監視カメラ

**気象庁の火山の監視カメラの位置に印を置き、押すと気象庁ホームページのいちばん新しい画像を吹き出しに出す** (2026-11-28。持ち主の依頼「ライブカメラを入れる。まず気象庁の火山カメラから」)。描くのは `#lib/map/style.ts` の層 `cameras`、吹き出しの中身とページの読み方は `#lib/map/cameras.ts`。確かめた日: 2026-11-28。

- **カメラの表:** 気象庁ホームページの「監視カメラ画像」(<https://www.data.jma.go.jp/vois/data/obs/volcam/volcam.php>) の地図が読む GeoJSON (`param/geojson/camicon.geojson`) を、`tools/cameras/build.sh` で `static/cameras/volcano-cameras.json` にする (火山の名前とカメラの名前を分け、名前に混ざる HTML のルビを外す)。2026-11-28 は 49 火山の 95 台。位置は小数 3 桁 (約 100 m) で、カメラを置いた正確な場所とは限らない。どの向きを撮っているかは書いていない (気象庁は「火山の活動状況により変わることがあります」とする)。カメラが増えたり減ったりしたら作り直す
- **画像の読み方:** 画像の名前は撮った時刻 (`camera/<火山>_<16 進 8 桁>/<YYYYMMDDHHmmss>.jpg`) で、いちばん新しい画像の決まった URL は無い。印を押したときに、ブラウザがカメラのページ (`volcam.php?VC=<番号>`、約 14KB) を読み、`file_array[0]` の名前を拾って画像を読む。ページも画像も CORS は `*`。拾う名前は決まった形 (3 桁・16 進 8 桁・14 桁の時刻) だけで、気象庁の画像の置き場の外は読まない (`latestFrame`)
- **サーバーで取らない訳:** 気象庁の規約に自動の取得を控えるよう頼む文は無いが、見る人がいないときに 95 台のページを読み続ける理由が無い。押したときに、押した人のブラウザが 1 台だけ読む。sonae のサーバーは画像に触れず、保存も配布もしない
- **読み直し:** 吹き出しを開いている間は 10 分ごとにページを読み直し、新しい画像があれば替える (`CAMERA_REFRESH_MS`)。画像は 2〜3 分ごとに撮られるが、ページは `Cache-Control: max-age=600` で気象庁の配信が最大 10 分古いので、それより短く読んでも新しい画像は来ない。画面が隠れている間は読み直さず、戻ったときに前に読んでから 10 分たっていれば読み直す。画像を読めなかった後は、同じ名前でも読み直す。閉じたらやめる
- **時刻:** 画像の下に「11/28 12:20 の画像」と撮った時刻を出す。30 分より古ければ「それより後の画像がありません。点検などで止まっていることがあります」と足す (`CAMERA_STALE_MS`)。2026-11-28 には、雲仙岳 垂木台地南と霧島山 八久保に画像が 1 枚も無かった。そのときは「いまは画像がありません」と出す。気象庁は無い名前にも 200 で 10×10 の小さな画像を返すので、幅 100 px 未満は無いとみなす
- **見た目:** 印は白い縁の暗い角丸の四角に白いカメラの形 (地理院地図Vector の記号は白い地に黒なので、地と字を入れ替えて見分ける)。色は段や危険の意味を持たない暗い灰色。大きさはズームで変える (ズーム 7 で 1・10 で 1.25・13 で 1.5)。ズーム 7 より引くと出さない (`CAMERA_MINZOOM`。1 つの火山に 2〜8 台が重なり、火山の印を隠すため)。名前は地図に書かない (押して読む)
- **置き場:** 海しるの点の上、観測点ごとの震度の丸の下。いつも出す層 (面を塗らないので、重ねる図を選んでいる間も、地震を選んでいる間もそのまま)
- **押したとき:** 観測点の丸・海しるの点と同じ部品の吹き出し (幅は 16rem か画面の 70% の狭いほう)。上から、名前 (「箱根山 大涌谷」)・「火山の監視カメラ (気象庁)」・画像 (読み終わるまで 16:9 の場所を取っておく)・撮った時刻・「気象庁の監視カメラのページ (前の画像も見られます)」のリンク・火山の防災は噴火警報と自治体の指示に従うようにという文・出典。動きは付けない
- **入れなかったもの:** 前の画像を並べる・動画のように順に見せる形は入れない (気象庁のページへのリンクで見る)。関東地方整備局のカメラは問い合わせてから (docs/design.md の 1 章「関東地方整備局のカメラ」)

## 現在地を自動で始めるとき

現在地のボタンは**既定でオン**です (2026-11-16。持ち主の声「デフォルトで現在地を表示してほしい」)。人が押して選んだオン・オフは端末に覚え (localStorage の `sonae.map.locate` に `on` か `off`)、次に開いたときもそれに従う (`#lib/map/locate.ts` の `autoLocate`)。
開いたときに `navigator.permissions.query({ name: "geolocation" })` で許可の状態を見る。

| 覚えた選択                   | 許可の状態                                            | すること                                                                                                                                                                                                                                  |
| ---------------------------- | ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| オン、またはまだ選んでいない | `granted`                                             | 自動で追い始める。**地図は寄せない** (選んだ地震の震央へ寄せる決まりとぶつけない)                                                                                                                                                         |
| まだ選んでいない             | `prompt`、または query が無い・geolocation を聞けない | 自動で追い始め、許可の窓を出す。地図は寄せない。断られたらオフを覚え、次からは聞かない (窓を閉じただけで許可も拒否もしなかったときは、次に開いたときにまた聞く)                                                                           |
| オン (人が押した)            | `prompt`、または query が無い・geolocation を聞けない | 始めない。オンは覚えたままで、ボタンはオンの見た目 (主の色の短い下線) のままアイコンを薄くする。押すとそこで始め (許可の窓はこのとき出る)、初めて取れた所へ寄せる。ボタンは `aria-pressed="mixed"` (オンを覚えているが、まだ追っていない) |
| オン、またはまだ選んでいない | `denied`                                              | オフを覚える (ボタンはオフ。聞き直さない)                                                                                                                                                                                                 |
| オフ                         | どれでも                                              | 始めない                                                                                                                                                                                                                                  |

開いている間に許可が変わったとき (サイトの設定で変えたとき) も同じ表で合わせる。追っている途中で拒まれたとき (`PERMISSION_DENIED`。初めの許可の窓で断ったときも) も、追うのをやめてオフを覚える。
もう一度押してやめると、オフを覚える (次に開いても始めない)。位置はこれまでどおり端末の中で描くだけで、サーバーには送らず、覚えもしない。

- 前は既定がオフで、オンにした端末だけ `on` を覚え、オフにしたら消していた。そのため、前にオフにした端末と一度もオンにしていない端末を見分けられず、どちらも「まだ選んでいない」として許可を聞く (断られたらオフを覚えるので、聞くのは許可か拒否が決まるまで)
- 人がオンにした端末で許可が消えていたときに窓をいきなり出さないのは、前からの決まりのまま (押すのを待つ)。まだ選んでいない端末だけ、既定のオンとして初めに聞く
- 現在地は、開いているときの通知の範囲「住んでいる地域と現在地のものだけ」にも使う (design.md の 2.4)。オフにすると、その範囲は住んでいる地域だけで見る

## 重ねる図の選択肢

**右下の「重ねる」は、面を塗る図を 1 つだけ選ぶ選択で、見出しで分けて並べる** (2026-11-21。持ち主の頼み「全ての災害情報と、災害の事前の情報を見られるようにしたい」で、ハザードマップの層と J-SHIS を足した)。見出し「雨・雷・竜巻」と「キキクル (危険度分布)」は `QuakeMap.svelte` に書き、中身は `#lib/map/nowc.ts` の `NOWC_KINDS` と `#lib/map/risk.ts` の `RISKS`。見出し「ハザードマップ」と「地震の備え」は `#lib/map/style.ts` の `HAZARDS`・`HAZARD_GROUPS`・`HAZARD_CHOICES`・`hazardFamily`。

| 見出し                          | 選択肢                                                                 |
| ------------------------------- | ---------------------------------------------------------------------- |
| (見出し無し)                    | なし                                                                   |
| 雨・雷・竜巻                    | 雨雲 (いま)・雨雲 (いま→予測)・今後の雨 (予測)・雷 (いま)・竜巻 (いま) |
| キキクル (危険度分布)           | 土砂・大雨 (浸水・洪水)                                                |
| ハザードマップ (水害・土砂災害) | 洪水・内水・高潮・津波・土砂災害                                       |
| 地震の備え                      | 活断層・揺れの確率 (30 年)・地盤の揺れやすさ                           |

- **浸水継続時間と家屋倒壊等氾濫想定区域は、選択肢に並べず、洪水の凡例の上で切り替える。** 洪水を選ぶと、凡例のタイトルの下に「浸水の深さ」「浸水が続く時間」「家屋倒壊等」の 3 つのチップ (1 つだけ選ぶ並び。`aria-pressed`) が出る。どれも同じ洪水 (想定最大規模) の想定を別の見方で塗った図で、選択肢に並べると洪水の名前の似たものが 3 つ続き、選択肢が 17 になってうるさいため。選んだ図は端末に覚え (`sonae.map.hazard` の `flood-duration`・`flood-collapse`)、メニューでは「洪水」を選んでいる印にする (`hazardChoice`)。メニューで「洪水」を押し直すと浸水の深さに戻る
- 選択肢は 16、見出しは 4。スマホの形で画面に入りきらないときは、メニューの中で巻く (`.menu` の `max-height: 100%`)
- 活断層は、前は見出し「ハザードマップ」の中にあった。地震の備えの図として、J-SHIS の 2 つと同じ見出しに移した
- ボタンは、なしのとき「重ねる: なし」。選んでいる間は何の図かを残す (`pill`)。「雨雲」「雨雲 (いま→予測)」「今後の雨 (予測)」「雷 (いま)」「竜巻 (いま)」「キキクル: 土砂」「ハザードマップ: 高潮」「ハザードマップ: 浸水が続く時間」「活断層」「揺れの確率 (30 年)」「地盤の揺れやすさ」のように出す。「高潮」「土砂」だけだと、いまそれが起きているように読めるため
- ハザードマップポータルサイトの図は、どれも凡例の下に出典と「想定の無い川や地域は塗られていません。色が無くても安全とは限りません。」を書く (`caveat`)。J-SHIS の図は「確率が低い所でも、強い揺れに見舞われないとは限りません」のように、図ごとの注意を書く
- 家屋倒壊等の公式の凡例の画像は字の無い模様 (100px) だけなので、「氾濫流」「河岸侵食」の名前を添え、画像を引き伸ばさない (`.legend img` の `width: auto`)

## 福祉避難所

**指定避難所のうち、福祉避難所 (`sfh`) を、一般の指定避難所 (`sih`) と同じ形で読み、白地に緑の「福」の印で置く** (2026-11-21)。データは国土地理院の指定緊急避難場所・指定避難所データ (地理院タイル一覧の「指定避難所 (福祉)」)。読み方は `skhb01`〜`08`・`sih` と同じ (ズーム 10 のタイルを、ズーム 14 から見ている範囲で 4 つまで)。

- 属性は `name`・`address`・`remarks` と、福祉避難所だけの `accept` (受け入れる人。「要配慮者」「障がい者」など、市町村が書いたまま) と `necessary_matters`。`accept` を吹き出しに「福祉避難所 (受け入れる人: 要配慮者)」と出す。空なら「福祉避難所」だけ。`necessary_matters` は 2026-11-21 に見た練馬区のあたりで空が多く、出していない
- 同じ場所・同じ名前の施設は 1 つにまとめる (`mergeShelters`)。一般の指定避難所と福祉避難所を兼ねるときは、印は「福」にし、吹き出しに両方を書く
- 印は、一般の避難所の「避」(緑の地に白い字) と地と字の色を入れ替え、白い地に緑の字と緑の太い縁にする。小さく引いても形が違って見分けられる
- 吹き出しには「配慮の要る人のための避難所で、受け入れる人が決まっています。」を足す。福祉避難所は受け入れる人を決めて指定するので、誰でも行ける所と読まれないようにする
- 災害の種類ごとの区分 (`disaster1`〜`8`) は、前から吹き出しに「指定緊急避難場所: 洪水、地震」のように出している (2026-11-21 に確かめた)

## J-SHIS

**防災科研の J-SHIS (地震ハザードステーション) の WMS から、今後 30 年に震度 6 弱以上の揺れに見舞われる確率と、表層地盤の揺れやすさ (地盤増幅率) の 2 つを、重ねる図の選択の 1 つとして重ねる** (2026-11-21)。確かめた日: 2026-11-21。

- **配信:** [WMS サービス一覧](https://www.j-shis.bosai.go.jp/wms-list)。確率論的地震動予測地図は `https://www.j-shis.bosai.go.jp/map/wms/pshm/<版>`、表層地盤は `…/sstrct/V4`。WMS 1.3.0 で EPSG:3857 を受け、CORS は `*`。GetMap は 1 枚 0.2 秒ほどで返る。`Cache-Control` は無い
- **版:** 確率論的地震動予測地図は `Y2024` (2024 年版。GetCapabilities が返る中でいちばん新しい。`Y2025` などは 400)。表層地盤は `V4` (`V5` は 400)。新しい版が出たら `JSHIS_PSHM_VERSION` を替える
- **層:** 確率は平均ケース・全ての地震の `T30_I55_PD` (5 段の色。境は 0.1・3・6・26 %)。連続の色の `PS` もあるが、段の色のほうが凡例と見比べやすい。増幅率は `IDARV2` (工学的基盤 Vs=400m/s から地表まで)
- **読み方:** MapLibre の raster の source の URL に `{bbox-epsg-3857}` を入れ、512px の透かした PNG を GetMap で読む (`wmsTiles`・`JSHIS_TILE_SIZE`。256px の 4 枚分を 1 枚で読み、リクエストを減らす)。図はズーム 4 から出す。画像を読むのはズーム 11 まで (`JSHIS_FETCH_MAXZOOM`。250m の格子なので、512px の 1 枚が約 38m/px で足りる) で、それより寄せたら読み足さずに引き伸ばす。不透明度 0.7 (陸の全面を塗る図なので写真を透かす)
- **凡例:** J-SHIS の GetLegendGraphic の画像 (白い台に載せる)。下に「防災科研の確率論的地震動予測地図 (2024 年版・平均ケース・全ての地震)。地震調査研究推進本部の評価をもとにした計算で、誤差を含みます。」と、出典のリンクと「確率が低い所でも、強い揺れに見舞われないとは限りません」を書く

### 規約

[J-SHIS 利用規約](https://www.j-shis.bosai.go.jp/agreement) (2026-11-21 に読んだ)。

- 5 条は、地震動予測地図データを編集・加工した成果物は自由に頒布してよいとし、データを「そのまま複製（ファイル形式を変換しての複製を含む）して、第三者に頒布、譲渡すること」を禁じる
- sonae は、利用者のブラウザが J-SHIS の WMS から地図画像を直接読み、地図に透かして重ねるだけにする。sonae のサーバーは画像を取らず、保存も配布もしない。WMS は J-SHIS が「J-SHIS Map で表示している地図画像を配信する」「ツールを用いて J-SHIS の地図を簡単に表示することができます」として公開しているもので、その使い方の範囲と読んだ。データ (ファイル) を複製して人に渡すことはしないので、5 条の禁止には当たらないと判断した
- 4 条の「出典元が本サイトであることを明示」に沿って、地図の隅の短い出典に「J-SHIS (防災科研)」、凡例の下と「出典と注意」の窓に J-SHIS のリンクと版を出す。表層地盤のデータの参考文献は J-SHIS の「表層地盤データ記述ファイル規約」にあるので、窓からリンクする
- 5 条の「成果物の販売を予定されている方は…お問い合わせください」は、sonae を商用にしないので当たらない
- 7 条のとおり、データの利用は利用者の判断と責任による。凡例の下に誤差を含むことを書く
- 2026-11-25 に J-SHIS (公開担当者) から、利用者のブラウザが WMS を直接読んで重ねる使い方は「特に問題ない」と返事をもらった。決まった頻度や条件は無いが、連続した大量のリクエストを避ける、または間に待ち時間を置くなど、負荷に配慮してほしいとのこと。そのために 512px の画像で読み、ズーム 11 より寄せたら読み足さない形にした (上の「読み方」)。どう使ったかが分かる資料を後日送る
- 防災科研の強震モニタは「転載、改変、送信、再配布等を行うことは固くお断りします」としているので重ねていない (docs/design.md の 1 章)。J-SHIS は WMS を公開していて規約も別なので、分けて判断した

## ハザードマップを重ねている間

ハザードマップと地震の備えの図 (活断層・J-SHIS の 2 つ) を選んでいる間は、面で塗る付加情報の色がハザードマップの色とぶつかって見分けられないので、次のとおりにする (`#lib/map/style.ts` の `overlayVisibility`)。「なし」に戻すと元に戻る。図のタイルが無いズーム (活断層はズーム 11 未満) では何も重ならないので隠さず、凡例の下に「寄せて図が重なると…隠します」と書く (`hazardCovers`)。
隠していることは、凡例の下に「警報・注意報と震度の塗りを隠しています … 「なし」に戻すと元に戻ります」と書いて分かるようにする。通れた道 (目安) の線を出していれば「警報・注意報と震度の塗り・通れた道 (目安) の線を隠しています」と書く。ただし、通れた道の線はズーム 13 以上ではもともと描かない (下の「災害時の通行止め」) ので、そのズームでは書かない (`roadSpeedDrawn`。動き終わったときのズームで出し入れする)。地震を選んでいる間は、「なし」に戻しても警報・注意報の塗りは隠したまま (下の「地震を選んでいる間」) なので、「「なし」に戻すと、震度の塗りは元に戻ります。警報・注意報の塗りは、一覧へ戻ると元に戻ります。」と書く。

## 地震を選んでいる間

**一覧で地震を選んでいる間は、気象警報・注意報の塗りを隠す** (2026-11-19。持ち主の声「地震表示してるときって注意報とか非表示やなかったっけ？今表示されちゃってるけど」)。決まりは `#lib/map/style.ts` の `overlayVisibility` (`HIDDEN_UNDER_QUAKE`)。選びを外す (一覧へ戻る) と元に戻る。一覧で府県予報区の警報・注意報を選ぶと地震の選びは外れるので、いままでどおり塗る。

- 警報・注意報の黄・赤・紫は、震度の色 (黄・橙・赤・紫) と重なって読み違える。地震を見ている間に読みたいのは震度なので、塗りを隠す
- 前に隠れて見えたのは、震度の塗り (不透明度 0.75) が下の警報・注意報の塗り (0.6) を覆っていたため。揺れた地域の上では、警報・注意報の色は 0.6 × 0.25 = 0.15 ほどしか透けなかった。揺れていない地域は前から塗っていた。2026-11-19 の観測点ごとの震度 (#317) で、丸を出している間は震度の塗りを寄せるほど薄くした (ズーム 9 で 0.3) ので、揺れた地域の上でも 0.6 × 0.7 = 0.42 ほど透けて見えるようになった。決まりとして隠したことは無く、見えなかったのは重なりのためだった (2026-11-19 に、#317 の前のコードで確かめた)
- 隠していることは、地図の右下の操作の上に「地震を選んでいる間は、気象警報・注意報の塗りを隠しています。一覧へ戻ると元に戻ります。」と書く。特別警報が出ていれば「(特別警報は縁取りで出します)」を足す。塗る市町村等が無いとき、ハザードマップの凡例が隠していることを書いているとき、地図の高さが 420px 未満のとき (スマホの形の一覧のタブで上に残す地図。一言が震央や丸を覆うため) は出さない

## 地図のメニュー (右クリック・長押し)

地図を右クリックすると (スマホは長押し)、押した所に小さいメニューが出る。

- 見出しに押した所の緯度・経度 (「北緯 35.6852・東経 139.7528」)、項目は 2 つ
  - **ここを住んでいる地域にする**: 押した所が入る市町村等を、「通知」の「現在地から選ぶ」と同じ道 (`#lib/push-client.ts` の `homeAt`。`warning-areas.geojson` を `cityAt` で引き、`homeOf` で組む) で探し、住んでいる地域にする。
    覚え方も「通知」の窓と同じ関数 (`saveHome` → `alerter.setPrefs`、Web Push に登録してあれば `queuePrefs` で順にサーバーへ)。決まったら地図の上の真ん中に「東京都千代田区を住んでいる地域にしました」と少しの間出す。
    海の上や日本の外で市町村等が見つからなければ「ここが入る市町村が見つかりませんでした (海の上や日本の外です)。住んでいる地域は変えていません」と出し、変えない。**緯度・経度はサーバーに送らない** (送るのは市町村等のコードと、そこから引いた地域だけ)
  - **緯度・経度を写す**: 「35.68520, 139.75280」(小数 5 桁、約 1 m) をクリップボードに写す。写せないブラウザでは知らせの中に出す
- 開け閉めは画面のほかのメニューと同じ `Menu.svelte` (押した所に大きさの無い引き金を置き、そこから右下へ出す)。↑↓で動き、Enter で選び、Esc か外を押すと閉じる (外を押した押下は地図に渡さない)。地図が動いたら閉じる
- 長押しは MapLibre が数える (指 1 本で 500 ミリ秒、クリックの許す幅より動かない。2 本指になったり動かしたりしたら取りやめ。iPhone の Safari のように contextmenu を出さない端末でも同じ)。念のため、指を置いてから地図が動いた・10 px より離れた所での長押しは出さない (`#lib/map/press.ts` の `longPressOk`)。Android の長押しで来るブラウザの contextmenu は MapLibre が止める
- メニューを開いている間と、長押しの指を離したときは、避難場所・警報・注意報・観測点の吹き出しを出さない
- 住んでいる地域が決まっていれば、その市町村等を黒い縁の上に水色の破線で縁取る (`home-casing`・`home-line`。府県予報区の白い縁取りと見分けられる色と形)

## 場所の検索

ヘッダーの検索の欄 (スマホの形は一覧の先頭の欄) は、一覧を地名で絞るのに加えて、欄の下に「場所の候補」を出す (`SearchField.svelte`・`#lib/places.ts`)。
候補を選ぶと地図をそこへ寄せ (`jumpTo`。市町村は外枠が収まるようズーム 13 まで、住所はズーム 16 から)、白い縁の橙の丸の印を置く。スマホの形では地図のタブへ移る (寄せた場所のまま。震央へ寄せ直さない)。

- **市町村は手元のデータから**、打つたびに探す。`cities.json` の名前と府県からの名前を、名前がそのまま同じ・頭が同じ・どこかに入る、の順に並べ、`offices.json` の外枠へ寄せる。外へは問い合わせない
- **住所・地名は国土地理院の住所検索** (`https://msearch.gsi.go.jp/address-search/AddressSearch?q=…`。地理院地図が使っているもの) に問い合わせる。問い合わせるのは Enter を押したときか、打つのが 0.6 秒止まったとき (2 文字から) だけで、打つたびには送らない。同じ文字の答えはタブの間は覚えて、問い合わせ直さない
- 並びは市町村が先、住所・地名が後 (`mergePlaces`)。住所検索が市町村そのもの (「北海道札幌市」) を返したときは、手元の市町村と重なるので捨てる。候補は 8 つまでで、市町村が多く当たる語 (「中央」「大和」) でも住所・地名に 3 枠は残す。欄を空にすると印も消える
- 欄は combobox (`role="combobox"`・`aria-expanded`・`aria-controls`・`aria-activedescendant`)、候補は `listbox` と `option`。↑↓で動き、Enter で選び (選んでいなければ住所を今すぐ探す)、Esc で候補だけを閉じる (欄の字は消さない)。候補の面は操作の層 (メニューと同じ面と影)
- 住所検索を読めないときは「住所を探せませんでした (地理院地図の地名検索API)。市町村だけを出しています」と出す

### 人の情報の扱い

- 打った文字は、住所検索のために**ブラウザから国土地理院へ直接送る**。sonae のサーバーは通さないので、サーバーには届かず、記録にも残らない。Cookie は送らず (`credentials: "omit"`)、`Referer` も付けない (`referrerPolicy: "no-referrer"`)。市町村の候補は端末の中だけで探す
- ブラウザから直接にしたのは、住所検索が CORS を許していて (`Access-Control-Allow-Origin: *`。2026-11-15 に確かめた)、サーバーを通すと打った文字が sonae のサーバーを通ることになるため

sonae はブラウザから直接送るので User-Agent は替えられない (ブラウザが付ける)。家族の数人が Enter か打つのが止まったときだけ問い合わせる量なので、運用を妨げる負荷にはならないと見ている。
仕様が変わったり止まったりしても、市町村の候補 (手元のデータ) は出る。問い合わせる所は `#lib/places.ts` の `GSI_ADDRESS_SEARCH` と `parseGsi` だけなので、替えるときはここを替える。
出典は「出典と注意」の窓の「場所の検索」に、記載例の「地理院地図の地名検索APIを利用」と、結果を加工している (市町村と重なるものを除き、数を絞って並べる) ことを書く (住所の中身は CSIS シンプルジオコーディング実験 (街区レベル位置参照情報))。候補の下にも「住所: 地理院地図の地名検索APIを利用」と出す。地図の隅の短い出典は「国土地理院」をもう含むので足さない。

## 地理院地図Vector と字体

確かめた日: 2026-11-14 (国土地理院の公式のページと、配信の応答で)。

- **配信:** `https://cyberjapandata.gsi.go.jp/xyz/optimal_bvmap-v1/optimal_bvmap-v1.pmtiles` (PMTiles の 1 ファイル、約 16.9 GB、ズーム 4〜16)。範囲 (Range) を指定して要るタイルだけを読み、CORS は `*`。`pmtiles` (Protomaps、BSD-3-Clause) で MapLibre に読ませる。
  前の `{z}/{x}/{y}.pbf` も応答するが、データは 2023-10 で止まり、README に「公開を停止する予定」とあるので使わない
- **位置づけ:** 試験公開 (2022-09 から「公開終了まで」)。URL や属性が変わることがあると書かれている。変わったら `GSI_VECTOR_URL` と `tools/gsi/build.ts` を直す
- **条件:** [README](https://github.com/gsi-cyberjapan/optimal_bvmap) は国土地理院コンテンツ利用規約 (公共データ利用規約 第 1.0 版) で使えるとしている。基本測量成果ではないので測量法の申請は要らない。出典は「国土地理院最適化ベクトルタイル」と書き、加工したことも書く。
  リポジトリに LICENSE のファイルは無い (GitHub のライセンス表示も無い)。スタイルとスプライトもこの README の条件で使えると読んだ
- **読む量:** ベクトルのタイルは 1 枚 20〜110 KB。層ごとの最小のズームより引いているときは読まない (日本全体を見ているときは読まない)。PMTiles の目次は初めに 16 KB と、要る所のディレクトリを読む
- **字体 (glyphs) は読まない。** MapLibre 6 は、スタイルに `glyphs` の URL が無いと、字を端末の字体でその場で描く (TinySDF)。漢字・かなはもともと端末で描いている。そのため PBF の字体を作って配る必要もなく、外から字体を読むことも無い。
  字体の名前は `"Noto Sans JP", sans-serif` で、入っていない端末は端末の既定のゴシックで描く。持ち主の頼みは「Noto Sans JP から PBF を作って自分で配る」だったが、字体を 1 つも読まずに済むこの形にした (束も 0 KB)
- **記号 (スプライト):** 国土地理院のスタイルのスプライト (`sprite/std`、約 110 KB) を `tools/gsi/build.ts` で写して自分で配る
- **写真の上で読む:** 地名は白い字に黒い縁 (幅 1.6)、道路は黒い縁取りの上に明るい線。国土地理院のスタイルの道路の色 (地図の地に合わせた色) は写真の上で沈むので使わない

カメラは、開いたときは日本全体で、何も選んでいなければ寄せない (緊急地震速報が出ていればそこへ寄せる)。選んでから一覧へ戻ったときは、次の節の決まりで開く前の位置へ戻す。

## 詳しい内容を閉じたら戻す

**詳しい内容を開いて地図が寄ったら、閉じたときに開く前の位置 (中心・ズーム・向き・傾き) へ戻す** (2026-11-17。持ち主の声「地震詳細閉じたら元の地図の位置に戻ってほしい」)。決まりは `#lib/map/restore.ts` の `ViewKeeper`。

- 控えるのは、何も開いていないところから詳しい内容を開き、地図がそれへ寄る直前の位置。地震だけでなく、地図が寄るもの (海外の地震・火山・府県予報区の警報・注意報・台風・緊急地震速報) も同じ
  - 詳しい内容から別の詳しい内容へ移っても (一覧へ戻らずに次の地震を開く・自動で開いたものが替わる)、控えは最初のまま。閉じると、一覧から開く前の位置へ戻る
  - 地図が寄らないもの (津波・お知らせなど) を開いただけのときは控えず、閉じても動かさない
  - 何も選んでいないときに出た緊急地震速報へ寄せたときも控える (2026-11-27。持ち主の声「緊急地震速報のあと、戻っても地図の位置が戻らん」)。速報は、届いて地図が寄った後に自動で開く ([ui.md](ui.md) の「自動で開く」) ので、寄せる所ではまだ何も選んでいない。前は、そのために控えず、出ている間が過ぎて一覧へ戻っても震央に残っていた。続報や別の速報が来ても、控えは最初のまま
- **控えている間 (開いている間と、緊急地震速報が出ている間) に人が地図を動かしたら、戻さない。** 人が自分で見に行った所を、閉じたときに勝手に動かさないため。動かしたかは MapLibre の `movestart` に付く `originalEvent` で見分ける (引く・つまむ・ホイール・ダブルクリック・キー。寄せるときの `jumpTo` と大きさの測り直しには付かない)。場所の検索と現在地のボタンで寄せたときも、人が動かしたものとする
- 閉じたときに出ている緊急地震速報 (取消を除く) があれば、震央を見せたまま控えを持ち続け、速報が終わったら (出ている間が過ぎた、または取り消された) 戻す。出ている間が過ぎて自動で一覧へ戻ったときも同じ所で戻る
- 地震を見ている間に緊急地震速報が来て自動で開いたときは、速報が終わると地震の詳しい内容へ戻り、地図は地震へ寄り直す。地震を閉じると、地震を開く前の位置へ戻る
- 戻すのも寄せるときと同じく飛ばさずに `jumpTo` で、動きは付けない (動きを減らす設定でも変わらない)
- 閉じたら控えを忘れる。同じものをもう一度開くと、また寄せる

## 描き方の決まり (docs/design.md の 6 章)

- カメラは飛ばさない (`jumpTo`)。寄せるのは、選んだ地震か、出ている緊急地震速報が替わったときだけ (続報で勝手に動かない)。
  スマホの形は一覧のタブでも地図を上に残すので、選んだときに寄せた所が地図のタブでも見えている。タブを移っても寄せ直さない (人が地図を動かしていれば、動かした所のまま)。
  一覧で選んだ府県予報区の警報・注意報も同じ決まりで、選んだときだけ、出ている市町村等が収まるよう寄せる (寄せすぎないようズーム 10 まで。続報や解除で勝手に動かない)。
  東京都のように離れた島を含む府県予報区で引きすぎないよう、寄せる範囲は府県予報区の全体ではなく、警報・注意報の出ている市町村等にする。先に出ているものの順 (緊急地震速報・火山・海外の地震・府県予報区・地震) は変えない
- 雨雲・キキクル・雷・竜巻は時刻の表が替わったときだけ (雨雲は 5 分ごと、ほかは 10 分ごと)、今後の雨は新しい予測が来たときと ‹ › で時刻を替えたときに、タイルの URL を差し替える (`setTiles`)。動きは付けない。
  時間で枚を替えるのは「雨雲 (いま→予測)」だけで、URL は替えずに、読んでおいた枚の層の透明度を替える (上の「雨雲 (いま→予測)」)
- 地図の上で押して吹き出しを出すのは、避難場所の印、観測点ごとの震度の丸、海しるの点、台風の中心、通行止めと通れた道の線、気象警報・注意報で塗った市町村等。震源の丸と海外の地震の丸は、押すとその地震を選ぶ (上の「震源の丸を押したとき」)。重なったときは上のものだけを使う (上の「押せる所が重なったとき」)。吹き出しの中身は DOM で組み、HTML として読まない。マウスでは押せる所の上でだけ指の形にする
- 下地はズーム 8 まで Blue Marble、9 から地理院の写真。境で白く抜けないよう、Blue Marble を 10 まで写真の下に残し、写真は 9 から 9.5 にかけて透かしから重ねる (上の「引いたときの下地」)。
- 震源の点の色は深さ (30・100・300 km で分ける)。震度の色と取り違えないよう、震源の丸は M で大きさを変えて半分透かし (不透明度 0.8)、観測点ごとの震度の丸は小さく (半径 2.5〜9 px) 透かさずに黒い細い縁を付ける。観測点の丸は地震を選んでいる間だけ出る。色の意味は「出典と注意」の「地図の見方」に書く。
- 地図の上の操作 (「重ねる」の選択と現在地のボタン) は右下に 1 行でまとめ、隅の出典の上に置く (スマホの形は `--map-bottom` で下のタブと dock の上)。凡例と位置の知らせはその上に積む。上は音が止まっているときの帯と重ならないよう空け、地図のメニューの知らせは上の真ん中に出す。寄せるときの余白は下を広く取る (`focusPadding`)
- 「重ねる」の選択肢は、`(hover: hover)` の端末でマウスを乗せただけで開き (フォーカスは動かさない。`Menu.svelte` の `focusOnOpen`)、外れると 0.3 秒待って閉じる。乗せて開いてから押すと開いたまま。指の端末は押して開き、キーボードは Enter で開く。動きはメニューと同じ CSS の透明度と transform
- 地図を回さない (北が上)。
- 動くのは緊急地震速報の震央の × が出たときの 3 回の脈打ちだけ (`transform: scale`)。動きを減らす設定では止まる。
- WebGL が使えない端末では地図を出さず、一覧で見てもらう。
- MapLibre (約 1.1MB) は画面を描いた後に動的 import で読む (最初の表示と一覧は待たせない)。
