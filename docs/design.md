# sonae の設計

地震・津波の情報を家のサーバーで受け、ブラウザで見て、Web Push で知らせるアプリの設計書。
まだ実装の前なので、ここに書いたことは「こう作る」という決めごとで、作りながら直す。
決めていないことは最後の「未決の点」にまとめた。

- 名前は「備え」から。
- 機能は [Zero Quake](https://github.com/0Quake/Zero-Quake) を参考にしたが、**コードは読まない・写さない** (クリーンルーム)。仕様は各情報源の公式の文書から取る。
- ライセンスは AGPL-3.0。

## 1. 目的と範囲

**目的:** 家族が、地震と津波の情報を 1 か所でまとめて見られ、タブを閉じていても大きな揺れや津波のときは端末に知らせが届くこと。
**まずは持ち主 1 人で使う** (ログインで閉じる)。家族との共有は、仕様 (Entra のアプリロール、2.6) だけ先に入れておき、招待はあとでする。
広く公開はまだしないが、公開しても困らない作りにしておく。

- **ホスト名は `s.doany.io`** (家のクラスタの Gateway の `doany`)。

| もの                                          | 理由                                                                                |
| --------------------------------------------- | ----------------------------------------------------------------------------------- |
| 推計震度分布・長周期地震動の観測情報 (VXSE62) | 図の作りが重い。長周期は電文の形が大きく、MVP の地図に入れる絵がまだ無い            |
| 気象庁の JSON (`www.jma.go.jp/bosai/...`)     | 公式の仕様と提供の約束が無い (ホームページの表示用)。過去の一覧の補いにだけ使う候補 |

| AXIS などの有料・申込みの配信                 | 問い合わせが先。家族だけで使う間は要らない                                          |

### 入れない

| もの                                                   | 理由                                                                                       |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| 自前の予想震度・猶予秒数 (地点ごとの計算)              | 地点の震度や到達時刻を予想して繰り返し提供するのは予報業務で、気象業務法 17 条の許可が要る |
| 緊急地震速報の予想震度の数字の表示                     | 下の「法と表示」。気象庁自身も警報では数字を出さず「強い揺れ」と言う                       |
| 強震モニタ・海しる・TREM-RTS・SeisJS・Early-Est        | 公式の利用条件がはっきりしない、または家族の用途に要らない                                 |
| 揺れの自前検知 (端末の加速度計・P2P地震情報の感知情報) | 誤報の扱いが難しく、公式の情報を優先するという方針に合わない                               |
| Wolfx の電文の原文 (`OriginalText`) の保存と表示       | Wolfx の規約で原文の公開の再配布が禁じられている。受けたら捨てる                           |

## 2. 全体の構成

```
            ┌──────────── サーバー (Bun 1 プロセス、SvelteKit + adapter-bun) ────────────┐
気象庁 Atom ─┤ JmaXmlSource ─┐                                                              │
P2P ws ──────┤ P2pSource ────┼─▶ 正規化 ─▶ 重複の除去・版の判定 ─▶ SQLite ─▶ Broker ─┬─▶ SSE ─────▶ ブラウザ
Wolfx ws ────┤ WolfxSource ──┘                                                     └─▶ Pusher ─▶ Web Push
             └──────────────────────────────────────────────────────────────────────────┘
```

- **1 つのプロセスで受信も配信もする。** SvelteKit の `init` (hooks.server.ts の `ServerInit`) で受信を起こす (ashi が歩みを起こすのと同じ形)。
  受信を別のプロセスに分けないのは、家族の数人に配るだけで分ける利点が無く、Wolfx の「1 クライアント 1 接続」・P2P の「IP ごとに 2 接続」を守るのも 1 プロセスのほうが確か。
- **レプリカは 1 つ、入れ替えは Recreate。** 2 つ立つと情報源への接続が倍になり、Push も二重に出る。入れ替えの数秒は受けられないが、戻ったときに履歴の API で埋める (下)。
- 依存は増やさない: XML は Bun 組み込みの `Bun.XML.parse` (1.4.4 の型定義で確かめた。外部の DTD や実体を読まないので XXE の心配が無い)、WebSocket の受信は Bun の `WebSocket`、DB は `bun:sqlite`。

### 2.1 受信 (情報源ごとのアダプター)

どのアダプターも同じ形にする。

```ts
interface Source {
  id: "jma-xml" | "p2p" | "wolfx";
  /** 止めるまで受け続ける。切れたら自分で張り直す */
  run(signal: AbortSignal, emit: (m: Incoming) => void): Promise<void>;
  status(): SourceStatus; // connected / retrying / down、最後に受けた時刻、直近のエラー
}
```

| 情報源                     | 方式                                                                                        | 受けるもの                                                                      | 行儀                                                                                                                                                                                                                               |
| -------------------------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 気象庁 防災情報 XML (PULL) | 高頻度フィード `https://www.data.jma.go.jp/developer/xml/feed/eqvol.xml` を 60 秒ごとに取る | 地震・津波・南海トラフ等の電文 (3 章)                                           | `If-None-Match` と `If-Modified-Since` を付ける (304 が返ることを確かめた)。`Cache-Control: max-age=60` なので 60 秒より短くしない。一度取った電文は取り直さない (Atom の `id` を DB に持つ)。1 日 10GB を超えると IP が遮断される |
| 気象庁 長期フィード        | `eqvol_l.xml` (毎時更新、数日分)                                                            | 止まっていた間の電文                                                            | 起動したときと、高頻度フィードの取得が 10 分以上途切れた後に 1 回だけ読む                                                                                                                                                          |
| P2P地震情報 API v2         | WebSocket `wss://api.p2pquake.net/v2/ws`                                                    | 551 地震情報・552 津波予報・554 緊急地震速報の発表検出・556 緊急地震速報 (警報) | IP ごとに 2 接続まで (1 つだけ使う)。同じ情報が何度も届くので `id` で除く。張り直したら `/v2/history?codes=551&codes=552&codes=556` で埋める (60 回/分まで)                                                                        |
| Wolfx Open API             | WebSocket `wss://ws-api.wolfx.jp/jma_eew`                                                   | 気象庁の緊急地震速報 (予報と警報)                                               | 1 クライアント 1 接続。約 1 分ごとの `heartbeat` に合わせて `ping` を送る。`OriginalText` は受けたら捨てる                                                                                                                         |

- **緊急地震速報は気象庁の公開フィードに載らない** (公開電文の一覧に「緊急地震速報等、公開されない電文もあります」とある。<https://xml.kishou.go.jp/xmllist.pdf>)。そのため予報と警報を Wolfx から、警報を P2P からも受け、2 つで欠けを補う。どちらも非公式で無保証なので、画面にはそう書く。
- **張り直し:** 指数のバックオフに揺らぎを足す (1 秒から倍々、上限 30 秒、full jitter)。60 秒つながっていたら間隔を戻す。Wolfx は 90 秒何も来なければ (heartbeat も含めて) 死んだとみなして張り直す。P2P は heartbeat を送ってこず、静かなときは何分も何も来ない (2026-11-13 に実際につないで確かめた) ので、無通信では切らず、切れたことは close で知る。つながるまでは、どちらも 30 秒で諦める。
- **重複の除去:** 情報源の中では、気象庁は Atom の `id`、P2P は `id` で除く。情報源をまたいだ重複は、正規化した後の「版」(2.2) で除く。
- **受けた原文は残す** (Wolfx を除く)。気象庁の XML と P2P の JSON を 30 日、圧縮して `raw_messages` に置き、正規化を直したときに流し直せるようにする。

### 2.2 正規化したイベントのモデル

情報源の違いはアダプターの中で吸収し、外へは次の 4 種類だけを出す。どれにも `sources` (どこから来たか) と `status` (通常 / 訓練 / 試験) を持たせる。

**緊急地震速報 `Eew`**

```ts
type Eew = {
  eventId: string; // 地震識別番号 (14 桁)
  serial: number; // 報数
  issuedAt: string;
  kind: "warning" | "forecast"; // 警報 / 予報
  final: boolean; // 最終報
  cancelled: boolean; // 取消
  status: "normal" | "training" | "test";
  assumed: boolean; // 仮定震源要素 (PLUM 法・レベル法)
  originTime?: string;
  hypocenter?: { name: string; lat: number; lon: number; depthKm: number };
  magnitude?: number;
  warnAreas: string[]; // 警報の対象の地域名 (警報のときだけ)
  sources: ("wolfx" | "p2p")[];
};
```

- **版の判定:** 鍵は `eventId`。報数が今より大きいものだけを採る。同じ報数が別の情報源から来たら `sources` に足し、警報の地域は和を取る。取消を受けたら、その地震の速報はそこで終わり (以後の報は捨てる)。
- **最大予測震度・地域ごとの予測震度は、正規化したモデルに入れない** (5 章)。SSE でブラウザに渡すのもこの形なので、画面にも知らせにも出ようがない。P2P の原文 (raw_messages) には残る。Wolfx の原文は残さない。
- 訓練と試験 (Wolfx の `isTraining`、P2P の `test`) は保存するが、知らせず、一覧にも「訓練」と付けて既定では隠す。

**地震情報 `Quake`** (1 つの地震に、発表された報をまとめる)

```ts
type QuakeReport = {
  kind: "scale" | "hypocenter" | "detail" | "update" | "foreign"; // 震度速報 / 震源 / 震源・震度 / 震源要素更新 / 遠地
  code?: "VXSE51" | "VXSE52" | "VXSE53" | "VXSE61";
  infoType: "発表" | "取消";
  reportedAt: string;
  // 中身 (震源・M・最大震度・地域と観測点ごとの震度・津波の有無の文・付加文)
};
```

- 一連の情報は「`Control/Title` + `Control/Status` + 地震識別番号」で見分ける (気象庁の運用指針)。取消は**その一連の情報全体**を取り消す。
- **地震識別番号は、自動の電文 (緊急地震速報・震度速報) と手動の電文 (地震情報・津波) で一致しないことがある** (気象庁のよくある質問)。そのため、震度速報と後の地震情報は、番号が合わないときは「発表の時刻が近く、震度の地域が重なる」もので結ぶ。結び方の閾値は fixture で詰める (未決の点)。
- `Serial` は連番とも一意とも保証されない。版は `ReportDateTime` の新しいほうで決める。
- P2P の 551 は気象庁の XML と同じ地震の情報なので、P2P で先に受けたら仮に出し、XML が来たら置き換える (XML を正とする)。

**津波 `Tsunami`**

- VTSE41 (津波警報・注意報・予報) は**その時点の全予報区の状態**を毎回まるごと持つので、新しい報で前の状態を置き換える。予報区ごとに「大津波警報 / 津波警報 / 津波注意報 / 津波予報 / 解除」を持つ。
- VTSE51 (津波情報) は到達予想時刻・予想の高さ・観測値、VTSE52 は沖合の観測。同じ一連の情報に付け足す。
- 原因の地震が複数のとき、地震識別番号は並びで来る (`xs:list`)。全部を持っておく。
- P2P の 552 は警報・注意報・予報の区域の状態だけ。XML が来るまでのつなぎに使う。

**お知らせ `Advisory`** — 南海トラフ地震臨時情報 (VYSE50)・関連解説情報 (VYSE51/52)・北海道・三陸沖後発地震注意情報 (VYSE60)・地震・津波に関するお知らせ (VZSE40)。
見出しと本文と種類 (調査中・巨大地震警戒・巨大地震注意・調査終了など) を持つ。VYSE50/60 の識別番号は物理的な意味を持たない任意の番号。

### 2.3 ブラウザへの配信: SSE

|                      | SSE (`text/event-stream`)                                                                                               | WebSocket                                                                      |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 向き                 | サーバーからだけ。sonae はこれで足りる (設定の変更は普通の POST)                                                        | 両向き                                                                         |
| 張り直し・取りこぼし | ブラウザが自動で張り直し、`Last-Event-ID` を送る。そこから DB で埋められる                                              | 自前で書く                                                                     |
| 認証                 | 普通の要求なので、セッションの Cookie と hooks の判定がそのまま効く                                                     | Upgrade の時に別に判定する                                                     |
| SvelteKit・Gateway   | `+server.ts` で `ReadableStream` を返すだけ。Cilium Gateway もそのまま通る                                              | SvelteKit に標準の口が無く、adapter-bun の外で `Bun.serve` の websocket を触る |
| 同時の接続数         | HTTP/1.1 だとブラウザの 6 本の上限に数える。HTTP/2 なら 1 本に束ねられる (Gateway が h2 を話すかは載せるときに確かめる) | 制限なし                                                                       |

**SSE にする。** `GET /api/stream`。

- 各イベントに DB の通し番号を `id:` で付ける。`Last-Event-ID` があれば、それより後を DB から送ってから生の配信に移る。
- **`s.doany.io` は Cloudflare のプロキシを通したワイルドカードの DNS で配信される** (DNS のレコードは足さない)。Cloudflare のプロキシは、応答の間に 100 秒何も流れないと接続を切り (Proxy Read Timeout)、圧縮やバッファリングで SSE を溜めて届けることがある。そのため:
  - **30 秒ごとにコメント行 (`: ping`) を送る。** Cloudflare の 100 秒、adapter-bun の `CONNECTION_IDLE_TIMEOUT` (Bun の idleTimeout、上限 255 秒)、Gateway の無通信の切断のどれよりも十分短い。同じ間隔で情報源の状況 (`event: status`) も送る。
  - 応答のヘッダーに `Content-Type: text/event-stream`・`Cache-Control: no-cache, no-transform`・`X-Accel-Buffering: no` を付ける (`no-transform` で圧縮を止め、`X-Accel-Buffering` で途中の溜め込みを止める)。
  - それでも切れることはあるので、ブラウザの側は切れたら `Last-Event-ID` で取り直す (EventSource が自分で張り直す)。最初の接続は、ページの `load` で渡した最後の番号を `?after=` で付ける。
- 最初の表示の中身はページの `load` で渡し、SSE は差分だけにする。

### 2.4 Web Push

**push-bridge は使えない。** memory にある infisical-push-bridge は、Infisical の Webhook を受けて InfisicalSecret の注釈を書き換える仕組みで、ブラウザへの Web Push とは関係が無い (2026-11-02 に撤去済み)。
ほかの自分のリポジトリにも Web Push の実装は無いので、sonae の中に書く。

| 候補                                                                                     | 版・更新        | ライセンス | 依存                                      | 所見                                                                                      |
| ---------------------------------------------------------------------------------------- | --------------- | ---------- | ----------------------------------------- | ----------------------------------------------------------------------------------------- |
| [web-push](https://github.com/web-push-libs/web-push)                                    | 4.0.0 (2026-11) | MPL-2.0    | jws・asn1.js・http_ece・https-proxy-agent | いちばん使われていて、RFC 8291 (aes128gcm)・VAPID の参照実装の扱い。Node の crypto に頼る |
| [@pushforge/builder](https://www.npmjs.com/package/@pushforge/builder)                   | 2.0.5 (2026-04) | MIT        | なし                                      | WebCrypto だけ。要求を組むだけで送るのは自分の fetch                                      |
| [@block65/webcrypto-web-push](https://www.npmjs.com/package/@block65/webcrypto-web-push) | 2.0.0 (2026-09) | MIT        | uint8array-extras                         | WebCrypto だけ。利用者が少ない                                                            |
| 自前 (WebCrypto で RFC 8291 + RFC 8292)                                                  |                 |            | なし                                      | 200 行ほど。暗号の誤りを自分で背負う                                                      |

**web-push を使う** (MPL-2.0 は AGPL と組み合わせられる)。devDependencies に入れ、Vite がサーバーに束ねる。
最初の実装の PR で Bun 1.4 の上で暗号化と送信が通ることを確かめ、通らなければ @pushforge/builder に替える。

- **鍵:** VAPID の鍵の組は SOPS の Secret (`deploy/secrets.sops.yaml`) に置く。公開鍵は画面に渡す。
- **購読:** 端末ごとに `push_subscriptions` に、利用者・endpoint・鍵・閾値 (下)・現在地 (地震情報の細分区域のコード) を持つ。送って 404・410 が返ったら消す。
- **何を知らせるか (端末ごとに選ぶ。括弧は既定):**
  - 緊急地震速報: 警報 (オン)・予報 (オフ)。予報を選んでも本文に予想震度は書かない。
  - 地震情報: 最大震度がいくつ以上 (震度 4)、または現在地の地域で震度いくつ以上 (震度 3)。
  - 津波: 津波注意報以上 (オン)。現在地の予報区に関わらず送る。
  - 南海トラフ・後発地震注意情報: オン。
  - 訓練・試験は送らない。
- **送り方:** 緊急地震速報と津波は `Urgency: high`。`TTL` は緊急地震速報 120 秒 (遅れて届いても意味が無い)、地震情報 1 時間、津波 6 時間。
  `Topic` に地震識別番号を元にした短い名前を付け、続報で前の知らせを置き換える。Service Worker の `showNotification` も `tag` で同じことをする。
- **iPhone・iPad:** ホーム画面に追加した Web アプリ (iOS 16.4 以降) でだけ Web Push が届く。設定の画面で案内する。
- **開いているとき:** SSE で受けたら、音 (短い音を `<audio>` で) と読み上げ (`speechSynthesis`) をする。どちらも端末ごとに切れる。読み上げは見出しだけ。

### 2.5 保存: SQLite

|                   | SQLite (`bun:sqlite`)                                       | PostgreSQL                                           | JSON のファイル  |
| ----------------- | ----------------------------------------------------------- | ---------------------------------------------------- | ---------------- |
| 足すもの          | なし (Bun 組み込み)                                         | クラスタに DB (operator か StatefulSet) と接続の秘密 | なし             |
| 書き手            | 1 プロセス (sonae はレプリカ 1 つなので合う)                | 複数でも可                                           | 1 プロセス       |
| 検索 (期間・震度) | SQL と索引                                                  | SQL と索引                                           | 全部読む         |
| バックアップ      | PVC ごと VolSync (ほかのアプリと同じ)                       | 別のやり方 (論理ダンプなど)                          | PVC ごと VolSync |
| 既存のアプリ      | yosegaki・xool・lgtm が同じ形 (ORM なし、素の `bun:sqlite`) | 無し                                                 | ashi             |

**SQLite にする。** WAL で、PVC (`local-path`) の `/data/sonae.db`。ORM は使わず、既存のアプリと同じく素の SQL と `PRAGMA user_version` で版を上げる。

| 表                                            | 中身                                                        | 残す期間 |
| --------------------------------------------- | ----------------------------------------------------------- | -------- |
| `raw_messages`                                | 受けた原文 (圧縮)・情報源・鍵 (Atom の id や P2P の id)     | 30 日    |

### 2.6 認証

ロールを持つ人だけが開けるようにする。ほかのアプリと同じく、パスワードは持たず OIDC でログインする。

- **OIDC のクライアントは自前** (noren の `src/lib/server/oidc.ts` と同じ形: discovery・認可コード + PKCE・素の fetch と WebCrypto で id_token の署名・発行元・宛先・期限・nonce を確かめる)。ライブラリは足さない。
- **IdP は doany.io の Entra ID の共用のアプリ登録 (Main、アプリケーション ID `b0fa498f-7e6a-4fe1-a1c6-16fbbb6f397e`)。新しくアプリは登録しない。** ashi と同じく、誰が使えるかはエンタープライズ アプリケーションのロールの割り当てで決める。
  - リダイレクト URI `https://s.doany.io/auth/callback` は gitops の `pulumi/entra.ts` で Main に足してある (ashi と同じパス)。
  - 通すロールは `OIDC_ROLE` で変えられ、**既定は `admin`** (Main のアプリロールはいま `admin` だけなので、まずは持ち主 1 人)。ロールを読む claim は `OIDC_ROLE_CLAIM` (既定は空で、`roles` と `groups` の両方を読む。noren と同じ)。
  - **家族と共有するときは**、Main に family 用のアプリロールを足し、家族を B2B のゲストとして招待してそのロールを割り当て、`OIDC_ROLE` をそのロールの値にする (コードの変更は要らない)。
  - 設定値は環境変数で受ける: `OIDC_ISSUER` (`https://login.microsoftonline.com/<テナント ID>/v2.0`)・`OIDC_CLIENT_ID`・`OIDC_CLIENT_SECRET`・`OIDC_ROLE`・`OIDC_ROLE_CLAIM`・`OIDC_SCOPE`・`PUBLIC_URL` (`https://s.doany.io`。リダイレクト URI はここから組み、要求の Host を信じない)。3 つ (issuer・client id・secret) が揃わないと、画面は開かない (`/health` だけ答える)。手元の開発だけ、`AUTH_DISABLED=1` でログインを飛ばせる (本番の `NODE_ENV=production` では効かない)。
  - クライアントシークレットは Main の共用のもの。載せるときに `deploy/secrets.sops.yaml` に入れる (ほかのアプリと同じ値)。
- **セッションは DB に持ち、180 日で、使うたびに延ばす。** 何度もログインさせない。Web Push は購読してあればセッションが切れても届く。
- ログイン無しで開けるのは `/auth/login`・`/auth/callback`・`/health`・Service Worker と Web アプリのマニフェストだけ。`/auth/logout` は POST だけ。

## 5. 法と表示

- **予想震度は出さない。** 緊急地震速報の最大予測震度・地域ごとの予測震度・到達予測時刻は、画面にも知らせにも出さない。
  気象庁は警報で「具体的な予測震度の値は ±1 程度の誤差を伴い、続報を避けたいので発表せず『強い揺れ』と表現する」としている ([緊急地震速報 (警報) 及び (予報) について](https://www.jma.go.jp/jma/kishou/know/jishin/eew/shikumi/shousai.html))。sonae も警報は「強い揺れに警戒」と、対象の地域名で伝える。
  予報は「緊急地震速報 (予報)」と震源・M だけを出す。
- **自前の予想をしない。** 地点の震度や到達時刻を計算して出すのは予報業務で、気象業務法 17 条の許可が要る ([よくある質問](https://www.jma.go.jp/jma/kishou/minkan/q_a_s.html))。地震動の警報は気象庁以外はできない (23 条)。
- **観測値は気象庁の値をそのまま出す。** 推計や補間で震度を足さない (気象庁の値の編集にあたりうる)。
- **出典:** 画面の下と「出典」のページに次を常に出す。
  - 「出典: 気象庁ホームページ (防災情報 XML) を加工して作成。編集の責任は sonae の運営者にあります」(気象庁の[留意事項](https://www.data.jma.go.jp/developer/ryuui.pdf)と[利用規約](https://www.jma.go.jp/jma/kishou/info/coment.html)。公共データ利用規約 第 1.0 版)
  - 「緊急地震速報: Wolfx Project・P2P地震情報」(Wolfx の規約で、利用者に見える形で Wolfx Project を出す)
  - 「地図: 国土地理院 (シームレス空中写真・淡色地図・都市圏活断層図)・気象庁 予報区等 GIS データを加工」
- **注意文:** どの画面にも「このアプリは気象庁の公式のものではありません。情報は遅れたり欠けたりすることがあります。身の安全に関わる判断は、気象庁・自治体・テレビやラジオの公式の情報を優先してください。」を出す (`src/lib/notice.ts`)。緊急地震速報の画面には、Wolfx と P2P のどちらも非公式で無保証であることも書く。
- **Wolfx:** 原文 (`OriginalText`) は保存も公開もしない。Wolfx を使う機能で収益を得ない。広く公開する前に、規約 6 条の「第三者へのデータの提供」に当たるか Wolfx に確かめる (未決の点)。

## 6. 見た目と動きの決まり

**見た目は denpa にそろえる** (denpa の `src/app.css` と docs/design.md の「作り方」)。土台は Blades の Pico。主の色は Pico の既定の azure のまま、状態の色は denpa と同じ 4 つ (赤・翡翠・琥珀・青緑)。テーマは暗いのが既定で、明るい・端末に合わせるも選べる (`sonae.theme` に覚える)。角丸・余白・字の大きさのトークンは denpa の `--dp-*` を `--so-*` にした段から選ぶ。一覧の件は面 (`.item`) に乗せ、線で区切らない。震度・津波の色だけは気象庁の配色の指針の色 (4 章) を使う。

ほかのアプリ (corp・mado・denpa の [docs/design.md](https://github.com/danything/denpa/blob/main/docs/design.md) 7・8 章) と同じ。

- 動かすのは **CSS の `opacity` と `transform` だけ**。JS のアニメーション (rAF・`setInterval` で値を書き換える・ライブラリ) は使わない。ぼかし・色・背景の位置は動かさない。
- 緊急地震速報の帯や震源の印を目立たせる点滅・脈打ちは、`transform: scale` と `opacity` の CSS アニメーションで、回数を決めて止める (常時は回さない)。
- 地図のカメラは飛ばさない (`jumpTo` と `duration: 0`)。MapLibre は止まっている間は描かないので、地図を開いているだけで CPU を使うことは無い。
- ソフトウェアで描いている端末 (WebGL の描き手が SwiftShader・llvmpipe など、または WebGL が無い) では `<html data-lite>` を付け、動き続けるものを止め、地図の代わりに一覧を先に出す。WebGL が無ければ地図は出さない。
- 画面の外の動くものは `content-visibility: auto` で止める。`prefers-reduced-motion` では全部止める。
- 検証は GPU を切った Chromium (`--disable-gpu --disable-gpu-compositing`) でも、止まって 5 秒の CPU を測る。

## 7. テスト

- **単体 (`bun test tests`)**: 電文の読み取り (fixture → 正規化したモデル)、版の判定と重複の除去 (同じ報の二重受信・報数の逆転・取消・訓練)、知らせるかどうかの判定 (閾値・現在地)、SSE の `Last-Event-ID` からの埋め直し。
- **fixture:**
  - 気象庁の[サンプル電文](https://xml.kishou.go.jp/tec_material.html) (`jmaxml_20260917_Samples.zip`、2026-09-17 一部更新) から、使う種別の分だけを `tests/fixtures/jma/` に写す。
    利用条件は気象庁ホームページの利用規約 (公共データ利用規約 第 1.0 版、CC BY 4.0 と互換) で、`tests/fixtures/jma/README.md` に出典「気象庁防災情報 XML フォーマット 技術資料 サンプルデータ (https://xml.kishou.go.jp/tec_material.html)」と規約を書く。中身は変えない (整形からも外す)。足りない場合 (取消と訓練の組など) は自分で作り、ファイル名で分かるようにする。
  - P2P は API 仕様書の例と、サンドボックス (`wss://api-realtime-sandbox.p2pquake.net/v2/ws`、2023 年の情報を約 30 秒ごとに流す) で取ったもの。
  - Wolfx は公式の文書の項目の一覧から自分で作る (原文は入れない)。
- **アダプター:** 情報源のサーバーを立てない。`fetch` と WebSocket を差し替えて、304・切断・張り直し・heartbeat の途絶を試す。
- **E2E (後で):** Playwright で、ログインを飛ばした画面に SSE で fixture を流し、表示と知らせの判定を見る。GPU を切った CPU の測定もここで。
- **CI:** `bun run lint` (oxlint・`bun fmt --check`)・`bun run check` (`svelte-check --tsgo --fail-on-warnings`)・`bun test tests`・`bun run build` (警告で失敗)・Docker のビルドと起動して `/health` を見る。

## 8. 家のクラスタへの載せ方

ashi・xool と同じく、リポジトリの `deploy/` を Argo CD が同期する (gitops の ApplicationSet が `deploy/argocd.yaml` を探す)。

- `deploy/`: `argocd.yaml`・`deployment.yaml` (レプリカ 1・Recreate・uid 1000・`/health` のプローブ・`TZ=Asia/Tokyo`)・`service.yaml`・`httproute.yaml` (Cilium Gateway の `doany`、ホスト名 `s.doany.io`)・`pvc.yaml` (`local-path` 1Gi、`dataSourceRef` で VolSync から戻す)・`volsync.yaml` (毎日 19:00 UTC に R2 へ)・`networkpolicy.yaml` (外向きは DNS と公開のインターネットだけ)・`secrets.sops.yaml` (`SESSION_SECRET`・`OIDC_CLIENT_SECRET`・VAPID の秘密鍵・VolSync の restic)。`.sops.yaml` はほかのリポジトリと同じ鍵。
- イメージ: main にマージすると `docker-publish.yml` が `ghcr.io/danything/sonae:<sha>` を作り、`deploy/deployment.yaml` のタグを差し替える PR を作って自分でマージする (`deploy/` ができるまでは何もしない)。
- 実行のイメージは `oven/bun:<ver>-distroless` (シェル無し・uid 1000)。
- 外への接続は気象庁・P2P・Wolfx・Web Push の配信サービス (FCM・Mozilla・Apple) だけ。気象庁のフィードは 1 日 1440 回の条件付きの取得で、ほとんどが 304 なので、帯域の上限 (10GB/日) には遠い。

## 9. 未決の点

持ち主が決めたこと (2026-11-13):

1. **ホスト名は `s.doany.io`。** Entra は共用の Main を使い回し、リダイレクト URI `https://s.doany.io/auth/callback` は gitops の `pulumi/entra.ts` で足した。
2. **家族との共有はまだやらない。** いまは持ち主 1 人で使う。仕様としてはアプリロール (`OIDC_ROLE`、既定 `admin`) で絞る形にしておき、family 用のロールと家族の招待 (Entra の Main に B2B のゲスト) はあとでする。
3. **広く公開はまだしない** (家族用の前提のまま)。公開するときは、Wolfx に規約 6 条の事前の許可が要るか確かめる。気象庁の情報だけで出せる範囲 (緊急地震速報なし) に絞る手もある。
4. **知らせの既定値は 2.4 の括弧の値のまま** (地震情報は最大震度 4 以上・現在地で震度 3 以上、緊急地震速報の予報は既定でオフ)。

作りながら決めること:

5. 震度速報と地震情報を、地震識別番号が合わないときに結ぶ閾値 (時刻の差と地域の重なり)。いまは仮に「発生の時刻 (震度速報は TargetDateTime) の差が 90 秒以内で、震度の地域が 1 つでも重なる (どちらかに地域が無ければ時刻だけ)」で、番号どうしが違うときは震度速報だけを結ぶ (`src/lib/server/merge.ts` の `sameQuakeByTime`)。P2P の 551 には地震識別番号が無いので、いつもこれで結ぶ。
6. web-push が Bun の上で動くか (だめなら @pushforge/builder)。
7. 区域の GeoJSON の簡略化の度合い (いまは 300m 間隔)。GIS データの更新 (年に 1〜2 回) をどう気づくか (pin-watch の `page-text-gone` で一覧のページを見張る案)。
8. 原文を残す期間 (いまは 30 日)。
9. 長周期地震動・推計震度分布を入れる時期。
