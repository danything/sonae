# sonae の設計

地震・津波・火山・気象の災害の情報を家のサーバーで受け、ブラウザで見て、Web Push で知らせるアプリの設計書。
ここに書いたのは作りの決めごとで、作りながら直す。決めていないことは最後の「未決の点」にまとめた。
画面の形は [ui.md](ui.md)、地図の層と出典は [map.md](map.md)、Web Push の運用は [push.md](push.md)、ログインの設定は [entra.md](entra.md)、台湾の中央氣象署の授権碼は [cwa.md](cwa.md) に書き、ここでは繰り返さない。

- 名前は「備え」から。
- 機能は [Zero Quake](https://github.com/0Quake/Zero-Quake) を参考にしたが、**コードは読まない・写さない** (クリーンルーム)。仕様は各情報源の公式の文書から取る。
- ライセンスは AGPL-3.0。

## 1. 目的と範囲

**目的:** 家族が、地震・津波・火山・気象の災害の情報を 1 か所でまとめて見られ、タブを閉じていても身を守る動きが要るときは端末に通知が届くこと。
地震と津波から始め、持ち主の決定 (2026-11-14) で災害の全般に広げる。**使うのは無料の情報源だけ。** まず気象庁防災情報 XML の気象の電文 (警報・注意報など、2.8) を足した。

**sonae は、使う人が自分で立てて使うアプリ (セルフホスト) にする** (持ち主の決定、2026-11-14)。

- 立てる人が、自分と家族のために、自分のサーバーに 1 つ立てる。ログインで閉じ、家族との共有は Entra のアプリロール (2.6) で絞る。
- 誰かが公開のサービスとして立て、知らない人に配ることはしない。コードは AGPL-3.0 で公開するが、配信のサービスは運営しない。
- 情報源へは、立てたサーバーがそれぞれ直接つなぐ。どの情報源も、1 つのサーバーが家族の数人のために取る量で行儀 (2.1) を決めている。
- 持ち主のサーバーのホスト名は `s.doany.io` (家のクラスタの Gateway の `doany`)。
- Kubernetes には Helm chart (`charts/sonae`、`oci://ghcr.io/danything/charts/sonae`) で入れる。入れ方は README の「Kubernetes に立てる」。持ち主の本番も同じ chart で出す (8 章)。

### 情報源の判断

持ち主の依頼 (2026-11-14) は「Zero Quake が対応している取得先は一通り、ほかにもあれば足す」。同じ日に「災害の全般に広げる。無料の情報源だけ」が加わった。
各情報源の利用規約を読んで、入れてよいものだけを入れる。下調べは 2026-11-14 (Zero Quake は README の出典の一覧だけを読み、コードは開いていない)。

規約は、セルフホスト (1 章) の形で読む。立てた人が自分と家族のために取って見るもので、公開のサービスとして第三者に配るものではない。
再配布や第三者への提供を絞っている情報源 (Wolfx の規約 6 条・EMSC) も、この形なら家族の間の利用に収まると読んだ。公開のサービスにする場合は読み直しが要る。

## 2. 全体の構成

```
            ┌──────────── サーバー (Bun 1 プロセス、SvelteKit + adapter-bun) ────────────┐
気象庁 Atom ─┤ jmaSource ────┐                                                              │
P2P ws ──────┤ p2pSource ────┼─▶ 正規化 ─▶ 重複の除去・新旧の判定 ─▶ SQLite ─▶ Broker ─┬─▶ SSE ─────▶ ブラウザ
Wolfx ws ────┤ wolfxSource ──┘                                                       └─▶ Pusher ─▶ Web Push
             └──────────────────────────────────────────────────────────────────────────┘
```

- **1 つのプロセスで受信も配信もする。** SvelteKit の `init` (hooks.server.ts の `ServerInit`) で受信を起こす (ashi が歩みを起こすのと同じ形)。
  受信を別のプロセスに分けないのは、家族の数人に配るだけで分ける利点が無く、Wolfx の「1 クライアント 1 接続」・P2P の「IP ごとに 2 接続」を守るのも 1 プロセスのほうが確か。
- **レプリカは 1 つ、入れ替えは Recreate。** 2 つ立つと情報源への接続が倍になり、Push も二重に出る。入れ替えの数秒は受けられないが、戻ったときに履歴の API で埋める (下)。
- 依存は増やさない: XML は Bun 組み込みの `Bun.XML.parse` (1.4.4 の型定義で確かめた。外部の DTD や実体を読まないので XXE の心配が無い)、WebSocket の受信は Bun の `WebSocket`、DB は `bun:sqlite`。

### 2.1 受信 (情報源ごとのアダプター)

どのアダプターも同じ形にする。

```ts
interface Source {
  id: "jma" | "p2p" | "wolfx";
  /** 止めるまで受け続ける。切れたら自分で張り直す (受けたものは作るときに渡す SourceContext の emit へ) */
  run(signal: AbortSignal): Promise<void>;
  status(): SourceStatus; // connecting / connected / retrying / stopped、最後に受けた時刻、直近のエラー
}
```

設定で切ってある情報源 (中央氣象署の授権碼が無いとき) はアダプターを作らず、状態 `off` と訳 (`reason`) だけを `statuses()` の後ろに足す。画面の「受信の状態」に並べるためで、`event: status` でも同じものを送る。

- **緊急地震速報は気象庁の公開フィードに載らない** (公開電文の一覧に「緊急地震速報等、公開されない電文もあります」とある。<https://xml.kishou.go.jp/xmllist.pdf>)。そのため予報と警報を Wolfx から、警報を P2P からも受け、2 つで欠けを補う。どちらも非公式で無保証なので、画面にはそう書く。
- **張り直し:** 指数のバックオフに揺らぎを足す (1 秒から倍々、上限 30 秒、full jitter)。60 秒つながっていたら間隔を戻す。Wolfx は 90 秒何も来なければ (heartbeat も含めて) 死んだとみなして張り直す。P2P は heartbeat を送ってこず、静かなときは何分も何も来ない (2026-11-13 に実際につないで確かめた) ので、無通信では切らず、切れたことは close で知る。つながるまでは、どちらも 30 秒で諦める。
- **重複の除去:** 情報源の中では、気象庁は Atom の `id`、P2P は `id` で除く。情報源をまたいだ重複は、正規化した後の新旧の判定 (2.2) で除く。
- **受けた原文は残す** (Wolfx を除く)。気象庁の XML と P2P の JSON を 30 日、圧縮して `raw_messages` に置き、正規化を直したときに流し直せるようにする。

### 2.2 正規化したイベントのモデル

情報源の違いはアダプターの中で吸収し、外へは次の 4 種類と、長周期地震動 (`LongPeriod`、2.7) だけを出す。どれにも `sources` (どこから来たか) と `status` (通常 / 訓練 / 試験) を持たせる。

**緊急地震速報 `Eew`**

```ts
type Eew = {
  eventId: string; // 地震識別番号 (14 桁)
  serial: number; // 報数
  issuedAt: string;
  kind: "warning" | "forecast"; // 警報 / 予報
  final: boolean; // 最終報
  cancelled: boolean; // 取消
  status: "normal" | "training" | "test";
  assumed: boolean; // 仮定震源要素 (PLUM 法・レベル法)
  originTime?: string;
  hypocenter?: { name: string; lat: number; lon: number; depthKm: number };
  magnitude?: number;
  warnAreas: string[]; // 警報の対象の地域名 (警報のときだけ)
  sources: ("wolfx" | "p2p")[];
};
```

- **新旧の判定:** 鍵は `eventId`。報数が今より大きいものだけを採る。同じ報数が別の情報源から来たら `sources` に足し、警報の地域は和を取る。取消を受けたら、その地震の速報はそこで終わり (以後の報は捨てる)。
- **最大予測震度・地域ごとの予測震度は、正規化したモデルに入れない** (5 章)。SSE でブラウザに渡すのもこの形なので、画面にも通知にも出ようがない。P2P の原文 (raw_messages) には残る。Wolfx の原文は残さない。
- 訓練と試験 (Wolfx の `isTraining`、P2P の `test`) は保存するが、知らせず、一覧にも「訓練」と付けて既定では隠す。

**地震情報 `Quake`** (1 つの地震に、発表された報をまとめる)

```ts
type QuakeReport = {
  kind: "scale" | "hypocenter" | "detail" | "update" | "foreign"; // 震度速報 / 震源 / 震源・震度 / 震源要素更新 / 遠地
  code?: "VXSE51" | "VXSE52" | "VXSE53" | "VXSE61";
  infoType: "発表" | "取消";
  reportedAt: string;
  // 中身 (震源・M・最大震度・地域と観測点ごとの震度・津波の有無の文・付加文)
};
```

- 一連の情報は「`Control/Title` + `Control/Status` + 地震識別番号」で見分ける (気象庁の運用指針)。取消は**その一連の情報全体**を取り消す。
- **地震識別番号は、自動の電文 (緊急地震速報・震度速報) と手動の電文 (地震情報・津波) で一致しないことがある** (気象庁のよくある質問)。そのため、震度速報と後の地震情報は、番号が合わないときは「発表の時刻が近く、震度の地域が重なる」もので結ぶ。結び方の閾値は fixture で詰める (未決の点)。
- `Serial` は連番とも一意とも保証されない。新旧は `ReportDateTime` で決める。
- P2P の 551 は気象庁の XML と同じ地震の情報なので、P2P で先に受けたら仮に出し、XML が来たら置き換える (XML を正とする)。

**津波 `Tsunami`**

- VTSE41 (津波警報・注意報・予報) は**その時点の全予報区の状態**を毎回まるごと持つので、新しい報で前の状態を置き換える。予報区ごとに「大津波警報 / 津波警報 / 津波注意報 / 津波予報 / 解除」を持つ。
- VTSE51 (津波情報) は到達予想時刻・予想の高さ・観測値、VTSE52 は沖合の観測。同じ一連の情報に付け足す。
- 原因の地震が複数のとき、地震識別番号は並びで来る (`xs:list`)。全部を持っておく。
- P2P の 552 は警報・注意報・予報の区域の状態だけ。XML が来るまでのつなぎに使う。
- **P2P の 551・552 には訓練・試験の印が無い** (API 仕様書 v2.3.0 で印があるのは 556 の `test` だけ。訓練の電文を流すかどうかも書かれていない、2026-11-13 に確かめた)。そのため P2P だけから来た地震・津波は、いつも本番 (`normal`) として持つ。訓練・試験の津波は、地震と同じく id の後ろに `-training` / `-test` を付けて分ける (P2P だけのものも同じ規則にしてあり、仕様に印が足されたら読み取りを直すだけで効く)。
  - 残る危うさ: P2P が訓練の津波を流したら、本番として仮に出る。気象庁の XML (訓練) は状態が違うので重ならず、P2P の仮のものは置き換わらない。訓練は事前に告知されるので、いまはこのままにする。

**お知らせ `Advisory`** — 南海トラフ地震臨時情報 (VYSE50)・関連解説情報 (VYSE51/52)・北海道・三陸沖後発地震注意情報 (VYSE60)・地震・津波に関するお知らせ (VZSE40)・地震の活動状況等に関する情報 (VXSE56)・地震回数に関する情報 (VXSE60)。一覧に新しい順に並べ (種類のチップは「お知らせ」)、選ぶと本文 (VXSE60 は期間ごとの回数の表) を出す。一覧の上の通知には、VXSE56・60 を出さない (地震回数は活動が続く間に何度も出るため)。

米国の太平洋津波警報センター (PTWC) の電報も `Advisory` (code は `PTWC`、`source` は `ptwc`) にして、お知らせの一覧に出す。持つのはフィードの要約 (種類・地域・規模・位置) と電報のページへのリンクで、英文の電報そのものは取りに行かない。米国の参考の情報なので、一覧の上の通知には出さず、知らせない。詳しい内容には「気象庁の発表ではない。日本の沿岸の津波は気象庁の津波の情報を確かめる」と書く。

気象庁の国際津波関連情報 (北西太平洋津波情報センターの電報 WEPA40) も `Advisory` (code は `WEPA40`、`source` は `jma-bosai`) にする。公開の防災情報 XML には無く、気象庁ホームページ (bosai) の JSON とテキストから取る。**公式の API ではないので、ほかと分けた独立のアダプター (`sources/jma-bosai.ts`) にし、形が変わって読めなくなっても、その回を捨てて状態にエラーを出すだけにする** (ほかの情報源と画面は止まらない)。各国の機関に向けた情報で日本の沿岸の津波予報ではないので、一覧の上の通知には出さず、知らせない。
見出しと本文と種類 (調査中・巨大地震警戒・巨大地震注意・調査終了など) を持つ。VYSE50/60 の識別番号は物理的な意味を持たない任意の番号。

**海外の地震 `ForeignQuake`** — USGS などの海外の機関の地震。機関ごとの発表 (`ForeignReport`: 機関・その機関の id・時刻・位置・深さ・M・場所・ページ) を、同じ地震ごとに 1 つにまとめる。

- 同じ機関の同じ id の続報は置き換える。ほかの機関の発表は、**発生の時刻の差が 60 秒以内・震央の距離が 150 km 以内・M の差が 1.0 以内** (どちらかに M が無ければ M は見ない) の地震にまとめる (`sameForeignQuake`)。同じ機関の別の id とはまとめない。
- いまの姿 (時刻・位置・M・場所) は、機関の順 (中央氣象署・GeoNet・USGS・EMSC) で先の機関の値を採る。地元の機関を先に、速報の EMSC を後にした。
- 遠地地震と同じく知らせない。日本に津波のおそれがあれば、気象庁が津波の情報を出す。
  **火山 `Volcano`** — 噴火警報・予報 (VFVO50) と噴火速報 (VFVO56)。報ごとに 1 件で、一覧には報を新しい順に並べる。

- 持つもの: 対象の火山 (コード・名前・位置・種類の名前とコード・引上げ／引下げ・前の種類)、警報の種類 (噴火警報・火口周辺警報・噴火予報・解除)、対象の市町村、見出し、火山活動の状況と防災上の警戒事項の文、噴火の時刻 (噴火速報)。
- 一連の情報は「種別 + 識別番号」。噴火警報・予報の識別番号は火山のコード (浅間山は `306`)、噴火速報は発表の時刻と火山のコード (`20140927120000_312`)。**取消はその一連の情報のいちばん新しい報に印を付け、訂正はその報を置き換える** (一覧に 2 つ並べない)。
- 警戒の段 (1〜5) は、種類のコード (コード表 VolcanicWarning) の噴火警戒レベル 11〜15 から取る。レベルの無い火山 (21〜25)・海底火山 (35・36) は、気象庁の配色の指針 (表 1-2) で同じ色の欄にあるものを同じ段に読み替える (居住地域厳重警戒は 5、山麓厳重警戒は 4、入山危険と周辺海域警戒は 3、火口周辺危険は 2)。
- 火山ごとのいまの噴火警報・予報は、受けた VFVO50 のうち火山ごとにいちばん新しいもの (取り消されたものは飛ばす)。地図の火山の印に使う。**sonae が受けていない火山 (長く発表の変わっていない火山) は入らない** (気象庁の長期フィードは数日分しか無い)。
- 噴火速報には火山の位置が無いので、地図では活火山の一覧 (`static/areas/volcano-points.json`、`tools/volcanoes/build.sh` で気象庁ホームページの一覧から作る) で位置を引く。

### 2.3 ブラウザへの配信: SSE

|                      | SSE (`text/event-stream`)                                                                                               | WebSocket                                                                          |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 向き                 | サーバーからだけ。sonae はこれで足りる (設定の変更は普通の POST)                                                        | 両向き                                                                             |
| 張り直し・取りこぼし | ブラウザが自動で張り直し、`Last-Event-ID` を送る。そこから DB で埋められる                                              | 自前で書く                                                                         |
| 認証                 | 普通の要求なので、セッションの Cookie と hooks の判定がそのまま効く                                                     | Upgrade の時に別に判定する                                                         |
| SvelteKit・Gateway   | `+server.ts` で `ReadableStream` を返すだけ。Cilium Gateway もそのまま通る                                              | SvelteKit に標準の仕組みが無く、adapter-bun の外で `Bun.serve` の websocket を触る |
| 同時の接続数         | HTTP/1.1 だとブラウザの 6 本の上限に数える。HTTP/2 なら 1 本に束ねられる (Gateway が h2 を話すかは載せるときに確かめる) | 制限なし                                                                           |

**SSE にする。** `GET /api/stream`。

- 各イベントに DB の通し番号を `id:` で付ける。`Last-Event-ID` があれば、それより後を DB から送ってから生の配信に移る。
  - 埋め直しは 500 件まで。**超えるときは埋め直しを送らず、`event: resync` を送る** (`id:` はいまの最後の番号、`data` は `{"after": 番号}`)。そこから生の配信に移る。ブラウザは受けたら `invalidateAll()` で `load` を走らせ直し、一覧を取り直す。
- **`s.doany.io` は Cloudflare のプロキシを通したワイルドカードの DNS で配信される** (DNS のレコードは足さない)。Cloudflare のプロキシは、応答の間に 100 秒何も流れないと接続を切り (Proxy Read Timeout)、圧縮やバッファリングで SSE を溜めて届けることがある。そのため:
  - **30 秒ごとにコメント行 (`: ping`) を送る。** Cloudflare の 100 秒、adapter-bun の `CONNECTION_IDLE_TIMEOUT` (Bun の idleTimeout、上限 255 秒)、Gateway の無通信の切断のどれよりも十分短い。同じ間隔で情報源の状況 (`event: status`) も送る。
  - 応答のヘッダーに `Content-Type: text/event-stream`・`Cache-Control: no-cache, no-transform`・`X-Accel-Buffering: no` を付ける (`no-transform` で圧縮を止め、`X-Accel-Buffering` で途中の溜め込みを止める)。
  - それでも切れることはあるので、ブラウザの側は切れたら張り直して、最後に受けた番号の後を取り直す。最初の接続は、ページの `load` で渡した最後の番号を `?after=` で付ける。
- **張り直しは画面が自分でする** (`src/lib/live.svelte.ts`。2026-11-15 に、EventSource の張り直しに任せるのをやめた。持ち主の声「接続を再試行するようにしてほしい」)。EventSource だけでは止まったままになる道があるため:
  - サーバーや途中 (Cloudflare・Gateway) が 200 の `text/event-stream` 以外 (入れ替え中の 502・503、ログインが切れた 401 など) を返すと、EventSource は張り直さずに CLOSED で止まる。
  - スリープから戻ったときなどに、TCP が死んでいるのに EventSource が気づかず、何も届かないままになる。`: ping` のコメント行は EventSource が画面に渡さないので、画面からは数えられない。
  - そこで、`error` が来たらいつも閉じて、自分で間を空けて張り直す (`#lib/backoff.ts` の Backoff。情報源の張り直しと同じく、1 秒から倍々・上限 30 秒・full jitter。60 秒続けてつながったら間隔を戻す)。張り直すたびに、そのとき最後に受けた番号を `?after=` に付けるので、切れていた間のものはサーバーが埋め直す (500 件を超えれば `resync` で一覧を取り直す。上の通り)。取りこぼさない。
  - すぐ張り直すきっかけ: `online`、画面に戻ったとき (`visibilitychange` で、切れているか 75 秒何も届いていないとき)、戻る・進むの控え (bfcache) から戻ったとき (`pageshow`)。`offline` では閉じて、間を空けた張り直しを続ける (`offline` の知らせは当てにならないことがあり、張り直しを止めると戻ったことに気づけない道ができるため。間隔は伸びて 30 秒で止まり、`online` で戻す)。
  - 心拍: サーバーが 30 秒ごとに送る `event: status` を心拍に使う。つながっているのに 75 秒 (`STALE_MS`。2 回半) 何も届かなければ、死んだとみなして張り直す (5 秒ごとに見る)。
  - 手元の Chromium で、`/api/stream` が 503 を返し続ける間も 20 秒に 6 回張り直し、戻すとつながり直すことを確かめた。
- **切れたことを知らせる** (`src/lib/connection.ts` の OutageWatch と `alerter.svelte.ts` の `connection`。持ち主の声「接続が切れたとき音声で通知してほしい」)。
  - 切れたまま 30 秒 (`OUTAGE_NOTIFY_MS`) 続いたら、1 度だけ「そなえの受信が切れました。再接続しています。」と知らせる。サーバーの入れ替えなどの短い切れ目では鳴らさない。開いてから一度もつながらないときも数える。
  - 知らせた後につながったら、短く「そなえの受信が戻りました。」と言う (知らせていない切れ目の戻りは言わない)。
  - 切れたり戻ったりを繰り返しても鳴りすぎないよう、前の「切れました」から 10 分 (`OUTAGE_COOLDOWN_MS`) は次の「切れました」を言わない (経った後も切れたままなら言う)。
  - 知らせ方は「通知」の「開いているとき」でオンにしたものだけ。切れたときは事象と同じく、チャイム・OS の通知 (tag `sonae:connection`。チャイムが鳴ったら音なし)・読み上げ。戻ったときは読み上げと、切れたときの通知が残っていれば音なしで置き換えるだけ (チャイムは鳴らさない。警報と紛れるため)。
  - スイッチ「受信が切れたら知らせる」(`sonae.alert` の `outage`。既定はオン) で止められる。
  - 読む文は `#lib/readout.ts` の `CONNECTION` の 2 文で、決まった文として起動したときに合成しておく。切れている間はサーバーに音を取りに行けないので、画面は読み上げがオンで VOICEVOX が使えるときに前もって取っておき (この家の声が替わったら取り直す)、取れていなければ端末の読み上げで読む。
  - タブが幾つあっても 1 つだけが知らせる (Web Locks。タブごとに見ているので 60 秒持つ)。
  - 画面の印も合わせる。切れている間は、ヘッダー (スマホの形は dock) の注意の印が「配信が切れています・再接続しています」、受信の状態の「画面への配信」が「再接続しています」になる。
- 最初の表示の中身はページの `load` で渡し、SSE は差分だけにする。

### 2.4 Web Push

**push-bridge は使えない。** memory にある infisical-push-bridge は、Infisical の Webhook を受けて InfisicalSecret の注釈を書き換える仕組みで、ブラウザへの Web Push とは関係が無い (2026-11-02 に撤去済み)。

**@block65/webcrypto-web-push を使う。** 最初は web-push の予定だったが、Bun の上で Node の https と CJS の依存を束ねるより、WebCrypto と fetch だけで済むほうが distroless の束ね方 (Dockerfile の「実行時の依存は無い」) に素直に合う。

devDependencies に入れ、Vite がサーバーに束ねる。テスト (`tests/push.test.ts`) で、送った本文をブラウザの側の手順 (RFC 8291) で復号できることまで確かめている。

- **鍵:** VAPID の秘密鍵 (P-256 の JWK の JSON) を環境変数 `VAPID_PRIVATE_JWK` で受ける。公開鍵は JWK の x・y から作り、`GET /api/push` で画面に渡す。
  **鍵が無ければ Web Push だけを切る** (登録を受けず、送らない。ほかは普段どおり)。本番は SOPS の Secret (`deploy/secrets.sops.yaml` の `vapid-private-jwk`) を `optional: true` で読む。連絡先 (`VAPID_SUBJECT`) は既定で `PUBLIC_URL`。
- **購読:** ブラウザごとに `push_subscriptions` に、ログインした人 (IdP の sub)・endpoint・鍵・条件 (下)・ブラウザの名前を持つ。セッションとは結ばない (ログインが切れても届く)。1 人 20 まで。
  - endpoint はブラウザから来るので、サーバーから任意の宛先へ POST させないよう、主な配信サービス (FCM・Mozilla・Apple・WNS) の https だけ受ける。転送 (3xx) も追わない。
  - 送って **404・410 が返ったら購読を消す**。ほかの失敗は記録に残すだけ。
- **登録の画面と API:** 画面はヘッダーの「通知」(スマホの形は下のタブの「通知」) から開くダイアログ 1 つ (`src/lib/components/PushSettings.svelte`)。API は `GET`・`PUT`・`DELETE /api/push` と、試しに送る `POST /api/push/test` (1 人 10 分に 5 回まで。超えたら 429 と `Retry-After`。`src/lib/server/rate.ts`)。どれもログインが要る (hooks)。
- **何を知らせるか (ブラウザごとに選ぶ。括弧は既定と、その理由):**
  - 緊急地震速報: 警報だけ / 予報も / 送らない (**警報だけ**)。警報は強い揺れが来る地域に出るもので、身を守る動きにつながる。予報は日に何度も出ることがあり、鳴りすぎると通知自体を切られてしまう。予報を選んでも本文に予想震度は書かない (5 章)。
  - 地震情報: 最大震度がいくつ以上 (**震度 4**)。震度 4 は「ほとんどの人が驚く」揺れで、家族の安否を気にし始める境目。震度 3 以下は全国で月に何十回もあり、鳴りすぎる。
  - **住んでいる地域** (**選ばない**)。地震と気象の両方に使う 1 つの設定で、1 つの市町村等 (気象警報等、7 桁のコード) を選ぶ (2026-11-14 に持ち主の指摘で、地震だけの「現在地」から替えた。前の「現在地」は読まず、選び直してもらう)。
    - Web Push はタブを閉じていても届くので、サーバーが地域を知っている必要がある。そのため購読の条件に持つ
    - 選んだときに、画面が市町村等の表 (`static/areas/cities.json`、docs/map.md) から、その市町村等が入る地震情報／細分区域・府県予報区・一次細分区域を引いて一緒に持つ。サーバーと Service Worker は表を読まずに判定できる
    - 選び方は都道府県と市町村の 2 つの欄か、「現在地から選ぶ」。現在地は端末の位置を 1 回だけ取り、端末の中で市町村等の面 (`warning-areas.geojson`) を引いて、市町村等のコードだけを持つ。**緯度・経度はサーバーに送らず、覚えもしない**
  - 住んでいる地域の地震情報／細分区域で震度いくつ以上 (**震度 3**)。最大震度の条件に届かなくても、自分の所で揺れたものは知りたいので、1 段下げる。P2P の震度速報には地域のコードが無いので、名前でも見る。
  - 津波: 注意報以上 / 警報以上 / 大津波警報だけ / 送らない (**注意報以上**)。注意報でも海の中や海岸の近くでは危ないので、住んでいる地域の予報区に関わらず送る (旅先や家族の居場所もあるため)。
  - 住んでいる地域の気象: 警報以上 / 注意報も / 送らない (**警報以上**。2026-11-14 に足した)。警報以上は、住んでいる市町村等に出た警報・危険警報・特別警報 (レベル 3〜5。土砂災害警戒情報にあたるレベル４土砂災害危険警報も入る) と、住んでいる地域が対象の記録的短時間大雨情報・竜巻注意情報。
    注意報は日に何度も出たり替わったりして鳴りすぎるので、既定では送らない。住んでいる地域の警報・注意報が解除されたら、前に知らせた端末にだけ置き換えに行く。指定河川洪水予報・熱中症警戒アラート・台風情報・気象防災速報は一覧に出すだけで送らない
  - 気象の特別警報は、住んでいる地域でなくても送る (**オン**)。数十年に一度の重大な災害のおそれで、旅先や家族の居場所もあるため (津波注意報と同じ考え)。住んでいる地域と同じ府県予報区のほかの市町村に特別警報が出ているときは、住んでいる地域の通知 (同じ tag) で特別警報を先に言い、住んでいる地域の状態を添える (住んでいる地域の続報や解除を落とさない)
  - 南海トラフ地震臨時情報・定例外の解説情報・後発地震注意情報 (**オン**)。めったに出ず、出たら備えを見直すべきもの。
  - 火山: 噴火速報と噴火警報 (居住地域) / それに火口周辺警報も / 送らない (**噴火速報と噴火警報 (居住地域)**。2026-11-14 に足した)。
    噴火速報は登山者や周辺の人がすぐ身を守るためのもので、出るのは年に数回。噴火警報 (居住地域) は警戒レベル 4・5 (高齢者等避難・避難) と、レベルの無い火山の山麓・居住地域厳重警戒で、住んでいる所に避難が要るもの。
    火口周辺警報 (レベル 2・3) は火口の近くに入らなければ身に及ばず、出たままの火山が常に幾つもあって引上げ・引下げのたびに鳴ると多すぎるので、既定では送らない。警報の解除と取消は、前に知らせた端末にだけ送る。
  - 訓練・試験・遠地地震は送らない。
  - 持ち主の決定 (2026-11-13、9 章の 4): 既定値はこのまま。
- **同じ事象で何度も鳴らさない:**
  - 事象ごとに tag を決める (`eew:<地震識別番号>`・`quake:<地震の id>`・`tsunami:<津波の id>`・`advisory:<id>`・`volcano:<火山のコード>`・噴火速報は `volcano:flash:<識別番号>`・気象警報・注意報は `warning:<住んでいる市町村等>:<種別>`、どこかの特別警報は `warning:special:<府県予報区>:<種別>`・記録的短時間大雨情報と竜巻注意情報は `weather:<一連の情報>`)。
    気象の通知は住んでいる地域で中身が変わるので、イベントから作った通知の元を購読の条件ごとに作り直す (`#lib/notify.ts` の `noticeFor`。Web Push も開いている画面の音も同じ)。Service Worker は `showNotification` の `tag` で前の通知を置き換える。
  - 購読ごとに、tag へ最後に送った「重さ」(震度の段・津波の区分・警報か予報か) と中身の要約を `push_log` に持つ。
    初めては鳴らす。**中身が同じなら送らない。重さが上がったら鳴らし直す** (`renotify`)。それ以外の続報 (震源や M が決まった・取消・解除) は、**同じ tag で鳴らさずに置き換える**。
  - 取消・解除は、前に知らせた購読にだけ送る (知らせていないものの取消は要らない)。
  - 鳴らすかどうかを決めて控えるところまでは同期でする (続報が続けて来ても二重に鳴らない)。送れなかったら控えを送る前に戻す (初めての通知なら消して、次の続報を初めてとして扱う)。購読の持ち主が替わったら控えを捨てる。控えは 30 日で捨てる。
  - Web Push の `Topic` に tag の SHA-256 の先頭 32 字を付ける。配信サービスがまだ届けていない前の通知は、続報で置き換わる。
  - 起動したときに長期フィードで埋めた昔の電文を鳴らさないよう、事象の時刻から緊急地震速報は 3 分・地震と記録的短時間大雨情報・竜巻注意情報は 1 時間・津波・お知らせ・火山・気象警報は 6 時間を過ぎたものは送らない。有効期限の過ぎた竜巻注意情報も送らない。
- **送り方:** 緊急地震速報と津波、噴火速報と噴火警報 (居住地域)、気象の危険警報・特別警報と記録的短時間大雨情報・竜巻注意情報は `Urgency: high`。`TTL` は緊急地震速報 120 秒 (遅れて届いても意味が無い)、地震情報と記録的短時間大雨情報・竜巻注意情報 1 時間、津波・お知らせ・火山・気象警報 6 時間。緊急地震速報の警報と津波警報以上、噴火速報と噴火警報 (居住地域)、気象の危険警報・特別警報は、閉じるまで残す (`requireInteraction`)。
- **Service Worker** (`src/service-worker/`、SvelteKit が自動で登録): 通知を出し、押されたらその事象の画面 (1 つの画面でその件を選んだ URL。`/?q=<id>`・`/?k=tsunami&t=<id>`・`/?k=eew&e=<識別番号>`。[ui.md](ui.md)) を開く。開いている画面があればそれを移して前に出す。このサイトの中のパスしか開かない。画面やデータの控え (オフライン) はしない (古い地震情報を出さないため)。型は WebWorker の型で、`bun run check` が別に見る。
- **iPhone・iPad:** ホーム画面に追加した Web アプリ (iOS 16.4 以降) でだけ Web Push が届く。そのための Web アプリのマニフェスト (`static/manifest.webmanifest`。明るいテーマでは地の色だけが違う `manifest-light.webmanifest`) を置き、ダイアログで案内する。
- **使えないブラウザ:** 機能が無い・届かない宛先を返す (Android の Edge は `permanently-removed.invalid`)・登録が例外で止まる、のどれでも、ダイアログに何ができないかと代わりの道 (ほかのブラウザ・開いている間の通知と音) を出し、黙って押せないままにしない。決めるのは機能の有無と宛先で、ブラウザの名前は文に添えるだけ (`#lib/push-support.ts`。[push.md](push.md) の「使えないブラウザ」)。
- **ホーム画面のアイコン:** iOS と Android のホーム画面は SVG のアイコンを使わないので、`static/favicon.svg` から PNG を作って `static/icons/` に置く (192・512・maskable の 512 をマニフェストに、180 の `apple-touch-icon.png` を `app.html` の `<link rel="apple-touch-icon">` に)。白い地に印を置き、maskable は印を安全な円 (直径 80%) に収まる 55% にする。作り方はホストに何も入れず、コンテナの rsvg-convert で描く。`favicon.svg` を変えたら、次のコマンドで作り直してコミットする。

  ```sh
  wslc run --rm -v "$PWD:/w" -w /w debian:trixie-slim sh tools/icons/build.sh
  ```

- **開いているとき:** SSE で受けたら、OS の通知と、短い音 (`<audio>`) と読み上げで知らせる (`src/lib/alerter.svelte.ts`)。読み上げの声は VOICEVOX で作る (下の「読み上げ」)。
  - **OS の通知も出す** (2026-11-15 に足した。持ち主の声「警報聞き逃しはまずいから開いてるときは通知ならして」)。ブラウザは操作の前だと `<audio>` も読み上げも鳴らさないが、`ServiceWorkerRegistration.showNotification` は通知の許可があれば操作なしで OS の通知音が鳴る。
    鳴らすと決めた事象 (`alertFor` と同じ所。`planAlert` の `renotify`) で出す。中身は Web Push と同じ関数で作る (`payloadOf` → `toNotification`。見出し・本文・tag・`renotify`・閉じるまで残すか (`requireInteraction`)・押したときの URL)。押したときは Service Worker の `notificationclick` がその事象の画面へ移す。
    鳴らさない続報 (取消・解除・震源が決まった) は、その tag の通知が出ていれば鳴らさずに置き換える (取消を残った通知に映す)。
  - **出すのは通知の許可 (`Notification.permission === "granted"`) があるときだけ。** 許可を求めるのは人が操作したときだけ (「通知」の「開いているとき」の「OS の通知を出す」のスイッチと、Web Push の「このブラウザで受ける」)。スイッチは `sonae.alert` の `notify` に持ち、既定は無し (許可があればオン)。許可はサイトの設定で変わるので、画面に戻ったとき (`visibilitychange`) と窓を開いたときに読み直す。
  - **Web Push と二重に鳴らさない。** Web Push に登録してあるブラウザには、同じ事象が SSE と Web Push の両方で届く。Service Worker は画面が開いているかで Web Push の通知を止めない (下の項。iOS が購読を止めるため) ので、どちらも通知を出す。
    同じ事象は同じ tag なので、後から出した通知は前の通知を置き換えるが、`renotify` が付いていると置き換えでも鳴り直す。そこで **後から出すほうが、同じ tag で見出しと本文も同じ通知がもう出ていないかを `getNotifications({ tag })` で見る** (`#lib/push.ts` の `isShown`)。
    - Service Worker (Web Push が後): 出ていれば、`renotify: false`・`silent: true` で置き換える (`quiet`)。出すことはやめない。
    - 画面 (SSE が後): 出ていれば出さない。ほかのタブが出したときも同じ (タブが幾つあっても 1 度)。
    - 条件は同じ `PushPrefs` を端末とサーバーで持つので、ふつうは同じ中身になる。重さが上がった続報は本文が変わるので、どちらからでも鳴らし直す。
    - 残ること: 見て出すまでの間は交わらないので、ほぼ同時に届くと 2 度鳴ることがある (ふつうは SSE が先に届き、Web Push は配信サービスを通るぶん遅い)。画面の通知を人が閉じた後に Web Push が届くと、もう出ていないので鳴る。
  - **チャイムと OS の通知音を重ねない。** チャイムがオンで鳴り始めたら (0.3 秒待つ)、通知は `silent` で出す (チャイムが代わりに鳴る。音なしで鳴らし直すことは無いので `renotify` は付けない。音なしの形で投げられたら、通知音つきで出し直す)。チャイムがオフか、操作の前で鳴らせないときは、OS の通知音に任せる。読み上げは、チャイムか OS の通知音が鳴ったら 0.75 秒おいて始める。`silent` を読まないブラウザでは、チャイムと通知音が重なることがある (確かめたのは Chromium だけ)。
  - **鳴らす判定は Web Push と同じ関数** (`src/lib/notify.ts` の `noticeOf`・`decide`)。サーバーの `plan` も、画面の `alertFor` (`src/lib/alert.ts`) も `decide` を呼び、違うのは控えの置き場 (サーバーは購読ごとの `push_log`、画面はメモリ) と中身の値 (サーバーは SHA-256、画面は元の字) だけ。同じ所で鳴ることを `tests/alert.test.ts` で確かめている。訓練・試験・遠地地震・古すぎるものは鳴らさず、続報は重さが上がったときだけ鳴らし直す。
  - **条件は「通知」のダイアログの条件 1 つ** (Web Push と同じ `PushPrefs`)。端末の localStorage (`sonae.alert.prefs`) に持ち、Web Push に登録してあればサーバーにも送る。新しいルートは作らない。
  - **現在地の気象も知らせる** (2026-11-15。持ち主の声「現在地か住んでる地域の注意報警報発表されたら読み上げてほしい」)。地図の現在地 (右下のボタン。4 章) が取れている間、その位置が入る市町村等を端末の中で探し (`#lib/push-client.ts` の `trackHere`。住んでいる地域の「現在地から選ぶ」と同じ面)、気象警報・注意報と記録的短時間大雨情報・竜巻注意情報を住んでいる地域に加えてそこでも知らせる。
    - **緯度・経度も現在地の市町村等も、サーバーに送らず覚えもしない** (`alerter.here` はメモリだけ)。Web Push は今までどおり住んでいる地域だけ。位置の許可を新しく求めることもしない (地図の現在地がオフなら住んでいる地域だけ)
    - 前の市町村等の面の中にいる間は面を引き直さない (`createHereFinder`。位置は数秒ごとに届くため)
    - 段は住んでいる地域と同じ「住んでいる地域の気象」(警報以上 / 注意報も / 知らせない)。注意報を知らせるかは、この 1 つの選択で決める (開いているときだけ別の既定にはしない。Web Push の既定は警報以上のまま)
    - 通知は住んでいる地域と同じ作り方 (`#lib/notify.ts` の `hereNoticeFor`) で、地域の名前の前に「現在地の」を付ける (「現在地の島根県松江市にレベル3大雨警報」)。同じ府県予報区のほかの市町村の特別警報を言う通知は、見出しが府県予報区の名前になるので「(現在地を含む地域)」を添える。tag は住んでいる地域と同じ形 (`warning:<市町村等>:<種別>`)。読み上げは、地域の文の前に決まった文「現在地の情報です。」を読む (地域は電文の名前で読むため)
    - 現在地が住んでいる地域と同じ市町村等なら、住んでいる地域の通知だけ。記録的短時間大雨情報・竜巻注意情報は 1 つの報に地域が並ぶので、住んでいる地域が対象なら現在地は足さない。どこかの特別警報は住んでいる地域の側の通知 1 つで言う
    - **同じ報が両方に当たったら 1 度だけ鳴らす** (`#lib/alert.ts` の `groupAlerts`)。重いほう (同じなら住んでいる地域) でチャイムと OS の通知を出し、もう 1 つは音なしの通知で並べ、読み上げは 1 つの原稿にまとめる (住んでいる地域を先に、現在地を後ろに「現在地の情報です。」から読み、冒頭の文と見出しを 2 度読まない。`readoutOfAll`)
    - スイッチは「開いているとき」の「現在地の気象も知らせる」(`sonae.alert` の `here`。既定は無し = オン)
    - 残ること: 動いて新しい市町村等に入ったとき、そこにもう出ている警報は知らせない (知らせるのは、入った後に出た報と続報)。前にいた市町村等の解除は、その市町村等を出た後は置き換えない
  - **音と読み上げは端末ごとにオン/オフでき、既定はどちらもオフ** (`sonae.alert`)。オンにしたときと「試しに鳴らす」で一度鳴らす。音の後に 0.75 秒おいて読む。
  - **音源は自作** (`src/lib/chime.ts`)。880 Hz から 660 Hz へ下がる 2 つの音を、その場で WAV (16 ビット・モノラル・22.05 kHz、0.7 秒) に組む。ファイルも外の音源も持たない。
  - **自動再生の制限:** ブラウザは、人がページを一度操作するまで音を出させない。最初の操作 (`pointerup`・`keydown`・`touchend`) の中で `<audio>` と読み上げを無音で一度動かし、後から鳴らせるようにする (iPhone・iPad の Safari は、操作の中で一度動かしたものでないと鳴らせない)。音か読み上げがオンなのに鳴らせない間 (`navigator.userActivation` がまだ立っていない、または再生を断られた) は、画面の上の端 (広い形はヘッダーのすぐ下、スマホの形はいちばん上) に帯を出す。何が止まっていて何は届くかを言い (「音と読み上げが止まっています」「押すと、警報を音と読み上げで知らせます」。通知の許可があれば「通知は出ます。読み上げも聞くなら押してください」。`#lib/alert.ts` の `mutedText`)、右に「音を出す」。帯のどこを押しても鳴らせるようになる。帯は中身に重ねず押し下げるので、地図・一覧・dock を隠さない。淡い面に注意の色のアイコンと見出しで、地は塗らない (6.2 の通り、塗るのは緊急地震速報 (警報) の帯だけ)。出るときに一度だけ上から滑り込み、アイコンは 3 回だけ脈打って止まる (6.3)。2026-11-15 に、ヘッダーと dock の小さい「音を出す」から替えた (持ち主の声「ミュート中は解除ボタンをもっと目立つようにしてほしい」)。 ただし、開いたときに自動再生を許しているブラウザ (Firefox は `navigator.getAutoplayPolicy`、ほかは作った `AudioContext` が `running` か で見る。Chrome・Edge はアプリとして入れたとき、Firefox・Safari・Edge はサイトの設定で許したとき) では、押さなくても鳴らせるので出さない (読み上げがオンで VOICEVOX が使えないときは除く。端末の読み上げは操作の前だと断られることがあり、断られても分からないため)。鳴らすのに失敗したら出す。
  - **裏のタブで止めない** (2026-11-16。持ち主の声「edge で裏側にしてると音声流れないことある。開くと音声流れる」)。Edge の「スリープ中のタブ」(既定は 2 時間使わなかった裏のタブ。省エネ機能 (旧称: 効率モード) では 30 分か 5 分。[Microsoft のサポート](https://support.microsoft.com/ja-jp/topic/learn-about-performance-features-in-microsoft-edge-7b36f363-2119-448a-8de6-375cfd88ab25)) と Chromium の止める仕組み (freezing) は、裏のタブの JavaScript をタイマーごと止める。SSE で届いた報はタブの中に溜まるだけで、前に出して動き出したときに遅れて鳴る。
    - Edge の [Sleeping Tabs FAQ](https://techcommunity.microsoft.com/t5/articles/sleeping-tabs-faq/m-p/1705434) は、眠らせないタブに「Web Lock か IndexedDB のトランザクションを持っている」「音を鳴らしている」「設定の除外の一覧にある」を挙げる。Chromium の止めない理由 (`components/performance_manager/public/freezing/cannot_freeze_reason.h`) にも `kHoldingWebLock` と `kAudible` がある。
    - そこで、OS の通知・音・読み上げのどれかがオンの間は、Web Lock (`sonae.awake`、共有) を 1 つ持ち続ける (`src/lib/awake.ts`。`alerter.start` が持ち、オフにしたら離す)。共有なのでタブが幾つあっても全部が持て、鳴らす控えの `sonae.alert:` のロックとも名前が別で交わらない。ロックそのものは CPU も電池も使わない (止められなくなるぶん、裏のタブでもタイマーと SSE が動き続け、その分は使う。オフにしたタブは今までどおり眠る)。
    - ただし、Edge の今の説明 ([Microsoft のサポート](https://support.microsoft.com/ja-jp/topic/learn-about-performance-features-in-microsoft-edge-7b36f363-2119-448a-8de6-375cfd88ab25)) の眠らせないタブの並びからは Web Lock が消えている。ロックで足りるとは言い切れないので、パソコンの Edge (UA に `Edg/`) で知らせるものがオンのときは、「通知」の「開いているとき」の説明の下に一言を添え、設定の除外の一覧に足してもらう (`#lib/awake.ts` の `EDGE_SLEEP_HINT`)。除外の一覧は Edge の説明でも眠らせないと書かれている。
    - 無音の音を流し続ける手は採らない。Chromium は本当に音が出ているタブだけを「音を鳴らしている」とみなす (消音の `<audio>` や無音では足りない) ので、聞こえないほど小さな音を流すことになり、タブにスピーカーの印が出続け、音の処理で電池も使う。
    - 裏のタブでは、チャイムから読み上げまでの 0.75 秒のタイマーは 1 秒刻みに丸められる (隠れたページのふつうの間引き)。強い間引き (1 分に 1 度) はタイマーから続けて張ったタイマーだけに掛かり、SSE を受けた中で張るこのタイマーには掛からない。
    - 残ること: メモリが足りないときに Edge がタブを捨てる (discard) のは、このロックで止められるとは書かれていない。捨てられたタブは前に出すと読み直すので、捨てられていた間の報は鳴らない (一覧には出る)。確実にするなら、上の一言のとおり Edge の設定 (「システムとパフォーマンス」の「パフォーマンス」にある「これらのサイトを常にアクティブに保つ」。`edge://settings/system`) に sonae を足す ([ui.md](ui.md))。確かめたのは文書と Chromium のソースまでで、Edge の実機で裏のタブが鳴るかはまだ確かめていない。閉じている・裏でも確実に届けるのは Web Push ([push.md](push.md))。
  - タブを幾つも開いていても、同じ通知は 1 つのタブだけが鳴らす (Web Locks で 5 秒持つ。鳴らせないタブはロックを取らない)。Web Push にも登録してあると、開いている間も Web Push の通知は届く (Service Worker は通知を出さないと iOS が購読を止めるため、画面を開いているかで止めない。二重に鳴らさない決まりは上の「Web Push と二重に鳴らさない」)。
  - **読み上げ始めた報の詳しい内容を開く** (2026-11-15。持ち主の声「情報読み上げ中は詳細開いてほしいかも」)。読み上げがオンで、事象の原稿を読み始めるときに `alerter.onread` を呼び、画面がその報を開く (一覧の行を押したときと同じ URL。地図はその報へ寄る)。読み上げがオフで音か OS の通知だけのときは開かない。人がほかのものを見ている・窓を開いているときに切り替えるかと、履歴の積み方は [ui.md](ui.md) の「自動で開く」。読み上げは 1 つのタブだけがするので、開くのもそのタブだけ (緊急地震速報は読み上げに関わらず、どのタブでも開く)

#### 読み上げ (VOICEVOX)

**読み上げの声は、sonae と一緒に動かす VOICEVOX のエンジンで作る。** `docker compose up` でも Helm chart (`charts/sonae`) でも、sonae と VOICEVOX のコンテナが一緒に起き、sonae は `VOICEVOX_URL` (`http://voicevox:50021`) でつなぐ。
VOICEVOX が止まっている・つながらないときは、画面が端末の読み上げ (`speechSynthesis`) で同じ原稿を読む。

- **エンジンの選び方 (2026-11-14):** 日本語の自然さ、CPU だけでの速さ、地名の読みを直すユーザー辞書の API、公式の CPU 用の Docker イメージ、クレジットを出せば無料で使えること、の 5 つで比べ、VOICEVOX にした。
  Kokoro・MeloTTS・Piper・GPT-SoVITS・Fish Speech・CosyVoice・Chatterbox・F5 は、日本語が弱い・GPU が要る・読み始めるまでが長すぎる・ライセンスが合わない、のどれかで外した。
- **sonae のイメージに入れず、別のコンテナにする理由** (公式の文書で確かめた):
  - ライセンス: VOICEVOX ENGINE は LGPL-3.0 (と別の許諾の二重)、VOICEVOX CORE は MIT だが、エンジンが読む VOICEVOX の ONNX Runtime と音声モデル (VVM) は独自の利用規約で、逆コンパイル・リバースエンジニアリングを禁じている ([VOICEVOX ONNX Runtime 利用規約](https://github.com/VOICEVOX/voicevox_resource/blob/main/onnxruntime/README.md)・[音声モデル利用規約](https://github.com/VOICEVOX/voicevox_vvm/blob/main/TERMS.txt))。AGPL-3.0 の sonae と 1 つのイメージにまとめて配ると、自由なソフトウェアの条件の無いものを sonae として一緒に配ることになる。公式のイメージを別に動かし HTTP で話せば、sonae のイメージは AGPL のままで、VOICEVOX の部分は VOICEVOX の配布物をそのまま使う形になる。
  - 大きさ: 公式の CPU のイメージは 2.4 GB (0.26.1、手元の `wslc image list`)。sonae のイメージ (distroless、約 120 MB) が 20 倍になり、sonae を直すたびの公開と入れ替えが重くなる。エンジンの更新は sonae と別の周期 (Renovate) でする。
  - 分離: 合成は CPU を数秒使い切り、モデルを読んだ声ごとにメモリを使う (手元で 3 人を読んで 1.9 GiB)。別のコンテナなら CPU とメモリの上限を別に掛けられ、エンジンが落ちたりメモリの上限で止められたりしても、受信・SSE・Web Push は止まらない。
- **流れ:** サーバーは事象を受けたら (Broker の配信と同時に)、読み上げの原稿 (`src/lib/readout.ts` の `readoutOf`) を作り、変わる文を**選んである声 1 つで**合成してメモリに持つ (`src/lib/server/voicevox.ts`)。
  画面も同じ原稿を自分で作り、文ごとに `POST /api/speech` (`{ text }`、ログインが要る。声は送らず、サーバーが選んである声で返す) で WAV を取って順に鳴らす。取れない文は端末の読み上げで読む。
  - 合成できるのは、決まった文と受けた事象の原稿の文だけ (ほかの文は 404。エンジンに勝手な文を読ませない)。
  - 音は (声, 文) の組でメモリに 64 MB まで持ち、古いものから捨てる。選んである声の決まった文は捨てない (前の声の決まった文は、ほかと同じく古いものから捨てる)。合成は 1 つずつ順に頼み、事象の文を下ごしらえより先にする。
  - つながりは 1 分ごとに確かめ、つながり直したら声の一覧と辞書を読み直して、決まった文を合成し直す。
- **すぐに読み始める:** 冒頭の決まった文 (`OPENINGS`。「緊急地震速報です。強い揺れに警戒してください。」など 17 文) と試しの文と、受信が切れた・戻ったときの文 (`CONNECTION`。2.3) は、起動したとき・つながり直したとき・声を替えたときに、選んである声で合成しておく。変わる文 (地域・震源) は、決まった文を読んでいる間に合成する。
  - 手元の測定 (2026-11-14、Ryzen 5 5600X、エンジンに 2 CPU・スレッド 2): 4 秒ほどの文の合成に 1.5〜2 秒、12 秒ほどの文に 4〜6 秒 (実時間の 0.4〜0.5 倍)。
    緊急地震速報 (警報) は受けてすぐ冒頭を鳴らせ (取りに来てから 1 ms。持っている音を返すだけ)、2 度目の冒頭を読み終える 8.2 秒より前に、地域の文 (11 秒) が 4.6 秒で、震源の文が 5.3 秒で揃った。起動して既定の声の冒頭 11 文がそろうまで 13 秒。
  - 家のクラスタの Z440 では測っていない (CPU が遅ければ合成も遅くなる)。そのため Deployment は CPU の上限を 4、スレッドを 4 にしてある。
- **声を選ぶ:** 「通知」のダイアログの「読み上げる」の下に、声の選択肢 1 つと「試しに聞く」を置く。選択肢は動いているエンジンの `/speakers` から作り、名前とスタイルを並べる (コードには書かない)。
  - **声はこの家で 1 つで、サーバーに持つ** (2026-11-15。持ち主の声「声は端末ごとじゃなくてサーバ側に保存して」)。DB の `settings` (2.5) の `voice` (VOICEVOX のスタイルの id) に、替えた人 (IdP の sub) と一緒に持つ。まだ選んでいなければ既定の声 (`VOICEVOX_SPEAKER`)。選んである声がエンジンの選べる声に無くなったら (エンジンを替えた・規約で外した)、既定の声で読む。
    前は端末ごとに `sonae.alert` の `voice` に持ち、サーバーは端末が使う声を「使われている声」として `voices.json` に覚えて声ごとに合成していた。端末ごとに違う声を選ぶと合成が声の数だけ増え、最後の声は最初の文が鳴るまで遅れた (本番では 4 つの声が使われていた)。端末の `voice` は読まずに消し、サーバーの `voices.json` も読まずに消す。
  - 選んだらすぐ保存する (`PUT /api/speech`、`{ voice }`。保存のボタンは無い)。保存している間は選択と「試しに聞く」を止める。窓には「声はこの家の全部の端末で同じになります」と書く。音・読み上げのオン/オフは、これまでどおり端末ごと。
  - **替えられるのは、ログインした人なら誰でも。** 通すロールは `OIDC_ROLE` の 1 つだけで (2.6)、ログインした人はみな同じロールを持ち、管理の役割を見分ける仕組みが無いため。家族と共有するのは家族が使う声を決めるためでもあるので、家族の誰が替えてもよいとした。
  - API は hooks のログインの判定の内側にあり (無ければ 401)、本文は `application/json` だけ受ける (ほかは 415)。別のオリジンから JSON で送るにはプリフライトが要り、sonae は答えないので通らない。フォームの形は SvelteKit が別のオリジンから受けない。セッションの Cookie も `SameSite=Lax`。
  - 替えたら、サーバーは新しい声で決まった文をすぐ合成し直し、開いている全部の画面に SSE の `event: voice` (`{ voice }`。番号は付けない) で知らせる。つないだとき (張り直したときも) にも送るので、切れていた間に替わっても揃う。画面は 5 分ごとにも `GET /api/speech` を読み直す。
  - 替えた直後の数十秒は、新しい声の冒頭がまだ合成できていないことがある。そのときは合成を待つ (前の声で代わりに読まない。鳴る声とクレジットを 1 つにするため)。
  - エンジンは一度読んだ声のモデルを手放さない (外す API が無い) ので、何度も替えるとエンジンのメモリが増える。メモリの上限で止められたら、エンジンは入れ替わり、sonae がつながり直して選んである声で決まった文を合成し直す。
  - 選べるキャラクターは、利用規約を読んで「クレジットを出すだけで、会社が公開するアプリの中で使える」と確かめたものだけ (`src/lib/voices.ts` の `ALLOWED_SPEAKERS`、2026-11-14 にエンジン 0.26.1 の 44 人を読んだ)。エンジンが新しく足したキャラクターは、規約を読んで足すまで出さない。
  - 外したもの: 企業が関わる利用・商用利用に事前の確認や申請が要るもの (青山龍星・もち子さん・後鬼・No.7・ユーレイちゃん・猫使アル・猫使ビィ・夜語トバリ・暁記ミタマ・里石ユカ・ぞん子)、法人の利用を許していないもの (Voidoll)、詳しい規約の本文が見つからないもの (琴詠ニア)。sonae は会社 (danything) が公開し、使う人が会社のこともあるので、個人の利用だけを許す規約では足りない。
  - 規約は予告なく変わる。エンジンを上げるときに、足されたキャラクターと規約の変わったものを読み直す。
- **既定の声は剣崎雌雄 (ノーマル、スタイルの id 21)。** 公式の紹介は「安心感のある落ち着いた声」で、警報を落ち着いて伝えるのに合う。利用規約は「VOICEVOX:剣崎雌雄」と書けば商用・非商用で使え、申請や報告は要らない ([規約](https://frontier.creatia.cc/fanclubs/413/posts/4507))。まだ画面で選んでいないときの声は、環境変数 `VOICEVOX_SPEAKER` (スタイルの id) で替えられる。替えるときは、そのキャラクターの規約を読む。
- **クレジット:** VOICEVOX で読み上げている端末では、「出典と注意」の窓の出典に、この家で選んである声を「VOICEVOX:<名前>」で出す (鳴る声はそれ 1 つ)。読み上げがオフか、VOICEVOX につながっていないときは出さない。
- **原稿 (`src/lib/readout.ts`):** 冒頭の決まった文のあと、変わる所を 1 文ずつ。気象庁の文 (見出し・津波の付加文・噴火速報の見出し) は言い換えずに読む。取消・解除は読まない (鳴らさないので)。
  - 緊急地震速報 (警報): 冒頭の文を 2 度読み (テレビ・ラジオの伝え方と同じ)、「強い揺れに警戒が必要な地域は、〜です。」「震源は〜です。」。**予想震度と到達予想時刻は読まない** (5 章)。
  - 緊急地震速報 (予報): 「緊急地震速報、予報です。」「震源は〜、規模はマグニチュード〜と推定されています。」。仮定震源なら「震源と規模は仮のものです。」。
  - 震度速報: 「震度速報です。」「〜ごろ、最大震度〜を観測する地震がありました。」と、震度の高いほうから 2 つの段の地域。
  - 震源・震度に関する情報: 「地震情報です。」・時刻と震源・深さと M・最大震度・2 つの段の地域・津波の付加文 (「この地震による津波の心配はありません。」など、気象庁の文のまま)。
  - 津波: 区分ごとの冒頭 (「大津波警報が発表されました。」など)、**大津波警報と津波警報の地域を先に全部読み**、気象庁の見出し、津波注意報の地域 (10 を超えたら「など、N の地域」)。
  - 南海トラフ地震臨時情報・関連解説情報・後発地震注意情報: 冒頭の文・情報の名前と種類・気象庁の見出し。噴火速報: 「噴火速報です。」と気象庁の見出し。噴火警報: 「火山の情報です。」・情報の名前・見出し。
  - 気象の特別警報: 「気象の特別警報です。」「<府県予報区>に、<種類の名前>が出ています。」「対象の市町村は、〜です。」。住んでいる地域がその府県予報区にあれば、その市町村等の文 (下) も続け、気象庁の見出しで終える。
  - 住んでいる地域の気象警報・注意報: 段ごとの冒頭 (「気象の危険警報です。」「気象の警報です。」「気象の注意報です。」)、「<市町村>には、<種類の名前>が出ています。」(段の高い順。「レベル4土砂災害危険警報」のように電文の名前のまま)、気象庁の見出し。
    土砂災害警戒情報はいまはレベル 4 の土砂災害危険警報 (2.8) なので、危険警報の冒頭で読む。市町村は住んでいる地域の名前ではなく電文の市町村等の名前で読む (端末ごとに違う名前ではサーバーが前もって合成できないため)。サーバーは電文に出てくる市町村等ごとの文を通す文に入れ (`readoutCandidates`)、合成は画面が取りに来たときにする
  - 記録的短時間大雨情報: 「記録的短時間大雨情報です。」と気象庁の見出し (時刻・地域・雨量は見出しの文のまま)。竜巻注意情報: 「竜巻注意情報です。」と気象庁の見出し、見出しに無ければ「この情報は〜まで有効です。」(電文の有効期限)。
  - **気象の予想は作らない** (5 章)。読むのは電文の種類の名前・見出し・有効期限だけ。
  - これから足す種類は、`readoutOf` の `switch` に種類の分を足す。足すまでは、通知の見出しと本文を読む。
  - 地域は 10 まで並べ、超えたら「など、N の地域」と言う (津波の警報の地域は縮めない)。読み上げるだけの文なので、半角の数字と日本語の間に空白を入れない。
- **地名の読み:** VOICEVOX が読み違える地名は、ユーザー辞書 (`src/lib/server/readings.ts`) で直す。エンジンは辞書をコンテナの中に持つので、sonae がつながるたびに足りない語を足す (優先度 10)。
  気象庁のコード表の震央地名 (343)・細分区域 (194)・津波予報区 (70)・活火山 (111) を `accent_phrases` に通して出たカナを見て、読み違えた 43 語を足した (渡島 → トトオ、後志 → シリベ、平野部 → ヒラノブ、沖縄県宮古島 → ミヤフルトオ、新潟県中越 → ナカコシ など)。足した後に、すべてがここの読みになることを確かめた。日向灘・釧路沖は辞書なしで正しく読む。
  アクセントは聞いて確かめていない (読みのカナだけを確かめた)。北方領土と海の火山のいくつか (茂世路岳・小田萌山・指臼岳・海形海山・若尊) の読みは、気象庁の読みと突き合わせていない。

### 2.6 認証

ロールを持つ人だけが開けるようにする。ほかのアプリと同じく、パスワードは持たず OIDC でログインする。

- **OIDC のクライアントは自前** (noren の `src/lib/server/oidc.ts` と同じ形: discovery・認可コード + PKCE・素の fetch と WebCrypto で id_token の署名・発行元・宛先・期限・nonce を確かめる)。ライブラリは足さない。
- **IdP は doany.io の Entra ID の共用のアプリ登録 `Main`。新しくアプリは登録しない。** ashi と同じく、誰が使えるかはエンタープライズ アプリケーションのロールの割り当てで決める。
  通すロールは `OIDC_ROLE` (**既定は `admin`**。まずは持ち主 1 人)。家族と共有するときはロールを足して `OIDC_ROLE` を替えるだけで、コードの変更は要らない。
  リダイレクト URI・環境変数の表・家族と共有する手順は [entra.md](entra.md)。
- issuer・client id・secret の 3 つが揃わないと、画面は開かない (`/health` だけ答える)。手元の開発だけ、`AUTH_DISABLED=1` でログインを飛ばせる (本番の `NODE_ENV=production` では効かない)。
- **信頼するネットワーク (`TRUSTED_NETWORKS`) の中からは、ログインなしで通す** (`src/lib/server/trust.ts`。denpa と同じ考え方)。1 行で入れたセルフホストの 1 台目が、IdP を用意しなくても開けるように。
  - 書いていなければ誰も通さない (いままでどおり)。本番 (家の Talos のクラスタ) と chart の既定は書かず、OIDC だけ。インストーラ (install.sh・install.ps1) は家の LAN とそのマシンのブラウザを書く ([install.md の「ログイン」](install.md#ログイン))
  - **アドレスに加えて名前も見る** (DNS リバインディング除け)。通すのは IP の直書き・localhost・ドットの無い名前・家の中だけの名前 (`.localhost`・`.local`・`.lan`・`.home.arpa`・`.internal`)・`ALLOWED_HOSTS` だけ
  - 接続元は、直の相手が前段 (`TRUSTED_PROXIES`) のときだけ `X-Forwarded-For` を右から読む。adapter-bun の `ADDRESS_HEADER` を設定していたら、信頼するネットワークは使わない (誰でも名乗れるため)
  - 通した人は全員 1 人の利用者 (`trusted-network`、「家のネットワーク」) として扱う。**その中の誰でも、読み上げの声・通知の条件・Web Push の購読を変えられる**
  - OIDC と一緒に使える (外の人はログイン、中の人はログインなし)。OIDC が無いとき、外の人には 403 と接続元を返す
  - **ログインなしの経路では、ほかのサイトから送らせた書き込みを断る** (`crossSiteWrite`)。Cookie の SameSite が効かず、LAN の人が開いた悪いサイトが `http://<LAN の IP>:3030/api/...` へ送らせることができるため。
    GET・HEAD・OPTIONS 以外は、`Sec-Fetch-Site` が same-origin (か none) のときだけ通す。`Sec-Fetch-Site` を付けない古いブラウザは `Origin` が自分のオリジンのときだけ。どちらも無い、ブラウザでない道具は通す
- **セッションは DB に持ち、180 日で、使うたびに延ばす。** 何度もログインさせない。**ID は Cookie にだけ生の値を置き、DB には SHA-256 (16 進) を持つ** (DB が漏れても、そのままでは成りすませない)。Web Push は購読してあればセッションが切れても届く。
- ログイン無しで開けるのは `/auth/login`・`/auth/callback`・`/health`・Service Worker と Web アプリのマニフェストだけ。`/auth/logout` は POST だけ。

### 2.7 長周期地震動と推計震度分布

調べた資料 (2026-11-14): [公開する電文の一覧](https://xml.kishou.go.jp/xmllist.pdf) (2026/8/6 現在)・地震火山関連 解説資料 (`jmaxml_20261104_Manual(pdf).zip` の「地震火山関連_解説資料」Ⅱ.(ⅰ)ウ.(キ))・サンプル電文 (`78_01_01_240613_VXSE62.xml`)・気象庁の[情報カタログ (地震)](https://www.data.jma.go.jp/suishin/cgi-bin/catalogue/make_product_page.cgi?id=Jishin)。

**長周期地震動に関する観測情報 (VXSE62) は公開のフィード (地震火山) に載る。受けて、地震に添えて出す。**

- 中身: 地震の諸要素 (発生時刻・震源・M)、全国の最大震度と最大長周期地震動階級 (`MaxLgInt`、0〜4)、情報の種類 (`LgCategory`、1〜4)、都道府県・地域 (地震情報／細分区域のコード)・観測点ごとの階級と震度、観測点の絶対速度応答スペクトル (`Sva`)、気象庁の観測情報のページの URI。続報は観測の全体を持ち直す (地域が足されたり階級が直されたりする。`Revise`)。取消は内容部が無い。
- モデルは `LongPeriod` (`src/lib/model.ts`)。鍵は地震識別番号 (訓練・試験は後ろに `-training` / `-test`)。新しい報で置き換え、古い報は捨て、取消は前の中身を残して印を付ける (`mergeLongPeriod`)。SSE のイベントの種類は `longperiod`。
- 画面: 一覧の種類 (チップ) は増やさない。長周期地震動は地震情報の後に出る観測の詳しい内容なので、同じ地震識別番号の地震に添える。地震の一覧の行の補足に「長周期地震動階級3」(階級 1 以上のとき)、地震の詳しい内容に「長周期地震動」の節 (地域を階級ごとに、観測点は畳んで、気象庁の観測情報のページへのリンク)。
- 地図: 層「長周期地震動階級」(既定はオフ)。選んだ地震で階級 1 以上の地域を、階級の色の太い枠で囲む (震度は面の色なので、枠で分ける)。色は気象庁の配色の指針に長周期地震動階級の表が無いので、表 2-1 の基本配色の上から 4 つを階級 4 から当てた (階級 4 `180,0,104`・3 `255,40,0`・2 `255,153,0`・1 `250,245,0`。自分で決めた割り当て)。ラベルにはいつも「階級3」と字でも書く。
- 知らせない (Web Push も、開いているときの音も)。同じ地震は地震情報 (震度) で知らせている。
- 長周期地震動の**予測** (緊急地震速報の `ForecastLgInt`) は公開のフィードに無く、地点の予想にあたるので出さない (5 章)。

**推計震度分布は入れない。** 公開の防災情報 XML に推計震度分布の電文は無い (公開する電文の一覧にも、解説資料の地震の電文にも無い)。

- 情報カタログでは、格子のデータ「推計震度分布図作図用データ」は 1 km メッシュ (IXAC40) と 250 m メッシュ (IXAC41) の BUFR (格子) で、提供は気象業務支援センターだけ (配信の契約が要る)。誰でも見られるのは気象庁ホームページの「推計震度分布図」の画像 (PNG。全国で震度 5 弱以上を観測した地震) だけで、機械で読む約束 (仕様と提供の保証) が無い。
- 入れるなら、支援センターの BUFR を受けて、格子の値 (気象庁が推計した震度) を震度の色の画像にし、MapLibre の `image` の source で、格子の範囲 (緯度・経度) に合わせて重ねる。格子の値をそのまま色にし、補間や足し引きはしない (5 章の「観測値は気象庁の値をそのまま出す」)。ホームページの PNG を重ねるやり方は、範囲の座標が文書に無く、画像の作りが変わると崩れるので採らない。
- 推計震度分布は気象庁が観測から推計したもので、地点の震度の予想 (予報業務) ではない。出すときも、気象庁の推計であることと出典を書く。

### 2.8 気象の警報・注意報と気象の報

**気象庁防災情報 XML の随時のフィード (`extra.xml`) から、いまの体系の電文だけを取る。** 気象庁の発表をそのまま中継し、警報や予想を自分で作らない (5 章)。

調べた資料 (2026-11-14): [公開する電文の一覧](https://xml.kishou.go.jp/xmllist.pdf) (2026/8/6 現在)・技術資料の表 1.1 (2026-08-06)・解説資料 (`jmaxml_20261104_Manual(pdf).zip`) の「気象警報・注意報（Ｒ０６）」と別表類・「記録的短時間大雨情報」・「気象解説情報形式」(府県気象防災速報)・「竜巻注意情報」・「指定河川洪水予報」・「一般報」(熱中症警戒アラート)・「台風解析・予報情報電文（新形式）」・サンプル電文 (`jmaxml_20260917_Samples.zip`)・2026-11-14 の `extra.xml` と `extra_l.xml` の中身。

- **令和 8 年 5 月下旬から新しい防災気象情報 (警戒レベルの付いた名前) が動いている。** 大雨・土砂災害・高潮は特別警報 (レベル 5)・危険警報 (レベル 4)・警報 (レベル 3)・注意報 (レベル 2) になった。電文は現象ごとの「気象警報・注意報（Ｒ０６）」(VPWW55〜61) で、名前は「レベル４土砂災害危険警報」のように来る
  - 前の形の電文 (VPWW53・54、土砂災害警戒情報 VXWW50、気象特別警報報知 VPNO50) は経過措置で、表 1.1 では令和 10 年度に廃止の予定。VPWW53 の種類は前の名前のままで、危険警報は `Notice` の文にしか出ない。**sonae は R06 の電文だけを使う**
  - 土砂災害警戒情報はいまは「レベル４土砂災害危険警報」(VPWW56 のコード 49) で、VXWW50 は同じものの経過措置の電文。二重になるので VXWW50 は取らない
  - 気象特別警報報知 (VPNO50) も取らない。特別警報は R06 の種類のコード (30 番台) で分かる

**気象警報・注意報 `WeatherWarning`**

- 1 通の電文は、その府県予報区のその現象の、いまの状態をまるごと持つ (市町村等は発表の無いものまで全部並ぶ)。そのため **府県予報区と種別ごとに 1 つ持ち、新しい報で置き換える**。鍵は `<種別>-<府県予報区のコード>`
  - 府県予報区は `Body/Warning[@type="気象警報・注意報（府県予報区等）"]/Item/Area/Code` (6 桁)。フィードのファイル名の後ろ (`_VPWW55_471000.xml`) も同じ
  - R06 には取消が無い (発表と訂正だけ)。訂正も置き換え。前の報より古い報 (長期フィードで後から読んだもの) は捨てる
  - フィードでは、同じ府県予報区と種別の電文は新しい 1 通だけを取る (古いものは置き換わるので取らない。帯域を使わない)
- 持つのは市町村等 (`気象・地震・火山情報／市町村等`、7 桁) ごとの、出ている種類 (コード・名前・段・状態) と、この報で解除された種類。発表警報・注意報はなしの市町村等は持たない
- 段は種類のコード (別表 3) から決める。30 番台は特別警報 (5)、40 番台は危険警報 (4)、01〜09 は警報 (3)、10〜29 は注意報 (2)。暴風・波浪・大雪には危険警報が無い
- 危険度 (`Kind/Property` の警戒レベル相当など) は発表の状況ではない (解説資料) ので持たない
- 残る危うさ: R06 の電文は変わったときにしか出ない。sonae が長期フィードの期間 (約 7 日) より長く止まっていた間に解除された警報は、次の報が来るまで残る

**気象の報 `WeatherInfo`** — 報ごとに 1 行 (火山と同じ)。一連の情報 (`series`) は、記録的短時間大雨情報と府県気象防災速報が EventID の前半、竜巻注意情報が発表細分 (府県予報区) のコード、洪水予報が予報区域のコード、台風が TC 番号。取消は一連の情報のいちばん新しい報に印を付け、訂正はその報を置き換える。
持つのは見出し・題名・種類の名前・地域 (見出しの `Information` に並ぶ府県予報区・一次細分区域等・市町村等のコードと名前。「なし」は除く)・竜巻注意情報の有効期限・洪水予報の段・熱中症警戒アラートの本文・台風の実況。

- 保存: 警報・注意報は `weather_warnings`、気象の報は `weather_infos`。警報・注意報は府県予報区の状態を報ごとに丸ごと積むので、`events` のうち気象のもの (`warning`・`weather`) は原文と同じ 30 日で捨てる (いまの状態は表にある)

## 5. 法と表示

- **予想震度は出さない。** 緊急地震速報の最大予測震度・地域ごとの予測震度・到達予測時刻は、画面にも通知にも出さない。
  気象庁は警報で「具体的な予測震度の値は ±1 程度の誤差を伴い、続報を避けたいので発表せず『強い揺れ』と表現する」としている ([緊急地震速報 (警報) 及び (予報) について](https://www.jma.go.jp/jma/kishou/know/jishin/eew/shikumi/shousai.html))。sonae も警報は「強い揺れに警戒」と、対象の地域名で伝える。
  予報は「緊急地震速報 (予報)」と震源・M だけを出す。
- **自前の予想をしない。** 地点の震度や到達時刻を計算して出すのは予報業務で、気象業務法 17 条の許可が要る ([よくある質問](https://www.jma.go.jp/jma/kishou/minkan/q_a_s.html))。地震動の警報は気象庁以外はできない (23 条)。
- **観測値は気象庁の値をそのまま出す。** 推計や補間で震度を足さない (気象庁の値の編集にあたりうる)。
- **気象の警報・注意報と気象の報も、気象庁の発表を中継するだけにする。** 種類の名前・見出し・本文は電文のまま出し、段も電文の種類のコードから取る。地点の雨や風を予想したり、警報を自分で判断したりしない (警報は気象庁以外はできない、気象業務法 23 条)。出典は「気象庁ホームページ」
- **火山の警報は気象庁の文のまま出す。** 噴火警報・予報と噴火速報は、見出し・活動の状況・防災上の警戒事項を言い換えずに出し、警戒の段も電文の種類から取る (自分で警戒を判断しない。噴火の警報も気象庁以外はできない、気象業務法 23 条)。
- **注意文と短い出典は一覧のいちばん下 (どちらの形も) に、出典の全文は「出典と注意」の窓にいつも出す。地図には短い出典を隅にいつも出す。** 文言は `src/lib/notice.ts` の `NOTICE`・`CREDITS`・`SHORT_CREDIT`・`mapCredit`・`EEW_NOTICE` の 1 か所に持つ。
  一覧の下は注意文と「出典: 気象庁ホームページ・国土地理院 ほか。全文は「出典と注意」にあります」(窓へのリンク) にし、全文を二重に並べない (2026-11-15。窓はヘッダーと「その他」からいつも開ける)。入れる理由と、規約の文言は次のとおり。
  - 気象庁の情報は加工して出しているので、「出典：気象庁ホームページ（URL）」と「気象庁「名称」（URL）を加工して作成」の形で書き、編集の責任を書く (気象庁の[留意事項](https://www.data.jma.go.jp/developer/ryuui.pdf)と[利用規約](https://www.jma.go.jp/jma/kishou/info/coment.html)。公共データ利用規約 第 1.0 版)
  - Wolfx の規約で、利用者に見える形で Wolfx Project を出す (窓の出典と、緊急地震速報の詳しい内容の `EEW_NOTICE`)。P2P地震情報は緊急地震速報と、地震情報・津波予報の速報 (気象庁の XML の前に出す仮のもの) に使う
  - **国土地理院の[出典の記載](https://www.gsi.go.jp/LAW/2930-meizi.html)は「システムやWebサイトに測量成果を利用する場合、原則、測量成果が表示画面に表示されている間は、常に見えるように表示画面に明示」とする。** MapLibre の畳んだ (i) は押すまで見えないので外し、地図の隅に短い出典を常に出す ([map.md](map.md))。
    文言は[地理院タイル一覧](https://maps.gsi.go.jp/development/ichiran.html)の「「国土地理院」または「地理院タイル」等と記載し、地理院タイル一覧ページへのリンク」と、加工したものの「地理院タイルに○○を追記して掲載」に合わせる。写真は備考どおり GRUS 画像の範囲で「GRUS画像（© Axelspace）」、都市圏活断層図は調査者 (図ごとに違うので、国土地理院の各図の案内へのリンクと例)
  - ハザードマップは[出典の記載方法](https://disaportal.gsi.go.jp/hazardmap/copyright/copyright.html)の「出典：「ハザードマップポータルサイト」」と「「ハザードマップポータルサイト」を加工して作成」。元の機関 (国土交通省各地方整備局等・都道府県・国土数値情報) も書く
  - USGS は「courtesy of the U.S. Geological Survey」、EMSC は「EMSC-CSEM SeismicPortal, https://www.seismicportal.eu」(CC BY 4.0)
  - 注意文は「公式ではない・遅れたり欠けたりする・公式の情報を優先する」の 3 つを言う。緊急地震速報の画面には、Wolfx と P2P のどちらも非公式で無保証であることも書く
- **Wolfx:** 原文 (`OriginalText`) は保存も公開もしない。Wolfx を使う機能で収益を得ない。sonae は公開のサービスにしない (1 章のセルフホスト) ので、規約 6 条の「第三者へのデータの提供」には当たらないと読んだ。公開のサービスにする話が出たら Wolfx に確かめる。

## 6. 見た目と動きの決まり

**見た目は denpa の [docs/design.md](https://github.com/danything/denpa/blob/main/docs/design.md) (見た目の決まり) に従い、言葉は同じリポジトリの [docs/writing.md](https://github.com/danything/denpa/blob/main/docs/writing.md) に従う。** 合言葉も同じで「塗らない。囲みすぎない。浮かせすぎない。でも、ちゃんと伝わる」。
画面の形 (何がどこにあるか) は [docs/ui.md](ui.md) に書く。ここには、denpa の決まりをどう当てたかと、sonae にしかない決まりを書く。

### 6.1 denpa の決まりの当て方

- **値は `src/app.css` の `--so-*` から選ぶ。** 名前は denpa の `--dp-*` を `--so-*` にしたもので、値は同じ (色・字の大きさの 6 段・余白の 6 段・時間と曲線・重なりの段)。写すのは sonae が使うものだけ。部品の CSS (ボタン・件の面・日付の見出し・チップ・メニュー・スイッチ・サイドバー・ダイアログ・dock) も denpa の `app.css` から写している。denpa の値を変えたら、こちらも合わせる
- **層は地・件の面・操作の層の 3 つ** (denpa の 2 章)
  - 地: 一覧の列の上の種類のチップ・詳しい内容・注意文
  - 件の面: 一覧の 1 行 (`Row.svelte`)
  - 操作の層: スマホの形の下のタブと dock・メニュー・ダイアログ・貼り付いた日付の見出し
- **浮かせるのは中身の上に重なるものだけ** (denpa の 3 章)。広い形のヘッダーは窓が巻けないので、いつも平ら (denpa の観る画面と同じ)。スマホの形の下のタブと dock は地図や一覧の上にいつも浮かせ、一覧を下へ読む間は引っ込める
- **選んでいるものは主の色の線と太字で、塗らない** (denpa の 4 章)。一覧の選んだ行は左の縦線。種類で絞るチップ (広い形は列の上、スマホの形は dock) は並び (`role="group"`) の中の押されているボタン (`aria-pressed`) なので、出しているもの (先頭の「すべて」か 1 つの種類) が字の幅いっぱいの下線と太字 (短い下線は引かない)。全部へ戻るのは選んだチップの ✕ ではなく「すべて」のチップにする (✕ は置かない決まりで、並びの中の 1 つを選ぶ形がほかのチップと同じ見た目で分かるため)。下のタブも字の幅いっぱいの下線。メニューの選択肢 (テーマ) は左の縦線、オン/オフ (「通知」の中) はスイッチ
- **スマホの形は 1000px 未満** (`#lib/phone-form.ts` と app.html の `<html data-phone>`。denpa と同じ線)。上のヘッダーを出さず、下のタブと dock に寄せる
- **閉じるのは左下の「閉じる」** (「出典と注意」と「通知」の窓)。中身を巻いても窓の下端に貼り付けて、いつも見せる (`.modal-foot`。denpa の番組の詳細と同じ)。段は薄く、面と影は敷かない。続きがあるときだけ、ボタンの手前で中身を薄く消していく (denpa の番組の詳細のフェード)。枠の外 (幕) を押しても Esc でも閉じる。✕ は置かない。詳しい内容から一覧へ戻るのは窓を閉じるのではないので、左上の「一覧」のリンク
- **動きは CSS の透明度と transform だけ** (denpa の 7 章)。JS がするのは印 (`data-view`・`data-retract`) の付け外しだけ。動きを減らす設定では時間を 0 にし、繰り返す動きを止める
- **空の状態と、絞り込んで当てはまらないときは `.empty-state`** (denpa の 8 章)。絞り込んで (欄かチップで) 無いときは「当てはまるものはありません」だけ。sonae には見せる画面が無いので、地の光 (`.glow`) は敷かない
- **テーマの既定は端末に合わせる** (denpa と同じ選べる 3 つ。暗い・明るい・端末に合わせる)。保存した選択はそのまま使う (localStorage の `sonae.theme`)
  - `app.html` のスクリプトが描く前に `<html data-theme>` とブラウザの枠の色 (`theme-color`) を付ける。`<html>` には決めたテーマを書かないので、明るい端末で暗い画面が一瞬出ることはない。スクリプトが動かなければ明るいテーマ (`app.css`)
  - 端末に合わせているときは、開いている間に端末の設定が変わっても付け直す
  - ホーム画面に足すときの地の色もテーマに合わせる。暗いテーマは `static/manifest.webmanifest`、明るいテーマは色だけが違う `static/manifest-light.webmanifest` を読ませる。ホーム画面に足したあとはブラウザが足したときの色を使い、テーマを変えても替わらない
- **お知らせは、問題があるときだけヘッダー (スマホの形は dock) の印に畳む** (denpa の 6 章「通知」)。受信の状態はふだん出さず、つながっていない情報源があるときだけ注意の印 (⚠ と一言) を出し、押すとメニューと同じ箱で情報源ごとの受信を出す
  - いつもの受信の状態は「出典と注意」の窓の「受信の状態」に置く (注意文のすぐ下。`StatusList.svelte` を印のメニューと共に使う)。どの情報源を受けているかを、問題が無いときにも確かめられるようにするため。ボタン・タブ・画面は足さない (2026-11-15。持ち主の声「同期中のデータがどれかわからん」「できるだけ要素とか画面は増やさない方向で」)。
    設定で切ってある情報源 (状態 `off`。いまは授権碼の無い中央氣象署) も訳を添えて並べ、控えた字のままにして注意の印は出さない (`#lib/format.ts` の `sourceInTrouble`)

### 6.2 sonae だけの決まり

- **震度・津波の区分・火山の警戒の段・気象警報・注意報の段は、気象庁の配色の指針の色で塗ったラベルにする** (4 章の色と、指針の表 1-2 の噴火警報・予報の色、表 1-1 の警戒レベルの色。`Intensity.svelte`・`Grade.svelte`・`VolcanoLevel.svelte`・`WarningLevel.svelte`)。denpa の「状態の色は状態だけ」とは別の、色そのものが意味を持つもの (denpa のリモコンの色のキーと同じ扱い)。
  色だけに頼らず、ラベルにはいつも「5弱」「津波警報」と字で書く。選んでいる印・オン・状態にはこの色を使わない
- **地図は操作の層ではなく中身** (地図の上に操作は重ねない)。層はいつも全部出し、切り替えは置かない (色の意味は「出典と注意」の「地図の見方」)。地図の上にあるのは隅の短い出典と、震度のラベル・震央の × と、ハザードマップの選択と、現在地のボタンだけ。出典は国土地理院の決まりでいつも見えるように出し (5 章)、操作の層と同じ面 (`--so-float`) に小さな字で載せて写真の上でも読めるようにする。押すと「出典と注意」の窓。スマホの形は地図の右上の角 (下の端は浮いた下のタブ・dock・右下の操作が重なり、ぴったり付ける角が無いため。上の帯は地図を押し下げるので隠れない)
  - 例外: ハザードマップの選択 (右下のカプセル。現在地のボタンと 1 行に並べ、隅の出典の上に置く。2026-11-15 に持ち主の頼みで左上から移した。マウスでは乗せただけで選択肢を開く)。持ち主の決定 (2026-11-14) で、層の切り替えを置かない中で、色がぶつかるハザードマップだけは 1 つを選ぶ。地図に重なるので操作の層に乗せ、選んでいる間はメニューを開くボタンと同じ短い下線 (`data-on`)。選択肢はメニューの左の縦線。選んだものの公式の凡例 (画像) をその下にメニューと同じ面で出す (凡例の画像は白い地なので、暗いテーマでも白い台に載せる)。
    都市圏活断層図も地形の分類で塗った全面の図なので、いつもは重ねず、この選択の 1 つ (「活断層」) にする (2026-11-15)。選んでいる間は、面で塗る警報・注意報と震度の色を隠し、命に関わるいま出ているもの (特別警報・緊急地震速報) は縁取りで残す ([map.md](map.md) の「ハザードマップを重ねている間」)
  - 例外: 現在地のボタン (右下の丸) は、地図で自分のいる所を探す操作なので地図の上に置く。地図 (動く中身) に重なるので操作の層 (面と影) に乗せ、オンは並びの外の切り替えと同じく主の色のアイコンと短い下線。押している間だけ `watchPosition` で追い、白い縁の青い点と誤差の円を描く。初めて取れたときだけそこへ寄せる (追う間に勝手に動かさない)。**緯度・経度は端末の中で描くだけで、サーバーには送らない**。許可されなかったときは追うのをやめ、ボタンの下に「位置の利用が許可されていません。…」と出す。
    オンにしたことは端末に覚え (`sonae.map.locate`)、開いたときに位置の許可がもう `granted` なら自動で始める (寄せない)。許可の窓は押したときにだけ出し、`prompt` のときは始めずにオンの見た目 (下線) のままアイコンを薄くして、押すのを待つ。`denied` なら覚えたオンを消す ([map.md](map.md) の「現在地を自動で始めるとき」)
  - 例外: 地図のメニュー (右クリック・スマホは長押し) は、押したときだけ押した所に出す操作の層のメニュー (`Menu.svelte`) で、地図にいつも重ねる操作ではない ([map.md](map.md) の「地図のメニュー」)。住んでいる地域の縁取り (水色の破線) と、検索の欄で選んだ場所の印 (白い縁の橙の丸) は、操作ではなく中身の印
  - 広い形は地図の箱を件の面と同じ角 (`--so-item-radius`) で切る。スマホの形は画面いっぱいで角を付けない
- **広い形の列は右の 1 本 (一覧か詳しい内容) だけにし、残りの幅を地図に回す。** denpa の観る画面 (映像と右の列) と同じく、主の中身 (地図) を左に、添える列を右に置く (denpa の左はナビゲーションの場所)。地図が主なので、ずっと見ていなくてよいもの (カレンダー・状態) は列に並べず、押したときだけ出すメニューに畳む。
  列は 22rem (1600px から 26rem)。種類のチップは列の幅に入りきらなければ折り返す (横に流すと後ろの種類が隠れる)
- **一覧は全部の種類を 1 本に、時刻の新しい順に並べる。** 種類は分けずにチップで絞り (全部か 1 つの種類。押すとその種類だけ、もう一度押すと全部)、どれを出しているかは端末に覚える (既定は全部出す)。種類をまたいで並ぶので、行の左のラベルの幅をそろえ、ラベルの無い種類も同じ幅を空ける
- **いま出ている緊急地震速報 (警報) だけは、詳しい内容の先頭の箱と、スマホの形の dock の 1 行を状態の赤で塗る** (denpa の通知の「地は状態の色で塗らない」の例外)。身を守る動きにつなげる通知で、どの画面のどこを見ていても一目で分かる必要があるため。予報と取消は塗らず、淡い面に注意の色のタイトル。2026-11-15 に画面の上の帯をやめ、出たら詳しい内容を開く形にした ([ui.md](ui.md) の「自動で開く」。持ち主の声「緊急地震速報も上に表示するんじゃなくてサイドバーで詳細表示にすればいいと思う」)
- **いま出ている緊急地震速報・大津波警報と津波警報・気象の特別警報 (レベル 5) は、チップにかかわらず一覧の先頭に通知の形で出す。** 身を守る動きにつなげるものと、数十年に一度の重大な災害のおそれを伝えるもので、ほかの種類だけを出しているときも目に入る必要があるため。並びは緊急地震速報・津波・特別警報の順で、時刻の順には並べない。
  形はほかの通知と同じ (塗らない)。特別警報には種類のラベル (指針の色) と対象の市町村等を添える。状態の赤は緊急地震速報 (警報) だけに残す
  - その後に、津波注意報・津波予報、噴火速報と噴火警報 (居住地域)、この 1 週間の南海トラフ地震の情報を、その種類を出しているときだけ続ける
- **事実はバッジにしない** (denpa の 4 章)。M・深さ・遠地地震・発表の種類は控えた字を「・」でつなぐ。バッジは状態 (取消・速報・訓練・試験) だけ
- **注意文と出典はいつも見える所に置く** (5 章)。どちらの形も一覧のいちばん下に注意文と短い出典、地図の隅 (広い形は右下、スマホの形は右上) に短い出典。全文は「出典と注意」の窓 (ヘッダーとスマホの形の「その他」、一覧の下と地図の隅の出典からいつも開ける)

### 6.3 動き

ほかのアプリ (corp・mado・denpa の docs/design.md 7・8 章) と同じ。

- 動かすのは **CSS の `opacity` と `transform` だけ**。JS のアニメーション (rAF・`setInterval` で値を書き換える・ライブラリ) は使わない。ぼかし・色・背景の位置は動かさない。
- 緊急地震速報の箱・dock の 1 行や震源の印を目立たせる点滅・脈打ちは、`transform: scale` と `opacity` の CSS アニメーションで、回数を決めて止める (常時は回さない)。
- スマホの形で地図と一覧を切り替えるときは、一覧の面を透明度と少しの `translateY` で出し入れする (地図は作り直さない)。
- 地図のカメラは飛ばさない (`jumpTo`。寄せるときの決まりは [map.md](map.md))。MapLibre は止まっている間は描かないので、地図を開いているだけで CPU を使うことは無い。
- 時間で動き続けるものは無い (脈打ちは決めた回数で止まる)。そのため denpa の `<html data-lite>` (ソフトウェアで描いている端末で止める印) と `content-visibility: auto` はまだ要らない。動き続けるものを足すときに入れる。WebGL が無ければ地図は出さない。
- `prefers-reduced-motion` では全部止める。
- 検証は GPU を切った Chromium (`--disable-gpu --disable-gpu-compositing`) でも、止まって 5 秒の CPU を測る。

## 8. 家のクラスタへの載せ方

**家の本番も、セルフホストの人と同じ Helm chart (`charts/sonae`) で出す。** denpa と同じ形で、gitops の ApplicationSet が `deploy/argocd.yaml` を探して `deploy/` を素のマニフェストとして同期し、その中の `deploy/application.yaml` (Argo CD の Application `sonae-chart`) が chart を展開する (App-of-Apps)。家の値は `application.yaml` の `helm.valuesObject` にインラインで持つ。

- chart (`charts/sonae`): sonae の Deployment (レプリカ 1・Recreate・uid 1000・`/health` のプローブ (起きていることだけを見る。情報源の受信の状態は見ない))・Service・HTTPRoute か Ingress・PVC `sonae-data`・VOICEVOX のエンジン (公式のイメージ `voicevox/voicevox_engine:<バージョン>` (CPU 用) の Deployment・Service。CPU は絞らず (limits 無し・requests 2)、合成のスレッドはマシンの全部を使う (`voicevox.cpuThreads`)。メモリの上限 3Gi。PVC は持たない。イメージは Renovate が上げる)・NetworkPolicy (VOICEVOX は sonae の Pod からしか受けず外へ出ない。sonae の外向きは DNS と公開のインターネットと VOICEVOX だけ)。リソースの名前は素のマニフェストのころと同じにしてあり、変えない (PVC を作り直すとデータが消える)。
- 家の値 (`deploy/application.yaml`): ホスト名 `s.doany.io` (Cilium Gateway の `doany`)、OIDC は docs/entra.md の表のとおり、Secret は `sonae-secrets`、PVC は `local-path` 1Gi で `dataSourceRef` で VolSync から戻す、外向きの NetworkPolicy を出す。
- chart に入れないもの (`deploy/` に素のまま): `argocd.yaml`・`volsync.yaml` (毎日 19:00 UTC に R2 へ)・`secrets.sops.yaml` (`oidc-client-secret` (Main の共用のもの)・VolSync の restic。VAPID の秘密鍵 `vapid-private-jwk` と中央氣象署の授権碼 `cwa-api-key` は任意で、入れ方は docs/push.md と docs/cwa.md)。R2 にまだバックアップが無い最初の 1 回は、populator が空の PVC を作る (gitops の recovery/README.md の 6)。`.sops.yaml` はほかのリポジトリと同じ鍵。この家の Argo CD は Secret を同期しないので、chart は Secret を作らず、名前 (`secrets.name`) で指す。
- 環境変数 (chart の `templates/deployment.yaml`): `PUBLIC_URL` と `ORIGIN` (adapter-bun) はどちらも `sonae.publicUrl` (家は `https://s.doany.io`)。`CONNECTION_IDLE_TIMEOUT=255` (既定の 10 秒だと 30 秒ごとの `: ping` を待つ間に SSE が切れる)。`SHUTDOWN_TIMEOUT=5` (SSE は終わらないので長く待たない)。`VOICEVOX_URL=http://voicevox:50021` (2.4 の「読み上げ」)。
- 外向きの NetworkPolicy は ashi と同じ形 (kube-dns と、プライベートでないアドレス全部)。クラスタに既定で閉じるポリシーは無いので、これが無くても外へは出られる。家の LAN とクラスタの中を閉じるために置く。DNS の Pod のラベルはクラスタで違うので、chart の既定では出さない。
- イメージ: main にマージすると `docker-publish.yml` が `ghcr.io/danything/sonae:<sha>` と `latest` を作り、`deploy/application.yaml` の `image.tag` を差し替える PR を作って自分でマージする。
- chart: PR と main で `chart.yml` が `helm lint` と `helm template` (chart の既定値・家の値・Ingress と VOICEVOX 無し) を回す。リリースを作ると `release.yml` が chart を `oci://ghcr.io/danything/charts/sonae` に出す。
- 実行のイメージは `oven/bun:<ver>-distroless` (シェル無し・uid 1000)。
- 外への接続は気象庁・P2P・Wolfx・USGS (earthquake.usgs.gov)・PTWC (www.tsunami.gov)・EMSC (www.seismicportal.eu の WebSocket)・気象庁ホームページ (www.jma.go.jp の bosai の国際津波)・GeoNet (api.geonet.org.nz)・中央氣象署 (opendata.cwa.gov.tw、授権碼があるときだけ)・Entra ID・Web Push の配信サービス (FCM・Mozilla・Apple・WNS) だけ。気象庁のフィードは地震火山と気象 (随時) の 2 つを 1 日 1440 回ずつ条件付きで取る。地震火山はほとんどが 304 で、随時の `extra.xml` (約 100KB) はほぼ毎分変わるので 1 日 150MB ほど。電文 (警報・注意報は 1 通 10〜40KB、1 日に数百通) を足しても、帯域の上限 (10GB/日) には遠い。

## 9. 未決の点

持ち主が決めたこと (2026-11-13):

1. **ホスト名は `s.doany.io`。** Entra は共用の Main を使い回し、リダイレクト URI `https://s.doany.io/auth/callback` は gitops の `pulumi/entra.ts` で足した。
2. **家族との共有はまだやらない。** いまは持ち主 1 人で使う。仕様としてはアプリロール (`OIDC_ROLE`、既定 `admin`) で絞る形にしておき、family 用のロールと家族の招待 (Entra の Main に B2B のゲスト) はあとでする。
3. **公開のサービスにはしない。セルフホストのアプリにする** (2026-11-14 に決めた。1 章)。使う人がそれぞれ自分と家族のために立てる。
   公開のサービスにする話が出たら、Wolfx の規約 6 条 (事前の許可) と EMSC の「サービスや DB の丸ごと・大部分の再配布」(書面の許可) を問い合わせてからにする。
4. **通知の既定値は 2.4 の括弧の値のまま** (地震情報は最大震度 4 以上・住んでいる地域で震度 3 以上、緊急地震速報の予報は既定でオフ)。気象は 2026-11-14 に、住んでいる地域の警報以上と、どこでも特別警報を既定にした (注意報は送らない)。

作りながら決めること:

5. 震度速報と地震情報を、地震識別番号が合わないときに結ぶ閾値 (時刻の差と地域の重なり)。いまは仮に「発生の時刻 (震度速報は TargetDateTime) の差が 90 秒以内で、震度の地域が 1 つでも重なる (どちらかに地域が無ければ時刻だけ)」で、番号どうしが違うときは震度速報だけを結ぶ (`src/lib/server/merge.ts` の `sameQuakeByTime`・`LINK_WINDOW_MS`、`tests/merge.test.ts` で固定)。P2P の 551 には地震識別番号が無いので、いつもこれで結ぶ。
   - **気象庁の文書を確かめた (2026-11-13)。結び方の規則は無い。** 書かれているのは次のことだけ:
     - 番号はずれうる: 「同一地震であっても、緊急地震速報・震度速報（以上、自動処理による発表）と、(中略) 地震情報 (中略)（以上、手動による発表）の間でEventIDが一致しないこともある。」(運用指針 別紙 2 の ※1)。地震火山関連 解説資料 Ⅰ.別 02「EventID 要素の運用」にも、システムの切り替えや地震の続発で番号が一貫しないことがあると、出現例付きで書かれている。番号は発生時刻などの物理的な意味を持たない。
     - 震度速報の TargetDateTime は「最初に地震波を自動検知した観測点における地震波の検知時刻」で、分まで有効 (解説資料 Ⅰ-2)。震度速報は地震発生の約 1 分半後に出る ([気象庁の解説](https://www.jma.go.jp/jma/kishou/know/jishin/joho/seisinfo.html))。
     - 地域の重なりで同じ地震とみなす記述は無い。逆に、震度速報に別の地震の震度が混ざる例がある (解説資料の出現例 4)。地域が重なっても同じ地震とは限らない。
   - そのため値は自前のまま。90 秒は、分の切り捨て (最大 59 秒) と検知までの遅れを足しても収まる幅として置いた。実際の電文で外れる例が見つかったら直す。
