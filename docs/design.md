# sonae の設計

地震・津波・火山・気象の災害の情報を家のサーバーで受け、ブラウザで見て、Web Push で知らせるアプリの設計書。
ここに書いたのは作りの決めごとで、作りながら直す。決めていないことは最後の「未決の点」にまとめた。
画面の形は [ui.md](ui.md)、地図の層と出典は [map.md](map.md)、Web Push の運用は [push.md](push.md)、ログインの設定は [entra.md](entra.md)、台湾の中央氣象署の授権碼は [cwa.md](cwa.md) に書き、ここでは繰り返さない。

- 名前は「備え」から。
- 機能は [Zero Quake](https://github.com/0Quake/Zero-Quake) を参考にしたが、**コードは読まない・写さない** (クリーンルーム)。仕様は各情報源の公式の文書から取る。
- ライセンスは AGPL-3.0。

## 1. 目的と範囲

**目的:** 家族が、地震・津波・火山・気象の災害の情報を 1 か所でまとめて見られ、タブを閉じていても身を守る動きが要るときは端末に通知が届くこと。
地震と津波から始め、持ち主の決定 (2026-11-14) で災害の全般に広げる。**使うのは無料の情報源だけ。** まず気象庁防災情報 XML の気象の電文 (警報・注意報など、2.8) を足した。

**sonae は、使う人が自分で立てて使うアプリ (セルフホスト) にする** (持ち主の決定、2026-11-14)。

- 立てる人が、自分と家族のために、自分のサーバーに 1 つ立てる。外からはログインで閉じ (家族との共有は Entra のアプリロールで絞る)、信頼するネットワーク (1 行のインストーラは家の LAN を書く) からはログインなしでも開ける (2.6)。
- 誰かが公開のサービスとして立て、知らない人に配ることはしない。コードは AGPL-3.0 で公開するが、配信のサービスは運営しない。
- 情報源へは、立てたサーバーがそれぞれ直接つなぐ。どの情報源も、1 つのサーバーが家族の数人のために取る量で行儀 (2.1) を決めている。
- 持ち主のサーバーのホスト名は `s.doany.io` (家のクラスタの Gateway の `doany`)。
- Kubernetes には Helm chart (`charts/sonae`、`oci://ghcr.io/danything/charts/sonae`) で入れる。入れ方は README の「Kubernetes に立てる」。持ち主の本番も同じ chart で出す (8 章)。

### 情報源の判断

持ち主の依頼 (2026-11-14) は「Zero Quake が対応している取得先は一通り、ほかにもあれば足す」。同じ日に「災害の全般に広げる。無料の情報源だけ」が加わった。
各情報源の利用規約を読んで、入れてよいものだけを入れる。下調べは 2026-11-14 (Zero Quake は README の出典の一覧だけを読み、コードは開いていない)。

規約は 2 つの形で読み、下の表の「セルフホスト」と「SaaS (商用を含む)」の列に分けて書く (2026-11-16 に全部の規約を読み直した)。

- **セルフホスト:** いまの形 (1 章)。立てた人が自分と家族のために取って見る。公開のサービスとして第三者に配るものではない。
  再配布や第三者への提供を絞っている情報源 (Wolfx の規約 二条の `jma_eew` の再配信・ExpTech の服務條款 §五) も、この形なら家族の間の利用に収まると読んだ。
- **SaaS (商用を含む):** 誰かが公開のサービスとして立て、知らない人に配る形。広告や課金のある商用も含める。sonae はこの形で運営しない (1 章) が、立てる人が出たときに何が要るかを先に分けておく。

sonae は商用にしない (持ち主の決定、2026-11-16)。民間にお金を払わないと統合された質の高い防災情報を受けられない、という今の形への反対として作っているため。広告・課金・有料のプランは付けず、商用の条件 (ExpTech の同意、京都府の土砂災害警戒区域の商用の制限など) のために問い合わせることもしない。「SaaS (商用を含む)」の列は、ほかの人が sonae を商用で立てるときの目安として残す。
無料の公開のサービス (SaaS) にするための問い合わせ (Wolfx の `jma_eew` など) は、セルフホストで情報源がひととおりそろい、使った実績ができてから進める (持ち主の決定、2026-11-16。実績があるほうが話を通しやすい)。

列の値は「可」(出典を書けば使える。書き方は 5 章)・「条件つき」(括弧の中の条件を満たせば使える)・「不可」・「未確認」。
SaaS で「不可」のものは無い。「未確認」は Wolfx SeisJS だけ (家庭のセルフホストでの使い方しか聞いていない)。「条件つき」は次の 3 つ。無料の公開のサービスで片づけが要るのは Wolfx の `jma_eew` だけで、ほかの 2 つは商用のときだけの条件。

- Wolfx の `jma_eew`: 二条 (`jma_eew` を独立したデータ源として再配信するには事前の許可) に当たらないかを Wolfx に問い合わせる
- ExpTech の TREM-RTS: 非商用の条件なので、商用なら ExpTech の同意が要る。無ければ `SONAE_TREM=off`
- ハザードマップの土砂災害警戒区域: 都道府県の条件で、京都府は「商用利用不可」。タイルは全国で 1 枚なので、商用なら土砂災害の選択を外すか、京都府に確かめる (下の「地図と声」)

EMSC は 2026-11-16 に、公開・商用も出典を書けばよいと答えをもらった。
Wolfx からは 2026-11-17 に、SeisJS を家庭のセルフホストで家族の地図に出すのは SeisJS の利用目的の範囲内で、個別の許諾は要らないと答えをもらった。出典は「Wolfx Project (SeisJS)」でよい。接続はサーバーごとに 1 本を目安に使い回し、切れたら間隔を延ばしながら張り直す。SeisJS のプライバシー通知は <https://seis.wolfx.jp/PrivatePolicy/ja_JP>。公開のサービス (SaaS) での使い方は聞いていない。
Wolfx の利用規約は 2026-11-14 23:02 (日本時間) に改訂された (WolfxProject/wolfx-project-site のコミット 519cec5。<https://wolfx.jp/legal/terms/> の「最終改訂日：2026年11月14日」)。
旧 6 条 (Wolfx のデータを使う機能は全員に無料で出すこと・出典「Wolfx Project」の表示・独立したデータ再提供は事前の許可) と旧 7 条 (権利者の許諾なく上流の原電文 (`OriginalText`) を公開で再配布しない) は消え、許可が要るのは `jma_eew` のデータを独立したデータ源として再配信することだけ (二条。最終利用者への表示・通知と、そのためのサーバーでの処理・中継・キャッシュは当たらない) になった。第三者のデータは、その権利者の条件に従う (五条)。商用・非商用を問わず使える (一条)。

**潮位観測情報を測った結果** (2026-11-16)

持ち主は、津波の警報・注意報の間と大きな地震の直後と波浪警報の間だけ、近くの 2〜3 の検潮所の潮位をグラフに出すと決めた (同じ日)。
ただし「値が 15 分より古いなら画面を作らずに戻す」という条件つきで、測ると古すぎたので入れていない。

- 端点 (公式の API ではない。気象庁ホームページの潮位観測情報の画面が読むもの):
  - `https://www.jma.go.jp/bosai/tidelevel/const/tide_area.json`: 検潮所の表 (約 140KB)。市町村 (class20) ごとに class30 と検潮所を持ち、検潮所は `code`・`name`・`type` (気象庁 71・港湾局 65・海上保安庁 20 など、全部で 166)・`lat`・`lon`・`missing` (欠測中) を持つ
  - `https://www.jma.go.jp/bosai/tidelevel/data/tide/tide_time.json`: いちばん新しい値の時刻 (`{"time":"2026-11-16T19:14:45+09:00"}`)
  - `https://www.jma.go.jp/bosai/tidelevel/data/tide/tide_obs_<YYYYMMDD>_<検潮所>.json`: その日の 0 時からの値 (`time`・`station_code`・`interval` (15 秒)・`tide` (cm)・`departure` (潮位偏差、cm))。1 日の終わりに 5760 個、約 30KB
  - どれも `Cache-Control: max-age=60`・ETag・Last-Modified が付く
- 遅れ: `tide_time.json` を 1 分ごとに 16 回取った。更新は 10 分ごと (10:27:20・10:37:20・10:47:16 UTC) で、どの回も最新の値は更新の約 12 分半前 (12 分 31〜35 秒) のもの (19:14:45・19:24:45・19:34:45)。そのため手元に届く値は、いつ見ても 12 分半から 22 分半古い (CDN の 60 秒を足せば最大 23 分半)。港湾局の検潮所 (室蘭) はさらに 5 分古かった。輪島港のように欠測で空の並びのものもある
- 津波の間に更新が速くなるかは分からない (津波の無いときにしか測れていない)。サーバーが津波・大きな地震・波浪警報の間に自動で測り直す (下の「測り直し」)。15 分より新しければ入れ直しを考える
- 規約は気象庁ホームページのもので利用は可。ただし公式の API ではなく、予告なく変わる (国際津波の pacifictsunami と同じ)
- 入れるなら考えておいたこと: 取るのはサーバーの 1 本だけ (2.3)・窓の間だけ・検潮所は VTSE51 に出る観測点の名前に合わせ、無ければ予報区のいちばん近いもの。値で知らせない・「上がっている」などの判断を書かない (気象業務法)。気象庁が更新を速くしたら測り直す

**測り直し** (`src/lib/server/tide-probe.ts`、2026-11-16 に足した)

サーバーは、次のどれかに当たる間だけ `tide_time.json` を 1 分ごとに取って、更新ごとの遅れを残す。
画面・通知・「受信の状態」には出さない。失敗してもログに出力するだけで、ほかの受信には響かない (続けて失敗したら間隔を倍々に空け、上限 15 分)。
環境変数 `SONAE_TIDE_PROBE=off` で切る。

- 動かす理由 (1 分ごとに、DB のいまの状態から決める。訓練・試験は数えない)
  - `tsunami`: 大津波警報・津波警報・津波注意報のどれかが、どこかの予報区に出ている (終わった・取り消された津波と、津波予報だけのものは数えない)
  - `quake`: 最大震度 5 弱以上 (5 弱以上未入電も) か、津波に触れたコメントのある地震の発生から 2 時間 (発生の時刻が無ければ更新の時刻から)。津波に触れたコメントは「津波」か「海面変動」を含む文で、「津波の心配はありません」「津波の影響はありません」を除く
  - `wave`: 波浪 (VPWW59) の警報以上 (波浪警報・波浪特別警報) が、どこかの市町村等に出ている
- 取るのは `tide_time.json` だけ (`If-None-Match`・`If-Modified-Since` を付ける)。検潮所ごとの値は取らない
- 中の時刻が前の行と変われば、表 `tide_latency` に 1 行を足し、`tide-latency` で始まる 1 行をログに出力する。304 と、中の時刻が同じ 200 は残さない。表は 90 日と 1 万行まで残す
- 列: `fetched_at` (取った時刻)・`data_time` (`tide_time.json` の時刻)・`last_modified` (応答の Last-Modified)・`fetch_delay_s` (取った時刻 − 中の時刻、秒)・`modified_delay_s` (Last-Modified − 中の時刻、秒)・`triggers` (動かした理由をカンマで)・`after_gap`。時刻は UTC の ISO 8601
- `after_gap` が 1 の行は、前に取れた回から 90 秒より空いている (起動・動き始め・失敗の後)。この行の `fetch_delay_s` は更新の時刻を表さないので、`modified_delay_s` だけを見る。`after_gap` が 0 の行の `fetch_delay_s` は、更新から 1 分以内に取った遅れ

読み方 (家のクラスタ。イメージにシェルと sqlite3 が無いので、bun で読む):

```sh
kubectl -n sonae logs deploy/sonae | grep tide-latency
kubectl -n sonae exec deploy/sonae -- bun -e 'import { Database } from "bun:sqlite"; console.table(new Database("/data/sonae.db").query("SELECT data_time, fetch_delay_s, modified_delay_s, triggers, after_gap FROM tide_latency ORDER BY id DESC LIMIT 50").all())'
```

平時の値は `modified_delay_s` が約 755 秒 (12 分半)。`modified_delay_s` が 900 秒 (15 分) を下回る行が続くか、`data_time` の間が 10 分より短くなれば、上の決定を見直す。

## 2. 全体の構成

```
            ┌──────────── サーバー (Bun 1 プロセス、SvelteKit + adapter-bun) ────────────┐
気象庁 Atom ─┤ jmaSource ────┐                                                              │
P2P ws ──────┤ p2pSource ────┼─▶ 正規化 ─▶ 重複の除去・新旧の判定 ─▶ SQLite ─▶ Broker ─┬─▶ SSE ─────▶ ブラウザ
Wolfx ws ────┤ wolfxSource ──┘                                                       ├─▶ Pusher ─▶ Web Push
             │                                                                        └─▶ Webhooks ─▶ Discord・Slack など
             └──────────────────────────────────────────────────────────────────────────┘
```

図は地震の主な 3 つの情報源だけを描いた。ほかの情報源 (2.1) も同じ形で正規化に渡す。観測点のいまの揺れ (TREM-RTS・SeisJS) だけは DB と Broker を通さず、メモリに持って SSE に渡す (2.9・2.10)。

- **1 つのプロセスで受信も配信もする。** SvelteKit の `init` (hooks.server.ts の `ServerInit`) で受信を起こす (ashi が歩みを起こすのと同じ形)。
  受信を別のプロセスに分けないのは、家族の数人に配るだけで分ける利点が無く、Wolfx の「接続を再利用し、不要な重複接続を避ける」・P2P の「IP ごとに 2 接続」を守るのも 1 プロセスのほうが確か。
- **レプリカは 1 つ、入れ替えは Recreate。** 2 つ立つと情報源への接続が倍になり、Push も二重に出る。入れ替えの数秒は受けられないが、戻ったときに履歴の API で埋める (下)。
- 依存は増やさない: XML は Bun 組み込みの `Bun.XML.parse` (1.4.4 の型定義で確かめた。外部の DTD や実体を読まないので XXE の心配が無い)、WebSocket の受信は Bun の `WebSocket`、DB は `bun:sqlite`。

### 2.1 受信 (情報源ごとのアダプター)

どのアダプターも同じ形にする。

```ts
interface Source {
  id: SourceId; // "jma" | "jma-weather" | "p2p" | "wolfx" | "usgs" | … (src/lib/model.ts)
  /** 止めるまで受け続ける。切れたら自分で張り直す (受けたものは作るときに渡す SourceContext の emit へ) */
  run(signal: AbortSignal): Promise<void>;
  status(): SourceStatus; // connecting / connected / retrying / stopped、最後に受けた時刻、直近のエラー
}
```

- **張り直し:** 指数のバックオフに揺らぎを足す (1 秒から倍々、上限 30 秒、full jitter)。60 秒つながっていたら間隔を戻す。Wolfx は 90 秒何も来なければ (heartbeat も含めて) 切れたとみなして張り直す。P2P は heartbeat を送ってこず、静かなときは何分も何も来ない (2026-11-13 に実際につないで確かめた) ので、無通信では切らず、切れたことは close で知る。つながるまでは、どちらも 30 秒で打ち切る。
- **重複の除去:** 情報源の中では、気象庁は Atom の `id`、P2P は `id` で除く。Wolfx の地震情報の一覧は毎回 50 件まるごと来るので、1 行ごとに地震識別番号と中身の要約を鍵にし、中身の変わった行だけを採る。情報源をまたいだ重複は、正規化した後の新旧の判定 (2.2) で除く。
- **Wolfx の地震情報の一覧を `all_eew` で受ける訳:** 一覧だけの端点 (`wss://ws-api.wolfx.jp/jma_eqlist`) もあるが、使うと Wolfx への接続が 2 本になる。`all_eew` は文書で「すべての JSON API の配信」とされ、`query_jmaeqlist` に `type: "jma_eqlist"` で答える (2026-11-16 に実際につないで確かめた)。HTTP の `https://api.wolfx.jp/jma_eqlist.json` は回数の目安が文書に無いので、定期の取得には使わない。
- **Wolfx の地震情報の一覧を定期に問い合わせる訳:** 地震のときに Wolfx が一覧を自分から送ってくるかは確かめられていない (文書は「緊急地震速報を受けたら配信する」とだけ書き、一覧には触れていない)。送ってこなくても P2P の予備として間に合うよう、つながっている間は問い合わせ直す。
  - 間隔は 60 秒。Wolfx の文書 (<https://wolfx.jp/en/docs/websocket/>) に問い合わせの回数の目安は無く、同じ接続を使い続け、つなぎ直しを繰り返さないことだけが書かれているので、サーバーの heartbeat と同じ 1 分にした。一覧は約 12KB なので、1 日 17MB ほど。
  - 一覧を受けたら (問い合わせの答えでも、Wolfx が自分から送ってきたものでも)、次の問い合わせをそこから 60 秒後に置き直す。答えと自分から送ってきたものが重なっても、中身の同じ行は鍵が同じなので報にならない (上の「重複の除去」)。
- **受けた原文は残す** (Wolfx を除く。TREM-RTS と SeisJS は DB に入れない)。気象庁の XML と P2P・海外の機関の JSON などを 30 日、圧縮して `raw_messages` に置き、正規化を直したときに流し直せるようにする。
  残す期間は 30 日に決めた (持ち主の決定、2026-11-19。`src/lib/server/store.ts` の `RAW_RETENTION_DAYS`)。

### 2.2 正規化したイベントのモデル

情報源の違いはアダプターの中で吸収し、外へは次の型と、長周期地震動 (`LongPeriod`、2.7)・気象 (`WeatherWarning`・`WeatherInfo`、2.8) だけを出す (`src/lib/model.ts`)。どれにも `status` (通常 / 訓練 / 試験) を持たせ、情報源をまたいでまとめる緊急地震速報・地震・津波には `sources` (どこから来たか) も持たせる。

**緊急地震速報 `Eew`**

```ts
type Eew = {
  eventId: string; // 地震識別番号 (14 桁)
  serial: number; // 報数
  issuedAt: string;
  kind: "warning" | "forecast"; // 警報 / 予報
  final: boolean; // 最終報
  cancelled: boolean; // 取消
  status: "normal" | "training" | "test";
  assumed: boolean; // 仮定震源要素 (PLUM 法・レベル法)
  originTime?: string;
  hypocenter?: { name: string; lat?: number; lon?: number; depthKm?: number };
  magnitude?: number;
  warnAreas: string[]; // 警報の対象の地域名 (警報のときだけ)
  areas?: string[]; // 電文に並ぶ地域名 (Wolfx の WarnArea の全部)。通知の判定だけに使い、画面に出さない (2.4)
  sources: ("wolfx" | "p2p")[];
  updatedAt: string; // 最後の報を受けた時刻。画面は、この 3 分後に緊急地震速報を出すのをやめる
};
```

- **新旧の判定:** 鍵は `eventId`。報数が今より大きいものだけを採る。同じ報数が別の情報源から来たら `sources` に足し、警報の地域は和を取る。取消を受けたら、その地震の速報はそこで終わり (以後の報は捨てる)。
- **最大予測震度・地域ごとの予測震度は、正規化したモデルに入れない** (5 章)。SSE でブラウザに渡すのもこの形なので、画面にも通知にも出ようがない。P2P の原文 (raw_messages) には残る。Wolfx の原文は残さない。
- 訓練と試験 (Wolfx の `isTraining`、P2P の `test`) は保存するが、知らせず、一覧にも「訓練」と付けて既定では隠す。
  一覧と地図に出すのは、サーバーの環境変数 `SONAE_TRAINING=on` のときだけ (ページの `load` が `training` として画面に渡す)。出しても音・読み上げ・OS の通知・Web Push・Webhook では知らせない (`noticeOf` が外す)。
  2026-11-16 に、「通知」の窓のスイッチ (URL の `training=1`) をやめて環境変数に移した (設定を減らす持ち主の決定)。`?training=1` の付いた古いリンクは、印を読まずに外す。
  - **`SONAE_TRAINING` がオフでも、`?e=<識別番号>` のリンクを開けば中身を出す** (ページの `load` が訓練・試験も DB から引く。持ち主の決定、2026-11-19)。送られたリンクが何も出さないと、何が届いたのか確かめられないため。
    そのときは詳しい内容の先頭に「訓練」(試験なら「試験」) を大きく出し、「訓練の緊急地震速報です。実際の地震ではありません。」と添えて、本物と取り違えないようにする (`EewDetail.svelte`・`#lib/format.ts` の `EEW_DRILL_NOTE`)。
    形はページの中の通知と同じ淡い面に注意の色のアイコンと字で、地は塗らない (状態の赤は本物の警報だけ、6.2)。`SONAE_TRAINING=on` で一覧から開いたときも同じに出す

**地震情報 `Quake`** (1 つの地震に、発表された報をまとめる)

```ts
type QuakeReport = {
  kind: "scale" | "hypocenter" | "detail" | "update" | "foreign" | "other"; // 震度速報 / 震源 / 震源・震度 / 震源要素更新 / 遠地
  code?: "VXSE51" | "VXSE52" | "VXSE53" | "VXSE61";
  source: "jma" | "p2p" | "wolfx";
  infoType: "発表" | "訂正" | "取消";
  reportedAt: string;
  // 中身 (震源・M・最大震度・地域と観測点ごとの震度・津波の有無の文・付加文)
};
```

- 一連の情報は「`Control/Title` + `Control/Status` + 地震識別番号」で見分ける (気象庁の運用指針)。取消は**その一連の情報全体**を取り消す。
- **地震識別番号は、自動の電文 (緊急地震速報・震度速報) と手動の電文 (地震情報・津波) で一致しないことがある** (気象庁のよくある質問)。そのため、震度速報と後の地震情報は、番号が合わないときは「発生の時刻が近く、震度の地域が重なる」もので結ぶ。
  - **閾値は、発生の時刻 (震度速報は TargetDateTime) の差が 90 秒以内で、震度の地域が 1 つでも重なる** (どちらかに地域が無ければ時刻だけ)。番号どうしが違うときは震度速報だけを結ぶ (`src/lib/server/merge.ts` の `sameQuakeByTime`・`LINK_WINDOW_MS`、`tests/merge.test.ts` で固定)。P2P の 551 には地震識別番号が無いので、いつもこれで結ぶ。
  - 気象庁の文書に結び方の規則は無い (2026-11-13 に確かめた)。運用指針 別紙 2 の ※1 と、地震火山関連 解説資料 Ⅰ.別 02「EventID 要素の運用」は、自動の電文と手動の電文で番号がずれうることと、番号に発生時刻などの物理的な意味が無いことだけを書く。震度速報の TargetDateTime は「最初に地震波を自動検知した観測点における地震波の検知時刻」で分まで有効 (解説資料 Ⅰ-2)、震度速報は地震発生の約 1 分半後に出る ([気象庁の解説](https://www.jma.go.jp/jma/kishou/know/jishin/joho/seisinfo.html))。震度速報に別の地震の震度が混ざる例もある (解説資料の出現例 4) ので、地域が重なっても同じ地震とは限らない。
  - 90 秒は、分の切り捨て (最大 59 秒) と検知までの遅れを足しても収まる幅として置いた。実際の電文で外れる例が見つかったら直す。
- `Serial` は連番とも一意とも保証されない。新旧は `ReportDateTime` で決める。
- P2P の 551 は気象庁の XML と同じ地震の情報なので、P2P で先に受けたら仮に出し、XML が来たら置き換える (XML を正とする)。
- **Wolfx の地震情報の一覧 (`jma_eqlist`) は P2P の予備。** 2026-11-16 に持ち主が決めて入れた (nTool は入れない)。1 行は 1 つの地震のいまの姿 (見出し・発生の時刻・震源・M・最大震度・津波の文) で、地域・観測点ごとの震度は無い。
  - 1 行を `source: "wolfx"` の報 1 つにする。見出し (`Title`) は気象庁ホームページの一覧と同じ (「震度速報」「震源・震度情報」など) なので、それで種類を決める。発表の時刻が無いので、報の時刻は受けた時刻にする。訓練・試験の印が無いので、P2P の 551 と同じく本番として持つ。
  - 地震識別番号 (`EventID`) は文書の項目の一覧に無いが、実際の JSON にある (2026-11-16 に確かめた)。あれば番号で、無ければ P2P と同じく発生の時刻で結ぶ (上の「番号が合わないとき」の決まり)。
  - **いまの姿は、XML の報があれば XML だけ、無ければ P2P だけ、どちらも無ければ Wolfx だけで組む** (`summarizeQuake`)。震度の地域の並びは報ごとにまるごとなので、震度は情報源を混ぜない。P2P を Wolfx より先にするのは、P2P には地域・観測点ごとの震度があるため。XML が来るまでは仮の姿 (`provisional`、一覧の「速報」) のまま。
  - 例外は震源だけ。XML が無く、P2P が震度速報だけで震源が無いとき (P2P が続報を出さずに止まったとき) は、Wolfx の一覧に震源があれば、震源・M・深さだけを Wolfx から補う。震度・地域・観測点・付加文は P2P のまま。補ったときは `hypocenterSource: "wolfx"` を持たせ、詳しい内容に「震源・M・深さは Wolfx Project、震度は P2P地震情報の速報です」と出す。XML が来たら XML だけの姿になり、この印も消える。
  - どの順に着いても 1 つの地震にまとまるので、一覧は 1 行、通知は同じ事象 (`quake:<id>`) で、二重には鳴らない (tests/store.test.ts で 6 通りの順を試す)。

**津波 `Tsunami`**

- VTSE41 (津波警報・注意報・予報) と VTSE51 (津波情報) は**その時点の全予報区の状態**を毎回まるごと持つので、新しい報で前の予報区の並びを置き換える。予報区ごとに「大津波警報 / 津波警報 / 津波注意報 / 津波予報 / 解除」を持ち、VTSE51 は到達予想時刻と予想の高さも持つ。
- VTSE51 の観測値と VTSE52 (沖合の観測) は、同じ一連の情報に付け足す。同じ観測点は新しいもので置き換える。
- 原因の地震が複数のとき、地震識別番号は並びで来る (`xs:list`)。全部を持っておく。
- P2P の 552 は警報・注意報・予報の区域の状態だけ。XML が来るまでのつなぎに使う。
- **P2P の 551・552 には訓練・試験の印が無い** (API 仕様書 v2.3.0 で印があるのは 556 の `test` だけ。訓練の電文を流すかどうかも書かれていない、2026-11-13 に確かめた)。そのため P2P だけから来た地震・津波は、いつも本番 (`normal`) として持つ。訓練・試験の津波は、地震と同じく id の後ろに `-training` / `-test` を付けて分ける (P2P だけのものも同じ規則にしてあり、仕様に印が足されたら読み取りを直すだけで効く)。
  - 残る危うさ: P2P が訓練の津波を流したら、本番として仮に出る。気象庁の XML (訓練) は状態が違うので重ならず、P2P の仮のものは置き換わらない。訓練は事前に告知されるので、いまはこのままにする。

**お知らせ `Advisory`** — 南海トラフ地震臨時情報 (VYSE50)・関連解説情報 (VYSE51/52)・北海道・三陸沖後発地震注意情報 (VYSE60)・地震・津波に関するお知らせ (VZSE40)・地震の活動状況等に関する情報 (VXSE56)・地震回数に関する情報 (VXSE60)。一覧に新しい順に並べ (種類のチップは「お知らせ」)、選ぶと本文 (VXSE60 は期間ごとの回数の表) を出す。一覧の上の通知には、VXSE56・60 を出さない (地震回数は活動が続く間に何度も出るため)。

米国の太平洋津波警報センター (PTWC) の電報も `Advisory` (code は `PTWC`、`source` は `ptwc`) にして、お知らせの一覧に出す。持つのはフィードの要約 (種類・地域・規模・位置) と電報のページへのリンクで、英文の電報そのものは取りに行かない。米国の参考の情報なので、一覧の上の通知には出さず、知らせない。詳しい内容には「気象庁の発表ではない。日本の沿岸の津波は気象庁の津波の情報を確かめる」と書く。

気象庁の国際津波関連情報 (北西太平洋津波情報センターの電報 WEPA40) も `Advisory` (code は `WEPA40`、`source` は `jma-bosai`) にする。公開の防災情報 XML には無く、気象庁ホームページ (bosai) の JSON とテキストから取る。**公式の API ではないので、ほかと分けた独立のアダプター (`sources/jma-bosai.ts`) にし、形が変わって読めなくなっても、その回を捨てて状態にエラーを出すだけにする** (ほかの情報源と画面は止まらない)。各国の機関に向けた情報で日本の沿岸の津波予報ではないので、一覧の上の通知には出さず、知らせない。
見出しと本文と種類 (調査中・巨大地震警戒・巨大地震注意・調査終了など) を持つ。VYSE50/60 の識別番号は物理的な意味を持たない任意の番号。

**海外の地震 `ForeignQuake`** — USGS などの海外の機関の地震。機関ごとの発表 (`ForeignReport`: 機関・その機関の id・時刻・位置・深さ・M・場所・ページ) を、同じ地震ごとに 1 つにまとめる。

- 同じ機関の同じ id の続報は置き換える。ほかの機関の発表は、**発生の時刻の差が 60 秒以内・震央の距離が 150 km 以内・M の差が 1.0 以内** (どちらかに M が無ければ M は見ない) の地震にまとめる (`sameForeignQuake`)。同じ機関の別の id とはまとめない。
- いまの姿 (時刻・位置・M・場所) は、機関の順 (中央氣象署・GeoNet・USGS・EMSC) で先の機関の値を採る。地元の機関を先に、速報の EMSC を後にした。
- 遠地地震と同じく知らせない。日本に津波のおそれがあれば、気象庁が津波の情報を出す。

**火山 `Volcano`** — 噴火警報・予報 (VFVO50) と噴火速報 (VFVO56)。報ごとに 1 件で、一覧には報を新しい順に並べる。

- 持つもの: 対象の火山 (コード・名前・位置・種類の名前とコード・引上げ／引下げ・前の種類)、警報の種類 (噴火警報・火口周辺警報・噴火予報・解除)、対象の市町村、見出し、火山活動の状況と防災上の警戒事項の文、噴火の時刻 (噴火速報)。
- 一連の情報は「種別 + 識別番号」。噴火警報・予報の識別番号は火山のコード (浅間山は `306`)、噴火速報は発表の時刻と火山のコード (`20140927120000_312`)。**取消はその一連の情報のいちばん新しい報に印を付け、訂正はその報を置き換える** (一覧に 2 つ並べない)。
- 警戒の段 (1〜5) は、種類のコード (コード表 VolcanicWarning) の噴火警戒レベル 11〜15 から取る。レベルの無い火山 (21〜25)・海底火山 (35・36) は、気象庁の配色の指針 (表 1-2) で同じ色の欄にあるものを同じ段に読み替える (居住地域厳重警戒は 5、山麓厳重警戒は 4、入山危険と周辺海域警戒は 3、火口周辺危険は 2)。
- 火山ごとのいまの噴火警報・予報は、受けた VFVO50 のうち火山ごとにいちばん新しいもの (取り消されたものは飛ばす)。地図の火山の印に使う。**sonae が受けていない火山 (長く発表の変わっていない火山) は入らない** (気象庁の長期フィードは数日分しか無い)。
- 噴火速報には火山の位置が無いので、地図では活火山の一覧 (`static/areas/volcano-points.json`、`tools/volcanoes/build.sh` で気象庁ホームページの一覧から作る) で位置を引く。

### 2.3 ブラウザへの配信: SSE

|                      | SSE (`text/event-stream`)                                                                                                         | WebSocket                                                                          |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 向き                 | サーバーからだけ。sonae はこれで足りる (設定の変更は普通の POST)                                                                  | 両向き                                                                             |
| 張り直し・取りこぼし | ブラウザが自動で張り直し、`Last-Event-ID` を送る。そこから DB で埋められる                                                        | 自前で書く                                                                         |
| 認証                 | 普通の要求なので、セッションの Cookie と hooks の判定がそのまま効く                                                               | Upgrade の時に別に判定する                                                         |
| SvelteKit・Gateway   | `+server.ts` で `ReadableStream` を返すだけ。Cilium Gateway もそのまま通る                                                        | SvelteKit に標準の仕組みが無く、adapter-bun の外で `Bun.serve` の websocket を触る |
| 同時の接続数         | HTTP/1.1 だとブラウザの 6 本の上限に数える。HTTP/2 なら 1 本に束ねられる (家の本番はブラウザとの間に Cloudflare があり、h2 か h3) | 制限なし                                                                           |

**SSE にする。** `GET /api/stream`。

- 各イベントに DB の通し番号を `id:` で付ける。`Last-Event-ID` があれば、それより後を DB から送ってから生の配信に移る。
  - 埋め直しは 500 件まで。**超えるときは埋め直しを送らず、`event: resync` を送る** (`id:` はいまの最後の番号、`data` は `{"after": 番号}`)。そこから生の配信に移る。ブラウザは受けたら `invalidateAll()` で `load` を走らせ直し、一覧を取り直す。
- **`s.doany.io` は Cloudflare のプロキシを通したワイルドカードの DNS で配信される** (DNS のレコードは足さない)。Cloudflare のプロキシは、応答の間に 100 秒何も流れないと接続を切り (Proxy Read Timeout)、圧縮やバッファリングで SSE を溜めて届けることがある。そのため:
  - **30 秒ごとにコメント行 (`: ping`) を送る。** Cloudflare の 100 秒、adapter-bun の `CONNECTION_IDLE_TIMEOUT` (Bun の idleTimeout、上限 255 秒)、Gateway の無通信の切断のどれよりも十分短い。同じ間隔で情報源の状況 (`event: status`) も送る。
  - 応答のヘッダーに `Content-Type: text/event-stream`・`Cache-Control: no-cache, no-transform`・`X-Accel-Buffering: no` を付ける (`no-transform` で圧縮を止め、`X-Accel-Buffering` で途中の溜め込みを止める)。
  - それでも切れることはあるので、ブラウザの側は切れたら張り直して、最後に受けた番号の後を取り直す。接続のたびに (張り直しも)、最後に受けた番号を `?after=` で付ける (最初はページの `load` で渡した番号)。サーバーは `Last-Event-ID` も読むが、画面は使わない。
- **張り直しは画面が自分でする** (`src/lib/live.svelte.ts`。2026-11-15 に、EventSource の張り直しに任せるのをやめた。持ち主の声「接続を再試行するようにしてほしい」)。EventSource だけでは止まったままになる道があるため:
  - サーバーや途中 (Cloudflare・Gateway) が 200 の `text/event-stream` 以外 (入れ替え中の 502・503、ログインが切れた 401 など) を返すと、EventSource は張り直さずに CLOSED で止まる。
  - スリープから戻ったときなどに、TCP の接続が切れているのに EventSource がそれを検知せず、何も届かないままになる。`: ping` のコメント行は EventSource が画面に渡さないので、画面からは数えられない。
  - そこで、`error` が来たらいつも閉じて、自分で間を空けて張り直す (`#lib/backoff.ts` の Backoff。情報源の張り直しと同じく、1 秒から倍々・上限 30 秒・full jitter。60 秒続けてつながったら間隔を戻す)。張り直すたびに、そのとき最後に受けた番号を `?after=` に付けるので、切れていた間のものはサーバーが埋め直す (500 件を超えれば `resync` で一覧を取り直す。上の通り)。取りこぼさない。
  - すぐ張り直すきっかけ: `online`、画面に戻ったとき (`visibilitychange` で、切れているか 75 秒何も届いていないとき)、戻る・進むの控え (bfcache) から戻ったとき (`pageshow`)。`offline` では閉じて、間を空けた張り直しを続ける (`offline` の知らせは当てにならないことがあり、張り直しを止めると戻ったことに気づけない道ができるため。間隔は伸びて 30 秒で止まり、`online` で戻す)。
  - 心拍: サーバーが 30 秒ごとに送る `event: status` を心拍に使う。つながっているのに 75 秒 (`STALE_MS`。2 回半) 何も届かなければ、切れたとみなして張り直す (5 秒ごとに見る)。
  - 手元の Chromium で、`/api/stream` が 503 を返し続ける間も 20 秒に 6 回張り直し、戻すとつながり直すことを確かめた。
- **切れたことを知らせる** (`src/lib/connection.ts` の OutageWatch と `alerter.svelte.ts` の `connection`。持ち主の声「接続が切れたとき音声で通知してほしい」)。
  - 切れたまま 30 秒 (`OUTAGE_NOTIFY_MS`) 続いたら、1 度だけ「そなえの受信が切れました。再接続しています。」と知らせる。サーバーの入れ替えなどの短い切れ目では鳴らさない。開いてから一度もつながらないときも数える。
  - 知らせた後につながったら、短く「そなえの受信が戻りました。」と言う (知らせていない切れ目の戻りは言わない)。
  - 切れたり戻ったりを繰り返しても鳴りすぎないよう、前の「切れました」から 10 分 (`OUTAGE_COOLDOWN_MS`) は次の「切れました」を言わない (経った後も切れたままなら言う)。
  - 知らせ方は「通知」の「開いているとき」でオンにしたものだけ。切れたときは事象と同じく、チャイム・OS の通知 (tag `sonae:connection`。チャイムが鳴ったら音なし)・読み上げ。戻ったときは読み上げと、切れたときの通知が残っていれば音なしで置き換えるだけ (チャイムは鳴らさない。警報と紛れるため)。
  - 止めるスイッチは無く、いつも知らせる (設定を減らす持ち主の決定、2026-11-16)。前のスイッチ「受信が切れたら知らせる」の値 (`sonae.alert` の `outage`) は読まず、残っていれば開いたときに消す。
  - 読む文は `#lib/readout.ts` の `CONNECTION` の 2 文で、決まった文として起動したときに合成しておく。切れている間はサーバーに音を取りに行けないので、画面は読み上げがオンで VOICEVOX が使えるときに前もって取っておき (この家の声が替わったら取り直す)、取れていなければ端末の読み上げで読む。
  - タブが幾つあっても 1 つだけが知らせる (Web Locks。タブごとに見ているので 60 秒持つ)。
  - 画面の印も合わせる。切れている間は、ヘッダーの注意の印が「受信が切れています・再接続しています」(スマホの形は dock の印で、読み上げソフトには「受信が切れています」)、受信の状態の「画面への配信」が「再接続しています」になる。印の一言は、読み上げと OS の通知の「受信が切れました」にそろえて「受信」と呼ぶ (2026-11-19 に「配信が切れています」から替えた。`#lib/connection.ts` の `troubleLabel`)。
- 最初の表示の中身はページの `load` で渡し、SSE は差分だけにする。

- **何を知らせるか (種類ごとに範囲を選ぶ。2026-11-16 に作り替えた):** 緊急地震速報・地震・津波・火山・気象のそれぞれで、「全国のものを知らせる」(`everywhere`) / 「住んでいる地域と現在地のものだけ」(`nearby`) / 「知らせない」(`off`) の 3 つから 1 つを選ぶ (`PushPrefs`)。

  - **既定は気象だけ「住んでいる地域と現在地」、ほかは「全国」。** 段を選べたころの既定 (最大震度 4 以上・住んでいる地域で震度 3 以上・津波注意報以上・噴火速報と噴火警報 (居住地域)。気象は住んでいる地域の警報以上と、どこでも特別警報) を知らせる組み合わせにした (持ち主の決定、2026-11-13・14)。緊急地震速報の予報と、住んでいる地域の気象の注意報 (1 日 1 回まで) は、2026-11-16 の返事で既定でも知らせるようになった。
  - **「全国」は「住んでいる地域と現在地」に、どこのものでも知らせる段を足したもの。** 全国を選んで、自分の所のものが減ることは無い。
  - **段の既定値と理由:**
    - 緊急地震速報は警報と予報 (2026-11-16 に予報を戻した。持ち主の声「予報を無くすと地震から逃げられない」)。警報は強い揺れが来る地域に出るもので、身を守る動きにつながる。予報は警報の基準 (最大予測震度 5 弱以上) に届かない揺れでも先に出るので、揺れに備える時間になる。
      予報は日に何度も出るが、**同じ地震の続報では鳴らし直さない** (中身の値は警報の地域だけで、予報の続報は M や震源が変わっても同じ値。警報に上がったら重さが上がるので鳴らし直す。`eewNotice` の `changeKey`)。予想震度は書かない (5 章)。
      - **「住んでいる地域と現在地」の照らし方:** 住んでいる地域と現在地の地震情報／細分区域の名前が、警報の地域 (`warnAreas`) か電文に並ぶ地域 (`areas`) にあれば知らせる。
        気象庁の[緊急地震速報 (警報) 及び (予報) について](https://www.jma.go.jp/jma/kishou/know/jishin/eew/shikumi/shousai.html) (2026-11-16 に確かめた) では、予報は「予測される最大震度が震度４以上 (中略) のときは、地域名に加えて」各地域の予測震度と到達予測時刻を出し、最大予測震度が 3 以下のときは最大予測震度だけで地域名を出さない。
        Wolfx の jma_eew は電文の地域を `WarnArea` に並べ、`Type` が `Warning` か `Forecast` ([Open API の項目の一覧](https://wolfx.jp/en/docs/open-api/))。sonae は名前 (`Chiiki`) だけを `areas` に持ち、予測震度 (`Shindo1`・`Shindo2`) と到達予測時刻は読まない (画面にも出さない)。P2P の 556 は警報だけを流し、予報は来ない
      - **電文に地域の無い予報は、「住んでいる地域と現在地」でも知らせる (全国と同じ)。** 地域が無いのは、ふつうは最大予測震度が 3 以下のとき。ただ、Wolfx が予報の地域を実際に並べるかは文書から言い切れず (手元の電文は作り物だけ)、並べないなら地域で照らす予報が 1 つも無くなる。震源からの距離で地域を決めるような自前の判定は、地点の揺れの予想 (予報業務、5 章) に近いのでしない。知らせない側に倒すと、地域の付かない予報で揺れに気づけないので、安全側に知らせる。本物の電文に地域が並ぶと分かっても絞らない (持ち主の声「鳴らしたほうがええんちゃう？」、2026-11-16)
      - 予報で地域が無く知らせた後に、同じ地震の続報で地域が付いても、続報なので鳴らし直さない。地域が付いて初めて住んでいる地域が当たったときは、初めての通知として鳴らす
    - **地震の震度** (2026-11-16 に選択を戻した。持ち主の返事): 範囲の下に選択を 1 つ置き (「地震を知らせる震度」、震度 1〜7)、選んだ範囲に使う。「全国」なら「どこかで最大震度 X 以上」、「住んでいる地域と現在地」なら「住んでいる地域か現在地で震度 X 以上」。全国用と地域用の 2 つには分けない。
      - **既定は範囲ごとに前と同じ (全国 4・地域 3)。** 選んでいない間 (`quakeMin` が無い) は範囲の既定で見るので、範囲を替えると震度も替えた先の既定になる。範囲の既定と違う値を選んだら覚え、範囲を替えても残す (替えた先の範囲の既定と同じ値なら覚えなくなり、戻すと戻した範囲の既定になる)。既定と同じ値を選んだら覚えない (`withQuakeMin`・`normalizePrefs`)
      - **「全国」では、住んでいる地域と現在地の震度 3 以上も続けて知らせる** (`QUAKE_LOCAL_FLOOR`)。選んだ震度が 3 以下なら、どこかで震度 X 以上に含まれるので足さない。比べた案は「全国 = どこかで最大震度 X 以上だけ」で、窓の文は短くなるが、既定 (震度 4) のままでも前の既定にあった「住んでいる地域で震度 3」が消え、「全国は地域に段を足したもの」(上) も崩れて、全国を選ぶと自分の所の揺れが減る。前の挙動と「全国を選んで自分の所が減らない」を取った (持ち主の返事、2026-11-16)。窓の文は「最大震度5弱以上の地震と、住んでいる地域か現在地で震度3以上の地震を知らせます。」のように両方を言う
      - 震度 4 は「ほとんどの人が驚く」揺れで、家族の安否を気にし始める境目。震度 3 以下は全国で月に何十回もあり、鳴りすぎる。自分の所で揺れたものは知りたいので、1 段下げる。P2P の震度速報には地域のコードが無いので、名前でも見る。
    - 津波は注意報以上 (前の既定のまま)。注意報でも海の中や海岸の近くでは危ない。
    - 火山は、どこでも噴火速報と噴火警報 (居住地域)。噴火速報は登山者や周辺の人がすぐ身を守るためのもので、出るのは年に数回。噴火警報 (居住地域) は警戒レベル 4・5 (高齢者等避難・避難) と、レベルの無い火山の山麓・居住地域厳重警戒で、住んでいる所に避難が要るもの。
      火口周辺警報 (レベル 2・3) は、出たままの火山が常に幾つもあって引上げ・引下げのたびに鳴ると多すぎるので、全国では知らせない。住んでいる地域か現在地が対象の市町村なら、その山に入る・近くにいる人に要るものなので知らせる。対象の市町村は噴火警報・予報 (VFVO50) と噴火速報 (VFVO56) の電文の「対象市町村等」(気象・地震・火山情報／市町村等のコード。住んでいる地域と同じコード) で照らす (`Volcano.cityCodes`。2026-11-16 より前に受けた報には無く、当たらない)。
    - 気象は、住んでいる地域と現在地の注意報以上。**全国の注意報は出さない** (毎日どこかの府県予報区で多数出る)。
      **注意報だけの通知は 1 日 1 回まで** (2026-11-16。持ち主の声「1 日 1 回なら注意報は鳴ってもよい」)。同じ市町村でも乾燥・雷・強風などが日に何度も出たり替わったりするので、数で抑える。2 回目からは一覧と地図に出すだけで、音・読み上げ・OS の通知・Web Push・Webhook では知らせない (`#lib/notify.ts` の `decideDaily`)。
      全国では、府県予報区ごとに危険警報 (レベル 4。前の土砂災害警戒情報にあたるレベル４土砂災害危険警報も入る) から知らせる (府県予報区と種別ごとに 1 つの通知。tag は特別警報と同じ `warning:special:<府県予報区>:<種別>`)。警報 (レベル 3) は全国では毎日のように出るので入れない。危険警報は大雨の季節には日に幾つも出ることがあるが、それでも「全国」に入れる (持ち主の決定、2026-11-16)。
      指定河川洪水予報・熱中症警戒アラート・台風情報・気象防災速報は一覧に出すだけで送らない。住んでいる地域の警報・注意報が解除されたら、前に知らせた端末にだけ置き換えに行く。府県予報区ごとに知らせた危険警報・特別警報も、終わったら前に知らせた端末にだけ置き換えに行く (下の「同じ事象で何度も鳴らさない」)。
      - **数えるもの:** 気象警報・注意報の通知で、いちばん高い段が注意報のもの (`isAdvisoryOnly`) を、新しく知らせるとき (その事象に前に送っていないか、解除の後にまた出たとき) だけ。前に知らせた注意報の続報 (種類が増えた・見出しが変わった) は、Web Push と開いている画面では鳴らさずに置き換えるだけなので数えない。警報以上に上がったもの・解除・記録的短時間大雨情報・竜巻注意情報・特別警報は数えず、いつもどおり知らせる
      - **区切りは日本時間の暦日** (0 時で戻る。`jstDay`)。24 時間の窓より、「1 日 1 回」を言葉どおりに読める。前の夜の注意報で翌朝の注意報が鳴らなくなることも無い。日をまたいだ 23 時台と 0 時台に 2 回鳴ることはある
      - **住んでいる地域と現在地は別に数える** (控えの tag `quota:advisory` と `quota:advisory:here`)。サーバー (Web Push・Webhook) は現在地を知らないので住んでいる地域しか数えられない。まとめて数えると、画面が先に現在地の注意報で数を使ったとき、住んでいる地域の注意報で Web Push は鳴り画面は鳴らない、と食い違う。別に数えれば、住んでいる地域の分は画面とサーバーで同じ決まりと同じ区切りになる。出かけている日は、多くて 2 回鳴る
      - **控えの置き場:** サーバーは送り先ごとの控え (`push_log`・`webhook_log`) に、tag が `quota:advisory` の行を作り、数えた日を digest に持つ (`SentLog.mark`)。送れなかったら注意報の控えと一緒に戻す (`undoJob`)。画面はメモリの控えと localStorage の `sonae.alert.quota` に持ち、決める前に読んで決めた後に書く (開き直しても、ほかのタブとも 1 日 1 回)。開いてから初めて取れた現在地の注意報と、開いているときの通知・音・読み上げがどれもオフの間の注意報は、鳴らさないので数えない
      - **Webhook は、注意報だけの通知の鳴らさない続報を送らない。** Webhook は前の投稿を置き換えられず、続報も新しい投稿になる (下の「Webhook」) ので、送ると 1 日 1 回を超えて届く。解除は前に送った Webhook に送る
      - 数は送り先ごとに持つので、画面を開いていなかった間にサーバーが数えた注意報は画面の数に入らない (その日の次の注意報で、画面だけが鳴ることがある)。逆も同じ。これで良いとした (持ち主の返事、2026-11-16)
  - **いつも知らせるもの (どの範囲でも、「知らせない」でも):** 特別警報にあたるもの (気象の特別警報・大津波警報・噴火警報 (居住地域)) と、南海トラフ地震臨時情報・定例外の解説情報・後発地震注意情報。
    - 気象の特別警報は、住んでいる地域でなくても送る。数十年に一度の重大な災害のおそれで、旅先や家族の居場所もあるため。住んでいる地域と同じ府県予報区のほかの市町村に特別警報 (全国なら危険警報) が出ているときは、住んでいる地域の通知 (同じ tag) で先に言い、住んでいる地域の状態を添える (住んでいる地域の続報や解除を落とさない)
    - 南海トラフ地震臨時情報等は、めったに出ず、出たら備えを見直すべきもの。
    - この 2 つは 2026-11-13 から既定がオンのスイッチだったが、2026-11-16 にスイッチを消していつも送ることにした (設定を減らす持ち主の決定)。条件 (`PushPrefs`) からも項目 (`weatherSpecial`・`advisory`) を消した。項目を残して読むときに `true` にする形より、型から消すほうを選んだ。読む所が `normalizePrefs` 1 つに集まっていて捨てるだけで済み、残すと判定や画面に使う所が残っていないかを型で確かめられないため。
  - **「住んでいる地域と現在地」でも、どこに出ても知らせる例外:** 大津波警報と噴火警報 (居住地域)。どちらも気象業務法の特別警報に当たり (気象庁が大津波警報・噴火警報 (居住地域)・噴火警報 (レベル 4・5) を特別警報に位置づけている)、気象の特別警報と同じく、旅先や家族の居場所のために安全側に倒した。津波警報と火口周辺警報は、住んでいる地域と現在地のものだけ。
    **「知らせない」を選んだ種類でも、この 2 つは知らせる** (2026-11-16。持ち主の問い「危険性的に知らせたほうがよい？」に、気象の特別警報を「知らせない」でも知らせる決定とそろえて決めた)。窓の「知らせない」の文は「特別警報にあたる大津波警報だけを知らせます。」「特別警報にあたる噴火警報 (レベル 4・5) だけを知らせます。」にした。噴火速報と火口周辺警報、津波警報・津波注意報は「知らせない」なら知らせない。
  - **住んでいる地域** (**選ばない**)。どの種類の「住んでいる地域」にも使う 1 つの設定で、1 つの市町村等 (気象警報等、7 桁のコード) を選ぶ (2026-11-14 に持ち主の指摘で、地震だけの「現在地」から替えた。前の「現在地」は読まず、選び直してもらう)。
    - Web Push と Webhook はタブを閉じていても届くので、サーバーが地域を知っている必要がある。そのため購読の条件に持つ
    - 選んだときに、画面が市町村等の表 (`static/areas/cities.json`、docs/map.md) から、その市町村等が入る地震情報／細分区域・府県予報区・一次細分区域・沿岸の津波予報区を引いて一緒に持つ。サーバーと Service Worker は表を読まずに判定できる
    - 選び方は都道府県と市町村の 2 つの欄か、「現在地から選ぶ」。現在地は端末の位置を 1 回だけ取り、端末の中で市町村等の面 (`warning-areas.geojson`) を引いて、市町村等のコードだけを持つ。**緯度・経度はサーバーに送らず、覚えもしない**
    - 選んでいないと、「住んでいる地域と現在地のものだけ」は開いている画面の現在地だけで見る。Web Push と Webhook には、どこに出ても知らせるもの (大津波警報・噴火警報 (居住地域)・特別警報など) だけが届く。窓の住んでいる地域の下にそう書く (`#lib/notify.ts` の `homeNote`)
  - **津波予報区と市町村の対応は、気象庁の「津波予報区に対応する沿岸の市町村対応表」を使う** (令和 8 年 3 月 26 日時点。[津波予報区のページ](https://www.jma.go.jp/jma/kishou/know/jishin/joho/tsunami-yohoku.html) の PDF。2026-11-16 に確かめた)。
    66 の予報区のすべてについて、予報区・都道府県・沿岸の市町村名が載っている。GIS データ (予報区の線と市町村の面) から接する・近い予報区を求めるより、気象庁が決めた対応のほうが根拠を示せるので、こちらにした。
    - 表は `tools/areas/tsunami-cities.tsv` に書き写し、`tools/areas/tsunami-cities.ts` が市町村等の表 (`cities.json`) の 7 列目に `[予報区のコード, 名前]` の並びを足す (`build-weather.sh` から呼ぶ。予報区のコードは `tsunami-areas.geojson` の名前から引く)。675 件の市町村名から、沿岸の市町村等 683 件に当たる
    - 市町村の一部の沿岸の書き方 (「稚内市（宗谷岬の西）」「豊橋市（三河湾沿岸）」) は、市町村等ごと両方の予報区に入れる (市町村等は区域を分けないので、どちらの津波も知らせる)
    - 読みが同じ市町村の前に付けた県・地方の名前 (「茨城鹿嶋市」「日高地方日高町」「大阪堺市」) は外して当てる。市町村等の表で 2 つ以上に分けた市町村 (仙台市東部・西部、神戸市の区、田辺市の旧町村、対馬市の上対馬・下対馬など) は、分けた全部に当てる (内陸の区も入る。安全側)。北方領土の 6 村は市町村等の表に無いので当てない
    - **海に面していない市町村等は、どの予報区にも当たらない。** 「住んでいる地域と現在地のものだけ」では、現在地の予報区と、どこに出た大津波警報だけを知らせる (窓の住んでいる地域の下に「海に面していないので…」と出す)。表の注にあるとおり、津波は海に直接面していない市町村まで遡上することがある。川沿いの低い所に住む人は「全国」を選ぶ (津波の既定は「全国」のまま)
    - 2026-11-16 より前に覚えた住んでいる地域は津波予報区を持たない。分からないので、どの予報区でも当たるとみなす (知らせない側に倒さない)。「通知」の窓を開くと表から引き直し、端末・サーバーの購読・Webhook に覚え直す
    - 気象庁が表を改めたら (予報区や市町村の変更)、TSV を書き直して作り直す
    - 津波の重さ (鳴らし直すかの判定) は、「住んでいる地域と現在地」では、そこの予報区に出ている区分にする (どこかに大津波警報が出ていれば大津波警報)。ほかの予報区の区分が上がっても鳴らし直さず、そこの区分が上がったら鳴らし直す。通知の見出しと本文は全国と同じ
  - **前の形の読み替え。** 購読・Webhook (DB)・端末 (localStorage の `sonae.alert.prefs`) に保存済みの値と、API に送られてきた値は、どれも `normalizePrefs` を通して読む。前の形の段は、知らせるものがいちばん近い範囲に読み替える (新しい値の名前 `everywhere`・`nearby` は、前の値 `all`・`warning` と重ならないようにした)。端末の値は、開いたときに読み替えた形で書き直す
    - 緊急地震速報: 警報だけ・予報も → 全国 (予報も知らせる)、送らない → 知らせない
    - 地震: 最大震度の段があれば → 全国で、その段を地震の震度にする。最大震度を「知らせない」にしていた (住んでいる地域の震度だけ) → 住んでいる地域と現在地で、住んでいる地域の震度の段 (`areaMinInt`) を地震の震度にする。どちらも範囲の既定と同じ値なら持たない。全国のときの `areaMinInt` は読まない (全国の地域の分は震度 3)
    - 津波: 注意報以上・警報以上・大津波警報だけ → 全国、送らない → 知らせない
    - 火山: 噴火速報と噴火警報・火口周辺警報も → 全国、送らない → 知らせない
    - 気象: 警報以上・注意報も → 住んでいる地域と現在地、送らない → 知らせない
  - 訓練・試験・遠地地震は送らない。

- **同じ事象で何度も鳴らさない:**
  - 事象ごとに tag を決める (`eew:<地震識別番号>`・`quake:<地震の id>`・`tsunami:<津波の id>`・`advisory:<id>`・`volcano:<火山のコード>`・噴火速報は `volcano:flash:<識別番号>`・気象警報・注意報は `warning:<住んでいる市町村等>:<種別>`、どこかの特別警報は `warning:special:<府県予報区>:<種別>`・記録的短時間大雨情報と竜巻注意情報は `weather:<一連の情報>`)。
    気象の通知は住んでいる地域で中身が変わるので、イベントから作った通知の元を購読の条件ごとに作り直す (`#lib/notify.ts` の `noticeFor`。Web Push も開いている画面の音も同じ)。Service Worker は `showNotification` の `tag` で前の通知を置き換える。
  - 購読ごとに、tag へ最後に送った「重さ」(震度の段・津波の区分・警報か予報か) と中身の要約を `push_log` に持つ。
    初めては鳴らす。**中身が同じなら送らない。重さが上がったら鳴らし直す** (`renotify`)。それ以外の続報 (震源や M が決まった・取消・解除) は、**同じ tag で鳴らさずに置き換える**。
  - 取消・解除は、前に知らせた購読にだけ送る (知らせていないものの取消は要らない)。
  - **府県予報区ごとに知らせる気象の通知 (どこかの特別警報と、「全国」の危険警報。tag は `warning:special:<府県予報区>:<種別>`) は、その段が府県予報区のどの市町村等からも無くなったら、終わりを伝える通知を送る** (`#lib/notify.ts` の `wideEndFor`・`noticesFor`)。見出しは「島根県の大雨の特別警報は終わりました」(「全国」なら「…の危険警報・特別警報は終わりました」)、本文は「どの市町村も危険警報以下になりました。」(「全国」なら「警報以下」)。
    - 解除と同じ閉じる通知で、前にその tag で知らせた送り先 (購読・Webhook・開いている画面) にだけ送り、鳴らさずに置き換える。閉じるまで残す通知 (`requireInteraction`) を、終わった後も特別警報のまま残さない。Webhook には新しい投稿として送る (住んでいる地域の解除と同じ。鳴らさない続報を Webhook に送らない決まりは、注意報だけの通知の 1 日 1 回のためのもので、これは当たらない)
    - 気象警報・注意報の電文は府県予報区と種別ごとに今の状態をまるごと持つので、解除・警報以下への切り替え・訂正のどれでも、段の出ている市町村等が無いことで終わったと分かる (R06 には取消が無く、誤って出したものは訂正の報で置き換わる)。段は送り先の条件で見る。「住んでいる地域と現在地」では特別警報が危険警報に下がったら終わり、「全国」では警報以下に下がったら終わり。「全国」で特別警報が危険警報に下がっただけなら終わりにせず、また上がっても鳴らし直さない (住んでいる地域の警報と同じ)。範囲を「全国」から「住んでいる地域と現在地」に替えた後は、危険警報で知らせた tag にも「…の特別警報は終わりました」が届く (見出しが実際とずれるが、置き換えるだけで鳴らず、範囲を替えたときだけなので、前の範囲を控えに持つことはしない)
    - 中身は電文によらず決まった文にする。終わった後の続報 (注意報の出し直しなど) で中身が変わり、送り直すことの無いように
    - 住んでいる地域が同じ府県予報区にあって住んでいる地域の tag で言っていたときは、終わりも住んでいる地域の通知が言う。どこかの特別警報の tag の控えが前から残っていれば、それにも終わりを送る (`noticesFor` は住んでいる地域の通知と一緒に返す)
    - 比べた案は、控えの持ち方を変えて府県予報区の今の状態から「新しく出た」かを決める形。終わりを控えに書かずに済むが、サーバーと画面がそれぞれ府県予報区ごとの前の状態を持ち、起動したときにそろえる必要があり、出たままの OS の通知も残る。終わりの通知なら、解除と同じ `keptLevel` (下の「鳴らす判定は Web Push と同じ関数」) で控えの重さが戻り、判定の作りを増やさない
  - 鳴らすかどうかを決めて控えるところまでは同期でする (続報が続けて来ても二重に鳴らない)。送れなかったら控えを送る前に戻す (初めての通知なら消して、次の続報を初めてとして扱う)。購読の持ち主が替わったら控えを捨てる。控えは 30 日で捨てる。
  - Web Push の `Topic` に tag の SHA-256 の先頭 32 字を付ける。配信サービスがまだ届けていない前の通知は、続報で置き換わる。
  - 起動したときに長期フィードで埋めた昔の電文を鳴らさないよう、事象の時刻から緊急地震速報は 3 分・地震と記録的短時間大雨情報・竜巻注意情報は 1 時間・津波・お知らせ・火山・気象警報は 6 時間を過ぎたものは送らない。有効期限の過ぎた竜巻注意情報も送らない。
- **送り方:** 緊急地震速報と津波、噴火速報と噴火警報 (居住地域)、気象の危険警報・特別警報と記録的短時間大雨情報・竜巻注意情報は `Urgency: high`。`TTL` は緊急地震速報 120 秒 (遅れて届いても意味が無い)、地震情報と記録的短時間大雨情報・竜巻注意情報 1 時間、津波・お知らせ・火山・気象警報 6 時間。緊急地震速報の警報と津波警報以上、噴火速報と噴火警報 (居住地域)、気象の危険警報・特別警報は、閉じるまで残す (`requireInteraction`)。
- **Service Worker** (`src/service-worker/`、SvelteKit が自動で登録): 通知を出し、押されたらその事象の画面 (1 つの画面でその件を選んだ URL。`/?q=<id>`・`/?t=<id>`・`/?e=<識別番号>`。[ui.md](ui.md)) を開く。開いている画面があればそれを移して前に出す。このサイトの中のパスしか開かない。画面やデータの控え (オフライン) はしない (古い地震情報を出さないため)。型は WebWorker の型で、`bun run check` が別に見る。
- **iPhone・iPad:** ホーム画面に追加した Web アプリ (iOS 16.4 以降) でだけ Web Push が届く。そのための Web アプリのマニフェスト (`static/manifest.webmanifest`。明るいテーマでは地の色だけが違う `manifest-light.webmanifest`) を置き、ダイアログで案内する。

- **ホーム画面のアイコン:** iOS と Android のホーム画面は SVG のアイコンを使わないので、`static/favicon.svg` から PNG を作って `static/icons/` に置く (192・512・maskable の 512 をマニフェストに、180 の `apple-touch-icon.png` を `app.html` の `<link rel="apple-touch-icon">` に)。白い地に印を置き、maskable は印を安全な円 (直径 80%) に収まる 55% にする。作り方はホストに何も入れず、コンテナの rsvg-convert で描く。`favicon.svg` を変えたら、次のコマンドで作り直してコミットする。

- **Webhook** (2026-11-16 に足した。issue #167「Web Push だけでなく、Discord や Slack などの Incoming Webhook エンドポイントへの通知があると便利」): Web Push と同じ報を、同じ見出しと本文で Discord・Slack などへ送る (`src/lib/server/webhook.ts`)。作りは denpa の `src/lib/server/webhook.ts` にそろえた。登録と送る本文は [push.md の「Webhook」](push.md#webhook)。
  - **鳴らす判定と控えは Web Push と同じ** (`planSends`・`sentLog`。控えは `webhook_log`)。初めてと重さが上がった続報は送り、中身が同じなら送らない。Web Push が鳴らさずに置き換える続報 (取消・解除・震源が決まった) は、チャンネルでは置き換えられないので、新しい投稿として送る。送れなかったら控えを戻し、送り直しはしない。404・410 でも Web Push の購読と違って自分では消さない (URL を見返す道が無く、消すと足した人が気づけないため。「直近の結果」に残す)
  - **条件は Webhook ごとに持つが、画面は増やさない。** 「通知」の条件をそのまま使い、足したときの条件で送る。その後に条件を変えると (「通知」の窓・地図のメニュー)、その人の Webhook 全部に送る (`PUT /api/webhooks`)。条件の欄を Webhook ごとに並べると窓が倍になるため。ブラウザごとに条件が違うときは、最後に変えたものになる
  - **URL は秘密** (知っていれば誰でも投稿できる)。DB には持つが、API は返さず (一覧はホストだけ)、記録にもホストだけを出す。送れなかった理由も、HTTP の状態か決まった言葉 (「時間切れです」「つながりませんでした (ECONNREFUSED)」) だけにする (例外の文には URL が入りうる)
  - **宛先のアドレスは縛らない** (Web Push の配信サービスの表とは違う)。家の中の Home Assistant のような LAN の送り先がふつうにあり、送り先を足せるのはログインした人だけだから (denpa と同じ考え方)。代わりに、送り先を足がかりに別の所を覗かせない。リダイレクトは追わず、相手の本文は読まずに捨て、画面にも返さない
  - 送る本文の形は送り先 (Discord・Slack・ほか) を URL で見分けて変える。形は [push.md の「Webhook」](push.md#webhook)
  - API は `GET`・`POST`・`PUT`・`DELETE /api/webhooks` と `POST /api/webhooks/test` (1 人 10 分に 5 回まで)。どれもログインが要り、本文は `application/json` だけ受ける (415)。1 人 10 まで。VAPID の鍵が無くても使える
  - 送るのは待たない (10 秒で切る)。相手が遅くても、ほかの送り先と Web Push は待たない
- **開いているとき:** SSE で受けたら、OS の通知と、短い音 (`<audio>`) と読み上げで知らせる (`src/lib/alerter.svelte.ts`)。読み上げの声は VOICEVOX で作る (下の「読み上げ」)。
  - **OS の通知も出す** (2026-11-15 に足した。持ち主の声「警報聞き逃しはまずいから開いてるときは通知ならして」)。ブラウザは操作の前だと `<audio>` も読み上げも鳴らさないが、`ServiceWorkerRegistration.showNotification` は通知の許可があれば操作なしで OS の通知音が鳴る。
    鳴らすと決めた事象 (`planAlerts` の `renotify`) で出す。中身は Web Push と同じ関数で作る (`payloadOf` → `toNotification`。見出し・本文・tag・`renotify`・閉じるまで残すか (`requireInteraction`)・押したときの URL)。押したときは Service Worker の `notificationclick` がその事象の画面へ移す。
    鳴らさない続報 (取消・解除・震源が決まった) は、その tag の通知が出ていれば鳴らさずに置き換える (取消を残った通知に映す)。
  - **出すのは通知の許可 (`Notification.permission === "granted"`) があるときだけ。** 許可を求めるのは人が操作したときだけ (「通知」の「開いているとき」の「OS の通知を出す」のスイッチと、Web Push の「このブラウザで受ける」)。スイッチは `sonae.alert` の `notify` に持ち、既定は無し (許可があればオン)。許可はサイトの設定で変わるので、画面に戻ったとき (`visibilitychange`) と窓を開いたときに読み直す。
  - **Web Push と二重に鳴らさない。** Web Push に登録してあるブラウザには、同じ事象が SSE と Web Push の両方で届く。Service Worker は画面が開いているかで Web Push の通知を止めない (下の項。iOS が購読を止めるため) ので、どちらも通知を出す。
    同じ事象は同じ tag なので、後から出した通知は前の通知を置き換えるが、`renotify` が付いていると置き換えでも鳴り直す。そこで **後から出すほうが、同じ tag で見出しと本文も同じ通知がもう出ていないかを `getNotifications({ tag })` で見る** (`#lib/push.ts` の `isShown`)。
    - Service Worker (Web Push が後): 出ていれば、`renotify: false`・`silent: true` で置き換える (`quiet`)。出すことはやめない。
    - 画面 (SSE が後): 出ていれば出さない。ほかのタブが出したときも同じ (タブが幾つあっても 1 度)。
    - 条件は同じ `PushPrefs` を端末とサーバーで持つので、ふつうは同じ中身になる。重さが上がった続報は本文が変わるので、どちらからでも鳴らし直す。
    - 残ること: 見て出すまでの間は交わらないので、ほぼ同時に届くと 2 度鳴ることがある (ふつうは SSE が先に届き、Web Push は配信サービスを通るぶん遅い)。画面の通知を人が閉じた後に Web Push が届くと、もう出ていないので鳴る。
  - **チャイムと OS の通知音を重ねない。** チャイムがオンで鳴り始めたら (0.3 秒待つ)、通知は `silent` で出す (チャイムが代わりに鳴る。音なしで鳴らし直すことは無いので `renotify` は付けない。音なしの形で投げられたら、通知音つきで出し直す)。チャイムがオフか、操作の前で鳴らせないときは、OS の通知音に任せる。読み上げは、音がオンか、OS の通知音で鳴らしたら 0.75 秒おいて始める。`silent` を読まないブラウザでは、チャイムと通知音が重なることがある (確かめたのは Chromium だけ)。
  - **鳴らす判定は Web Push と同じ関数** (`src/lib/notify.ts` の `noticeOf`・`decideDaily`・`decide`)。サーバーの `planSends` (`src/lib/server/notify.ts`) も、画面の `planAlerts` (`src/lib/alert.ts`) も `decideDaily` を呼び、違うのは控えの置き場 (サーバーは購読ごとの `push_log`、画面はメモリ) と中身の値 (サーバーは SHA-256、画面は元の字) だけ。同じ所で鳴ることを `tests/alert.test.ts` で確かめている。訓練・試験・遠地地震・古すぎるものは鳴らさず、続報は重さが上がったときだけ鳴らし直す。
    - 控えに残す重さはどちらも `keptLevel`。続報では大きいほうを残し、解除・取消ではその報の重さに戻す。気象 (`warning:<市町村等>:<種別>`・`warning:special:<府県予報区>:<種別>`) と火山 (`volcano:<火山のコード>`) の tag は出来事ごとに分かれないので、戻さないと控えの残る 30 日の間、解除の後に同じ所でまた出た同じ段の警報・注意報が鳴らない (#210)。府県予報区ごとの tag は、住んでいる地域と関係しない送り先にも終わりを伝える通知を送って戻す (上の「同じ事象で何度も鳴らさない」)
  - **条件は「通知」のダイアログの条件 1 つ** (Web Push と同じ `PushPrefs`)。端末の localStorage (`sonae.alert.prefs`) に持ち、Web Push に登録してあればサーバーにも送る。新しいルートは作らない。
  - **範囲の「現在地」** (2026-11-15 に気象で始め、2026-11-16 に全部の種類へ広げた。持ち主の声「現在地か住んでる地域の注意報警報発表されたら読み上げてほしい」)。地図の現在地 (右下のボタン。6.2。既定はオン) が取れている間、その位置が入る市町村等を端末の中で探し (`#lib/push-client.ts` の `trackHere`。住んでいる地域の「現在地から選ぶ」と同じ面と、同じ表から引いた細分区域・津波予報区)、範囲の「住んでいる地域と現在地」(と「全国」の中の地域の分) を住んでいる地域に加えてそこでも見る。
    - **緯度・経度も現在地の市町村等も、サーバーに送らず覚えもしない** (`alerter.here` はメモリだけ)。Web Push と Webhook は今までどおり住んでいる地域だけ。位置の許可を求めるのは地図の現在地のボタンだけ (地図の現在地がオフなら住んでいる地域だけ)
    - 前の市町村等の面の中にいる間は面を引き直さない (`createHereFinder`。位置は数秒ごとに届くため)
    - 段は住んでいる地域と同じ (上の表)。開いているときだけ別の段にはしない
    - 気象のほかの種類 (緊急地震速報・地震・津波・火山) は、通知の中身が地域で変わらないので、通知は全国と同じ 1 つ (同じ tag) のまま、知らせるかの判定 (`matches`・`decide` の `here`) に現在地を足す。「現在地の」とは付けない
    - 前の「現在地の気象も知らせる」のスイッチ (`sonae.alert` の `here`) はやめた。範囲の選択肢が「住んでいる地域と現在地」と言うので、別のスイッチで現在地だけを切れると食い違う。前の値は読まず、開いたときに消す
    - 通知は住んでいる地域と同じ作り方 (`#lib/notify.ts` の `hereNoticeFor`) で、地域の名前の前に「現在地の」を付ける (「現在地の島根県松江市にレベル3大雨警報」)。同じ府県予報区のほかの市町村の特別警報を言う通知は、見出しが府県予報区の名前になるので「(現在地を含む地域)」を添える。tag は住んでいる地域と同じ形 (`warning:<市町村等>:<種別>`)。読み上げは、地域の文の前に決まった文「現在地の情報です。」を読む (地域は電文の名前で読むため)
    - 現在地が住んでいる地域と同じ市町村等なら、住んでいる地域の通知だけ。記録的短時間大雨情報・竜巻注意情報は 1 つの報に地域が並ぶので、住んでいる地域が対象なら現在地は足さない。どこかの特別警報は住んでいる地域の側の通知 1 つで言う
    - **同じ報が両方に当たったら 1 度だけ鳴らす** (`#lib/alert.ts` の `groupAlerts`)。重いほう (同じなら住んでいる地域) でチャイムと OS の通知を出し、もう 1 つは音なしの通知で並べ、読み上げは 1 つの原稿にまとめる (住んでいる地域を先に、現在地を後ろに「現在地の情報です。」から読み、冒頭の文と見出しを 2 度読まない。`readoutOfAll`)
    - **別の市町村等に入ったら、そこにもう出ているものを 1 度知らせる** (`#lib/alert.ts` の `planEntry`。`alerter.moveHere` が呼ぶ)。画面が持ついまの気象警報・注意報 (府県予報区と種別ごとの最新の報)・まだ終わっていない津波・火山ごとのいまの噴火警報・予報 (`presentEvents`) から、入った市町村等のものを同じ作り方・同じ段で知らせる。津波・火山は全国と同じ通知なので、もう知らせてあれば (控えがあり中身が同じなら) 鳴らさない。報が 6 時間より古くても、出たままなら知らせる。いくつも出ていれば重いほうを鳴らし、ほかは音なしで並べて 1 つの原稿で読む (`groupAlerts`)
      - 同じ中身は控え (メモリ) で 1 度だけ。境目で位置が揺れて行き来しても、戻ってきても鳴らし直さない (中身が変わっていれば、重さが上がったときだけ鳴らし直す。ほかの続報と同じ `decide`)
      - 開いてから初めて取れた市町村等は知らせず、控えだけ付ける (開いたときに出ているものは画面で見える。住んでいる地域と同じ)。現在地は覚えないので、こうしないと開き直すたびに鳴る。地図の現在地を切ってから別の所で入れ直したときは、入ったものとして知らせる
    - **出た市町村等の通知も、解除・続報で置き換える** (`planAlerts` の `left`)。出た市町村等は新しい順に 20 までメモリに持ち (`alerter.left`)、そこで知らせたもの (控えのある tag) だけ、届いた報で中身が変われば同じ tag で音なしで置き換える (解除なら「…の警報・注意報の解除」)。もういないので「現在地の」は付けず、重さが上がっても鳴らし直さない (入り直したら上の決まりで知らせる)。画面に通知が残っていなければ何もしない (今までの `replace`)。Web Push は現在地を使わないので、置き換えは開いている画面の中だけ
  - **音と読み上げは端末ごとに 1 つの選択で、「オフ」/「通知音だけ」/「読み上げも」。既定はオフ** (`sonae.alert` の `sound`・`speech`。`#lib/alert.ts` の `AUDIO_MODES`)。選んだときと「試しに鳴らす」で一度鳴らす。「読み上げも」は通知音 (チャイム) の後に 0.75 秒おいて読む (前と同じ)。OS の通知のスイッチは別のまま。
    - 2026-11-16 に、2 つのスイッチ (「音を鳴らす」「読み上げる」) から替えた (持ち主の決定)。読み上げだけで通知音を鳴らさない形は選べなくなる。保存済みの値は、音と読み上げのオン → 「読み上げも」、音だけ → 「通知音だけ」、読み上げだけ (音はオフ) → 「読み上げも」(通知音も鳴る)、どちらもオフ → 「オフ」と読み (`parseAlertSettings`)、開いたときに読み替えた形で書き直す
    - 読み上げに対応しないブラウザ (VOICEVOX も端末の読み上げも使えない) では、「読み上げも」を「(このブラウザは対応していません)」と添えて選べなくする。前に選んであったときは選んだままにして、下に「このブラウザは読み上げに対応していないため、通知音だけを鳴らします」と出す (鳴らすのはチャイムだけ)
  - **音源は自作** (`src/lib/chime.ts`)。880 Hz から 660 Hz へ下がる 2 つの音を、その場で WAV (16 ビット・モノラル・22.05 kHz、0.7 秒) に組む。ファイルも外の音源も持たない。
  - **自動再生の制限:** ブラウザは、人がページを一度操作するまで音を出させない。最初の操作 (`pointerup`・`keydown`・`touchend`) の中で `<audio>` と読み上げを無音で一度動かし、後から鳴らせるようにする (iPhone・iPad の Safari は、操作の中で一度動かしたものでないと鳴らせない)。音か読み上げがオンなのに鳴らせない間 (`navigator.userActivation` がまだ立っていない、または再生を断られた) は、画面の上の端 (広い形はヘッダーのすぐ下、スマホの形はいちばん上) に帯を出す。何が止まっていて何は届くかを言い (「音と読み上げが止まっています」「押すと、警報を音と読み上げで知らせます」。通知の許可があれば「通知は出ます。音と読み上げも聞くなら押してください」。`#lib/alert.ts` の `mutedText`)、右に「音を出す」。帯のどこを押しても鳴らせるようになる。帯は中身に重ねず押し下げるので、地図・一覧・dock を隠さない。淡い面に注意の色のアイコンと見出しで、地は塗らない (6.2 の通り、塗るのはいま出ている緊急地震速報 (警報) の、詳しい内容の先頭の箱と dock の 1 行だけ)。出るときに一度だけ上から滑り込み、アイコンは 3 回だけ脈打って止まる (6.3)。2026-11-15 に、ヘッダーと dock の小さい「音を出す」から替えた (持ち主の声「ミュート中は解除ボタンをもっと目立つようにしてほしい」)。 ただし、開いたときに自動再生を許しているブラウザ (Firefox は `navigator.getAutoplayPolicy`、ほかは作った `AudioContext` が `running` か で見る。Chrome・Edge はアプリとして入れたとき、Firefox・Safari・Edge はサイトの設定で許したとき) では、押さなくても鳴らせるので出さない (読み上げがオンで VOICEVOX が使えないときは除く。端末の読み上げは操作の前だと断られることがあり、断られても分からないため)。鳴らすのに失敗したら出す。
  - **裏のタブで止めない** (2026-11-16。持ち主の声「edge で裏側にしてると音声流れないことある。開くと音声流れる」)。Edge の「スリープ中のタブ」(既定は 2 時間使わなかった裏のタブ。省エネ機能 (旧称: 効率モード) では 30 分か 5 分。[Microsoft のサポート](https://support.microsoft.com/ja-jp/topic/learn-about-performance-features-in-microsoft-edge-7b36f363-2119-448a-8de6-375cfd88ab25)) と Chromium の止める仕組み (freezing) は、裏のタブの JavaScript をタイマーごと止める。SSE で届いた報はタブの中に溜まるだけで、前に出して動き出したときに遅れて鳴る。
    - Edge の [Sleeping Tabs FAQ](https://techcommunity.microsoft.com/t5/articles/sleeping-tabs-faq/m-p/1705434) は、眠らせないタブに「Web Lock か IndexedDB のトランザクションを持っている」「音を鳴らしている」「設定の除外の一覧にある」を挙げる。Chromium の止めない理由 (`components/performance_manager/public/freezing/cannot_freeze_reason.h`) にも `kHoldingWebLock` と `kAudible` がある。
    - そこで、OS の通知・音・読み上げのどれかがオンの間は、Web Lock (`sonae.awake`、共有) を 1 つ持ち続ける (`src/lib/awake.ts`。`alerter.start` が持ち、オフにしたら離す)。共有なのでタブが幾つあっても全部が持て、鳴らす控えの `sonae.alert:` のロックとも名前が別で交わらない。ロックそのものは CPU も電池も使わない (止められなくなるぶん、裏のタブでもタイマーと SSE が動き続け、その分は使う。オフにしたタブは今までどおり眠る)。
    - ただし、Edge の今の説明 ([Microsoft のサポート](https://support.microsoft.com/ja-jp/topic/learn-about-performance-features-in-microsoft-edge-7b36f363-2119-448a-8de6-375cfd88ab25)) の眠らせないタブの並びからは Web Lock が消えている。ロックで足りるとは言い切れないので、パソコンの Edge (UA に `Edg/`) で知らせるものがオンのときは、「通知」の「開いているとき」の説明の下に一言を添え、設定の除外の一覧に足してもらう (`#lib/awake.ts` の `EDGE_SLEEP_HINT`)。除外の一覧は Edge の説明でも眠らせないと書かれている。
    - 無音の音を流し続ける手は採らない。Chromium は本当に音が出ているタブだけを「音を鳴らしている」とみなす (消音の `<audio>` や無音では足りない) ので、聞こえないほど小さな音を流すことになり、タブにスピーカーの印が出続け、音の処理で電池も使う。
    - 裏のタブでは、チャイムから読み上げまでの 0.75 秒のタイマーは 1 秒刻みに丸められる (隠れたページのふつうの間引き)。強い間引き (1 分に 1 度) はタイマーから続けて張ったタイマーだけに掛かり、SSE を受けた中で張るこのタイマーには掛からない。
    - 残ること: メモリが足りないときに Edge がタブを捨てる (discard) のは、このロックで止められるとは書かれていない。捨てられたタブは前に出すと読み直すので、捨てられていた間の報は鳴らない (一覧には出る)。確実にするなら、上の一言のとおり Edge の設定 (「システムとパフォーマンス」の「パフォーマンス」にある「これらのサイトを常にアクティブに保つ」。`edge://settings/system`) に sonae を足す ([ui.md](ui.md))。確かめたのは文書と Chromium のソースまでで、Edge の実機で裏のタブが鳴るかはまだ確かめていない。閉じている・裏でも確実に届けるのは Web Push ([push.md](push.md))。
  - タブを幾つも開いていても、同じ通知は 1 つのタブだけが鳴らす (Web Locks で 5 秒持つ。鳴らせないタブはロックを取らない)。Web Push の通知と二重に鳴らさない決まりは上の「Web Push と二重に鳴らさない」。
  - **読み上げは人が途中で止められる** (2026-11-17。持ち主の声「読み上げ中に読み上げ中断ボタンほしい」)。読んでいる間 (`alerter.reading`。最初の文の音を取りに行っている間も含む) だけ地図の左下 (スマホの形は dock のすぐ上の左) に「読み上げ中断」を出し、押すか Esc で `alerter.stopReading` を呼ぶ。読み上げの回数を進めて残りの文へ進ませず、VOICEVOX の `<audio>` を止め、端末の読み上げを `speechSynthesis.cancel()` で止める。
    止めるのはいまの読み上げだけで、音と読み上げの設定は変えない (次に届いた報はいつもどおり鳴らして読む)。チャイムから読み始めるまでの 0.75 秒の間は、まだ読んでいないので出さない。通知の窓の「試しに鳴らす」の間は窓が前にあるので、窓の外のボタンは押せない (Esc は窓を閉じる)。
  - **読み上げ始めた報の詳しい内容を開く** (2026-11-15。持ち主の声「情報読み上げ中は詳細開いてほしいかも」)。音と読み上げが「読み上げも」で、事象の原稿を読み始めるときに `alerter.onread` を呼び、画面がその報を開く (一覧の行を押したときと同じ URL。地図はその報へ寄る)。読み上げがオフで音か OS の通知だけのときは開かない。人がほかのものを見ている・窓を開いている・出ている緊急地震速報を見ている (同じ地震の地震情報なら替える) ときに切り替えるかと、履歴の積み方は [ui.md](ui.md) の「自動で開く」。読み上げは 1 つのタブだけがするので、開くのもそのタブだけ (緊急地震速報は読み上げに関わらず、どのタブでも開く)

#### 読み上げ (VOICEVOX)

**読み上げの声は、sonae と一緒に動かす VOICEVOX のエンジンで作る。** `docker compose up` でも Helm chart (`charts/sonae`) でも、sonae と VOICEVOX のコンテナが一緒に起き、sonae は `VOICEVOX_URL` (`http://voicevox:50021`) でつなぐ。
VOICEVOX が止まっている・つながらないときは、画面が端末の読み上げ (`speechSynthesis`) で同じ原稿を読む。

- **エンジンの選び方 (2026-11-14):** 日本語の自然さ、CPU だけでの速さ、地名の読みを直すユーザー辞書の API、公式の CPU 用の Docker イメージ、クレジットを出せば無料で使えること、の 5 つで比べ、VOICEVOX にした。
  Kokoro・MeloTTS・Piper・GPT-SoVITS・Fish Speech・CosyVoice・Chatterbox・F5 は、日本語が弱い・GPU が要る・読み始めるまでが長すぎる・ライセンスが合わない、のどれかで外した。
- **sonae のイメージに入れず、別のコンテナにする理由** (公式の文書で確かめた):
  - ライセンス: VOICEVOX ENGINE は LGPL-3.0 (と別の許諾の二重)、VOICEVOX CORE は MIT だが、エンジンが読む VOICEVOX の ONNX Runtime と音声モデル (VVM) は独自の利用規約で、逆コンパイル・リバースエンジニアリングを禁じている ([VOICEVOX ONNX Runtime 利用規約](https://github.com/VOICEVOX/voicevox_resource/blob/main/onnxruntime/README.md)・[音声モデル利用規約](https://github.com/VOICEVOX/voicevox_vvm/blob/main/TERMS.txt))。AGPL-3.0 の sonae と 1 つのイメージにまとめて配ると、自由なソフトウェアの条件の無いものを sonae として一緒に配ることになる。公式のイメージを別に動かし HTTP で話せば、sonae のイメージは AGPL のままで、VOICEVOX の部分は VOICEVOX の配布物をそのまま使う形になる。
  - 大きさ: 公式の CPU のイメージは 2.4 GB (0.26.1、手元の `wslc image list`)。sonae のイメージ (distroless、約 120 MB) が 20 倍になり、sonae を直すたびの公開と入れ替えが重くなる。エンジンの更新は sonae と別の周期 (Renovate) でする。
  - 分離: 合成は CPU を数秒使い切り、モデルを読んだ声ごとにメモリを使う (手元で 3 人を読んで 1.9 GiB)。別のコンテナなら CPU とメモリの上限を別に掛けられ、エンジンが落ちたりメモリの上限で止められたりしても、受信・SSE・Web Push は止まらない。
- **流れ:** サーバーは事象を受けたら (Broker の配信と同時に)、読み上げの原稿 (`src/lib/readout.ts` の `readoutOf`) を作り、変わる文を**選んである声 1 つで**合成してメモリに持つ (`src/lib/server/voicevox.ts`)。
  画面も同じ原稿を自分で作り、文ごとに `POST /api/speech` (`{ text }`、ログインが要る。声は送らず、サーバーが選んである声で返す) で WAV を取って順に鳴らす。取れない文は端末の読み上げで読む。
  - 合成できるのは、決まった文と受けた事象の原稿の文だけ (ほかの文は 404。エンジンに勝手な文を読ませない)。
  - 音は (声, 文) の組でメモリに 64 MB まで持ち、古いものから捨てる。選んである声の決まった文は捨てない (前の声の決まった文は、ほかと同じく古いものから捨てる)。合成は 1 つずつ順に頼み、事象の文を下ごしらえより先にする。
  - つながりは 1 分ごとに確かめ、つながり直したら声の一覧と辞書を読み直して、決まった文を合成し直す。
- **すぐに読み始める:** 冒頭の決まった文 (`OPENINGS`。「緊急地震速報です。強い揺れに警戒してください。」など 17 文) と試しの文と、受信が切れた・戻ったときの文 (`CONNECTION`。2.3) と、現在地の情報の前に読む文 (`HERE`。「現在地の情報です。」) は、起動したとき・つながり直したとき・声を替えたときに、選んである声で合成しておく。変わる文 (地域・震源) は、決まった文を読んでいる間に合成する。
  - 手元の測定 (2026-11-14、Ryzen 5 5600X、エンジンに 2 CPU・スレッド 2): 4 秒ほどの文の合成に 1.5〜2 秒、12 秒ほどの文に 4〜6 秒 (実時間の 0.4〜0.5 倍)。
    緊急地震速報 (警報) は受けてすぐ冒頭を鳴らせ (取りに来てから 1 ms。持っている音を返すだけ)、2 度目の冒頭を読み終える 8.2 秒より前に、地域の文 (11 秒) が 4.6 秒で、震源の文が 5.3 秒で揃った。起動して既定の声の冒頭 11 文がそろうまで 13 秒。
  - 家のクラスタの Z440 では測っていない (CPU が遅ければ合成も遅くなる)。そのため chart は VOICEVOX の CPU を絞らず (limits 無し)、合成のスレッドにマシンの論理 CPU の全部を使わせる (`voicevox.cpuThreads` の既定 0。8 章)。
- **声を選ぶ:** 「通知」のダイアログの「音と読み上げ」で「読み上げも」を選んでいて VOICEVOX が使えるとき、その下に声の選択肢 1 つを置く。声を試すのは「開いているとき」の「試しに鳴らす」1 つで、いまの選択どおりに鳴らす (通知音だけなら音、読み上げもなら音の後に選んである声で試しの文。2026-11-16 に「試しに聞く」をまとめた。持ち主の声「2 つ並んでいて分かりにくい」)。選択肢は動いているエンジンの `/speakers` から作り、名前とスタイルを並べる (コードには書かない)。
  - **声はこの家で 1 つで、サーバーに持つ** (2026-11-15。持ち主の声「声は端末ごとじゃなくてサーバ側に保存して」)。DB の `settings` (2.5) の `voice` (VOICEVOX のスタイルの id) に、替えた人 (IdP の sub) と一緒に持つ。まだ選んでいなければ既定の声 (剣崎雌雄)。選んである声がエンジンの選べる声に無くなったら (エンジンを替えた・規約で外した)、既定の声で読む。
    前は端末ごとに `sonae.alert` の `voice` に持ち、サーバーは端末が使う声を「使われている声」として `voices.json` に覚えて声ごとに合成していた。端末ごとに違う声を選ぶと合成が声の数だけ増え、最後の声は最初の文が鳴るまで遅れた (本番では 4 つの声が使われていた)。端末の `voice` は読まずに消し、サーバーの `voices.json` も読まずに消す。
  - 選んだらすぐ保存する (`PUT /api/speech`、`{ voice }`。保存のボタンは無い)。保存している間は選択と、「読み上げも」のときの「試しに鳴らす」を止める (前の声で試しの文を読まないように)。窓には「声はこの家の全部の端末で同じになります」と書く。音と読み上げの選択は、これまでどおり端末ごと。
  - **替えられるのは、ログインした人なら誰でも。** 通すロールは `OIDC_ROLE` の 1 つだけで (2.6)、ログインした人はみな同じロールを持ち、管理の役割を見分ける仕組みが無いため。家族と共有するのは家族が使う声を決めるためでもあるので、家族の誰が替えてもよいとした。
  - API は hooks のログインの判定の内側にあり (無ければ 401)、本文は `application/json` だけ受ける (ほかは 415)。別のオリジンから JSON で送るにはプリフライトが要り、sonae は答えないので通らない。フォームの形は SvelteKit が別のオリジンから受けない。セッションの Cookie も `SameSite=Lax`。
  - 替えたら、サーバーは新しい声で決まった文をすぐ合成し直し、開いている全部の画面に SSE の `event: voice` (`{ voice }`。番号は付けない) で知らせる。つないだとき (張り直したときも) にも送るので、切れていた間に替わっても揃う。画面は 5 分ごとにも `GET /api/speech` を読み直す。
  - 替えた直後の数十秒は、新しい声の冒頭がまだ合成できていないことがある。そのときは合成を待つ (前の声で代わりに読まない。鳴る声とクレジットを 1 つにするため)。
  - エンジンは一度読んだ声のモデルを手放さない (外す API が無い) ので、何度も替えるとエンジンのメモリが増える。メモリの上限で止められたら、エンジンは入れ替わり、sonae がつながり直して選んである声で決まった文を合成し直す。
  - 選べるキャラクターは、利用規約を読んで「クレジットを出すだけで、会社が公開するアプリの中で使える」と確かめたものだけ (`src/lib/voices.ts` の `ALLOWED_SPEAKERS`、2026-11-14 にエンジン 0.26.1 の 44 人を読んだ)。エンジンが新しく足したキャラクターは、規約を読んで足すまで出さない。
  - 外したもの: 企業が関わる利用・商用利用に事前の確認や申請が要るもの (青山龍星・もち子さん・後鬼・No.7・ユーレイちゃん・猫使アル・猫使ビィ・夜語トバリ・暁記ミタマ・里石ユカ・ぞん子)、法人の利用を許していないもの (Voidoll)、詳しい規約の本文が見つからないもの (琴詠ニア)。sonae は会社 (danything) が公開し、使う人が会社のこともあるので、個人の利用だけを許す規約では足りない。
  - 規約は予告なく変わる。エンジンを上げるときに、足されたキャラクターと規約の変わったものを読み直し、下に記録する。
    - 2026-11-14 (エンジン 0.26.1): 44 人のキャラクターの規約を読み、上の選べるものと外したものに分けた。
    - 2026-11-19 (エンジン 0.26.2。2026-11-14 公開): 変わった点は無い。0.26.2 の変更は Windows 版で合成できないことがある問題の修正と、依存パッケージの更新 (セキュリティの更新) だけで、規約・LICENSE・話者には触れていない。
      [VOICEVOX の利用規約](https://voicevox.hiroshiba.jp/term/) (サイトのソースの最後の変更は 2024-12-23)・[ONNX Runtime 利用規約](https://github.com/VOICEVOX/voicevox_resource/blob/main/onnxruntime/README.md) (2025-02-16)・[音声モデル利用規約](https://github.com/VOICEVOX/voicevox_vvm/blob/main/TERMS.txt) (2026-10-31)・voicevox_resource の `character_info` (2026-10-31 の 0.26.1 向けの変更が最後。44 人) は、前に読んだときから変わっていない。
      既定の声の剣崎雌雄は、[規約の全文](https://frontier.creatia.cc/fanclubs/413/posts/4507) (2022-06-30 の投稿。改定日の記載は無い) を最後まで読んだ。「VOICEVOX:剣崎雌雄」の表記で商用・非商用に使え、申請・報告は要らない (ハッシュタグで知らせてほしいという任意のお願いだけ)。作者はいつでも規約を変えられるとある。
- **既定の声は剣崎雌雄 (ノーマル、スタイルの id 21)。** 公式の紹介は「安心感のある落ち着いた声」で、警報を落ち着いて伝えるのに合う。利用規約は「VOICEVOX:剣崎雌雄」と書けば商用・非商用で使え、申請や報告は要らない ([規約](https://frontier.creatia.cc/fanclubs/413/posts/4507))。まだ画面で選んでいないときは、いつもこの声で読む (`src/lib/voices.ts` の `DEFAULT_SPEAKER`)。
  前は環境変数 `VOICEVOX_SPEAKER` (スタイルの id) で替えられたが、声は画面で選べる (サーバーの DB に持つ) ので、2026-11-16 に環境変数をやめた (設定を減らす持ち主の決定)。入れたままでも読まない。
- **クレジット:** VOICEVOX で読み上げている端末では、「出典と注意」の窓の出典に、この家で選んである声を「VOICEVOX:<名前>」で出す (鳴る声はそれ 1 つ)。読み上げがオフか、VOICEVOX につながっていないときは出さない。
- **原稿 (`src/lib/readout.ts`):** 冒頭の決まった文のあと、変わる所を 1 文ずつ。気象庁の文 (見出し・津波の付加文・噴火速報の見出し) は言い換えずに読む。取消・解除は読まない (鳴らさないので)。
  - 緊急地震速報 (警報): 冒頭の文を 2 度読み (テレビ・ラジオの伝え方と同じ)、「強い揺れに警戒が必要な地域は、〜です。」「震源は〜です。」。**予想震度と到達予想時刻は読まない** (5 章)。
  - 緊急地震速報 (予報): 「緊急地震速報、予報です。」「震源は〜、規模はマグニチュード〜と推定されています。」。仮定震源なら「震源と規模は仮のものです。」。
  - 震度速報: 「震度速報です。」「〜ごろ、最大震度〜を観測する地震がありました。」と、震度の高いほうから 2 つの段の地域。
  - 震源・震度に関する情報: 「地震情報です。」・時刻と震源・深さと M・最大震度・2 つの段の地域・津波の付加文 (「この地震による津波の心配はありません。」など、気象庁の文のまま)。
  - 津波: 区分ごとの冒頭 (「大津波警報が発表されました。」など)、**大津波警報と津波警報の地域を先に全部読み**、気象庁の見出し、津波注意報の地域 (10 を超えたら「など、N の地域」)。
  - 南海トラフ地震臨時情報・関連解説情報・後発地震注意情報: 冒頭の文・情報の名前と種類・気象庁の見出し。噴火速報: 「噴火速報です。」と気象庁の見出し。噴火警報: 「火山の情報です。」・情報の名前・見出し。
  - 気象の特別警報: 「気象の特別警報です。」「<府県予報区>に、<種類の名前>が出ています。」「対象の市町村は、〜です。」。住んでいる地域がその府県予報区にあれば、その市町村等の文 (下) も続け、気象庁の見出しで終える。
  - 住んでいる地域の気象警報・注意報: 段ごとの冒頭 (「気象の危険警報です。」「気象の警報です。」「気象の注意報です。」)、「<市町村>には、<種類の名前>が出ています。」(段の高い順。「レベル4土砂災害危険警報」のように電文の名前のまま)、気象庁の見出し。
    土砂災害警戒情報はいまはレベル 4 の土砂災害危険警報 (2.8) なので、危険警報の冒頭で読む。市町村は住んでいる地域の名前ではなく電文の市町村等の名前で読む (端末ごとに違う名前ではサーバーが前もって合成できないため)。サーバーは電文に出てくる市町村等ごとの文を通す文に入れ (`readoutCandidates`)、合成は画面が取りに来たときにする
  - 記録的短時間大雨情報: 「記録的短時間大雨情報です。」と気象庁の見出し (時刻・地域・雨量は見出しの文のまま)。竜巻注意情報: 「竜巻注意情報です。」と気象庁の見出し、見出しに無ければ「この情報は〜まで有効です。」(電文の有効期限)。
  - **気象の予想は作らない** (5 章)。読むのは電文の種類の名前・見出し・有効期限だけ。
  - これから足す種類は、`readoutOf` の `switch` に種類の分を足す。足すまでは、通知の見出しと本文を読む。
  - 地域は 10 まで並べ、超えたら「など、N の地域」と言う (津波の警報の地域は縮めない)。読み上げるだけの文なので、半角の数字と日本語の間に空白を入れない。
- **地名の読み:** VOICEVOX が読み違える地名は、ユーザー辞書 (`src/lib/server/readings.ts`) で直す。エンジンは辞書をコンテナの中に持つので、sonae がつながるたびに足りない語を足す (優先度 10)。
  気象庁のコード表の震央地名 (343)・細分区域 (194)・津波予報区 (70)・活火山 (111) を `accent_phrases` に通して出たカナを見て、読み違えた 43 語を足した (渡島 → トトオ、後志 → シリベ、平野部 → ヒラノブ、沖縄県宮古島 → ミヤフルトオ、新潟県中越 → ナカコシ など)。足した後に、すべてがここの読みになることを確かめた。日向灘・釧路沖は辞書なしで正しく読む。
  アクセントは聞いて確かめていない (読みのカナだけを確かめた)。北方領土と海の火山のいくつか (茂世路岳・小田萌山・指臼岳・海形海山・若尊) の読みは、気象庁の読みと突き合わせていない。

### 2.6 認証

ロールを持つ人だけが開けるようにする。ほかのアプリと同じく、パスワードは持たず OIDC でログインする。

- **OIDC のクライアントは自前** (noren の `src/lib/server/oidc.ts` と同じ形: discovery・認可コード + PKCE・素の fetch と WebCrypto で id_token の署名・発行元・宛先・期限・nonce を確かめる)。ライブラリは足さない。
- **IdP は doany.io の Entra ID の共用のアプリ登録 `Main`。新しくアプリは登録しない。** ashi と同じく、誰が使えるかはエンタープライズ アプリケーションのロールの割り当てで決める。
  通すロールは `OIDC_ROLE` (**既定は `admin`**。まずは持ち主 1 人)。家族と共有するときは、家族を Entra に招き (B2B のゲスト)、このロールを割り当てる。`admin` を家族に渡したくなければ、family 用のロールを足して `OIDC_ROLE` を替える。どちらもコードの変更は要らない (2026-11-16 に確かめた)。
  リダイレクト URI・環境変数の表・家族と共有する手順は [entra.md](entra.md)。
- issuer・client id・secret の 3 つが揃わず、信頼するネットワーク (下) も書いていなければ、画面は開かない (`/health` だけ答え、ほかは 503)。信頼するネットワークだけを書いたときは、その外からは 403。手元の開発だけ、`AUTH_DISABLED=1` でログインを飛ばせる (本番の `NODE_ENV=production` では効かない)。
- **信頼するネットワーク (`TRUSTED_NETWORKS`) の中からは、ログインなしで通す** (`src/lib/server/trust.ts`。denpa と同じ考え方)。1 行で入れたセルフホストの 1 台目が、IdP を用意しなくても開けるように。
  - 書いていなければ誰も通さない (いままでどおり)。本番 (家の Talos のクラスタ) と chart の既定は書かず、OIDC だけ。インストーラ (install.sh・install.ps1) は家の LAN とそのマシンのブラウザを書く ([install.md の「ログイン」](install.md#ログイン))
  - **アドレスに加えて名前も見る** (DNS リバインディング除け)。通すのは IP の直書き・localhost・ドットの無い名前・家の中だけの名前 (`.localhost`・`.local`・`.lan`・`.home.arpa`・`.internal`)・`ALLOWED_HOSTS` だけ
  - 接続元は、直の相手が前段 (`TRUSTED_PROXIES`) のときだけ `X-Forwarded-For` を右から読む。adapter-bun の `ADDRESS_HEADER` を設定していたら、信頼するネットワークは使わない (誰でも名乗れるため)
  - 通した人は全員 1 人の利用者 (`trusted-network`、「家のネットワーク」) として扱う。**その中の誰でも、読み上げの声・通知の条件・Web Push の購読・Webhook を変えられる**
  - OIDC と一緒に使える (外の人はログイン、中の人はログインなし)。OIDC が無いとき、外の人には 403 と接続元を返す
  - **ログインなしの経路では、ほかのサイトから送らせた書き込みを断る** (`crossSiteWrite`)。Cookie の SameSite が効かず、LAN の人が開いた悪いサイトが `http://<LAN の IP>:3030/api/...` へ送らせることができるため。
    GET・HEAD・OPTIONS 以外は、`Sec-Fetch-Site` が same-origin (か none) のときだけ通す。`Sec-Fetch-Site` を付けない古いブラウザは `Origin` が自分のオリジンのときだけ。どちらも無い、ブラウザでない道具は通す
- **セッションは DB に持ち、180 日で、使うたびに延ばす。** 何度もログインさせない。**ID は Cookie にだけ生の値を置き、DB には SHA-256 (16 進) を持つ** (DB が漏れても、そのままでは成りすませない)。Web Push は購読してあればセッションが切れても届く。
- ログイン無しで開けるのは `/auth/login`・`/auth/callback`・`/health`・Service Worker と Web アプリのマニフェストだけ。`/auth/logout` は POST だけ。

### 2.7 長周期地震動と推計震度分布

調べた資料 (2026-11-14): [公開する電文の一覧](https://xml.kishou.go.jp/xmllist.pdf) (2026/8/6 現在)・地震火山関連 解説資料 (`jmaxml_20261104_Manual(pdf).zip` の「地震火山関連_解説資料」Ⅱ.(ⅰ)ウ.(キ))・サンプル電文 (`78_01_01_240613_VXSE62.xml`)・気象庁の[情報カタログ (地震)](https://www.data.jma.go.jp/suishin/cgi-bin/catalogue/make_product_page.cgi?id=Jishin)。

**長周期地震動に関する観測情報 (VXSE62) は公開のフィード (地震火山) に載る。受けて、地震に添えて出す。**

- 中身: 地震の諸要素 (発生時刻・震源・M)、全国の最大震度と最大長周期地震動階級 (`MaxLgInt`、0〜4)、情報の種類 (`LgCategory`、1〜4)、都道府県・地域 (地震情報／細分区域のコード)・観測点ごとの階級と震度、観測点の絶対速度応答スペクトル (`Sva`)、気象庁の観測情報のページの URI。続報は観測の全体を持ち直す (地域が足されたり階級が直されたりする。`Revise`)。取消は内容部が無い。
- モデルは `LongPeriod` (`src/lib/model.ts`)。鍵は地震識別番号 (訓練・試験は後ろに `-training` / `-test`)。新しい報で置き換え、古い報は捨て、取消は前の中身を残して印を付ける (`mergeLongPeriod`)。SSE のイベントの種類は `longperiod`。
- 画面: 一覧の種類 (チップ) は増やさない。長周期地震動は地震情報の後に出る観測の詳しい内容なので、同じ地震識別番号の地震に添える。地震の一覧の行の補足に「長周期地震動階級3」(階級 1 以上のとき)、地震の詳しい内容に「長周期地震動」の節 (地域を階級ごとに、観測点は畳んで、気象庁の観測情報のページへのリンク)。
- 地図: 層「長周期地震動階級」(ほかの層と同じくいつも出す)。選んだ地震で階級 1 以上の地域を、階級の色の太い枠で囲む (震度は面の色なので、枠で分ける)。色は気象庁の配色の指針に長周期地震動階級の表が無いので、表 2-1 の基本配色の上から 4 つを階級 4 から当てた (階級 4 `180,0,104`・3 `255,40,0`・2 `255,153,0`・1 `250,245,0`。自分で決めた割り当て)。ラベルにはいつも「階級3」と字でも書く。
- 知らせない (Web Push も、開いているときの音も)。同じ地震は地震情報 (震度) で知らせている。
- 長周期地震動の**予測** (緊急地震速報の `ForecastLgInt`) は公開のフィードに無く、地点の予想にあたるので出さない (5 章)。

**推計震度分布は入れない。** 公開の防災情報 XML に推計震度分布の電文は無い (公開する電文の一覧にも、解説資料の地震の電文にも無い)。

- 情報カタログでは、格子のデータ「推計震度分布図作図用データ」は 1 km メッシュ (IXAC40) と 250 m メッシュ (IXAC41) の BUFR (格子) で、提供は気象業務支援センターだけ (配信の契約が要る)。誰でも見られるのは気象庁ホームページの「推計震度分布図」の画像 (PNG。全国で震度 5 弱以上を観測した地震) だけで、機械で読む約束 (仕様と提供の保証) が無い。
- 入れるなら、支援センターの BUFR を受けて、格子の値 (気象庁が推計した震度) を震度の色の画像にし、MapLibre の `image` の source で、格子の範囲 (緯度・経度) に合わせて重ねる。格子の値をそのまま色にし、補間や足し引きはしない (5 章の「観測値は気象庁の値をそのまま出す」)。ホームページの PNG を重ねるやり方は、範囲の座標が文書に無く、画像の作りが変わると崩れるので採らない。
- 推計震度分布は気象庁が観測から推計したもので、地点の震度の予想 (予報業務) ではない。出すときも、気象庁の推計であることと出典を書く。

  - [RTS の文書](https://exptech.dev/docs/api/stream/rts/): token は要らない。値は観測点ごとの計測震度 `i` (小数 1 桁。信号が無ければ -3.0) を読み、`pga` から震度を作らない。`stations` は直前 5 秒に送ってきた観測点だけで、無い観測点は「届いていない」で震度 0 ではない
- **受け方** (`src/lib/server/sources/trem.ts`。ほかの情報源と同じ Source の形で、壊れても他に響かない):
  - SSE `https://api.lb.exptech.dev/api/v1/trem/sse/rts` を 1 本。`data` は base64 の gzip の JSON (`Bun.gunzipSync` で開く)
  - **既定の sleep の形でつなぐ。** 地震の間 (どこかの観測点に `alert` が付いている間) だけ 0.5 秒ごとにスナップショットを送り、ふだんは 60 秒ごとの `: ping <秒>` だけ。live の形 (`?mode=live`) は 0.5 秒ごとに全部の観測点を送り、1 秒に約 2KB (1 日に約 190MB) になる。文書が「地震の間のデータだけ要るなら sleep」と勧めていて、sonae も地震の間の揺れだけを見せればよいので sleep にした。ふだんの観測点は表から灰色の点で置く
  - 量の目安: ふだんは 1 分に 1 行 (約 20 バイト)。地震の間は 1 秒に 2 つのスナップショット (1 つ 1〜2KB)。観測点の表 (CSV、約 7.6KB、使っている観測点は 136) は起動したときと 1 日に 1 回で、変わっていなければ 304
  - 張り直し: 90 秒何も来なければ切れたとみなす。3 秒から倍々、上限 60 秒に 1 秒までの揺らぎ (文書の「等 3 秒後重連；連續失敗時加倍等待（3、6、12…最多 60 秒）並加上隨機延遲」)。429 は 60 秒より短く張り直さない。60 秒つながっていたら間隔を戻す
  - 観測点の表 (`https://static.core-tnn1.exptech.dev/resource/station`、取れなければ `core-tyo1`) は CSV で、`work` が 1 の観測点だけを使う。ETag はノードごとなので、取ったノードの ETag だけをそのノードに送る
  - 読めないスナップショットは捨て、受信の状態の直近のエラーに出す。続いても知らせるのは最初の 1 回と、また読めたとき (エラーを消す) だけ (地震の間は 0.5 秒ごとに来るため)
  - 環境変数 `SONAE_TREM=off` で切れる (状態は `off`。商用で立てるのに ExpTech の同意が無いとき)
- **配り方:** 受けたスナップショットは DB に入れず、Broker にも流さない (`SonaeEvent` にしない)。メモリの `RtsBoard` にいまの値だけを持ち、開いている画面の SSE (`/api/stream`) に `event: rts-stations` (観測点の位置。つないだときと表が替わったとき) と `event: rts` (位置の分かる観測点の [経度, 緯度, 計測震度]。受けるたび) を番号なしで送る。埋め直しはしない (いまの値だけに意味がある)。つないだときは 10 秒以内に受けた値だけを送る
- **画面:** 地図の観測点の小さな点 (`#lib/rts.ts` の `rtsFeatures`)。ふだんは控えた灰色で、値が 0.5 以上の観測点は気象庁の震度の階級の境で切った震度の色で塗り、少し大きくする (大きい値ほど上)。10 秒 (`RTS_STALE_MS`) 次が届かなければ灰色に戻す。震源の丸より下に置き、押しても何も出さない。一覧には出さない。
  音・読み上げ・OS の通知・Web Push・Webhook では知らせない (この値は `alert.ts`・`notify.ts` に届かない)。色の意味と非公式であることは「出典と注意」の「地図の見方」に書く
- **出典:** 「出典と注意」の窓に、授權頁の書き方のままの文と、非公式で中央氣象署の発表を優先する旨・知らせには使わない旨を日本語で出す (`#lib/notice.ts` の `CREDITS`)。地図の source の `attribution` にも同じ文。受信の状態には「ExpTech TREM (台湾の観測点の揺れ・非公式)」と並ぶ

### 2.10 有志の観測点の揺れ (Wolfx SeisJS)

**Wolfx SeisJS (有志がブラウザやスマートフォンで動かす観測点のいまの揺れ) を、地図の点の色だけに使う** (持ち主の決定、2026-11-17)。
扱いは台湾の TREM-RTS (2.9) と同じで、知らせには使わない。

- **使ってよいこと:** 家庭のセルフホストで家族の地図に出すのは個別の許諾が要らないと、2026-11-17 に Wolfx から答えをもらった (1 章の「情報源の判断」。メールは持ち主の OneDrive に置いた)。公開のサービス (SaaS) での使い方は聞いていない
- **観測点:** 2026-11-17 に測ると、公開の観測点は 7 か所 (重慶のあたり 3・昆明・広州・オルドス・台南) で、日本には無い。持ち主は、それでも既定で入れると決めた。観測点が増えれば、そのまま地図に増える
- **プライバシー:** [SeisJS のプライバシー通知](https://seis.wolfx.jp/PrivatePolicy/ja_JP) で、公開のデータには観測点の UUID・地域・緯度経度が入り、持ち主は位置を隠すよう頼める (`private`)。sonae は `private` の観測点を出さず、地域の名前も出さない
- **受け方** (`src/lib/server/sources/seisjs.ts`):
  - WebSocket `wss://seisjs.wolfx.jp/all_seis` を 1 本。張り直しは P2P・Wolfx と同じ `runSocket` (1 秒から倍々、上限 30 秒、full jitter。60 秒つながっていたら戻す)。90 秒何も来なければ張り直す。Wolfx の頼み (1 台に 1 本を目安に使い回す・短い間に張り直しを繰り返さない) に合う
  - 観測点はそれぞれ約 1 秒ごとに 1 件 (約 1.3KB) を送ってくる。7 か所で 1 日 800MB ほど (2026-11-17 に 60 秒測った)。帯域を食うので、`SONAE_SEISJS=off` で切れる (状態は `off`)
  - 値は `CalcShindo` (観測点が気象庁の計測震度の求め方で計算したもの)。`Shindo`・PGA などは使わない。heartbeat は数えるだけ
  - 観測点の一覧 (`https://api.wolfx.jp/seis_list.json`) は起動したときと 1 日に 1 回、ETag で条件付きで取る。`enable` が false のものは外す。一覧に無くても、観測に位置が付いていれば足す (200 か所まで)。観測点の表が変わったら、次のまとめ (1 秒ごと) で画面に配る。`private` と分かった観測点は覚えておき、一覧を取り直しても出さない
- **配り方:** 受けた値は観測点ごとにいまの値だけを持ち、1 秒ごとに 5 秒以内の値をまとめて、TREM と同じ形の `RtsBoard` (`src/lib/server/rts-board.ts`) に入れる。DB にも Broker にも入れない。
  画面には `event: seis-stations` (観測点の位置) と `event: seis` (位置の分かる観測点の [経度, 緯度, 計測震度]) で送る。毎秒送ると開いている画面ごとに 1 日 20MB ほどになるので、見た目 (観測点ごとの震度の階級) が変わったときと、変わらなくても 5 秒ごと (画面が 10 秒で灰色に戻す `RTS_STALE_MS` より短く) にだけ送る
- **画面:** 地図の点 (層 `seis`)。見た目は台湾の観測点と同じ (`stationLayer`、`rtsFeatures`)。値が 0.5 以上なら震度の色、それ未満は灰色。押しても何も出さず、一覧にも出さない。音・読み上げ・OS の通知・Web Push・Webhook では知らせない
- **出典:** 「出典と注意」の窓に「Wolfx Project (SeisJS)」と、非公式で公式の発表を優先する旨・知らせには使わない旨を出す (`#lib/notice.ts` の `CREDITS`)。地図の source の `attribution` にも出典。受信の状態には「Wolfx SeisJS (有志の観測点の揺れ・非公式)」と並ぶ

### 2.11 海しるの点の層 (海底地殻変動観測点・海域火山)

**海上保安庁の海しる (海洋状況表示システム) の API から、海底地殻変動観測点 (GNSS-A、31 点) と海域火山データベース (35 点) を取り、地図の点にする** (持ち主の決定、2026-11-20。キーは 2026-11-19 に受け取った)。
どちらもめったに変わらない、場所の見当のための点なので、知らせには使わない。

- **規約** (海しる API 利用規約):
  - 5 条の文「このサービスは、海しるAPIを利用して取得した情報をもとに作成しているが、サービスの内容は海上保安庁によって保証されたものではない」を出す
  - 出典は「出典：海洋状況表示システム (URL)」。加工したら、そのことも書く (sonae は点の属性を選んで並べ、表示用に整えている)
  - 短い間に大量に取りに行かない
- **キー:** 環境変数 `MSIL_API_KEY` (chart は `secrets.keys.msilApiKey`、既定 `msil-api-key`、`optional: true`。持ち主の本番は `deploy/secrets.sops.yaml` の `sonae-secrets`)。
  無ければ情報源を作らず、「受信の状態」に `off` (「API のキーがありません」) で並べ、層を出さない (ほかは普段どおり)。キーはヘッダー `Ocp-Apim-Subscription-Key` で送り、URL・ログ・状態の欄・ブラウザには出さない
- **取り方** (`src/lib/server/sources/msil.ts`):
  - `https://api.msil.go.jp/<層>/v2/MapServer/1/query?f=geojson&where=1=1&outFields=*`。層は `seabed-crust-deformation-info` (海底地殻変動観測点) と `marine-volcano-DB` (海域火山DB)。どちらも層の番号は 1 (0 は 400 が返る。2026-11-20 に確かめた)
  - 1 回の答えは 1,000 件・64MB まで。超えると `exceededTransferLimit` が付くので、`resultOffset` で続きを取る (いまは 1 回で済む)
  - 1 日 1 回、層を 1 つずつ順に取る。取ったものは表 `layer_cache` (2.5) に置き、起動し直しても前に取ってから 1 日たつまでは取りに行かない。応答が遅いことがある (1 回目は 19 秒かかった) ので、90 秒で諦める
  - 失敗したら 15 分から倍々 (上限 6 時間)。前に取ったものがあれば、それを出し続け、状態は「受信中」のまま直近のエラーだけを出す (場所の見当のための点で、注意の印を出すほどではないため)。点が 0 の答えは相手の不具合とみなして、前のものを残す
  - 点の属性は、海底地殻変動観測点が `観測地点名`・`設置水深_m`・`設置機関`・`設置年月`・`URL`、海域火山が `火山名`・`点名`・`標高_水深` (「732m」「-81m」「‐95m」、空もある)・`出典` (位置の出どころ)・`URL` (`<a href="…">` の形)。URL は海上保安庁 (`*.mlit.go.jp`) の https だけを採る
- **配り方:** 画面は `/api/marine` (ログインの後ろ) から 1 度だけ読む。サーバーは置いてあるものを返すだけで、海しるへは取りに行かない。キーが無ければ `enabled: false` で点は空
- **画面:** 地図の点 (層 `marine`)。見た目と押したときの吹き出しは [map.md](map.md) の「海しるの点」。一覧・音・読み上げ・通知には使わない
- **出典:** 「出典と注意」の窓に、出典と加工したことと 5 条の文 (`#lib/notice.ts` の `CREDITS`)。吹き出しの下と地図の source の `attribution` にも出典。受信の状態には「海しる (海上保安庁。海底地殻変動観測点・海域火山)」と並ぶ
- **次の候補** (9 章): 海上保安部署等 (191 点)・潮汐推算 (`tide-prediction/v3/station`・`/data`)

### 2.12 災害時の通行止め

**国土交通省が災害ごとに出す「通れるマップ」の GeoJSON を、管理者が URL を登録したときだけ取り、通行止めと通れた道 (目安) の線を地図に出す** (持ち主の決定、2026-11-20。「交通状況は、無料で取れるものを作る」)。知らせには使わない。

- **情報源:** 例は「令和8年熊本地震 通れるマップ」(<https://www.mlit.go.jp/road/saigai/r8kumamoto/index.html>)。地図のページ (`map/map.html`) が読む `map/json/dourokisei.geojson` (道路規制情報) と `map/json/ETC2.0_speed_data.geojson` (ETC2.0 の平均速度) を、そのまま URL として登録できる (2026-11-20 に確かめた。`ETag`・`Last-Modified` が付き、CloudFront から返る)。能登の「道路復旧見える化マップ」も同じ類のもの。災害ごとに URL が違い、一覧は国土交通省 道路局の災害情報 (<https://www.mlit.go.jp/road/road_fr4_000201.html>)
- **規約:** 登録は要らない。公共データ利用規約 1.0 で、出典を書き、加工したら書けば配り直してよい。出典は「出典：国土交通省「通れるマップ」」と、加工したこと
- **URL の置き場: 環境変数 `SONAE_ROAD_GEOJSON`** (カンマか空白で区切る。chart は `sonae.roadGeojson` の並び。1 行のインストーラは `sonae.env`)。選んだ訳:
  - サーバーが取りに行く先を決めるもので、sonae に「管理者」の役は無い (画面を開ける人は全員、声や通知の条件を変えられる。2.6)。画面や DB の設定にすると、家族や信頼するネットワークの誰でも、サーバーに好きな所を取りに行かせられる (SSRF)
  - 取りに行く先はさらに https の `*.go.jp` に絞る (`roadUrlProblem`)。地方整備局 (`qsr.mlit.go.jp` など) も通る
  - 災害のたびに替えるので、設定ファイルを書き換えて入れ直す手間はかかる。家の本番は `deploy/application.yaml` の `sonae.roadGeojson` を替えて main に入れる (Argo CD が入れ替える。数秒つながらない)
  - 登録が無ければ情報源を作らず、「受信の状態」に「オフ (URL が登録されていません)」と並べるだけで、何もしない。使わない URL は起動したときにログに出して外す
- **取り方** (`src/lib/server/sources/roads.ts`): 30 分ごと (国土交通省の更新は 1 日に数回)。URL ごとに 1 つずつ順に、`If-None-Match`・`If-Modified-Since` を付けて取る。取ったものは表 `layer_cache` (2.5) に URL ごとに置き、取れない間は前のものを出し続ける (状態は「受信中」のまま直近のエラーを出す)。失敗したら 5 分から倍々 (上限 30 分)。1 つ 30MB まで (ETC2.0 の速度は 3〜12MB だった。content-length が無くても、読みながら数えて打ち切る)。リダイレクトは自分で 3 回まで辿り、行き先も https の `*.go.jp` か確かめる (絞った意味をリダイレクトで崩さない)。go.jp の名前が内部のアドレスを指す (DNS) 場合は防がない。URL は環境変数で管理者が決めるので、そこまでは割り切った
- **読み方:** 1 つのファイルに形の違う行が混ざる (高速道路は `規制内容`・`始点`・`終点`、県道などは `規制開始_内容`・`始点住所`・`終点住所`・`規制開始_日時`・`延長_Km`)。
  - 道路規制情報 (`規制内容`・`規制開始_内容`・`路線名` などを持つ行) は、規制の内容が全面通行止めで、まだ解除されていないものだけを「通行止め (災害)」にする。解除は、`規制内容` の「通行止め解除」と、通れるマップの色で見分ける。県道などは解除されても `規制開始_内容` が「全面通行止」のまま残り、色だけが灰色 (`#999999`、凡例の「規制解除後」) になるため。「緊急車両のみ通行可」や紫の線 (属性の無い線) などは採らない
  - ETC2.0 の平均速度 (属性が `_color`・`_weight` だけの行) は、色で区分にする (凡例の橙 `#ff9900` が時速 20 km 以下、青 `#0000ff` が 21 km 以上)
  - 座標は 0.00001 度に丸め、吹き出しに使う項目 (路線名・区間・規制の内容と理由・始めた時刻・延長) と、ファイルの更新の時刻 (Last-Modified) だけを残す
- **入れないもの:** 道路情報提供システム・NEXCO・VICS・JARTIC の渋滞と規制と、ITS Japan の通行実績は、有料か転載が禁じられているので取らない。このうち道路情報提供システム・JARTIC・NEXCO 3 社は、「出典と注意」の窓に外へのリンクだけを置く (`#lib/map/roads.ts` の `ROAD_LINKS`)。熊本のデータ一式にある `tukoujisseki.geojson` (通行実績) も読まない。交通量 API は規約の 4 条があいまいなので入れない
- **配り方:** 画面は `/api/roads` を開いたときと 10 分ごとに読む。サーバーは置いてあるものを返すだけ。登録から外した URL のものは返さない
- **画面:** 線の見た目と重ね順は [map.md](map.md) の「災害時の通行止め」。一覧・音・読み上げ・通知には使わない
- **出典:** 「出典と注意」の窓・吹き出しの下・地図の source の `attribution` に「出典：国土交通省「通れるマップ」」と加工したこと。受信の状態には「国土交通省 (災害時の通行止め)」と並ぶ

## 5. 法と表示

- **予想震度は出さない。** 緊急地震速報の最大予測震度・地域ごとの予測震度・到達予測時刻は、画面にも通知にも出さない。
  気象庁は警報で「具体的な予測震度の値は ±1 程度の誤差を伴い、続報を避けたいので発表せず『強い揺れ』と表現する」としている ([緊急地震速報 (警報) 及び (予報) について](https://www.jma.go.jp/jma/kishou/know/jishin/eew/shikumi/shousai.html))。sonae も警報は「強い揺れに警戒」と、対象の地域名で伝える。
  予報は「緊急地震速報 (予報)」と震源・M だけを出す。
- **自前の予想をしない。** 地点の震度や到達時刻を計算して出すのは予報業務で、気象業務法 17 条の許可が要る ([よくある質問](https://www.jma.go.jp/jma/kishou/minkan/q_a_s.html))。地震動の警報は気象庁以外はできない (23 条)。
- **観測値は気象庁の値をそのまま出す。** 推計や補間で震度を足さない (気象庁の値の編集にあたりうる)。観測点ごとの震度は、電文に並ぶ観測点の値をその観測点の位置に置くだけにし、観測点の間を補って面で塗ることも、観測点の無い所の震度を推し量ることもしない ([map.md](map.md) の「観測点ごとの震度」)。
- **気象の警報・注意報と気象の報も、気象庁の発表を中継するだけにする。** 種類の名前・見出し・本文は電文のまま出し、段も電文の種類のコードから取る。地点の雨や風を予想したり、警報を自分で判断したりしない (警報は気象庁以外はできない、気象業務法 23 条)。出典は「気象庁ホームページ」
- **雨雲は気象庁の観測の 1 枚をそのまま重ねるだけにする。** 高解像度降水ナウキャストの「いま」のタイルを、色も値も変えずに透かして重ね、いつの観測かを出す。外挿・合成・補間で先の雨を予想しない (観測資料に基づく独自の予想を繰り返し提供するのは予報業務で、気象業務法 17 条の許可が要る)。出典は「出典：気象庁ホームページ」と「気象庁「高解像度降水ナウキャスト」を加工して作成」([map.md](map.md) の「雨雲」)
- **火山の警報は気象庁の文のまま出す。** 噴火警報・予報と噴火速報は、見出し・活動の状況・防災上の警戒事項を言い換えずに出し、警戒の段も電文の種類から取る (自分で警戒を判断しない。噴火の警報も気象庁以外はできない、気象業務法 23 条)。
- **注意文と短い出典は一覧のいちばん下 (どちらの形も) に、出典の全文は「出典と注意」の窓にいつも出す。地図には短い出典を隅にいつも出す。** 文言は `src/lib/notice.ts` の `NOTICE`・`CREDITS`・`SHORT_CREDIT`・`mapCredit`・`EEW_NOTICE` に持つ (層の規約の文とリンク先は、層の部品 (`#lib/map/marine.ts` の `MSIL_DISCLAIMER`・`#lib/map/roads.ts` の `ROAD_LINKS` など) に置き、`notice.ts` が読む)。
  一覧の下は注意文と「出典: 気象庁ホームページ・国土地理院 ほか。全文は「出典と注意」にあります」(窓へのリンク) にし、全文を二重に並べない (2026-11-15。窓はヘッダーと「その他」からいつも開ける)。入れる理由と、規約の文言は次のとおり。
  - 気象庁の情報は加工して出しているので、「出典：気象庁ホームページ（URL）」と「気象庁「名称」（URL）を加工して作成」の形で書き、編集の責任を書く (気象庁の[留意事項](https://www.data.jma.go.jp/developer/ryuui.pdf)と[利用規約](https://www.jma.go.jp/jma/kishou/info/coment.html)。公共データ利用規約 第 1.0 版)
  - 利用者に見える形で Wolfx Project を出す (窓の出典と、緊急地震速報の詳しい内容の `EEW_NOTICE`)。2026-11-14 の改訂で出典の義務 (旧 6 条) は消えたが、どこから中継したかを利用者が分かるよう続ける (Wolfx の三条も、非公式で公的機関とつながりが無いと断る)。P2P地震情報は緊急地震速報と、地震情報・津波予報の速報 (気象庁の XML の前に出す仮のもの) に使う。Wolfx Project は地震情報の速報の予備 (P2P地震情報の予備) にも使い、窓の出典に「地震情報の速報 (P2P地震情報の予備)」の項目で出す
  - **国土地理院の[出典の記載](https://www.gsi.go.jp/LAW/2930-meizi.html)は「システムやWebサイトに測量成果を利用する場合、原則、測量成果が表示画面に表示されている間は、常に見えるように表示画面に明示」とする。** MapLibre の畳んだ (i) は押すまで見えないので外し、地図の隅に短い出典を常に出す ([map.md](map.md))。
    文言は[地理院タイル一覧](https://maps.gsi.go.jp/development/ichiran.html)の「「国土地理院」または「地理院タイル」等と記載し、地理院タイル一覧ページへのリンク」と、加工したものの「地理院タイルに○○を追記して掲載」に合わせる。写真は備考どおり GRUS 画像の範囲で「GRUS画像（© Axelspace）」、都市圏活断層図は調査者 (図ごとに違うので、国土地理院の各図の案内へのリンクと例)
  - ハザードマップは[出典の記載方法](https://disaportal.gsi.go.jp/hazardmap/copyright/copyright.html)の「出典：「ハザードマップポータルサイト」」と「「ハザードマップポータルサイト」を加工して作成」。元の機関 (国土交通省各地方整備局等・都道府県・国土数値情報) も書く
  - USGS は「courtesy of the U.S. Geological Survey」、EMSC は「EMSC-CSEM SeismicPortal, https://www.seismicportal.eu」(CC BY 4.0)
  - 海しるは「出典：海洋状況表示システム（URL）」と、加工したこと、海しる API 利用規約 5 条の文 (2.11)
  - 通れるマップは「出典：国土交通省「通れるマップ」」と、加工したこと (公共データ利用規約 1.0。2.12)。有料か転載禁止の道路交通の情報は取らず、外へのリンクだけを置く
  - 注意文は「公式ではない・遅れたり欠けたりする・公式の情報を優先する」の 3 つを言う。緊急地震速報の画面には、Wolfx と P2P のどちらも非公式で無保証であることも書く
- **Wolfx:** 原文 (`OriginalText`) は保存も公開もしない (中身は気象庁の緊急地震速報の電文で、規約の五条で気象庁の条件に従う。配り直してよいと確かめられない)。
  2026-11-14 の改訂で、許可が要るのは `jma_eew` のデータを独立したデータ源として再配信することだけになった (二条)。sonae は受けたものを家族の画面と通知に出すだけで、ほかの人やアプリが使えるデータ源として出さないので、これに当たらない (二条の「最終利用者への表示・通知と、そのためのサーバーでの処理・通信・キャッシュ」)。
- **観測点のいまの揺れ (ExpTech TREM-RTS・Wolfx SeisJS):** 地図の点の色で出すだけにし、一覧・音・読み上げ・OS の通知・Web Push・Webhook では知らせない (TREM は服務條款 §五の「予警報に使わない」と、安全の判断の唯一の根拠にしない)。「出典と注意」の窓に出典と、非公式で公式の発表を優先する旨を出す (2.9・2.10)。TREM は非商用のデータなので、商用で立てるなら ExpTech の同意が要る (README)

## 6. 見た目と動きの決まり

**見た目は denpa の [docs/design.md](https://github.com/danything/denpa/blob/main/docs/design.md) (見た目の決まり) に従い、言葉は同じリポジトリの [docs/writing.md](https://github.com/danything/denpa/blob/main/docs/writing.md) に従う。** 合言葉も同じで「塗らない。囲みすぎない。浮かせすぎない。でも、ちゃんと伝わる」。
画面の形 (何がどこにあるか) は [docs/ui.md](ui.md) に書く。ここには、denpa の決まりをどう当てたかと、sonae にしかない決まりを書く。

### 6.1 denpa の決まりの当て方

- **値は `src/app.css` の `--so-*` から選ぶ。** 名前は denpa の `--dp-*` を `--so-*` にしたもので、値は同じ (色・字の大きさの 6 段・余白の 6 段・時間と曲線・重なりの段)。写すのは sonae が使うものだけ。部品の CSS (ボタン・件の面・日付の見出し・チップ・メニュー・スイッチ・サイドバー・ダイアログ・dock) も denpa の `app.css` から写している。denpa の値を変えたら、こちらも合わせる
- **層は地・件の面・操作の層の 3 つ** (denpa の 2 章)
  - 地: 一覧の列の上の種類のチップ・詳しい内容・注意文
  - 件の面: 一覧の 1 行 (`Row.svelte`)
  - 操作の層: スマホの形の下のタブと dock・メニュー・ダイアログ・貼り付いた日付の見出し
- **浮かせるのは中身の上に重なるものだけ** (denpa の 3 章)。広い形のヘッダーは窓が巻けないので、いつも平ら (denpa の観る画面と同じ)。スマホの形の下のタブと dock は地図や一覧の上にいつも浮かせる。下のタブはいつも出し、低い画面 (高さ 600px 未満) で一覧を下へ読む間だけ dock を引っ込める (denpa の 3 章と同じ条件。[ui.md](ui.md) の「スマホの形」)
- **選んでいるものは主の色の線と太字で、塗らない** (denpa の 4 章)。一覧の選んだ行は左の縦線。種類で絞るチップ (広い形は列の上、スマホの形は dock) は並び (`role="group"`) の中の押されているボタン (`aria-pressed`) なので、出しているもの (先頭の「すべて」か 1 つの種類) が字の幅いっぱいの下線と太字 (短い下線は引かない)。全部へ戻るのは選んだチップの ✕ ではなく「すべて」のチップにする (✕ は置かない決まりで、並びの中の 1 つを選ぶ形がほかのチップと同じ見た目で分かるため)。下のタブも字の幅いっぱいの下線。メニューの選択肢 (テーマ) は左の縦線、オン/オフ (「通知」の中) はスイッチ
- **スマホの形は 1000px 未満** (`#lib/phone-form.ts` と app.html の `<html data-phone>`。denpa と同じ線)。上のヘッダーを出さず、下のタブと dock に寄せる
  - 一覧のタブは窓ごと巻き、地図は上に貼り付けて残す (denpa の一覧の画面と同じくページごと巻く。Android のブラウザは窓が巻かれたときだけアドレスバーを隠し、戻ったときに見ていた位置へも帰る)。地図の高さは画面の 40% で、`html` から受け継いだ外枠の高さから採る ([ui.md](ui.md) の「スマホの形」)。広い形は今までどおり画面ぴったりで、一覧は列の箱の中で巻く
- **閉じるのは左下の「閉じる」** (「出典と注意」と「通知」の窓)。中身を巻いても窓の下端に貼り付けて、いつも見せる (`.modal-foot`。denpa の番組の詳細と同じ)。段は薄く、面と影は敷かない。続きがあるときだけ、ボタンの手前で中身を薄く消していく (denpa の番組の詳細のフェード)。枠の外 (幕) を押しても Esc でも閉じる。✕ は置かない。詳しい内容から一覧へ戻るのは窓を閉じるのではないので、左上の「一覧」のリンク
- **動きは CSS の透明度と transform だけ** (denpa の 7 章)。JS がするのは印 (`data-view`・`data-retract`) の付け外しだけ。動きを減らす設定では時間を 0 にし、繰り返す動きを止める
- **空の状態と、絞り込んで当てはまらないときは `.empty-state`** (denpa の 8 章)。絞り込んで (欄かチップで) 無いときは「当てはまるものはありません」だけ。sonae には見せる画面が無いので、地の光 (`.glow`) は敷かない
- **テーマの既定は端末に合わせる** (denpa と同じ選べる 3 つ。暗い・明るい・端末に合わせる)。保存した選択はそのまま使う (localStorage の `sonae.theme`)
  - `app.html` のスクリプトが描く前に `<html data-theme>` とブラウザの枠の色 (`theme-color`) を付ける。`<html>` には決めたテーマを書かないので、明るい端末で暗い画面が一瞬出ることはない。スクリプトが動かなければ明るいテーマ (`app.css`)
  - 端末に合わせているときは、開いている間に端末の設定が変わっても付け直す
  - ホーム画面に足すときの地の色もテーマに合わせる。暗いテーマは `static/manifest.webmanifest`、明るいテーマは色だけが違う `static/manifest-light.webmanifest` を読ませる。ホーム画面に足したあとはブラウザが足したときの色を使い、テーマを変えても替わらない
- **お知らせは、問題があるときだけヘッダー (スマホの形は dock) の印に畳む** (denpa の 6 章「通知」)。受信の状態はふだん出さず、つながっていない情報源があるときだけ注意の印 (⚠ と一言) を出し、押すとメニューと同じ箱で情報源ごとの受信を出す
  - いつもの受信の状態は「出典と注意」の窓の「受信の状態」に置く (注意文のすぐ下。`StatusList.svelte` を印のメニューと共に使う)。どの情報源を受けているかを、問題が無いときにも確かめられるようにするため。ボタン・タブ・画面は足さない (2026-11-15。持ち主の声「同期中のデータがどれかわからん」「できるだけ要素とか画面は増やさない方向で」)。
    設定で切ってある情報源 (状態 `off`。授権碼の無い中央氣象署・API のキーの無い海しる・URL を登録していない通行止め・`SONAE_TREM=off`・`SONAE_SEISJS=off`) も訳を添えて並べ、控えた字のままにして注意の印は出さない (`#lib/format.ts` の `sourceInTrouble`)

### 6.2 sonae だけの決まり

- **震度・津波の区分・火山の警戒の段・気象警報・注意報の段は、気象庁の配色の指針の色で塗ったラベルにする** (4 章の色と、指針の表 1-2 の噴火警報・予報の色、表 1-1 の警戒レベルの色。`Intensity.svelte`・`Grade.svelte`・`VolcanoLevel.svelte`・`WarningLevel.svelte`)。denpa の「状態の色は状態だけ」とは別の、色そのものが意味を持つもの (denpa のリモコンの色のキーと同じ扱い)。
  色だけに頼らず、ラベルにはいつも「5弱」「津波警報」と字で書く。選んでいる印・オン・状態にはこの色を使わない
- **地図は操作の層ではなく中身** (地図の上に操作は重ねない)。層はいつも全部出し、切り替えは置かない (色の意味は「出典と注意」の「地図の見方」)。地図の上にあるのは隅の短い出典と、震度のラベル・震央の × と、ハザードマップと雨雲の選択 (と、選んだものの凡例) と、現在地のボタンと、読んでいる間の「読み上げ中断」だけ。出典は国土地理院の決まりでいつも見えるように出し (5 章)、地図の角にぴったり付けた小さく薄い帯 (地の色を 65% の濃さで敷く。[map.md](map.md)) にして写真の上でも読めるようにする。押すと「出典と注意」の窓。スマホの形は地図の右上の角 (下の端は浮いた下のタブ・dock・右下の操作が重なり、ぴったり付ける角が無いため。上の帯は地図を押し下げるので隠れない)
  - 例外: ハザードマップと雨雲の選択 (右下のカプセル。雨雲は 2026-11-20 に足した。色が震度・警報・注意報とぶつかるため、ハザードマップと同じ選択の 1 つにした。現在地のボタンと 1 行に並べ、隅の出典の上に置く。2026-11-15 に持ち主の頼みで左上から移した。マウスでは乗せただけで選択肢を開く)。持ち主の決定 (2026-11-14) で、層の切り替えを置かない中で、色がぶつかるハザードマップだけは 1 つを選ぶ。地図に重なるので操作の層に乗せ、選んでいる間はメニューを開くボタンと同じ短い下線 (`data-on`)。選択肢はメニューの左の縦線。選んだものの公式の凡例 (画像) をその下にメニューと同じ面で出す (凡例の画像は白い地なので、暗いテーマでも白い台に載せる)。
    都市圏活断層図も地形の分類で塗った全面の図なので、いつもは重ねず、この選択の 1 つ (「活断層」) にする (2026-11-15)。選んでいる間は、面で塗る警報・注意報と震度の色を隠し、命に関わるいま出ているもの (特別警報・緊急地震速報) は縁取りで残す ([map.md](map.md) の「ハザードマップを重ねている間」)
  - 例外: 現在地のボタン (右下の丸) は、地図で自分のいる所を探す操作なので地図の上に置く。地図 (動く中身) に重なるので操作の層 (面と影) に乗せ、オンは並びの外の切り替えと同じく主の色のアイコンと短い下線。オンの間だけ `watchPosition` で追い、白い縁の青い点と誤差の円を描く。押して始めたときは初めて取れたときだけそこへ寄せる (追う間に勝手に動かさない)。**緯度・経度は端末の中で描くだけで、サーバーには送らない**。許可されなかったときは追うのをやめ、ボタンの上に「位置の利用が許可されていません。…」と積む。
    **既定はオン** (2026-11-16。持ち主の声「デフォルトで現在地を表示してほしい」)。人が選んだオン・オフは端末に覚え (`sonae.map.locate` の `on`・`off`)、オフを選んだ端末では自動で始めない。開いたときに位置の許可がもう `granted` なら自動で始める (寄せない)。まだ選んでいない端末で許可をまだ聞いていない (`prompt`) ときは、自動で始めて許可の窓を出す (寄せない。断られたらオフを覚えるので、聞くのは許可か拒否が決まるまで)。人がオンにした端末で `prompt` のときは始めずにオンの見た目 (下線) のままアイコンを薄くして、押すのを待つ。`denied` か、許可の窓で断られたら、オフを覚えて聞き直さない。既定がオフだったころはオフを覚えていなかったので、前にオフだった端末にも一度だけ許可を聞く (持ち主の返事、2026-11-16。[map.md](map.md) の「現在地を自動で始めるとき」)
  - 例外: 「読み上げ中断」(左下。スマホの形は dock のすぐ上の左) は、読み上げている間だけ浮かせるボタン (2.4 の「読み上げは人が途中で止められる」・[ui.md](ui.md))
  - 例外: 地図のメニュー (右クリック・スマホは長押し) は、押したときだけ押した所に出す操作の層のメニュー (`Menu.svelte`) で、地図にいつも重ねる操作ではない ([map.md](map.md) の「地図のメニュー」)。住んでいる地域の縁取り (水色の破線) と、検索の欄で選んだ場所の印 (白い縁の橙の丸) は、操作ではなく中身の印
  - 例外: 押したときだけ出す吹き出し (避難場所の印・観測点ごとの震度の丸・気象警報・注意報の市町村等)。メニューと同じ面と影で、地図の上に 1 つだけ。押せる所が重なったときは、いちばん上に描いているもので吹き出しを持つものを出す ([map.md](map.md) の「押せる所が重なったとき」)
  - 例外: 地震を選んでいる間に気象警報・注意報の塗りを隠していることの一言 (右下の操作の上)。隠しているのに書かないと、警報・注意報が出ていないように見えるため ([map.md](map.md) の「地震を選んでいる間」)
  - 広い形は地図の箱を件の面と同じ角 (`--so-item-radius`) で切る。スマホの形は画面いっぱいで角を付けない
- **地図で 1 つのものを見ている間は、色がぶつかる面の塗りを隠す。** 塗りの色が意味を持つので (上の配色の指針の色)、2 つの面を重ねると読み違える。ハザードマップを重ねている間は警報・注意報と震度の塗りを、一覧で地震を選んでいる間は警報・注意報の塗りを隠す (2026-11-19。警報・注意報の黄・赤・紫が震度の色と重なるため)。
  どちらのときも、命に関わるいま出ているもの (気象の特別警報・緊急地震速報・津波の線) は縁取りか線で残し、隠していることを地図の上に書く ([map.md](map.md) の「ハザードマップを重ねている間」「地震を選んでいる間」)
- **広い形の列は右の 1 本 (一覧か詳しい内容) だけにし、残りの幅を地図に回す。** denpa の観る画面 (映像と右の列) と同じく、主の中身 (地図) を左に、添える列を右に置く (denpa の左はナビゲーションの場所)。地図が主なので、ずっと見ていなくてよいもの (カレンダー・状態) は列に並べず、押したときだけ出すメニューに畳む。
  列は 22rem (1600px から 26rem)。種類のチップは列の幅に入りきらなければ折り返す (横に流すと後ろの種類が隠れる)
- **一覧は全部の種類を 1 本に、時刻の新しい順に並べる。** 種類は分けずにチップで絞り (全部か 1 つの種類。押すとその種類だけ、もう一度押すと全部)、どれを出しているかは端末に覚える (既定は全部出す)。種類をまたいで並ぶので、行の左のラベルの幅をそろえ、ラベルの無い種類も同じ幅を空ける
- **いま出ている緊急地震速報 (警報) だけは、詳しい内容の先頭の箱と、スマホの形の dock の 1 行を状態の赤で塗る** (denpa の通知の「地は状態の色で塗らない」の例外)。身を守る動きにつなげる通知で、どの画面のどこを見ていても一目で分かる必要があるため。予報と取消は塗らず、淡い面に注意の色のタイトル。2026-11-15 に画面の上の帯をやめ、出たら詳しい内容を開く形にした ([ui.md](ui.md) の「自動で開く」。持ち主の声「緊急地震速報も上に表示するんじゃなくてサイドバーで詳細表示にすればいいと思う」)
- **いま出ている緊急地震速報・大津波警報と津波警報・気象の特別警報 (レベル 5) は、チップにかかわらず一覧の先頭に通知の形で出す。** 身を守る動きにつなげるものと、数十年に一度の重大な災害のおそれを伝えるもので、ほかの種類だけを出しているときも目に入る必要があるため。並びは緊急地震速報・津波・特別警報の順で、時刻の順には並べない。
  形はほかの通知と同じ (塗らない)。特別警報には種類のラベル (指針の色) と対象の市町村等を添える。状態の赤は緊急地震速報 (警報) だけに残す
  - その後に、津波注意報・津波予報、噴火速報と噴火警報 (居住地域)、この 1 週間の南海トラフ地震の情報と地震・津波に関するお知らせ (VZSE40) を、その種類を出しているときだけ続ける
- **事実はバッジにしない** (denpa の 4 章)。M・深さ・遠地地震・発表の種類は控えた字を「・」でつなぐ。バッジは状態 (取消・速報・訓練・試験) だけ
- **注意文と出典はいつも見える所に置く** (5 章)。どちらの形も一覧のいちばん下に注意文と短い出典、地図の隅 (広い形は右下、スマホの形は右上) に短い出典。全文は「出典と注意」の窓 (ヘッダーとスマホの形の「その他」、一覧の下と地図の隅の出典からいつも開ける)

### 6.3 動き

ほかのアプリ (corp・mado・denpa の docs/design.md 7・8 章) と同じ。

- 動かすのは **CSS の `opacity` と `transform` だけ**。JS のアニメーション (rAF・`setInterval` で値を書き換える・ライブラリ) は使わない。ぼかしと背景の位置は動かさない。色・地・影は、指を乗せたときと押したときに `--so-duration` で移すだけ (denpa の 7 章の `--dp-duration` と同じ)。
- 緊急地震速報の箱の見出し・dock の 1 行・震央の ×・音が止まっている帯のアイコンを目立たせる脈打ちは、`transform: scale` と `opacity` の CSS アニメーションで、回数を決めて止める。脈打ちは `app.css` の 1 つ (`--so-pulse`) を使い、強さだけを要素ごとに `--so-pulse-opacity`・`--so-pulse-scale` で決める。
- スマホの形で地図と一覧を切り替えるときは、一覧を透明度と少しの `translateY` で出し入れする (地図は作り直さない)。地図の高さ (一覧のタブは画面の 40%、地図のタブは画面いっぱい) は動かさずに替える。
- 地図のカメラは飛ばさない (`jumpTo`。寄せるときの決まりは [map.md](map.md))。MapLibre は止まっている間は描かないので、地図を開いているだけで CPU を使うことは無い。
- 時間で動き続けるものは無い (脈打ちは決めた回数で止まる)。そのため denpa の `<html data-lite>` (ソフトウェアで描いている端末で止める印) と `content-visibility: auto` はまだ要らない。動き続けるものを足すときに入れる。WebGL が無ければ地図は出さない。
- `prefers-reduced-motion` では全部止める。
- 検証は GPU を切った Chromium (`--disable-gpu --disable-gpu-compositing`) でも、止まって 5 秒の CPU を測る。

## 7. テスト

- **単体 (`bun test tests`)**: 電文の読み取り (fixture → 正規化したモデル)、新旧の判定と重複の除去 (同じ報の二重受信・報数の逆転・取消・訓練)、知らせるかどうかの判定 (閾値・住んでいる地域)、SSE の埋め直し (`sseStream` が渡された backlog を送ってから生の配信に移る)、hooks の振り分け (ログイン無しで開けるパス・401・ログインへの送り分け・`AUTH_DISABLED`)。
- **fixture:**
  - 気象庁の[サンプル電文](https://xml.kishou.go.jp/tec_material.html) (`jmaxml_20260917_Samples.zip`、2026-09-17 一部更新) から、使う種別の分だけを `tests/fixtures/jma/` に写す。
    利用条件は気象庁ホームページの利用規約 (公共データ利用規約 第 1.0 版、CC BY 4.0 と互換) で、`tests/fixtures/jma/README.md` に出典「気象庁防災情報 XML フォーマット 技術資料 サンプルデータ (https://xml.kishou.go.jp/tec_material.html)」と規約を書く。中身は変えない (整形からも外す)。足りない場合 (取消と訓練の組など) は自分で作り、ファイル名で分かるようにする。
  - P2P は API 仕様書 (v2.3.0) の例の写し (`spec-551.json`・`spec-552.json`・`spec-556.json`)。取消や訓練など例に無い組み合わせは、試験の中で値を書き換えて作る。
  - Wolfx は公式の文書の項目の一覧から自分で作る (原文は入れない)。地震情報の一覧 (`made-eqlist.json`) は、受けた一覧の形に合わせ、値は気象庁のサンプル電文の地震にした作り物。
  - ほかの情報源 (USGS・EMSC・GeoNet・中央氣象署・PTWC・気象庁 bosai) も `tests/fixtures/<情報源>/` に置き、それぞれの README.md に、取ったものを縮めたのか作り物なのかと出典を書く。TREM-RTS と SeisJS は試験の中で値を作る。
- **アダプター:** 情報源のサーバーを立てない。`fetch` と WebSocket を差し替えて、304・切断・張り直し・heartbeat の途絶を試す。
- **E2E (後で):** Playwright で、ログインを飛ばした画面に SSE で fixture を流し、表示と通知の判定を見る。GPU を切った CPU の測定もここで。
- **CI:** `bun run lint` (oxlint・`bun fmt --check`)・`bun run check` (`svelte-check --tsgo --fail-on-warnings`)・`bun test tests`・`bun run build` (警告で失敗)・Docker のビルドと起動して `/health` を見る。chart は `chart.yml` (8 章)、インストーラは `installers.yml` (インストーラと配布物に関わるファイルと、誰を通すかのコード (`hooks.server.ts`・`trust.ts`・`address.ts`) を変えたときと、手で回したときだけ。各 OS で入れて、上げ直して、外すまで)。

## 8. 家のクラスタへの載せ方

**家の本番も、セルフホストの人と同じ Helm chart (`charts/sonae`) で出す。** denpa と同じ形で、gitops の ApplicationSet が `deploy/argocd.yaml` を探して `deploy/` を素のマニフェストとして同期し、その中の `deploy/application.yaml` (Argo CD の Application `sonae-chart`) が chart を展開する (App-of-Apps)。家の値は `application.yaml` の `helm.valuesObject` にインラインで持つ。

- chart (`charts/sonae`): sonae の Deployment (レプリカ 1・Recreate・uid 1000・`/health` のプローブ (起きていることだけを見る。情報源の受信の状態は見ない))・Service・HTTPRoute か Ingress・PVC `sonae-data`・VOICEVOX のエンジン (公式のイメージ `voicevox/voicevox_engine:<バージョン>` (CPU 用) の Deployment・Service。CPU は絞らず (limits 無し・requests 2)、合成のスレッドはマシンの全部を使う (`voicevox.cpuThreads`)。メモリの上限 3Gi。PVC は持たない。イメージは Renovate が上げる)・NetworkPolicy (VOICEVOX は sonae の Pod からしか受けず外へ出ない。sonae の外向きは DNS と公開のインターネットと VOICEVOX だけ)。リソースの名前は素のマニフェストのころと同じにしてあり、変えない (PVC を作り直すとデータが消える)。
- 家の値 (`deploy/application.yaml`): ホスト名 `s.doany.io` (Cilium Gateway の `doany`)、OIDC は docs/entra.md の表のとおり (Entra は共用の Main で、リダイレクト URI `https://s.doany.io/auth/callback` は gitops の `pulumi/entra.ts` で足した)、Secret は `sonae-secrets`、PVC は `local-path` 1Gi で `dataSourceRef` で VolSync から戻す、外向きの NetworkPolicy を出す。
- chart に入れないもの (`deploy/` に素のまま): `argocd.yaml`・`volsync.yaml` (毎日 19:30 UTC に R2 へ。時刻はアプリごとに gitops で散らしてある)・`secrets.sops.yaml` (`oidc-client-secret` (Main の共用のもの)・VolSync の restic。VAPID の秘密鍵 `vapid-private-jwk` と中央氣象署の授権碼 `cwa-api-key`・海しるの API のキー `msil-api-key` は任意で、入れ方は docs/push.md と docs/cwa.md と 2.11)。R2 にまだバックアップが無い最初の 1 回は、populator が空の PVC を作る (gitops の recovery/README.md の 6)。`.sops.yaml` はほかのリポジトリと同じ鍵。この家の Argo CD は Secret を同期しないので、chart は Secret を作らず、名前 (`secrets.name`) で指す。
  `secrets.name` の Secret に `oidc-client-secret` のキーが無いと、Pod は起動しない (`secretKeyRef` に `optional` を付けない。持ち主の決定、2026-11-19)。ログインの設定の漏れに、起動したときすぐ気づけるようにするため。付けると Pod は起動するが、画面は開かず `/health` だけ答えるので、漏れに気づくのが遅れる。任意の `vapid-private-jwk`・`cwa-api-key`・`msil-api-key` は `optional: true` で、無ければその機能だけを切って動く。
- 環境変数 (chart の `templates/deployment.yaml`): `PUBLIC_URL` と `ORIGIN` (adapter-bun) はどちらも `sonae.publicUrl` (家は `https://s.doany.io`)。`CONNECTION_IDLE_TIMEOUT=255` (既定の 10 秒だと 30 秒ごとの `: ping` を待つ間に SSE が切れる)。`SHUTDOWN_TIMEOUT=5` (SSE は終わらないので長く待たない)。`VOICEVOX_URL=http://voicevox:50021` (2.4 の「読み上げ」)。
- 外向きの NetworkPolicy は ashi と同じ形 (kube-dns と、プライベートでないアドレス全部)。クラスタに既定で閉じるポリシーは無いので、これが無くても外へは出られる。家の LAN とクラスタの中を閉じるために置く。DNS の Pod のラベルはクラスタで違うので、chart の既定では出さない。
- イメージ: main にマージすると `docker-publish.yml` が `ghcr.io/danything/sonae:<sha>` と `latest` を作り、`deploy/application.yaml` の `image.tag` を差し替える PR を作って自分でマージする。**イメージの中身に関わらないものだけを変えたマージでは組まず、差し替えもしない** (`paths-ignore` の `docs/`・`tests/`・`tools/`・`charts/`・`deploy/`・`.github/`・直下の `*.md` など)。入れ替えは Recreate で、そのたびに数秒〜十数秒つながらないため。並べるのはビルドが読まないと言い切れるものだけで、分からないものは組む側に倒す。タグのコミットにイメージが無ければ、`release.yml` は中身を変えた最後のコミットのものを使う (同じ除外の一覧を持つ)。
- chart: PR と main で `chart.yml` が `helm lint` と `helm template` (chart の既定値・外向きの宛先を足した値・家の値・Ingress と VOICEVOX 無し) を回す。リリースを作ると `release.yml` が chart を `oci://ghcr.io/danything/charts/sonae` に出す。
- 実行のイメージは `oven/bun:<ver>-distroless` (シェル無し・uid 1000)。
