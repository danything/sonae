# sonae の設計

地震・津波の情報を家のサーバーで受け、ブラウザで見て、Web Push で知らせるアプリの設計書。
ここに書いたのは作りの決めごとで、作りながら直す。決めていないことは最後の「未決の点」にまとめた。
画面の形は [ui.md](ui.md)、地図の層と出典は [map.md](map.md)、Web Push の運用は [push.md](push.md)、ログインの設定は [entra.md](entra.md) に書き、ここでは繰り返さない。

- 名前は「備え」から。
- 機能は [Zero Quake](https://github.com/0Quake/Zero-Quake) を参考にしたが、**コードは読まない・写さない** (クリーンルーム)。仕様は各情報源の公式の文書から取る。
- ライセンスは AGPL-3.0。

## 1. 目的と範囲

**目的:** 家族が、地震と津波の情報を 1 か所でまとめて見られ、タブを閉じていても大きな揺れや津波のときは端末に通知が届くこと。
**まずは持ち主 1 人で使う** (ログインで閉じる)。家族との共有は、仕様 (Entra のアプリロール、2.6) だけ先に入れておき、招待はあとでする。
広く公開はまだしないが、公開しても困らない作りにしておく。

- **ホスト名は `s.doany.io`** (家のクラスタの Gateway の `doany`)。

## 2. 全体の構成

```
            ┌──────────── サーバー (Bun 1 プロセス、SvelteKit + adapter-bun) ────────────┐
気象庁 Atom ─┤ jmaSource ────┐                                                              │
P2P ws ──────┤ p2pSource ────┼─▶ 正規化 ─▶ 重複の除去・新旧の判定 ─▶ SQLite ─▶ Broker ─┬─▶ SSE ─────▶ ブラウザ
Wolfx ws ────┤ wolfxSource ──┘                                                       └─▶ Pusher ─▶ Web Push
             └──────────────────────────────────────────────────────────────────────────┘
```

- **1 つのプロセスで受信も配信もする。** SvelteKit の `init` (hooks.server.ts の `ServerInit`) で受信を起こす (ashi が歩みを起こすのと同じ形)。
  受信を別のプロセスに分けないのは、家族の数人に配るだけで分ける利点が無く、Wolfx の「1 クライアント 1 接続」・P2P の「IP ごとに 2 接続」を守るのも 1 プロセスのほうが確か。
- **レプリカは 1 つ、入れ替えは Recreate。** 2 つ立つと情報源への接続が倍になり、Push も二重に出る。入れ替えの数秒は受けられないが、戻ったときに履歴の API で埋める (下)。
- 依存は増やさない: XML は Bun 組み込みの `Bun.XML.parse` (1.4.4 の型定義で確かめた。外部の DTD や実体を読まないので XXE の心配が無い)、WebSocket の受信は Bun の `WebSocket`、DB は `bun:sqlite`。

### 2.1 受信 (情報源ごとのアダプター)

どのアダプターも同じ形にする。

```ts
interface Source {
  id: "jma" | "p2p" | "wolfx";
  /** 止めるまで受け続ける。切れたら自分で張り直す (受けたものは作るときに渡す SourceContext の emit へ) */
  run(signal: AbortSignal): Promise<void>;
  status(): SourceStatus; // connecting / connected / retrying / stopped、最後に受けた時刻、直近のエラー
}
```

| 情報源                     | 方式                                                                                        | 受けるもの                                                                      | 行儀                                                                                                                                                                                                                               |
| -------------------------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 気象庁 防災情報 XML (PULL) | 高頻度フィード `https://www.data.jma.go.jp/developer/xml/feed/eqvol.xml` を 60 秒ごとに取る | 地震・津波・南海トラフ等の電文 (3 章)                                           | `If-None-Match` と `If-Modified-Since` を付ける (304 が返ることを確かめた)。`Cache-Control: max-age=60` なので 60 秒より短くしない。一度取った電文は取り直さない (Atom の `id` を DB に持つ)。1 日 10GB を超えると IP が遮断される |
| 気象庁 長期フィード        | `eqvol_l.xml` (毎時更新、数日分)                                                            | 止まっていた間の電文                                                            | 起動したときと、高頻度フィードの取得が 10 分以上途切れた後に 1 回だけ読む                                                                                                                                                          |
| P2P地震情報 API v2         | WebSocket `wss://api.p2pquake.net/v2/ws`                                                    | 551 地震情報・552 津波予報・554 緊急地震速報の発表検出・556 緊急地震速報 (警報) | IP ごとに 2 接続まで (1 つだけ使う)。同じ情報が何度も届くので `id` で除く。張り直したら `/v2/history?codes=551&codes=552&codes=556` で埋める (60 回/分まで)                                                                        |
| Wolfx Open API             | WebSocket `wss://ws-api.wolfx.jp/jma_eew`                                                   | 気象庁の緊急地震速報 (予報と警報)                                               | 1 クライアント 1 接続。約 1 分ごとの `heartbeat` に合わせて `ping` を送る。`OriginalText` は受けたら捨てる                                                                                                                         |

- **緊急地震速報は気象庁の公開フィードに載らない** (公開電文の一覧に「緊急地震速報等、公開されない電文もあります」とある。<https://xml.kishou.go.jp/xmllist.pdf>)。そのため予報と警報を Wolfx から、警報を P2P からも受け、2 つで欠けを補う。どちらも非公式で無保証なので、画面にはそう書く。
- **張り直し:** 指数のバックオフに揺らぎを足す (1 秒から倍々、上限 30 秒、full jitter)。60 秒つながっていたら間隔を戻す。Wolfx は 90 秒何も来なければ (heartbeat も含めて) 死んだとみなして張り直す。P2P は heartbeat を送ってこず、静かなときは何分も何も来ない (2026-11-13 に実際につないで確かめた) ので、無通信では切らず、切れたことは close で知る。つながるまでは、どちらも 30 秒で諦める。
- **重複の除去:** 情報源の中では、気象庁は Atom の `id`、P2P は `id` で除く。情報源をまたいだ重複は、正規化した後の新旧の判定 (2.2) で除く。
- **受けた原文は残す** (Wolfx を除く)。気象庁の XML と P2P の JSON を 30 日、圧縮して `raw_messages` に置き、正規化を直したときに流し直せるようにする。

### 2.2 正規化したイベントのモデル

情報源の違いはアダプターの中で吸収し、外へは次の 4 種類と、長周期地震動 (`LongPeriod`、2.7) だけを出す。どれにも `sources` (どこから来たか) と `status` (通常 / 訓練 / 試験) を持たせる。

**緊急地震速報 `Eew`**

```ts
type Eew = {
  eventId: string; // 地震識別番号 (14 桁)
  serial: number; // 報数
  issuedAt: string;
  kind: "warning" | "forecast"; // 警報 / 予報
  final: boolean; // 最終報
  cancelled: boolean; // 取消
  status: "normal" | "training" | "test";
  assumed: boolean; // 仮定震源要素 (PLUM 法・レベル法)
  originTime?: string;
  hypocenter?: { name: string; lat: number; lon: number; depthKm: number };
  magnitude?: number;
  warnAreas: string[]; // 警報の対象の地域名 (警報のときだけ)
  sources: ("wolfx" | "p2p")[];
};
```

- **新旧の判定:** 鍵は `eventId`。報数が今より大きいものだけを採る。同じ報数が別の情報源から来たら `sources` に足し、警報の地域は和を取る。取消を受けたら、その地震の速報はそこで終わり (以後の報は捨てる)。
- **最大予測震度・地域ごとの予測震度は、正規化したモデルに入れない** (5 章)。SSE でブラウザに渡すのもこの形なので、画面にも通知にも出ようがない。P2P の原文 (raw_messages) には残る。Wolfx の原文は残さない。
- 訓練と試験 (Wolfx の `isTraining`、P2P の `test`) は保存するが、知らせず、一覧にも「訓練」と付けて既定では隠す。

**地震情報 `Quake`** (1 つの地震に、発表された報をまとめる)

```ts
type QuakeReport = {
  kind: "scale" | "hypocenter" | "detail" | "update" | "foreign"; // 震度速報 / 震源 / 震源・震度 / 震源要素更新 / 遠地
  code?: "VXSE51" | "VXSE52" | "VXSE53" | "VXSE61";
  infoType: "発表" | "取消";
  reportedAt: string;
  // 中身 (震源・M・最大震度・地域と観測点ごとの震度・津波の有無の文・付加文)
};
```

- 一連の情報は「`Control/Title` + `Control/Status` + 地震識別番号」で見分ける (気象庁の運用指針)。取消は**その一連の情報全体**を取り消す。
- **地震識別番号は、自動の電文 (緊急地震速報・震度速報) と手動の電文 (地震情報・津波) で一致しないことがある** (気象庁のよくある質問)。そのため、震度速報と後の地震情報は、番号が合わないときは「発表の時刻が近く、震度の地域が重なる」もので結ぶ。結び方の閾値は fixture で詰める (未決の点)。
- `Serial` は連番とも一意とも保証されない。新旧は `ReportDateTime` で決める。
- P2P の 551 は気象庁の XML と同じ地震の情報なので、P2P で先に受けたら仮に出し、XML が来たら置き換える (XML を正とする)。

**津波 `Tsunami`**

- VTSE41 (津波警報・注意報・予報) は**その時点の全予報区の状態**を毎回まるごと持つので、新しい報で前の状態を置き換える。予報区ごとに「大津波警報 / 津波警報 / 津波注意報 / 津波予報 / 解除」を持つ。
- VTSE51 (津波情報) は到達予想時刻・予想の高さ・観測値、VTSE52 は沖合の観測。同じ一連の情報に付け足す。
- 原因の地震が複数のとき、地震識別番号は並びで来る (`xs:list`)。全部を持っておく。
- P2P の 552 は警報・注意報・予報の区域の状態だけ。XML が来るまでのつなぎに使う。
- **P2P の 551・552 には訓練・試験の印が無い** (API 仕様書 v2.3.0 で印があるのは 556 の `test` だけ。訓練の電文を流すかどうかも書かれていない、2026-11-13 に確かめた)。そのため P2P だけから来た地震・津波は、いつも本番 (`normal`) として持つ。訓練・試験の津波は、地震と同じく id の後ろに `-training` / `-test` を付けて分ける (P2P だけのものも同じ規則にしてあり、仕様に印が足されたら読み取りを直すだけで効く)。
  - 残る危うさ: P2P が訓練の津波を流したら、本番として仮に出る。気象庁の XML (訓練) は状態が違うので重ならず、P2P の仮のものは置き換わらない。訓練は事前に告知されるので、いまはこのままにする。

**お知らせ `Advisory`** — 南海トラフ地震臨時情報 (VYSE50)・関連解説情報 (VYSE51/52)・北海道・三陸沖後発地震注意情報 (VYSE60)・地震・津波に関するお知らせ (VZSE40)。
見出しと本文と種類 (調査中・巨大地震警戒・巨大地震注意・調査終了など) を持つ。VYSE50/60 の識別番号は物理的な意味を持たない任意の番号。

### 2.3 ブラウザへの配信: SSE

|                      | SSE (`text/event-stream`)                                                                                               | WebSocket                                                                          |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 向き                 | サーバーからだけ。sonae はこれで足りる (設定の変更は普通の POST)                                                        | 両向き                                                                             |
| 張り直し・取りこぼし | ブラウザが自動で張り直し、`Last-Event-ID` を送る。そこから DB で埋められる                                              | 自前で書く                                                                         |
| 認証                 | 普通の要求なので、セッションの Cookie と hooks の判定がそのまま効く                                                     | Upgrade の時に別に判定する                                                         |
| SvelteKit・Gateway   | `+server.ts` で `ReadableStream` を返すだけ。Cilium Gateway もそのまま通る                                              | SvelteKit に標準の仕組みが無く、adapter-bun の外で `Bun.serve` の websocket を触る |
| 同時の接続数         | HTTP/1.1 だとブラウザの 6 本の上限に数える。HTTP/2 なら 1 本に束ねられる (Gateway が h2 を話すかは載せるときに確かめる) | 制限なし                                                                           |

**SSE にする。** `GET /api/stream`。

- 各イベントに DB の通し番号を `id:` で付ける。`Last-Event-ID` があれば、それより後を DB から送ってから生の配信に移る。
  - 埋め直しは 500 件まで。**超えるときは埋め直しを送らず、`event: resync` を送る** (`id:` はいまの最後の番号、`data` は `{"after": 番号}`)。そこから生の配信に移る。ブラウザは受けたら `invalidateAll()` で `load` を走らせ直し、一覧を取り直す。
- **`s.doany.io` は Cloudflare のプロキシを通したワイルドカードの DNS で配信される** (DNS のレコードは足さない)。Cloudflare のプロキシは、応答の間に 100 秒何も流れないと接続を切り (Proxy Read Timeout)、圧縮やバッファリングで SSE を溜めて届けることがある。そのため:
  - **30 秒ごとにコメント行 (`: ping`) を送る。** Cloudflare の 100 秒、adapter-bun の `CONNECTION_IDLE_TIMEOUT` (Bun の idleTimeout、上限 255 秒)、Gateway の無通信の切断のどれよりも十分短い。同じ間隔で情報源の状況 (`event: status`) も送る。
  - 応答のヘッダーに `Content-Type: text/event-stream`・`Cache-Control: no-cache, no-transform`・`X-Accel-Buffering: no` を付ける (`no-transform` で圧縮を止め、`X-Accel-Buffering` で途中の溜め込みを止める)。
  - それでも切れることはあるので、ブラウザの側は切れたら `Last-Event-ID` で取り直す (EventSource が自分で張り直す)。最初の接続は、ページの `load` で渡した最後の番号を `?after=` で付ける。
- 最初の表示の中身はページの `load` で渡し、SSE は差分だけにする。

### 2.4 Web Push

**push-bridge は使えない。** memory にある infisical-push-bridge は、Infisical の Webhook を受けて InfisicalSecret の注釈を書き換える仕組みで、ブラウザへの Web Push とは関係が無い (2026-11-02 に撤去済み)。
ほかの自分のリポジトリにも Web Push の実装は無いので、sonae の中に書く。鍵の作り方・入れ方と確かめ方は [docs/push.md](push.md)。

**@block65/webcrypto-web-push を使う。** 最初は web-push の予定だったが、Bun の上で Node の https と CJS の依存を束ねるより、WebCrypto と fetch だけで済むほうが distroless の束ね方 (Dockerfile の「実行時の依存は無い」) に素直に合う。
@pushforge/builder も WebCrypto だけだが、試したところ `Content-Encoding: aesgcm` (RFC 8291 の前の形式) で送るので外した。
devDependencies に入れ、Vite がサーバーに束ねる。テスト (`tests/push.test.ts`) で、送った本文をブラウザの側の手順 (RFC 8291) で復号できることまで確かめている。

- **鍵:** VAPID の秘密鍵 (P-256 の JWK の JSON) を環境変数 `VAPID_PRIVATE_JWK` で受ける。公開鍵は JWK の x・y から作り、`GET /api/push` で画面に渡す。
  **鍵が無ければ Web Push だけを切る** (登録を受けず、送らない。ほかは普段どおり)。本番は SOPS の Secret (`deploy/secrets.sops.yaml` の `vapid-private-jwk`) を `optional: true` で読む。連絡先 (`VAPID_SUBJECT`) は既定で `PUBLIC_URL`。
- **購読:** ブラウザごとに `push_subscriptions` に、ログインした人 (IdP の sub)・endpoint・鍵・条件 (下)・ブラウザの名前を持つ。セッションとは結ばない (ログインが切れても届く)。1 人 20 まで。
  - endpoint はブラウザから来るので、サーバーから任意の宛先へ POST させないよう、主な配信サービス (FCM・Mozilla・Apple・WNS) の https だけ受ける。転送 (3xx) も追わない。
  - 送って **404・410 が返ったら購読を消す**。ほかの失敗は記録に残すだけ。
- **登録の画面と API:** 画面はヘッダーの「通知」(スマホの形は「その他」の「通知」) から開くダイアログ 1 つ (`src/lib/components/PushSettings.svelte`)。API は `GET`・`PUT`・`DELETE /api/push` と、試しに送る `POST /api/push/test`。どれもログインが要る (hooks)。
- **何を知らせるか (ブラウザごとに選ぶ。括弧は既定と、その理由):**
  - 緊急地震速報: 警報だけ / 予報も / 送らない (**警報だけ**)。警報は強い揺れが来る地域に出るもので、身を守る動きにつながる。予報は日に何度も出ることがあり、鳴りすぎると通知自体を切られてしまう。予報を選んでも本文に予想震度は書かない (5 章)。
  - 地震情報: 最大震度がいくつ以上 (**震度 4**)。震度 4 は「ほとんどの人が驚く」揺れで、家族の安否を気にし始める境目。震度 3 以下は全国で月に何十回もあり、鳴りすぎる。
  - 現在地の地域 (地震情報の細分区域、**選ばない**) で震度いくつ以上 (**震度 3**)。最大震度の条件に届かなくても、自分の所で揺れたものは知りたいので、1 段下げる。P2P の震度速報には地域のコードが無いので、名前でも見る。
  - 津波: 注意報以上 / 警報以上 / 大津波警報だけ / 送らない (**注意報以上**)。注意報でも海の中や海岸の近くでは危ないので、現在地の予報区に関わらず送る (旅先や家族の居場所もあるため)。
  - 南海トラフ地震臨時情報・定例外の解説情報・後発地震注意情報 (**オン**)。めったに出ず、出たら備えを見直すべきもの。
  - 訓練・試験・遠地地震は送らない。
  - 持ち主の決定 (2026-11-13、9 章の 4): 既定値はこのまま。
- **同じ事象で何度も鳴らさない:**
  - 事象ごとに tag を決める (`eew:<地震識別番号>`・`quake:<地震の id>`・`tsunami:<津波の id>`・`advisory:<id>`)。Service Worker は `showNotification` の `tag` で前の通知を置き換える。
  - 購読ごとに、tag へ最後に送った「重さ」(震度の段・津波の区分・警報か予報か) と中身の要約を `push_log` に持つ。
    初めては鳴らす。**中身が同じなら送らない。重さが上がったら鳴らし直す** (`renotify`)。それ以外の続報 (震源や M が決まった・取消・解除) は、**同じ tag で鳴らさずに置き換える**。
  - 取消・解除は、前に知らせた購読にだけ送る (知らせていないものの取消は要らない)。
  - 鳴らすかどうかを決めて控えるところまでは同期でする (続報が続けて来ても二重に鳴らない)。送れなかったら控えを送る前に戻す (初めての通知なら消して、次の続報を初めてとして扱う)。購読の持ち主が替わったら控えを捨てる。控えは 30 日で捨てる。
  - Web Push の `Topic` に tag の SHA-256 の先頭 32 字を付ける。配信サービスがまだ届けていない前の通知は、続報で置き換わる。
  - 起動したときに長期フィードで埋めた昔の電文を鳴らさないよう、事象の時刻から緊急地震速報は 3 分・地震は 1 時間・津波とお知らせは 6 時間を過ぎたものは送らない。
- **送り方:** 緊急地震速報と津波は `Urgency: high`。`TTL` は緊急地震速報 120 秒 (遅れて届いても意味が無い)、地震情報 1 時間、津波とお知らせ 6 時間。緊急地震速報の警報と津波警報以上は、閉じるまで残す (`requireInteraction`)。
- **Service Worker** (`src/service-worker/`、SvelteKit が自動で登録): 通知を出し、押されたらその事象の画面 (1 つの画面でその件を選んだ URL。`/?q=<id>`・`/?k=tsunami&t=<id>`・`/?k=eew&e=<識別番号>`。[ui.md](ui.md)) を開く。開いている画面があればそれを移して前に出す。このサイトの中のパスしか開かない。画面やデータの控え (オフライン) はしない (古い地震情報を出さないため)。型は WebWorker の型で、`bun run check` が別に見る。
- **iPhone・iPad:** ホーム画面に追加した Web アプリ (iOS 16.4 以降) でだけ Web Push が届く。そのための Web アプリのマニフェスト (`static/manifest.webmanifest`) を置き、ダイアログで案内する。
- **ホーム画面のアイコン:** iOS と Android のホーム画面は SVG のアイコンを使わないので、`static/favicon.svg` から PNG を作って `static/icons/` に置く (192・512・maskable の 512 をマニフェストに、180 の `apple-touch-icon.png` を `app.html` の `<link rel="apple-touch-icon">` に)。白い地に印を置き、maskable は印を安全な円 (直径 80%) に収まる 55% にする。作り方はホストに何も入れず、コンテナの rsvg-convert で描く。`favicon.svg` を変えたら、次のコマンドで作り直してコミットする。

  ```sh
  wslc run --rm -v "$PWD:/w" -w /w debian:trixie-slim sh tools/icons/build.sh
  ```

- **開いているとき:** SSE で受けたら、短い音 (`<audio>`) と見出しの読み上げ (`speechSynthesis`) で知らせる (`src/lib/alerter.svelte.ts`)。
  - **鳴らす判定は Web Push と同じ関数** (`src/lib/notify.ts` の `noticeOf`・`decide`)。サーバーの `plan` も、画面の `alertFor` (`src/lib/alert.ts`) も `decide` を呼び、違うのは控えの置き場 (サーバーは購読ごとの `push_log`、画面はメモリ) と中身の値 (サーバーは SHA-256、画面は元の字) だけ。同じ所で鳴ることを `tests/alert.test.ts` で確かめている。訓練・試験・遠地地震・古すぎるものは鳴らさず、続報は重さが上がったときだけ鳴らし直す。
  - **条件は「通知」のダイアログの条件 1 つ** (Web Push と同じ `PushPrefs`)。端末の localStorage (`sonae.alert.prefs`) に持ち、Web Push に登録してあればサーバーにも送る。新しいルートは作らない。
  - **音と読み上げは端末ごとにオン/オフでき、既定はどちらもオフ** (`sonae.alert`)。オンにしたときと「試しに鳴らす」で一度鳴らす。読み上げは通知の見出し (`title`) だけで、括弧は読ませない。音の後に 0.75 秒おいて読む。
  - **音源は自作** (`src/lib/chime.ts`)。880 Hz から 660 Hz へ下がる 2 つの音を、その場で WAV (16 ビット・モノラル・22.05 kHz、0.7 秒) に組む。ファイルも外の音源も持たない。
  - **自動再生の制限:** ブラウザは、人がページを一度操作するまで音を出させない。最初の操作 (`pointerup`・`keydown`・`touchend`) の中で `<audio>` と読み上げを無音で一度動かし、後から鳴らせるようにする (iPhone・iPad の Safari は、操作の中で一度動かしたものでないと鳴らせない)。音か読み上げがオンなのに鳴らせない間 (`navigator.userActivation` がまだ立っていない、または再生を断られた) は、広い形はヘッダーのナビ、スマホの形は dock に「音を出す」を出す。押すと鳴らせるようになる。
  - タブを幾つも開いていても、同じ通知は 1 つのタブだけが鳴らす (Web Locks で 5 秒持つ。鳴らせないタブはロックを取らない)。Web Push にも登録してあると、開いている間も Web Push の通知は届く (Service Worker は通知を出さないと iOS が購読を止めるため、画面を開いているかで止めない)。

### 2.6 認証

ロールを持つ人だけが開けるようにする。ほかのアプリと同じく、パスワードは持たず OIDC でログインする。

- **OIDC のクライアントは自前** (noren の `src/lib/server/oidc.ts` と同じ形: discovery・認可コード + PKCE・素の fetch と WebCrypto で id_token の署名・発行元・宛先・期限・nonce を確かめる)。ライブラリは足さない。
- **IdP は doany.io の Entra ID の共用のアプリ登録 `Main`。新しくアプリは登録しない。** ashi と同じく、誰が使えるかはエンタープライズ アプリケーションのロールの割り当てで決める。
  通すロールは `OIDC_ROLE` (**既定は `admin`**。まずは持ち主 1 人)。家族と共有するときはロールを足して `OIDC_ROLE` を替えるだけで、コードの変更は要らない。
  リダイレクト URI・環境変数の表・家族と共有する手順は [entra.md](entra.md)。
- issuer・client id・secret の 3 つが揃わないと、画面は開かない (`/health` だけ答える)。手元の開発だけ、`AUTH_DISABLED=1` でログインを飛ばせる (本番の `NODE_ENV=production` では効かない)。
- **セッションは DB に持ち、180 日で、使うたびに延ばす。** 何度もログインさせない。**ID は Cookie にだけ生の値を置き、DB には SHA-256 (16 進) を持つ** (DB が漏れても、そのままでは成りすませない)。Web Push は購読してあればセッションが切れても届く。
- ログイン無しで開けるのは `/auth/login`・`/auth/callback`・`/health`・Service Worker と Web アプリのマニフェストだけ。`/auth/logout` は POST だけ。

### 2.7 長周期地震動と推計震度分布

調べた資料 (2026-11-14): [公開する電文の一覧](https://xml.kishou.go.jp/xmllist.pdf) (2026/8/6 現在)・地震火山関連 解説資料 (`jmaxml_20261104_Manual(pdf).zip` の「地震火山関連_解説資料」Ⅱ.(ⅰ)ウ.(キ))・サンプル電文 (`78_01_01_240613_VXSE62.xml`)・気象庁の[情報カタログ (地震)](https://www.data.jma.go.jp/suishin/cgi-bin/catalogue/make_product_page.cgi?id=Jishin)。

**長周期地震動に関する観測情報 (VXSE62) は公開のフィード (地震火山) に載る。受けて、地震に添えて出す。**

- 中身: 地震の諸要素 (発生時刻・震源・M)、全国の最大震度と最大長周期地震動階級 (`MaxLgInt`、0〜4)、情報の種類 (`LgCategory`、1〜4)、都道府県・地域 (地震情報／細分区域のコード)・観測点ごとの階級と震度、観測点の絶対速度応答スペクトル (`Sva`)、気象庁の観測情報のページの URI。続報は観測の全体を持ち直す (地域が足されたり階級が直されたりする。`Revise`)。取消は内容部が無い。
- モデルは `LongPeriod` (`src/lib/model.ts`)。鍵は地震識別番号 (訓練・試験は後ろに `-training` / `-test`)。新しい報で置き換え、古い報は捨て、取消は前の中身を残して印を付ける (`mergeLongPeriod`)。SSE のイベントの種類は `longperiod`。
- 画面: 一覧の種類は増やさない。長周期地震動は地震情報の後に出る観測の詳しい内容なので、同じ地震識別番号の地震に添える。地震の一覧の行の補足に「長周期地震動階級3」(階級 1 以上のとき)、地震の詳しい内容に「長周期地震動」の節 (地域を階級ごとに、観測点は畳んで、気象庁の観測情報のページへのリンク)。
- 地図: 層「長周期地震動階級」(既定はオフ)。地図に出している地震で階級 1 以上の地域を、階級の色の太い枠で囲む (震度は面の色なので、枠で分ける)。色は気象庁の配色の指針に長周期地震動階級の表が無いので、表 2-1 の基本配色の上から 4 つを階級 4 から当てた (階級 4 `180,0,104`・3 `255,40,0`・2 `255,153,0`・1 `250,245,0`。自分で決めた割り当て)。ラベルにはいつも「階級3」と字でも書く。
- 知らせない (Web Push も、開いているときの音も)。同じ地震は地震情報 (震度) で知らせている。
- 長周期地震動の**予測** (緊急地震速報の `ForecastLgInt`) は公開のフィードに無く、地点の予想にあたるので出さない (5 章)。

**推計震度分布は入れない。** 公開の防災情報 XML に推計震度分布の電文は無い (公開する電文の一覧にも、解説資料の地震の電文にも無い)。

- 情報カタログでは、格子のデータ「推計震度分布図作図用データ」は 1 km メッシュ (IXAC40) と 250 m メッシュ (IXAC41) の BUFR (格子) で、提供は気象業務支援センターだけ (配信の契約が要る)。誰でも見られるのは気象庁ホームページの「推計震度分布図」の画像 (PNG。全国で震度 5 弱以上を観測した地震) だけで、機械で読む約束 (仕様と提供の保証) が無い。
- 入れるなら、支援センターの BUFR を受けて、格子の値 (気象庁が推計した震度) を震度の色の画像にし、MapLibre の `image` の source で、格子の範囲 (緯度・経度) に合わせて重ねる。格子の値をそのまま色にし、補間や足し引きはしない (5 章の「観測値は気象庁の値をそのまま出す」)。ホームページの PNG を重ねるやり方は、範囲の座標が文書に無く、画像の作りが変わると崩れるので採らない。
- 推計震度分布は気象庁が観測から推計したもので、地点の震度の予想 (予報業務) ではない。出すときも、気象庁の推計であることと出典を書く。

共通の読み方:

- 電文は管理部 (`Control`)・ヘッダ部 (`Head`)・内容部 (`Body`) の 3 つ。`Control/Status` が「通常」以外 (訓練・試験) は保存だけして知らせない。
- 種別のコードはフィードのリンクのファイル名 (`..._VXSE53_...xml`) から取り、読む前に振り分ける。知らない種別は取らない (帯域を使わない)。
- 時刻は `Control/DateTime` が UTC (`Z`)、`Head` の時刻は `+09:00`。DB には ISO 8601 のまま持つ。
- 取消の電文は `Serial` が空で、`Body` は文だけ。

## 5. 法と表示

- **予想震度は出さない。** 緊急地震速報の最大予測震度・地域ごとの予測震度・到達予測時刻は、画面にも通知にも出さない。
  気象庁は警報で「具体的な予測震度の値は ±1 程度の誤差を伴い、続報を避けたいので発表せず『強い揺れ』と表現する」としている ([緊急地震速報 (警報) 及び (予報) について](https://www.jma.go.jp/jma/kishou/know/jishin/eew/shikumi/shousai.html))。sonae も警報は「強い揺れに警戒」と、対象の地域名で伝える。
  予報は「緊急地震速報 (予報)」と震源・M だけを出す。
- **自前の予想をしない。** 地点の震度や到達時刻を計算して出すのは予報業務で、気象業務法 17 条の許可が要る ([よくある質問](https://www.jma.go.jp/jma/kishou/minkan/q_a_s.html))。地震動の警報は気象庁以外はできない (23 条)。
- **観測値は気象庁の値をそのまま出す。** 推計や補間で震度を足さない (気象庁の値の編集にあたりうる)。
- **出典と注意文は、画面の下 (広い形はサイドバーの下、スマホの形は一覧の下) と「出典と注意」の窓にいつも出す。** 文言は `src/lib/notice.ts` の `NOTICE`・`CREDITS`・`EEW_NOTICE` の 1 か所に持つ。入れる理由は次のとおり。
  - 気象庁の情報は加工して出しているので、出典に「加工して作成」と編集の責任を書く (気象庁の[留意事項](https://www.data.jma.go.jp/developer/ryuui.pdf)と[利用規約](https://www.jma.go.jp/jma/kishou/info/coment.html)。公共データ利用規約 第 1.0 版)
  - Wolfx の規約で、利用者に見える形で Wolfx Project を出す。P2P地震情報は緊急地震速報と、地震情報・津波予報の速報 (気象庁の XML の前に出す仮のもの) に使う
  - 地図は国土地理院のタイルと気象庁の GIS データを加工したもの ([map.md](map.md))
  - 注意文は「公式ではない・遅れたり欠けたりする・公式の情報を優先する」の 3 つを言う。緊急地震速報の画面には、Wolfx と P2P のどちらも非公式で無保証であることも書く
- **Wolfx:** 原文 (`OriginalText`) は保存も公開もしない。Wolfx を使う機能で収益を得ない。広く公開する前に、規約 6 条の「第三者へのデータの提供」に当たるか Wolfx に確かめる (未決の点)。

## 6. 見た目と動きの決まり

**見た目は denpa の [docs/design.md](https://github.com/danything/denpa/blob/main/docs/design.md) (見た目の決まり) に従い、言葉は同じリポジトリの [docs/writing.md](https://github.com/danything/denpa/blob/main/docs/writing.md) に従う。** 合言葉も同じで「塗らない。囲みすぎない。浮かせすぎない。でも、ちゃんと伝わる」。
画面の形 (何がどこにあるか) は [docs/ui.md](ui.md) に書く。ここには、denpa の決まりをどう当てたかと、sonae にしかない決まりを書く。

### 6.1 denpa の決まりの当て方

- **値は `src/app.css` の `--so-*` から選ぶ。** 名前は denpa の `--dp-*` を `--so-*` にしたもので、値は同じ (色・字の大きさの 6 段・余白の 6 段・時間と曲線・重なりの段)。写すのは sonae が使うものだけ。部品の CSS (ボタン・件の面・日付の見出し・チップ・メニュー・スイッチ・サイドバー・ダイアログ・dock) も denpa の `app.css` から写している。denpa の値を変えたら、こちらも合わせる
- **層は地・件の面・操作の層の 3 つ** (denpa の 2 章)
  - 地: サイドバー (カレンダー・状態・絞り込み・表示)・詳しい内容・注意文
  - 件の面: 一覧の 1 行 (`Row.svelte`)
  - 操作の層: スマホの形の下のタブと dock・メニュー・ダイアログ・貼り付いた日付の見出し
- **浮かせるのは中身の上に重なるものだけ** (denpa の 3 章)。広い形のヘッダーは窓が巻けないので、いつも平ら (denpa の観る画面と同じ)。スマホの形の下のタブと dock は地図や一覧の上にいつも浮かせ、一覧を下へ読む間は引っ込める
- **選んでいるものは主の色の線と太字で、塗らない** (denpa の 4 章)。一覧の選んだ行と、サイドバーの絞り込みは左の縦線。dock のチップと下のタブは字の幅いっぱいの下線。メニューの選択肢 (テーマ) は左の縦線、オン/オフ (層) は右のスイッチ
- **スマホの形は 1000px 未満** (`#lib/phone-form.ts` と app.html の `<html data-phone>`。denpa と同じ線)。上のヘッダーを出さず、下のタブと dock に寄せる
- **閉じるのは左下の「閉じる」** (「出典と注意」の窓)。✕ は置かない。詳しい内容から一覧へ戻るのは窓を閉じるのではないので、左上の「一覧」のリンク
- **動きは CSS の透明度と transform だけ** (denpa の 7 章)。JS がするのは印 (`data-view`・`data-retract`) の付け外しだけ。動きを減らす設定では時間を 0 にし、繰り返す動きを止める
- **空の状態と、絞り込んで当てはまらないときは `.empty-state`** (denpa の 8 章)。絞り込んで無いときは「当てはまるものはありません」だけ。sonae には見せる画面が無いので、地の光 (`.glow`) は敷かない

### 6.2 sonae だけの決まり

- **震度と津波の区分は、気象庁の配色の指針の色で塗ったラベルにする** (4 章の色。`Intensity.svelte`・`Grade.svelte`)。denpa の「状態の色は状態だけ」とは別の、色そのものが意味を持つもの (denpa のリモコンの色のキーと同じ扱い)。
  色だけに頼らず、ラベルにはいつも「5弱」「津波警報」と字で書く。選んでいる印・オン・状態にはこの色を使わない
- **地図は操作の層ではなく中身** (地図の上に操作は重ねない)。層の切り替えはサイドバーの「表示」、スマホの形は dock の「⋯」に置く。地図の上にあるのは MapLibre の出典の (i) と、震度のラベル・震央の × だけ。出典の (i) は畳んでおき、同じ出典は注意文の下にいつも出す
  - 広い形は地図の箱を件の面と同じ角 (`--so-item-radius`) で切る。スマホの形は画面いっぱいで角を付けない
- **緊急地震速報 (警報) だけは、帯を状態の赤で塗る** (denpa の通知の「地は状態の色で塗らない」の例外)。身を守る動きにつなげる通知で、どの画面のどこを見ていても一目で分かる必要があるため。予報と取消は塗らず、淡い面に注意の色のタイトル
- **事実はバッジにしない** (denpa の 4 章)。M・深さ・遠地地震・発表の種類は控えた字を「・」でつなぐ。バッジは状態 (取消・速報・訓練・試験) だけ
- **注意文と出典はいつも見える所に置く** (5 章)。広い形はサイドバーのいちばん下、スマホの形は一覧のいちばん下。全文は「出典と注意」の窓

### 6.3 動き

ほかのアプリ (corp・mado・denpa の docs/design.md 7・8 章) と同じ。

- 動かすのは **CSS の `opacity` と `transform` だけ**。JS のアニメーション (rAF・`setInterval` で値を書き換える・ライブラリ) は使わない。ぼかし・色・背景の位置は動かさない。
- 緊急地震速報の帯や震源の印を目立たせる点滅・脈打ちは、`transform: scale` と `opacity` の CSS アニメーションで、回数を決めて止める (常時は回さない)。
- スマホの形で地図と一覧を切り替えるときは、一覧の面を透明度と少しの `translateY` で出し入れする (地図は作り直さない)。
- 地図のカメラは飛ばさない (`jumpTo`。寄せるときの決まりは [map.md](map.md))。MapLibre は止まっている間は描かないので、地図を開いているだけで CPU を使うことは無い。
- 時間で動き続けるものは無い (脈打ちは決めた回数で止まる)。そのため denpa の `<html data-lite>` (ソフトウェアで描いている端末で止める印) と `content-visibility: auto` はまだ要らない。動き続けるものを足すときに入れる。WebGL が無ければ地図は出さない。
- `prefers-reduced-motion` では全部止める。
- 検証は GPU を切った Chromium (`--disable-gpu --disable-gpu-compositing`) でも、止まって 5 秒の CPU を測る。

- **fixture:**
  - 気象庁の[サンプル電文](https://xml.kishou.go.jp/tec_material.html) (`jmaxml_20260917_Samples.zip`、2026-09-17 一部更新) から、使う種別の分だけを `tests/fixtures/jma/` に写す。
    利用条件は気象庁ホームページの利用規約 (公共データ利用規約 第 1.0 版、CC BY 4.0 と互換) で、`tests/fixtures/jma/README.md` に出典「気象庁防災情報 XML フォーマット 技術資料 サンプルデータ (https://xml.kishou.go.jp/tec_material.html)」と規約を書く。中身は変えない (整形からも外す)。足りない場合 (取消と訓練の組など) は自分で作り、ファイル名で分かるようにする。
  - P2P は API 仕様書の例と、サンドボックス (`wss://api-realtime-sandbox.p2pquake.net/v2/ws`、2023 年の情報を約 30 秒ごとに流す) で取ったもの。
  - Wolfx は公式の文書の項目の一覧から自分で作る (原文は入れない)。
- **アダプター:** 情報源のサーバーを立てない。`fetch` と WebSocket を差し替えて、304・切断・張り直し・heartbeat の途絶を試す。

- **CI:** `bun run lint` (oxlint・`bun fmt --check`)・`bun run check` (`svelte-check --tsgo --fail-on-warnings`)・`bun test tests`・`bun run build` (警告で失敗)・Docker のビルドと起動して `/health` を見る。

## 9. 未決の点

持ち主が決めたこと (2026-11-13):

1. **ホスト名は `s.doany.io`。** Entra は共用の Main を使い回し、リダイレクト URI `https://s.doany.io/auth/callback` は gitops の `pulumi/entra.ts` で足した。
2. **家族との共有はまだやらない。** いまは持ち主 1 人で使う。仕様としてはアプリロール (`OIDC_ROLE`、既定 `admin`) で絞る形にしておき、family 用のロールと家族の招待 (Entra の Main に B2B のゲスト) はあとでする。
3. **広く公開はまだしない** (家族用の前提のまま)。公開するときは、Wolfx に規約 6 条の事前の許可が要るか確かめる。気象庁の情報だけで出せる範囲 (緊急地震速報なし) に絞る手もある。
4. **通知の既定値は 2.4 の括弧の値のまま** (地震情報は最大震度 4 以上・現在地で震度 3 以上、緊急地震速報の予報は既定でオフ)。

作りながら決めること:

5. 震度速報と地震情報を、地震識別番号が合わないときに結ぶ閾値 (時刻の差と地域の重なり)。いまは仮に「発生の時刻 (震度速報は TargetDateTime) の差が 90 秒以内で、震度の地域が 1 つでも重なる (どちらかに地域が無ければ時刻だけ)」で、番号どうしが違うときは震度速報だけを結ぶ (`src/lib/server/merge.ts` の `sameQuakeByTime`・`LINK_WINDOW_MS`、`tests/merge.test.ts` で固定)。P2P の 551 には地震識別番号が無いので、いつもこれで結ぶ。
   - **気象庁の文書を確かめた (2026-11-13)。結び方の規則は無い。** 書かれているのは次のことだけ:
     - 番号はずれうる: 「同一地震であっても、緊急地震速報・震度速報（以上、自動処理による発表）と、(中略) 地震情報 (中略)（以上、手動による発表）の間でEventIDが一致しないこともある。」(運用指針 別紙 2 の ※1)。地震火山関連 解説資料 Ⅰ.別 02「EventID 要素の運用」にも、システムの切り替えや地震の続発で番号が一貫しないことがあると、出現例付きで書かれている。番号は発生時刻などの物理的な意味を持たない。
     - 震度速報の TargetDateTime は「最初に地震波を自動検知した観測点における地震波の検知時刻」で、分まで有効 (解説資料 Ⅰ-2)。震度速報は地震発生の約 1 分半後に出る ([気象庁の解説](https://www.jma.go.jp/jma/kishou/know/jishin/joho/seisinfo.html))。
     - 地域の重なりで同じ地震とみなす記述は無い。逆に、震度速報に別の地震の震度が混ざる例がある (解説資料の出現例 4)。地域が重なっても同じ地震とは限らない。
   - そのため値は自前のまま。90 秒は、分の切り捨て (最大 59 秒) と検知までの遅れを足しても収まる幅として置いた。実際の電文で外れる例が見つかったら直す。
